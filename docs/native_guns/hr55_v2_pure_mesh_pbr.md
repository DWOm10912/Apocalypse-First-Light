## 共面重叠面（z-fighting）消除：GROW

- **问题**：BR51 V2 的已知问题是 525 对共面、同朝向、互相重叠的面（约 58 平方单位），会随视角闪烁，显得杂、有锯齿。原因是逐组、逐层挤出时，重叠部分没有合并。
- **做法**：库函数 `zFightLevels`。
  1. 每个挤出形状或定向盒记为一个 slab。
  2. 找出不同 slab 之间“同一平面、同朝向、重叠面积大于 1e−5”的面对。
  3. 体积大的一方胜出。
  4. 每个胜者取一个等级，比它压住的所有 slab 高一级；整块按“等级 × 0.0025 单位”向外膨胀，使它的面总在前面。
  5. 重建后再检查。膨胀可能让同级的面在共享边上新搭出一条细缝，或者让某个面正好落到邻面的平面上，所以迭代直到归零。
- **HR55 结果**：

  | 轮次 | 冲突面对 | 重叠面积（平方单位） |
  | --- | --- | --- |
  | 1 | 251 | 13.55 |
  | 2 | 20 | 0.58 |
  | 3 | 1 | 0.05 |
  | 4 | 0 | 0 |

  - 93 个 slab 被膨胀，最大 0.0175 单位（第 7 级，约 0.28 像素），肉眼不可见。
  - 按第一人称距离算，这个间隔远大于深度缓冲的分辨率。
- **独立复查**：校验脚本把成品 sidecar 的每个面都当作独立个体再查一遍，共面重叠为 0 对。
- **BR51 没有应用**：它的输出保持不变。以后如果要消除 BR51 的闪烁，可以在它的生成器里打开同一规则。

## 零厚度面板：THIN

- 原作者有 6 个零厚度 cube 当作“衬板”：
  - 机匣右侧（+x）的窗口和长凹槽背后各 1 块；
  - 弹匣井后部 2 块；
  - 下护木通风孔背后 2 块。
- 直接挤出会得到两个重合、朝向相反的面。维护台用 NoCull 渲染，这两个面会闪烁；离线背面检测也在这里看到了背面。
- 现在每块都变成 0.03 厚的薄板，朝枪身中线方向加厚，外露的那一面留在原位置。

## 动态弹药（顶部两发）

- **弹药资产**：12.7×55mm Pure Mesh 整弹 `geo/12_7x55mm_round.geo.json` + `textures/item/12_7x55mm_ammo_v1.png`，见 `native_ammo_assets_v1.md`。
- **配置**：`native_guns/hr55.json` 的 `presentation.magazine_round_visual`：

  ```json
  "anchor": ["bullet1", "bullet2"],
  "loaded_auxiliary_anchor": ["reload_bullet1", "reload_bullet2"],
  "local_offset": [0, 0, 2.11708],
  "local_rotation": [-90, 0, 0]
  ```

  - `bullet1` 是最上面一发（较高），`bullet2` 是第二发。
  - HR55 的这两根骨骼没有旋转，所以用 `local_rotation` 让弹头朝枪口（−Z）。
  - `local_offset` 把弹底放到原 cube 弹的弹底 z 7.91724。
  - 弹轴、弹底、弹尖与原 cube 弹相差不超过 0.005。
- **新增骨骼** `reload_bullet1` / `reload_bullet2`：
  - 挂在 `reload_mag_standard` 下，枢轴与 `bullet1` / `bullet2` 相同，无动画；
  - 原来的换弹新匣没有顶弹骨骼；
  - 放在 `reload_mag_standard` 下面，是因为它在换弹以外缩放为 0，顶弹会跟着隐藏。检视时也就不会在枪内弹匣的位置重复画一份。
- **显示规则**：通用 `NativeMagazineRoundRendering`。
  - 枪内弹匣：余弹 ≥1 显示 `bullet1`，≥2 再显示 `bullet2`。
  - 战术换弹：取下的旧匣按当时余弹显示。
  - 换弹新匣：两发都显示。
  - 检视：HR55 的检视不取下弹匣，按实际余弹显示。
  - 第三人称和维护台：换弹匣整棵子树不渲染，顶弹也不画。
- **尺寸与贴合**：
  - 新弹直径 0.636，比原 cube 弹的 0.5 粗；两发中心距 0.688，不相交。
  - 两发都在弹匣外形之内：半宽 0.88，顶面 7.632。
  - 离线采样发现两处轻微穿插，都在弹匣内部，只有弹匣离枪时从正上方才看得到：
    - 顶层弹上侧被弹匣唇口吃进约 0.054，看起来像被唇口压住；

## 空仓换弹右手接触修正（2026-09-29）

用户实机反馈：空仓换弹“不跟手”。

**原因**
- HR55 全部 9 条动画的 `right_hand_anchor` 都带一个常量位置 `[0, -7, 0]`。它是之前为调整待机时第一人称右手构图加的，见 `hr55_native_integration.md`。
- 只有空仓换弹是右手离开握把去操作：
  1. 拔下旧弹匣；
  2. 插入新弹匣（战术换弹换弹匣的是左手，所以不受影响）；
  3. 拍拉机柄释放枪机。
- 游戏里手臂画在锚点上：锚点就是手掌末端，前臂沿锚点的局部 −Y 方向。
- 这 7 个单位沿前臂方向把右手推离了操作对象：手到弹匣底部、手到拉机柄的距离都是 8–11 个单位，看起来手没碰到东西。
- 把偏移去掉后，原作者的动作是对上的。

**做法**
只在 `reload_empty` 里把 `right_hand_anchor.position` 从常量改为 5 个线性关键帧 `[0, y, 0]`：

| 时间（秒） | y | 说明 |
| --- | --- | --- |
| 0 | −7 | 开始时右手在握把上，与待机相同 |
| 0.0833 | −7 | 右手开始离开握把 |
| 0.25 | 0 | 右手摆向旧弹匣的途中过渡完毕 |
| 3.2167 | 0 | 右手离开拉机柄 |
| 3.4667 | −7 | 回握把的途中恢复，动画结束时与待机相同 |

- 其他通道和其他 8 条动画都没改，枪、弹匣和拉机柄的运动也不变。
- 其他动画的右手基本不离开握把（检视最多偏 2.1 个单位，其余为 0），常量偏移无害，保留。

**离线结果**（按 Blockbench 约定求值，右手接触点到目标的最大距离，单位为模型单位）

| 动作 | 时间（秒） | 修正前 | 修正后 |
| --- | --- | --- | --- |
| 拔旧弹匣（手到旧匣底部） | 0.33–0.75 | 8.7–10.7 | 1.1–2.5 |
| 插新弹匣（手到新匣底部） | 1.5–2.33 | 7.9–9.4 | 1.5–4.2 |
| 拍拉机柄（手到拉机柄） | 2.8–3.13 | 8.1–11.7 | 0.9–3.6 |

**工具**
- 生成器 `tools/build-hr55-v2-mesh.mjs` 的 `RELOAD_EMPTY_RIGHT_HAND` 同时写入源文件和运行时动画。
- `tools/verify-hr55-v2-mesh.mjs` 校验三项接触距离，以及动画首尾的右手与待机一致。

**未实机验证**：过渡段（0.08–0.25 秒、3.22–3.47 秒）右手的观感。
