**材质**：

## 换弹覆盖（通用机制，2026-09-28）

弹匣配件可以在 `data/<ns>/native_attachments/<id>.json` 里覆盖枪的战术换弹和 / 或空仓换弹：

```json
{"reload_overrides": {"empty": {"clip": "reload_empty_drum", "seconds": 3.1667}}}
```

| 字段 | 含义 |
| --- | --- |
| `tactical` / `empty` | 分别覆盖战术换弹 / 空仓换弹，可以只写其中一项，未写的一项使用枪自己的 |
| `clip` | 必须是 `reload_<名称>`，并且在该枪的动画资产和动画清单里都存在，否则忽略覆盖，退回枪自己的换弹 |
| `seconds` | 整个换弹的时长，取值 (0, 60]，换算为 `ceil(seconds × 20)` tick |
| `mag_in_tick`（可选） | 弹药写入的时刻，不能超过总 tick；缺省为换弹结束时（与步枪默认一致） |

- **代码**：
  - `NativeAttachmentData.ReloadOverride` 负责解析；
  - `NativeGunItem.reloadOverride / reloadClip / reloadTicks / magInTick` 读取当前有效的弹匣配件；
  - `ConfiguredNativeGunItem.supportsClip` 负责验证动画是否存在；
  - `NativeGunActions` 在换弹开始时一次性确定动画、结束时刻和写入时刻，换弹途中不会改变。
- **客户端**：凡是以 `reload_` 开头的动画，都按换弹处理：
  - 新弹匣的顶弹显示（`NativeMagazineRoundRendering`）；
  - 镜头骨骼跟随（`NativeCameraBoneConsumer`）；
  - ADS 中断、晃动抑制、膛口气体特效（这三处原本就按 `reload` 前缀判断）。
- **BR51**：动画清单新增 `reload_empty_drum`。弹鼓只覆盖空仓换弹，不覆盖战术换弹，所以战术换弹、35 发匣和标准匣的行为都不变。

## 拼接的空仓换弹 `reload_empty_drum`

原空仓换弹 `reload_empty` 是“以匣击匣”：新弹匣撞出旧弹匣，旧弹匣翻转 −140° 甩出。弹鼓做不了这个动作，所以用 `tools/build-br51-drum-reload.mjs` 把两段已有动画拼成一段（`--check` 只校验不写入）：

| 时间（秒） | 来源 |
| --- | --- |
| 0 – 1.6333 | `reload_tactical` 原样：手拔下空弹鼓、在画面外换上新弹鼓、装入（1.4 秒装入声）。唯一的例外是枪机保持在后方（空仓挂机） |
| 1.6333 – 1.8333 | 所有通道线性过渡到 `reload_empty` 在 1.5 秒时的姿态（接缝处最大差异：枪体旋转约 11°、镜头约 6.5°、左手约 1 单位） |
| 1.8333 – 3.1666 | `reload_empty` 1.5 秒之后的部分，整体后移 0.3333 秒：手移到挂机钮，2.3 秒释放音效，枪机在 2.3666 秒复进，然后收尾 |

- **音效**：0.3 秒 `reload_tactical_1`、1.4 秒 `reload_tactical_2`、2.3 秒 `reload_empty_4`，全部复用已注册的事件。
- **关键帧处理**：两段的关键帧原样复制，保留原有插值方式；只有两个接缝关键帧用线性插值。
- **显隐**：
  - 旧弹鼓副本 `empty_old_mag_standard` 全程缩放为 0；
  - 枪内弹匣 `magazine` 全程缩放为 0；
  - 画面中出现的弹鼓始终是 `reload_mag_standard` 这一份。
- **弹药**：64 tick 结束时写入，服务端换弹也持续 64 tick。
- **来源说明**：这段动画只写在运行时动画文件里，可编辑的 Blockbench 源仍然只保留两段原始换弹。以后枪械师做了正式版本，用同名 `reload_empty_drum` 替换即可。

## 维护台平放

- **原因**：枪在维护垫上侧躺，模型 +X 侧朝下。弹鼓宽 ±3.03，比裸枪在这一侧最远的 2.45 还多出 0.58 单位，会插进垫子。
- **修复**：`MaintenanceGunRendering.transform` 新增抬升量 `restLift`。
  - 用维护台同一套旋转，比较“已装的替换弹匣在绑定姿态下的包围盒”与“裸枪包围盒”在台面竖直方向的最低点；弹匣更低时，整把枪沿竖直方向抬高这段差值乘以缩放。
  - 只会抬高，不会降低，也不会侧移。
  - 按“枪模型 × 弹匣物品”缓存，资源重载时清空。
- **一致性**：渲染、热点、点击拾取、检视几何都走同一个 `transform`，所以热点位置会随枪一起抬高。
- **数值**：BR51 装弹鼓时抬高 0.58 × 0.29 / 16 ≈ 0.0105 格。标准匣和 35 发匣不超出裸枪，抬升为 0。

## 离线校验（`node tools/verify-br51-drum-magazine-50.mjs`：BR51_DRUM50_V1_OFFLINE_PASS）

- 资产规格、材质表与 BR51 一致；外形尺寸不超出参考 cube 的范围。
- 注册：容量 50、三根替换骨骼、整棵子树替换、物品抬升使弹鼓居中、创造标签、中英文名称与说明、物品模型、BR51 的可装配列表。
- 顶部与顶弹：供弹口高度和上段宽度与标准匣一致；顶弹骨骼不在被替换的子树里，锚点落在供弹口内。
- 干涉：颈部以下的鼓体包围盒内没有枪体几何（不含弹匣相关骨骼）。
- 换弹覆盖：
  - 动画在动画文件和 BR51 动画清单里都存在，音效都已注册；
  - 64 tick 不短于动画长度，写入时刻在结束时；
  - 枪机在释放音效之前一直在后方，结束时复进；
  - 不会出现第二个弹鼓。
- 维护台：计算出的抬升量与上文一致。
- 相关生成器的 `--check`（BR51、35 发匣、弹鼓、拼接动画）全部通过。

## 待实机验收

- 装在枪上的外观、第三人称、背包图标、手持和掉落展示。
- **战术换弹**（复用动画）：左手握的是标准弹匣的位置，弹鼓体积大，可能穿插或手形不贴合；换匣时拉到最低点，弹鼓是否仍露在画面里。
- **空仓换弹**（拼接动画）：1.63–1.83 秒接缝处是否顺滑，枪机、手部与挂机释放的节奏。
- **检视**：检视动画会把弹匣拔出、拿到眼前，弹鼓体积大，可能贴脸或穿插。
- **维护台**：平放是否刚好贴住垫子，热点位置是否正确。
