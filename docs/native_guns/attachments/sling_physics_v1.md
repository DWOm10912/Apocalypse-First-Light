## 4. 物理（`physics/rope`）

- `RopeChain`：节点链，Verlet 积分，固定步长 1/240 s，一帧最多 24 步，帧间隔超过 0.1 s 按 0.1 s 算。每步：积分；4 轮｛弯曲、长程约束、快速投影（三对角牛顿，2 轮）、碰撞｝；再自碰撞、摩擦、最后投影。两头钉住，在子步之间插值。
  - 不可伸长：快速投影把每段拉回原长，静止和 Z 页面快速转枪时实测伸长 0.0000。
  - 弯曲：最小弯曲角 0.8、刚度 0.5，像有点硬的尼龙带，不像绳子那样随便打折。
  - 横向刚度（第二轮）：织带是扁的，在自己的平面里几乎弯不动。每个节点沿宽度方向的弯曲不超过一段的 0.1（约 6°），宽度方向取上一帧的 `frames()`；静置算形状时每 24 步刷新一次。圆绳、电线把 `lateralMax` 设成 0。
  - 分量（第二轮）：每步保留 0.986 的速度（三分之一秒后剩约四分之一），节点相对持有者最快 2.5 m/s。晃开 8 cm 后不到 1 s 停稳。
  - 扭转：`frames()` 沿带子传递宽度方向，两头对齐背带环的杆，中间按最小转角分摊；贴着东西时压平（0.8）。
  - 挂钩：第一段和最后一段（销子到出带口 0.0817 m），挂钩节点质量 3（一段带子是 1）。
- `MeshCollider` + `MeshShape`：枪每个骨骼的三角面放进均匀网格。每个节点和段中点在一个子步里的移动做扫掠（第二轮）：相对部件（部件在子步开头和结尾的位置）沿线段找第一个穿进去的三角面，停在入口外一个半径；没穿过再查最近点，封闭部件在背面就算在里面，从最近的面推出去。碰撞体记住上一帧的位置，在子步之间插值；带子被持有者的运动带走多少，碰撞体上一帧的位置也带走多少，扫掠看到的是带子和部件真实的相对运动。每个子步最后再碰撞一次，投影不会把节点拉回部件里。
- `BoxCollider`：人物的头、身体、手臂、腿（立方体放大 0.4–0.8 px，给皮肤外层和身上的装备留位置），也做扫掠（按穿进的面停下）。第一人称的两条手臂按画出来的样子做成盒子（`NativePlayerArmRenderer` 每帧报给 `SlingStraps.arm`）。
- 换上的弹匣（扩容弹匣、弹鼓，`NativeMagazineRendering.drawn`）按弹匣自己的 mesh 碰撞，挂在被替换的骨骼上；没换的标准弹匣是枪 mesh 的一部分。
- 离线检查（scratchpad `rope/RopeCheck.java`，不进仓库）：自由一圈、旋转的 mesh 盒子、绕身体的盒子、两头跳变；第二轮加了快速摆过的 6 mm 薄板、平放、晃动停稳。全部 OK：
  - 伸长 0，转动的枪最深 −0.0029 m（没穿进去），60 fps 一帧 0.244 ms（第一轮 0.146 ms，多了扫掠和横向刚度）；
  - 薄板按真枪比例（每格 0.33 m），尖端最快 7.4 m/s 摆过下垂的带子：只查最近点时 181 帧里 41 帧穿过，扫掠 0 帧；12 m/s 时扫掠还有 2 帧穿过；
  - 侧放的枪旁边平放：在地面里每个节点最多拐 3.5°，没有来回折（以前的方法最多 180°、来回折 3 次）；
  - 两头 0.1 s 内横移 8 cm，0.93 s 后停稳。

## 5. 带子和挂钩怎么画

- 带子（`client/sling/SlingStrapRenderer`）：沿链画一条扁盒子（两个大面 + 两条边，32 × 2.5 mm），贴图取 `gun_sling_strap` mesh（6 cm 一段，`tools/build-equipment-meshes-v1.mjs gunSlingStrap`）各面的 UV，沿带子每 6 cm 镜像重复一次，在段与段交界处切开，不拉伸。
- 挂钩：`gun_sling_hook` mesh（772 个三角形，销子在出带口上方 8.17 cm），画在两头的挂钩段上：+y 从出带口指向销子，+x 沿出带口的带宽；用 Vextris `MeshRenderer.renderParts`，PBR 贴图 `gun_sling_hook_mesh(_n/_s)`。
- 贴图都在 `textures/item`，进方块图集，所以地上和枪架上的枪能连带子一起画进区块。
- 原来身上的 `gun_sling_worn` 不再画（mesh 和贴图还在，没删）。

## 6. 坐标

- 模拟空间：米，世界坐标轴。每根带子的形状按它画的那个框架（枪的根、人物模型的根）缓存，影子渲染直接用缓存画，不再算。
- 第一人称：手的视图空间没有固定比例，按枪的真实长度换算（k = 真实长度 / 模型长度，再除以手持的缩放），枪在模拟里是真实大小。
- 世界里（第三人称、维护台）：视图单位就是米。
- 地上和枪架：在枪自己的模型空间里算（乘 k），重力是世界的下方换到模型空间里。

| 问题 | 原因 | 改法 |

| 甩头穿过枪 | 碰撞只查最近点（约 1 cm 的范围），快速转动时一个子步里部件就越过了带子；最后一次投影还会把节点拉回部件里 | 扫掠碰撞（第 4 节）；每个子步最后再碰撞一次；碰撞体上一帧的位置跟着带子一起被带走 |

| 穿过弹鼓 | 换上的弹匣不在碰撞里 | 弹匣按自己的 mesh 碰撞 |
| 地上歪歪扭扭 | 带子先沿重力方向往地里放一个 V，被地面顶上来挤成之字；没有横向刚度，在地面里能随便折 | 先在枪旁边铺成一道弯（远离枪的中心），再加横向刚度 |

### 11.1 第二轮的回归：装上背带掉到 7 帧、带子不显示（用户 2026-10-22）

> 你到底干啥了，装上背带之后直接掉到7帧，而且背带完全没有渲染出来 / 关了光影也一样

原因：BR-51 的动画把备用弹匣骨骼（`empty_old_mag`、`reload_magazine`）缩放到 0 来隐藏（draw、empty_idle、inspect 等片段）。第二轮让换上的弹匣也当碰撞体，这两根骨骼的矩阵是奇异的，求逆得到 NaN。扫掠的三角形测试用 `u < 0 || u > 1` 这种写法，NaN 让这些判断全部不成立，于是被当成命中，节点位置变成 NaN，一个子步内就传遍整条带子：带子和挂钩都画不出来；NaN 也不会触发"拉断"，带子一直处在 NaN 状态。NaN 节点每次查询的耗时远高于正常（离线实测每帧 20 ms，正常是 0.28 ms），帧数一低，每帧要补的子步变多（最多 24 个），越卡越慢，掉到 7 帧。

离线复现（`GunCheck`：BR-51 真实 mesh，11 根骨骼，14475 个三角形，世界坐标约 (1197, 105, −2138)，鼠标一秒甩两次、每次 120°）：

| 情况 | 修之前 | 修之后 |
|---|---|---|
| 正常 | 0.28 ms / 帧，NaN 0 / 600 | 0.28 ms / 帧，NaN 0 / 600 |
| 两块备用弹匣缩放 0 | 20.3 ms / 帧，NaN 600 / 600 | 0.29 ms / 帧，NaN 0 / 600 |
| 缩放 0.01（过渡中） | — | 0.26 ms / 帧，NaN 0 / 600 |
| 帧时间 0.1 s（每帧 24 子步） | — | 1.36 ms / 帧 |

改法：
- `SlingStraps.colliders`：画出来的尺寸不到原来四分之一的骨骼（动画正在隐藏它）不当碰撞体；这一帧没用到的碰撞体丢掉，重新出现时从当前位置开始，不从几帧前的位置扫过来。
- `MeshCollider`、`BoxCollider`：没有尺寸（缩放到 0）或不是有限数的摆放不参与碰撞；`MeshCollider` 一个子步内移动超过半格的扫掠只按终点处理。
- `MeshShape`：输入不是有限数时直接返回；三角形测试改成 NaN 一律不通过的写法。
- `RopeChain`：节点出现 NaN 也算拉断，重新摆放；`SlingStraps` 里 60 帧内再次摆放时跳过预沉降，带子反复断开也不会每帧多花 20 ms。

改到的文件：`physics/rope/MeshShape.java`、`MeshCollider.java`、`BoxCollider.java`、`RopeChain.java`；`client/sling/SlingStraps.java`。
