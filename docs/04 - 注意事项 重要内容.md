### 1. codex 提示词要求
-**Verified / Frozen 区必须放在提示词最前面。** 已经实机验证过的 Barn、Road Facing、Biome Gate、GenerationStub medianY、Fence topology、Terrain Adaptation、chunk-safe 等，全部明确写成“禁止修改、禁止重写、禁止复制第二套实现”。
- **不仅冻结“结果”，还冻结“正确实现方式”。** 比如 Barn 不能只写“保持可生成”，还要写死必须使用 `real rotated footprint + dynamic lateral search`；Biome Gate 必须使用 AFL 自己的 tag；这样 Codex不能换一套看似等价、实际上有坑的方案。
- **建立“已踩雷禁止清单”。** 像 `StructureTemplate.save()` 进入 worldgen candidate 热路径、Natural另写第二套 Planner、固定 Y=0 做 biome gate、依赖 neighbor update 连接跨 chunk Fence、rotation 变了但 roadFacing 不同步、整个 Lot 拉成泥土平台，这些以后直接作为 `DO NOT USE` 写进相关提示词。
- **任何性能敏感代码必须明确生命周期。** 我不能再只写“解析模板”，而要明确“什么时候解析、最多几次、是否允许出现在 retry loop、是否允许出现在 `/locate` 热路径”。模板级数据默认只能模板级缓存/metadata，一次解析，多次复用。
- **禁止 Codex自由重构已工作的模块。** 新任务只解决当前 bug。需要碰冻结代码时，必须停止并报告冲突，不能自己决定“顺便重构”。
- **修改前必须先审计真实代码和 diff。** `git status --short`、`git diff --stat`、`git diff`，然后明确列出“本轮要复用哪些现有 helper，哪些文件绝对不碰”。
- **提示词里明确 Allowed Files / Forbidden Files。** 如果任务只该动 3 个文件，我会尽量直接写死范围；新增文件也必须说明用途，避免 Codex横向扩散。
- **BUILD 不再等于完成。** 像 worldgen、性能、视觉问题，`BUILD SUCCESSFUL` 只能算 BUILD。没有真正进入新世界执行对应命令，就必须写 `RUNTIME NOT VERIFIED`，不能把启动到主菜单当作验证。
- **每个任务加入“失败即停止”条件。** 例如 `/locate >10s`、出现 far-chunk write、旧 Manual Rural 回归、出现新的空 StructureStart，就立即判 FAIL，不允许继续在失败基础上叠补丁。
- **新增优化必须先证明瓶颈。** 这次 Foundation Support 就是典型教训。以后涉及性能，先计数/计时，再改；禁止“觉得这里可能慢，所以加 cache / 改算法”。
- **新实现必须通过旧问题回归表。** 每次 Rural 改动都要检查我们过去已经修过的关键坑，而不是只测试这轮新需求。
- **如果一个系统已经迭代很多轮，我会把它当成成熟系统维护，而不是原型开发。** 后面 Rural、Highway、Biome、Radiation 等都会越来越严格地采用这种方式。
- **先复用现有逻辑，禁止为一个小问题新建一整套系统。
- **最小改动优先。** 能改 20 行解决，就不能新建 4 个 class。
- **不得为了理论上的完美边界情况牺牲主流程性能。**
- **不得在高频路径做本可延后的精确计算。**
- **Planning 只做 planning，Generation 才做施工。**
- **能用固定数量采样解决，就禁止全 footprint / 全 mask 扫描。**
- **能用已有 metadata，就禁止重新解析模板。**
- **能局部施工，就禁止构建全局 terrain model。**
- **禁止“为了以后扩展”提前加 abstraction。** 当前版本没有明确需求就不要做。
- **禁止 duplicate architecture。** 已有 Planner / helper 就复用，不能另起炉灶。
- **禁止无证据优化。** 没 profiling 证明瓶颈，不允许加 cache、memoization、复杂索引。
- **禁止无限 fallback/retry。** 所有搜索必须有 deterministic hard cap。
- **禁止复杂方案绕过已验证行为。** 简单可以，但不能越过已经冻结的正确性边界。
- 绝对不能为了简单而删掉的正确性底线，例如：

```
chunk-safe
deterministic worldgen
Biome Gate
Road Facing
Barn true footprint
Tier 组成规则
Farm atomicity
Fence topology
不允许 far-chunk writes
不允许强制加载邻区块
```

另一类则允许主动简化：

```
精确 foundation engineering
每格 farm terrain validation
过度复杂的 fallback 搜索
全模板扫描
复杂 cache
为未来预留的抽象层
重复 profiling infrastructure
```

当“更复杂但理论上更完整”和“更简单但满足当前验收标准”两种方案都可行时，必须选择后者。不得
自行追求过度工程化。任何新增 class、cache、planner layer、metadata layer、retry loop 都必须先说明为什么现有代码无法用更简单方式完成；否则禁止新增。
