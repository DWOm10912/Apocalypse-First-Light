### 1. 热力发电机
- 储能上限：100,000 FE
- 发电速度：16 FE/t
- 最大输出：16 FE/t
- 进度条满时暂停燃烧，不浪费剩余燃料
- 进度条有空间后继续燃烧

| 燃料 | 总发电量 | 以 16 FE/t 结算 |
| --- | ---: | --- |
| 煤炭 | 500 FE | 31 ticks × 16 FE + 末 tick 4 FE |
| 木炭 | 500 FE | 31 ticks × 16 FE + 末 tick 4 FE |
| 煤炭块 | 5,000 FE | 312 ticks × 16 FE + 末 tick 8 FE |
| 熔岩桶 | 20,000 FE | 1,250 ticks × 16 FE；返回空桶 |

每 tick 实际生成量为 `min(16, fuelEnergyRemaining, freeCapacity)`，所以不整除时精确结算，不截断或向上补齐。储能满时当前燃料 remaining 保持不变；重新出现空间后继续同一批燃料。

隔离 GameTest 已验证四种燃料精确总量、末 tick 余数、空桶返回、16 FE/t 生成 / 输出以及满电暂停 / 恢复；图形客户端 tooltip 与 `/reload` 操作仍待实机验证。

Power Network V2 在 Level tick 末尾聚合同网 producer 并公平分配；1/3/6 台 Thermal 给 3 台 Crusher 的实测分别为轮转 6/5/5、16/16/16、32/32/32 FE/t。Cable 不储电、不限流、不损耗；完整算法与验证边界见《工业》。

### 2. 能量单元

### 7. 化学反应器
- 储能上限：60,000 FE
- 玩家面对机器正面时，左侧输入液槽：8,000 mB，仅允许外部填充
- 玩家面对机器正面时，右侧废液槽：8,000 mB，仅允许外部抽取
- 最大能量输入：128 FE/t
- 工作消耗：32 FE/t
- 已实现 `chemical_reacting`：黑钨矿 x1 + 水 1,000 mB → 氧化钨 x1 + 工业废液 1,000 mB，15 秒（300 ticks），总能耗 9,600 FE
- 每 tick 仅在物品、输入液、输出空间、废液兼容/容量及 FE 全部满足时推进；阻塞时暂停且不耗 FE。完成 tick 再次验证并原子结算全部输入输出
- 背面为能源线缆接口；流体侧面按玩家面对机器正面时的左右关系动态换算，正面、顶部和底部不提供流体能力
- GUI 通过 `machine_layout/chemical_reactor.json` 共用坐标，显示输入物品槽、Vanilla Furnace 箭头、输出物品槽、FE 与两槽实际 Fluid still sprite
- FE、输入液、废液、物品与进度均保存到方块实体 NBT；拆机时物品独立掉落，机器物品保留 FE 与两槽流体
- Jade 已接入：始终显示 Energy；非空输入液、真实非零加工进度、非空废液和真实输出按顺序显示。流体条复用 Jade 原生容器与真实 STILL atlas sprite、tint、动画；视觉层级仍待客户端检查
- 拆下的 Reactor Tooltip 显示非零 FE / 当前容量、非空输入液和废液名称与储量 / 8,000 mB；空段不显示，读取不修改 NBT。实际钻石镐拆除与重新放置状态一致性已通过服务器 GameTest
- AFL 流体管道不受高度差限制：Fluid Tank 可经管道向反应器左侧输入口自动输送；废液槽非空时，反应器也会从右侧经管道自动输出。左侧输入端口与右侧废液输出端口分别拥有独立的同 tick 累计预算，各最多 `25 mB/t`
- 满载或本 tick 输入预算耗尽的兼容目标不会让选中的压力路线立即消失：在没有其它可立即填充目标时，管网保持刷新同一路径的流体视觉，但传输量为 `0 mB`。可立即填充目标始终优先；目标恢复接收后自动恢复正常传输
- 四朝向右侧上行输出与水平输出已通过 1,000 mB / 40 ticks 服务器测试；满罐不扣源、释放空间后恢复也通过。用户具体故障接法尚未复现，本轮未对现有废液传输代码作推测性修改

### 8. 流体储罐
- Registry ID：`apocalypse_firstlight:fluid_tank`
- 容量：20,000 mB（20 桶），仅存储一种流体
- 带液物品 Tooltip 显示真实流体本地化名称与储量 / 20,000 mB，空液隐藏；水与工业废液的真实钻石镐拆除、Tooltip 读取及 BlockItem 重新放置均已通过服务器 GameTest
- 自动顶面：只允许输入流体，同一 tick 累计最多 `25 mB`
- 自动底面：只允许输出流体，同一 tick 累计最多 `25 mB`
- 四个水平侧面：不提供自动流体能力
- 玩家手持 Forge 流体容器可从堆叠中任意成员的六个面输入或取出统一逻辑槽中的流体；桶等手动交互按容器正常容量一次完成，不受自动端口 `25 mB/t` 限制
- 管道传输不受重力或高度差限制；储罐自身仍保持顶部输入、底部输出、水平面无能力
- V1.5：Fluid Tank 与 Chemical Reactor 的接口外观固定，不因管道连接、拆除或输送状态切换透明开口；Pipe 直接接到接口表面。Tank 外露顶底盖固定使用原封闭端口模型，堆叠内部拼接与连续液面保持原样，邻接 Tank 的 Pipe 使用自身 Core + Arm
- 管道没有真实储液：目标满载或输入预算暂时耗尽时显示的是兼容 Source → Target 路线的背压状态，不会向管道写入流体，也不会从源槽扣除流体
- V1.4.1 管内贴图：真实输送使用 Fluid 的 FLOWING sprite；满载或输入预算阻塞使用 STILL sprite，均保留对应 tint 与 atlas 动画。恢复接收后直接切回 FLOWING，源空或路线失效后继续按原 20 ticks 保留机制清除
