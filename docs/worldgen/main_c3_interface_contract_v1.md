## 0. 为什么要这份契约

用户 2026-10-14 的决定：
- "道路与建筑占地必须由规划阶段协调，不能依赖区块生成先后顺序决定"；
- "请与 Claude C 统一道路连接节点、空间占用、地形施工和结构预留的接口契约，避免双方重复实现"。

Main 和 C 会同时改世界生成，下面四件事必须只有一份：
1. 道路在哪里交接；
2. 地块归谁；
3. 谁动地形；
4. 结构放在哪里。

## 2. 规划顺序（一次算完，和区块无关）

建世界时，在出生点设好、第一个区块生成之前，按固定顺序算完整份规划：
- 只用种子和规划算，不读、不加载、不生成任何区块；
- 结果存进存档（SavedData），并纳入版本锁（第 10 节）；
- 区块生成时，每个区块只读这份规划，各自放自己那部分。谁先生成都一样，也不用常驻加载区块。

编排器 `WorldNetworkPlan` 由 C 写：按 G1..G6 的顺序跑，算出给版本锁的摘要，结果缓存。

| 步 | 谁 | 输入 | 输出 |
|---|---|---|---|
| G0 | 已有 | 种子 | 联邦地图 + C2 地形规划 |
| G1 | C（C3.1） | G0 | 州际、州道的路线，和**沿折线的走廊禁区**（不是包围盒）：硬禁区每 2 m 断面给一次半宽（路基 + 边坡 + 2 m）；软禁区州际半宽 60 m、州道 30 m |
| G2 | Main | G0、G1 的禁区 | **老宅预留**：选址、占地、老宅一侧的连接节点 `H`（院子出口，第 4 节）；2026-10-15 起不含车道走向 |
| G3 | C | G1、G2 | **县道**：`H` → A1 沿路地块区（离 `H` 沿路 0.8–1.5 km）→ 小镇节点 `TownSite`（1.5–3 km，C 在路线上选一块平地）→ 州道，或州际的互通匝道（**不直接接州际主线**）。绕开 G2 的占地；输出沿路地块（第 7 节）。**2026-10-19 起（侧接）**：县道是路过老宅的一条路（离占地 ≥ 80 m），碎石车道从 `H` 接到它的路边；A1 沿路距离以后从车道口沿县道量 |
| G4 | Main | G3 的沿路地块 | **地块预留**：A1 和其他搜刮建筑，各自的连接节点 |
| G5 | C | G3、G4 | 地块进出口：从公路路边接到 G4 的节点 |
| G6 | C 的施工 | G1–G5 的施工请求 | 一份合并好的**地形施工层**（第 6 节） |

- **G2 是纯函数**：（种子、联邦地图、规划面、G1 禁区）→ 老宅预留。只在规划阶段调用，不碰区块和 `Level`。G3 在同一次规划里直接调用它。
- **M4 选址读 C3 的新路线，不读 C1 的 `NationalRoadPlan`**：C3 是在 C2 地形上重新选线，位置会变。
- **G3 接不上**：在规划阶段报冲突，不挪 `H`。退路（Main 提议，C 同日同意）：
  - `StartAreaPlanner` 按优先返回最多 8 个候选址；
  - `WorldNetworkPlan` 按顺序逐个跑 G3，第一个接得上的就用，过程确定；
  - 全部接不上：用第一个，`H` 记成 `DEAD_END`，日志警告；
  - 冲突明细写进规划报告，方便查。
- **老宅先于县道**：老宅先定，`H` 就是县道的必经起点。没有 C3 的世界里，规划停在 G2：
  - 有老宅和 `H`（院子出口），`H` 记成 `DEAD_END`；
  - 没有车道（2026-10-15 起车道归 C，跟县道一起修）；
  - 没有县道，也不放 A1。
- **测试替身**：两边各自开发时用替身，都明确标成"测试替身"，不进正式生成：
  - C 的隔离测试客户端用一个开发专用的 `H`，等 Main 的 G2 进了 C 的分支再换；
  - Main 在独立测试世界里开发 M4 时，用临时路线（例如 C1 的走廊）或明确标出的测试接入点当 G1 替身；C1 的旧路线不能当正式选址依据（用户 2026-10-14）。

## 3. 坐标、方向、形状

- 坐标用 `double`，单位米（= 方块）。
- 方向用度：0 = +X（东），90 = +Z（南），和 R4 样板的 `plan` 命令一致。
- 占地形状三种，不只有包围盒：
  - 水平多边形；
  - 旋转矩形；
  - 折线 + 半宽（道路和车道用）。
- 形状和轻量索引由 Main 放进 `worldgen/network/contract`，C 直接用（C 同日同意）。要求：
  - 纯 Java，不引用 Minecraft，结果确定；
  - 每种形状有 `bounds()`、`contains(x, z)`、`distance(x, z)`：外部为正，内部为 0 或负数，注释里写明是哪一种；
  - 折线 + 半宽：`distance` = 到中心线的距离减半宽；
  - 索引按固定格子分桶（例如 64 m），`query(范围)` 按插入顺序返回，不靠 `HashMap` 的遍历顺序；
  - 不放 `QueryBudget` 这类东西。
- 不用 `worldgen/spatial`（WG-05）：
  - WG-05 只有包围盒，查询接口（`QueryBudget`、`WorldgenIdentity`）也重，而道路是弯折线；
  - WG-05 留着不动，以后真要用再适配。
- 包：契约类型都在 `worldgen/network/contract`（Main 写，C 只读、只同步）；C3 的实现放在 `worldgen/network/` 下的其他子包（`route`、`road` 等），不进 `contract`。两边没有同名文件。

## 4. 道路连接节点 `RoadNode`

公共道路和私人道路 / 地块在这里交接。两边的路面在这一点上**高度相同、方向相同**。

| 字段 | 说明 |
|---|---|
| `id` | 稳定字符串，例：`forest_home_b/driveway`、`lot/<地块 id>/main_entrance` |
| `pos` | 交接点（x, y, z），y 是完工路面的高度 |
| `heading` | 水平方向（第 3 节），从私人一侧指向公共道路 |
| `privateSpec` | 私人一侧的路面规格：`PRIVATE_GRAVEL`（老宅车道，3 m）或 `LOT_APRON`（地块进出口） |
| `publicClass` | 要接的公共道路等级：`COUNTY` / `STATE` / `INTERSTATE`（州际不直接接地块） |
| `width` | 交接处宽度，米 |
| `grade` | 交接处的纵坡；C 的路口按它做过渡 |
| `owner` | 谁建的节点（老宅、地块的节点由 Main 建） |
| `state` | `PLANNED`（只有规划）/ `DEAD_END`（还没有公共道路，私人一侧在这里收尾）/ `CONNECTED` |
| `version` | 记录格式版本 |

规则：
- 私人一侧修到节点为止，公共一侧从节点开始。两种路面的过渡（路口小沥青面、碎石到沥青）**由 C 做**。
- 节点只由结构的主人建，C 不改它的位置。
- **老宅的私人车道（2026-10-15 改）**：用户 2026-10-15："谁来修最有效率就归谁"。C 已经有选线、地形施工、Mesh 路面底座和区块写入，车道只是最低一级的一条路；Main 来修只能在 C 的底座上再包一层。所以私人车道归 C。
  - `H` 在院子出口（老宅模板坐标 (32.5, 26)，占地南边、车棚那条线，随房子转），高度是院子地面；
  - C 从 `H` 修 3 m 碎石车道（`privateSpec = PRIVATE_GRAVEL`，施工参数 `PRIVATE_DRIVEWAY`）接到县道；车道和县道的交口、碎石到沥青的过渡也是 C；
  - 2026-10-19 起（侧接）：车道 100–250 m（最短 100 m，房子从县道上看不到），最后 20 m 垂直接到县道铺装边（两侧半径 6 m 喇叭口），纵坡最后 20 m 不超过 5 %；车道口不立停车让行牌；
  - 原来 P1 选址里的"车道不过溪、长度不超过 250 m"改由 G3 查：接不上就按第 2 节的退路换下一个候选址；
  - 车道口的信箱和大门（Main 的方块 `rural_mailbox`、`tube_farm_gate`）：C 在车道口给一个路边锚点（第 9 节，信箱在路肩外，大门离路肩约 8 m），Main 提供放置方法，C 的区块写入调用。放置方法等 C 的车道有了再一起定。侧接后的锚点（`home`）：大门在车道上离铺装边 8 m、横跨车道；信箱在车道口右侧（从车道往路看），沿路离车道中心 9.5 m、铺装边外 1.2 m，面朝县道；县道到头时另有 ROAD ENDS 路障锚点 `barrier`（模型以后做）；PRIVATE DRIVE 牌以后做；
  - `H` 之内（院子、车棚前）由老宅模板自己负责，C 不进占地。
- 老宅的 `H` 要满足（C 的条件）：
  - `publicClass = COUNTY`；
  - 离任何 G1 硬禁区 ≥ 30 m；
  - 交接处纵坡 ≤ 8%。

## 5. 空间占用 `SpatialClaim`

| 字段 | 说明 |
|---|---|
| `id`、`owner` | 例：`forest_home_b/house`，Main |
| `kind` | `BUILDING` / `YARD` / `PRIVATE_ROAD` / `LOT` / `ROAD_SURFACE` / `ROAD_CORRIDOR` / `TERRAIN_KEEP`（不许别人改地形，例如老宅周围） |
| `shape` | 第 3 节的三种形状之一 + 高度范围 |
| `buffer` | 外扩缓冲，米 |
| `priority`、`hard` | 见下 |

- 优先级从高到低：老宅（硬）> 已放结构的地块（硬）> 公路路面和路基（硬）> 公路走廊软禁区（用来选址，可以在规划阶段让路）> 自然地物（树在占地里不生成，复用 `ForestPlan.exclude`）。
- **老宅的占地和 `TERRAIN_KEEP` 是硬的**：C3 的路面、路基、边坡、排水都不能进去（用户："C3 不能覆盖住宅预留地块，不得破坏老宅周围地形"）。
- 冲突只在规划阶段按优先级解决，结果写进规划。区块生成时不再判断"谁先来"。

## 6. 地形施工 `TerrainWork`（C 提供，Main 是使用者之一）

做成接口，不是数据数组：

| 方法 | 说明 |
|---|---|
| `bounds()` | 施工的外包范围 |
| `double target(x, z)` | 目标高度：平台（房基），或者沿折线的纵断面加横坡（道路） |
| `double weight(x, z)` | 0..1：核心区为 1，外缘羽化带降到 0 |
| `blendWidth()` | 外缘羽化宽度 |
| `priority()` | 和第 5 节一致 |
| `params()` | 施工参数组（下表） |
| `minStableDepth()` | 施工面下面这个深度以内不开洞穴 |
| `waterSpans()` | 桥、涵洞的范围：不填、不压水道 |

施工参数组（用户："公路与房基可以共享基础能力，但必须具有不同施工参数"）：

| 参数组 | 谁用 | 要点（Main 一侧是建议值） |
|---|---|---|
| `ROAD_INTERSTATE` / `ROAD_STATE` / `ROAD_COUNTY` | C | C 定 |
| `HOUSE_PAD` | Main | 小挖小填；外缘缓坡融回林地，不出现直壁；房基石墙按设计露出地面；不压溪岸 |
| `PRIVATE_DRIVEWAY` | C（2026-10-15 起，原来是 Main） | 3 m 碎石；最大纵坡约 12%；随地形起伏，少挖少填；不过溪（G3 查，接不上换候选址） |

合并：
- 先在规划阶段查冲突：
  - 硬占地（老宅、`TERRAIN_KEEP`）里不许出现低优先级施工的核心区；
  - 同一优先级、不同主人的施工重叠，算冲突。
- 生成时按优先级从低到高逐个叠加：`H' = H' + w · (target − H')`。

在密度里的位置：
- 施工层包在 `PlanHeightDensity` 和稳定层外面（在 `Plan*Density` 读高度之前），噪声直接生成成形的地形，不是先生成再挖；
- 规划面本身和它的指纹不变，区块生成先后无关；
- 密度按 4 格网格双线性插值，只能精确到约 ±1 格。精确的面（路面、坡面草皮、房基边缘和基础）由主人自己的区块步骤在噪声之后补齐。

**M4 第一版的房基**（施工层在 C3.2，M4 不等）：
- 老宅注册成一个真正的 `Structure`，带 `terrain_adaptation`，用原版的 beardifier 在区块生成时按结构垫平或压平，和区块生成先后无关；
- 依据：原版的 `overworld.json` 和 AFL 的两份噪声设置里都没有写 beardifier，它是代码统一加在最终密度上的；它只对注册成结构、带 `terrain_adaptation` 的生效；
- **还没实测**，要在测试世界里量跨区块；
- C3.2 的施工层进 Main 后，`HOUSE_PAD` 改走它。这是一次地形规则变化，要升版本锁。

## 8. 结构预留 `StructureReservation`（Main）

| 字段 | 说明 |
|---|---|
| `id` | 例：`forest_home_b`、`lot/<id>` |
| `template` | 结构资产 id，例：`forest_home_b`、`gas_station_01` |
| `pos`、`rotation`、`mirror` | 放置变换 |

## 10. 版本锁

三个子系统，都是 HARD，在锁的历史表里登记：
- `road_network`（C）：路线和路面的规则版本；
- `terrain_works`（C）：施工层怎么应用到密度；
- `start_area`（Main）：老宅选址、预留和放置的规则版本。

现在的锁把"记录里没有的子系统"一律当 HARD（[版本锁](worldgen_version_lock_v1.md)"未知子系统"）。直接加这三个，会拦住所有已经存在的联邦世界。所以要先给锁加**按世界的开关**（C 的设计）：
- 新世界建立时全部打开；
- 已有记录的世界：记录里有这个子系统才打开，版本不同照常算 HARD；
- 记录里没有的就关闭，旧世界的新区块不会长出半截路或半栋房子；
- 领养的旧世界一律关闭。

开关和版本锁由 C 统一负责，在 C3.1 阶段提供，只有这一份；Main 不另写（用户 2026-10-14，第 12 节第 5 条）。老宅的 `start_area` 由 Main 按 C 的规则登记。

C3.1 的实现（C 2026-10-14 通知；在 `feature/federal-highways-c3`，开关 `c41dc17a`、路线 `96683c73`，基于 `a650e8d6`，**还没合进 Main**）：
- 开关清单：`worldgen/lock/WorldgenGates.GATED` = `road_network`、`terrain_works`、`start_area`；
- 规则：新世界全开；已有记录的世界按记录；领养的旧世界全关；记录里没有的子系统不算变化；
- 查询：`WorldgenGateState.enabled(level 或 RandomState, id)`，开关在加载时、第一个区块之前绑到主世界的 `RandomState`；
- 现在没有任何开关子系统被声明，所有世界行为不变；
- 路线：20 段，按 C2 地形重算，数据在 `docs/worldgen/federal_highways_c3.md` 和 `design/worldgen/federal_c3/c3_routes.json`（含每 2 m 的硬禁区半宽）。示范段 `interstate_ew` 和南北线的互通在 (247, −999)，离开局区中心约 600 m。

Main 在这个分支进 Main 以后要做：
1. 在 `WorldgenRules` 里声明 `start_area`，id 用 `WorldgenGates.START_AREA`；
2. 老宅生成里查 `WorldgenGateState.enabled(level, WorldgenGates.START_AREA)`，关着就完全不生成；
3. M4 选址避让读 C3 的路线，不读 C1。
