## 1. 64×64 地块：保留

逐项按 A1 设计坐标核对（地块坐标 u 向东、v 向南、原点在西北角，单位格）：

| 检查 | 结论 |
|---|---|
| 完整方案是否装得下 | 能。所有建筑、设备、停车、车道都在 u、v ∈ [0, 64) 内。最靠边的是西侧车位（u 3）、垃圾围栏和价格牌（u 59）、价格牌（v 61） |
| 是否有东西超出地块 | 结构件都不超出。只有景观树冠超出：u 1.5、u 62、v 0.5、v 62 的树冠半径约 2 格，会伸进相邻地块或道路红线（P2） |
| 停车、车道、加油区是否互相侵占 | 不侵占。前排车位 v 27..32 → 店前通道 v 33..39 → 顶棚 v 40..50，依次相接；西、东车道和顶棚两侧的加油车道是有意重叠（顶棚下就是加油车道）；车位都朝 7 格车道倒车 |
| 道路连接空间 | 南侧临主干道 64 格、东侧临支路 64 格；入口问题见 §3 |
| 旋转后是否还满足 | 地块是正方形，整体刚性旋转，内部距离不变；但 A1 是"右手转角地块"，四向旋转只能覆盖支路在主干道逆时针一侧的转角（§5.4） |
| 顶棚和附属设备是否超出允许范围 | 顶棚 u 12..50、v 40..50，距地块边 ≥ 12 格；边檐压顶模型比格子外挑 0.35 px（§6） |

**结论**：A1 作为一个正式的 64×64 加油站地块变体保留，不扩大地块，也不改 Codex 的 64×72 标准建议。两者并存：

| 变体 | 地块 | 说明 |
|---|---|---|
| A1（本方案） | 64×64 | 右手转角地块，主干道在前、支路在右 |
| Codex 标准加油站 | 64×72 | 临街宽64、纵深72，见正式规格§5 |

命名：仓库现有结构用 `<类型>_<两位序号>`（`convenience_store_01`、`gas_station_01`），旧 `gas_station_01.nbt` 已退出当前源码资产，不复用历史ID，所以建议 A1 的资产 ID 为 `gas_station_02`。地块变体显式记录宽/深及主临街边，A1为64×64；地块配方parser尚未实现，不伪造可加载注册。不要把 A1 放进 64×72 的槽位，除非规格写明多出的 8 格放在哪一侧、入口怎么平移。

## 2. 与 Codex 64×72 的关系

- A1 不依赖 64×72 的任何尺寸；Codex 不需要为 A1 改标准。
- 如果以后要一个 64×72 的 A1，最小改法是在后侧（v 0 一侧）加 8 格后车道或绿化，主干道一侧的入口、店前距离、顶棚位置都不动。这是 P2，不在本轮做。

## 3. 车辆出入口

### 3.1 参数定义

正式规格定义断面并集及8格臂过渡，实际节点尚未规划，因此仍用两个计划相关数表示（东南角是主干道和支路的路口）：
- `L_S`：路口施工边界沿南侧临街面伸进地块正面的距离，从地块东边线（u = 64）往西量。边界停在支路红线以内时 `L_S ≤ 0`。
- `L_E`：同一个路口沿东侧临街面的伸入距离，从地块南边线（v = 64）往北量。
- 距离按入口路面最近的边量，不按入口中心，偏保守。A1 的入口是直切的路缘开口，不带喇叭口；如果规格要求圆角喇叭口，圆角半径要从下面的余量里再扣掉。

### 3.2 逐个入口

| 入口 | 临街面 | 道路 | 原范围 | 中心 | 净宽 | 距东南路口施工边界 | 24 格要求 |
|---|---|---|---|---|---|---|---|
| S1 | 南 | 主干道 | u 8..16 | u 12.5 | 9 | 47 − `L_S` | `L_S ≤ 23` 时满足 |
| E1 | 东 | 支路 | v 1..6 | v 4.0 | 6 | 57 − `L_E` | `L_E ≤ 33` 时满足 |
| E2 | 东 | 支路 | v 51..58 | v 55.0 | 8 | 5 − `L_E` | **不满足**：需要 `L_E ≤ −19`，即路口施工边界停在地块角以南 19 格以外，实际不可能 |

另一头的相邻路口（地块西边、北边以外）距离未知：
- S1 西缘在 u 8，要求西侧路口施工边界在地块西边线以西 ≥ 16 格；
- E1 北缘在 v 1，要求北侧路口施工边界在地块北边线以北 ≥ 23 格。

也就是说，A1 不能紧贴下一个路口，城市规划要在中间至少留出这些临街长度。

### 3.3 E2 处理（P0，已在本文定下最小调整）

- **原值**：东侧支路入口 E2，v 51..58，8 格宽，对着顶棚南侧车道。
- **新值**：删除 E2，那段临街面恢复成绿化（u 60..63、v 51..58）。东侧只保留 E1。
- **原因**：E2 离东南路口的施工边界至多 5 格，远小于 24。放宽安全距离不行；移到 v ≤ 40 − `L_E` 又会撞上东侧车位和绿化，而且只有在路口施工边界完全不伸进地块正面时才勉强达标。所以按"合并出入口"处理。
- **内部车流**：E2 删掉后不需要改内部车道。东车道 u 47..53 从 v 1 一直通到 v 59，南侧车道 v 51..59 东端接东车道。
  - 油罐车：E1 进 → 东车道 → 南侧车道卸油 → S1 出（或反向）。
  - 送货车：E1 进 → 后车道 → 送货门。
  - 加油车：S1、E1 两个方向都能进出。
- **备选（P2，不推荐现在用）**：如果 Codex 规格确认 `L_E ≤ 0`（路口施工边界不伸进地块正面），可以在 v 33..39 开一个对齐店前通道的东侧入口，余量正好 24，没有冗余。

### 3.4 其它入口问题

| 项 | 结论 |
|---|---|
| 行人道和路缘 | S1、E1 都要切断红线内的人行道和路缘。切口喉部取S，通向G的地坪按统一规格§4做3格过渡；具体净宽、行人连续路径及薄路面待实现验证 |
| 连接停车场 | S1 对齐西车道（u 9..15），E1 对齐后车道（v 1..6），都直接接上 |
| 相邻地块 | S1 西缘距西边线 8 格。E1 北缘距北边线只有 1 格，如果规格要求入口离侧向地界有最小距离，或要求圆角喇叭口，E1 会伸进北邻地块的临街面（P1 条件：拿到规格后核对；不满足时把 E1 收成 v 2..6 的 5 格单向入口，或北邻地块的入口与它合并） |
| E1 宽度 | 6 格（约 19.7 ft）双向偏窄（常见商业双向 24 ft ≈ 7.3 格）。作为次要入口可以接受；如果规格有最小入口宽度且大于 6，就是冲突（P1 条件） |
| 消防和送货 | 车道一圈都是 6–7 格。后车道 6 格（19.7 ft）比美国消防通道常见的 20 ft 少 0.1 m（P2） |
| 内部通道 | 前排、西排、东排车位都对着 7 格车道；岛与岛之间净 9 格，两条 4.5 格加油车道 |

## 4. 高度契约

### 4.1 基准

A1 图纸里的 **±0.00 = G**（便利店室内地面 = 人行道顶 = 入口地面）。原设计稿的三维预览把沥青画在 −0.03，只是示意，从本文起按契约改成 `S = G − 3/16`（−0.1875 m）。

下表用"层"表示方块所在的格：第 k 层指 [G + k, G + k + 1)。例如路面方块在第 −1 层，顶面高度 13/16。

| 部位 | 顶面高度 | 所在层 | 说明 |
|---|---|---|---|
| 主干道、支路车行道（入口喉部） | S = G − 3/16 | −1 | 道路自身标高归 Codex；A1 要求 S1、E1 两个喉部的 S 都正好等于 G − 3/16 |
| 红线内人行道、路缘 | G | −1 | 规格原文 |
| 停车场、车位、所有车道 | S | −1 | 商业停车场默认值 |
| 店前、侧面人行道，后墙混凝土 | G | −1 | 店前人行道临停车场一侧自然形成 3/16 路缘 |
| 便利店室内地面、玻璃门、后门 | G | 地面层 0 | 门槛和人行道齐平 |
| 加油顶棚地坪（u 12..50，v 40..50） | **G（推荐，见 4.2）** | −1 | 偏离停车场默认值，有意为之 |
| 油罐卸油区地坪（u 23..39，v 51..59） | **G（同上）** | −1 | 同上 |
| 加油岛路缘 / 端头 | G + 3/16 | 0 | 现有方块，3 px 路缘从格底起 |
| 加油机、底槽 | 加油机 0..2 层，底槽 −2..−1 层 | — | 现有规则 |
| 顶棚立柱 | 0..4 层；吊顶底 G + 5，顶 G + 6 | 0..5 | 现有规则 |
| 泵井盖、卸油口盖 | G | −1 | 关着是整格，顶面在格顶 |
| 潜油泵、管道 | — | −2 | |
| 地下油罐 | 罐顶在 G − 2 | −5..−3 | 3 格高 |

### 4.2 加油区地坪为什么定在 G

现有加油站套件（加油岛路缘和端头、加油机自带路缘、立柱底座、泵井盖、卸油口盖）都按"地面顶 = 整数格"做。
- **放在 S 上（G − 3/16）**：这些件会悬空 3/16，井盖凸出 3/16。要改就得给五种方块各做一个下沉 3/16 的变体。
- **放在 G 上**：现有方块全部原样可用；岛高 3/16（18.75 cm），和真实加油岛一致。

所以推荐：顶棚地坪和卸油区地坪定在 G，四周用 1/16 路面做两圈过渡（S → 14/16 → 15/16 → G），车开上去是缓坡，不是一圈路缘。过渡圈放在地块的车道范围里（地块层负责铺），不进 NBT。

这需要 Codex 的 1/16 路面方块（至少 13/16、14/16、15/16 三档）。仓库文档只说 1/16 道路高程"保持"，没写方块已经可用，按待实现处理（P0 依赖）。

备选：整块停车场都定在 G（只在 S1、E1 喉部过渡），最省事，但店前路缘会消失，并且偏离"商业停车场默认 = S"更多，不推荐。

**不允许的做法**：把整栋店或顶棚整体挪高或挪低半格来掩盖错层。上表各层就是施工依据。

## 5. 坐标与 NBT 契约

### 5.1 地块局部坐标

- (u, k, v)：u 0..63 向东，v 0..63 向南，k 为相对 G 的层号（k = 0 是地面上第一层空气，k = −1 是地面层）。
- 设计方向：主干道在 +v（SOUTH），支路在 +u（EAST），西、北两边接相邻地块。
- 地块整体以旋转 R 放置：世界坐标 = W0 + `StructureTransform.local((u, k, v), R)`，W0 是地块原点 (0, 0, 0) 的世界位置。各模块用同一个 R，模块世界原点 = W0 + `StructureTransform.local(模块地块原点, R)`。这就是原版零点 pivot 规则，不改 `StructureTransform`。
- 已知地块要落在世界矩形最小角 (Xmin, Zmin) 时，W0 = (Xmin + dx, G, Zmin + dz)：

  | R | dx | dz |
  |---|---|---|
  | NONE | 0 | 0 |
  | CLOCKWISE_90 | 63 | 0 |
  | CLOCKWISE_180 | 63 | 63 |
  | COUNTERCLOCKWISE_90 | 0 | 63 |

## 6. 行人和车辆 Socket

`StructureSocket` 只有名字、局部坐标、朝向、类型，没有宽度和连接高度字段。所以车辆入口的净宽和高度写在本文和地块数据里，不塞进 socket。这是给 Codex 的接口提示，不在本轮改 socket 体系。

### 6.1 地块边界上的道路连接（地块数据，不是 NBT socket）

| 名称 | 类型 | 地块坐标（格） | 朝外 | 净宽 | 连接面高度 | 道路 |

## 8. 问题分级

### P0：正式施工前必须解决

1. **E2 入口离东南路口太近**：已在本文删除 E2（§3.3）。需要用户确认这个调整。
2. **实际路口计划待验**：规范已明确节点边界算法；S1/E1仍须对具体节点计算L_S≤23、L_E≤33及相邻路口16/23格余量。没有实际计划，不能标记通过。
3. **地下油罐模板旋转**：`UndergroundFuelTankBlock#rotate` 要按旋转把 `along`、`across` 改成 6 − along、2 − across。代码改动加 GameTest，下一轮经用户同意后做；修好之前油罐模块只能 NONE。
4. **加油区地坪基准**：确认采用 §4.2 的方案（加油区和卸油区为 G，四周 1/16 过渡），依赖 Codex 的 1/16 路面方块（13/16、14/16、15/16）。停车场本身按 S 铺，同样依赖这批方块。
5. **正面方向已解决**：采用NORTH和§5.3。旧exporter固定SOUTH的限制仍存在，正式metadata使用StructureDefinition schema1，不直接采用旧sidecar。
6. **外墙 P0 方块**：A1 设计稿里已经列出的店面玻璃幕墙、两种砖（或大规格砌块）、砌块勒脚、铝檐口、深灰金属板和门框薄侧板、金属雨篷。

   - 新值：外挑 1.0，正好收在后墙混凝土那一格里。
