## 1. 这一轮做什么

## 2. 什么世界会放老宅（临时开关）

> **已过时（2026-10-19）**：`AFL_HOME_` 前缀已去掉。选址也改成读县道 G3 的 `home`，新的联邦世界按 `start_area` 开关都放老宅，见 [M4 第二轮](forest_home_b_m4_round2.md) 第 2 节。下面是第一轮当时的规则；用这个前缀建的旧测试世界照样放它存着的房子。

同时满足才放：
- 新建的世界（`LevelEvent.CreateSpawnPosition`，只在世界第一次创建时触发）；
- 主世界绑定的是联邦规划面（`TerrainPlanSurface#federal()`，新建普通世界的默认）；
- **存档文件夹名以 `AFL_HOME_` 开头**。

这个文件夹前缀是测试替身。契约第 12 节：世界级开关和版本锁归 C，C3.1 进 Main 后换成 C 的开关。旧世界、r1 世界、不带前缀的联邦世界都不放，也没有存档数据。

以后的规则（用户 2026-10-15 定）：联邦新世界**每次都规划和生成老宅**。C 的按世界开关和版本锁只管生不生成（旧世界不生成）；出生看玩家选的开局（选了老宅开局才出生在前廊，选别的开局就出生在别处，老宅留在世界里；选择界面和数据接口归 D 的开局模板池，还没定）。前缀先不去掉：Main 里还没有 C3.1 的路线（G1 走廊是空的），现在每个世界都放，房子可能压在以后的公路上；C3.1 进 Main、选址读到走廊后再去掉。

`/afl dev forest_home find` 列出的 8 个是**候选址**，不是 8 栋房子：只用第 1 个；其余留给 C 接县道时的退路（契约第 2 节：第 1 个接不上就试下一个）。

## 3. 选址（P1，契约 G2）

代码：`worldgen/home/StartAreaPlanner.java`（纯函数，只读种子和规划面，不读世界）。

- 范围：`FederalMap.forSeed(seed).start()` 的开局区（S1 森林州，半径 2 km），按 8 m 网格扫，每处试 4 个朝向；
- 条件（沿用 M0 离线研究，[M0 文档](forest_home_b_whitebox_m0.md) 第 8 节）：
  - 群系：混合阔叶林、坡地林；都没有时才用河岸林；
  - 小溪：离建造区边界 12–40 m，溪宽小于 8 m，占地里没有河；
  - 房子比溪面高至少 2 格；
  - 规划高差：房子范围内不超过 2 格，建造区内不超过 4 格；
  - 前院干地，高度至少 64；
- 去重：同一片地方只留一个（相隔至少 120 m），按种子打分排序，最多 8 个候选；
- 走廊：契约的 G1 禁区还没有（Main 里没有 C3 路线），第一轮传空列表；
- 第一个候选写进存档，其余写进报告（`/afl dev forest_home info` 能看到）；
- 找不到：日志警告，这个世界不放老宅，出生照旧。

## 4. 放置和清场（P3）

代码：`worldgen/home/ForestHomeChunkPass.java`，由 `mixin/ChunkGeneratorForestHomeMixin` 在每个区块的地物步骤开头调用（结构和地物之前）。

模板：`data/apocalypse_firstlight/structures/forest_home_b.nbt`，是 `run/afl_authoring_exports/forest_home_b_m1.nbt`（2026-10-14 18:36 导出）的副本。37 × 13 × 26，空气也在里面，带暗线包和方块实体。模板坐标见 `ForestHomeLayout` 的类注释（模板 y 3 = 地面上第一层空气）。

每个压在房子或整平圈上的区块，只处理自己的列：
1. **房子占地**：地面以下填满（土，深处石头），模板顶以上的地形削平；中间由模板整块覆盖（里面的地形、洞穴、含水层都被模板的方块和空气替换）；
2. **整平圈**：占地外 8 m（`GRADE_MARGIN`），地面从院子的草皮层平滑过渡到自然地面（smoothstep）；保留原来的顶层方块（草、灰化土、石头……）和下面一层；地面上有水的列不动（规划保证占地里没有溪）；
3. **放模板**：只放落在本区块里的那一块（`setBoundingBox`）；`knownShape`，不跨区块边更新形状；不保留液体；带 `AflBlockEntityProcessor`，暗线包和插头偏移跟着房子转；
4. **挡住后来的写入**：`mixin/WorldGenRegionForestHomeGuardMixin`：世界生成期间，别的地物、结构（本区块或邻区块的）都不能写进模板范围，只有模板自己能写。

每一列只看自己和预留，每一块只看本区块，所以区块生成的先后不影响结果。这是临时的土方做法，C3.2 的施工层（`TerrainWork` 的 `HOUSE_PAD`）进 Main 后改用它（契约第 6 节）。

**树让位（P2）**：`ForestHomeRuntime` 给 `ForestPlan.exclude` 注册一条：树干离房子占地小于 14 m（`TREE_CLEARANCE` = 整平圈 8 m + 6 m）就不长。树冠最多伸出 12 m，所以树冠不会盖到房顶上。

## 5. 节点 H 和道路（等 C）

- `H` 放在院子出口：模板坐标 (32.5, 26)，占地南边、车棚那一条线上（纸面 X 22），随房子转；
- 高度 = 地面上第一层空气（`groundY`），朝向 = 房子正面朝向；
- 字段：`forest_home_b/driveway`、`PRIVATE_GRAVEL`、要接 `COUNTY`、宽 3 m、纵坡 0、状态 `DEAD_END`（还没有公共道路）；
- 写在预留里，存档只存原点、朝向、状态和版本，`H` 和占地每次从模板坐标算出来，不会和房子错开。

**车道归 C（2026-10-15 定）**：契约原来写的是 Main 自己把私人车道修到 `H`、在 `H` 收尾成碎石回车场。用户同日定"谁来修最有效率就归谁"：C 有选线、地形施工和路面底座，私人车道归 C，从院子出口的 `H` 修到县道；"不过溪、不超过 250 m"由 C 的 G3 查。契约第 1、2、4、6 节已改，已通知 C。Main 只剩车道口信箱和大门的放置方法，跟 C 的车道一起定。

## 6. 存档、运行时、开发命令

- 存档：`ForestHomeSavedData`（`apocalypse_firstlight_forest_home`），只存模板名、原点、朝向、状态、版本，加上建世界时的选址报告；
- 运行时：`ForestHomeRuntime`。主世界加载时读存档、在服务器线程读模板，交给区块生成线程用；服务器停了就清掉；
- 状态一直是 `PLANNED`：第一轮不统计哪些区块放完了，所以不会变成 `PLACED`；
- 契约类型：`worldgen/network/contract/`，纯 Java，有 `Shape`、`Polygon`、`RotatedRect`、`Polyline`、`RoadNode`、`SpatialClaim`、`StructureReservation`。契约第 3 节的空间索引还没写，第一轮只有老宅一个占用，用不上；
- 开发命令（只在开发环境，OP 2，主世界）：
  - `/afl dev forest_home find`：在当前联邦世界重跑选址，列出候选和用时，不改任何东西；
  - `/afl dev forest_home info`：存档里的预留、模板范围、地面高度、前廊、`H`，加上建世界时的报告；
  - `/afl dev forest_home tp`：传到前廊外。

## 9. 已知问题和下一步

- 铁丝网围栏的立柱按世界坐标排（`(x + z) mod 3`，形状更新时重算）。老宅放下时不更新形状（`knownShape`，免得跨区块边去改邻区块），所以院子围栏的立柱留在模板里的位置，和世界坐标的排法可能差一格；玩家改动旁边的方块后，那一段会重排。只是外观；
- 整平圈外缘如果是很深的沟，8 m 的过渡会比较陡；没加更远的过渡；
- 自然地面上的小地物（草、花、石块）如果在整平前已经由邻区块放下，抬高的列会盖住它们，压低的列会把它们清掉；
- 世界开关是文件夹前缀，C3.1 进 Main 后换；
- 下一轮：P4 出生、P5 物资、P6 燃料（第二轮），P8 广播和调台（第三轮）。
