## 1. A1 做了什么

- 地表变成一张连续的高度场。开发命令可以在地上挖出圆坑，也可以把挖出来的土填回去。
- 坑壁是斜面，没有方形台阶。走进坑里，碰撞贴着画面。
- 体积按整数量子精确守恒：挖出多少，身上就带多少；填下去多少，就扣多少。
- 存档重进以后形状不变；多人时所有看着这个区块的玩家看到同一个形状。
- 没编辑过的地面和现在一模一样，仍然由 Terrain Smooth 画。

## 2. 规则

### 2.1 可编辑列

- 按**列**（一个方块的 x, z）编辑，不是按整个区块激活。这一点和设计 3.1 不同：按区块激活会把整个区块的地面都改成覆盖层来画，风险更大。
- 一列能编辑（`Earthwork.status` 返回 FREE），必须同时满足：
  1. Terrain Smooth 认定的自然地表顶 `t` 存在；
  2. `t` 和 `t - 1` 都是土类方块：草方块、泥土、砂土、灰化土、沙子、红沙、沙砾、泥巴、黏土（`Earthwork.soil`）；
  3. `t - 2` 是实心渲染方块；
  4. `t + 1` 和 `t + 2` 是空的：空气、草丛 / 花这类 `BushBlock`、雪层；
  5. `SmoothRules.freeCorners`：周围 3×3 列都是自然地表（K_NAT），没有被钉住的角点；
  6. 这一列和它东、南、东南三列所在的区块都已加载。
- 一个顶点被最多 4 列读到（方块角上的顶点）。只有读它的每一列都是"已编辑"或"能编辑"时，这个顶点才能动。所以已编辑区域的边缘顶点和未编辑地面共用、而且永远不动，不会出缝，A1 也不需要画侧壁。
- 一列第一次被编辑时（`Earthwork.convert`）：
  - 先按 Terrain Smooth 当前的角点（`TerrainSmooth.fresh` + `SmoothRules.corners/surface`）给这一列的 25 个顶点拍快照，写进 `h` 和 `base`；已经有值的共用顶点保持不动；
  - 记下这一列原来的顶 `top0` 和顶方块 `topState`；
  - 删掉 `t + 1`、`t + 2` 上的草丛、花、雪层。

### 2.2 顶点和数值

| 量 | 值 | 代码 |
|---|---|---|
| 每个方块的格数 | 4（顶点间距 0.25 m，**待验证参数**，A1 实机看了再定） | `EarthGrid.PER_BLOCK` |
| 每列顶点 | 5 × 5 | `EarthGrid.SIDE` |
| 每区块顶点 | 64 × 64，东、南边那一排属于邻区块 | `EarthGrid.CHUNK` |
| 高度量子 | 1/256 方块 | `EarthGrid.Q` |
| 1 量子的体积 | 0.25 × 0.25 × 1/256 m³ ≈ 0.244 L | `EarthGrid.LITRES_PER_QUANTUM` |
| 最深挖到 | `top0` 下 1 格 | `Earthwork.DIG` |
| 最高堆到 | `top0` 上 3 格 | `Earthwork.RAISE` |
| 草皮阈值 | 离原高度不到 1/8 格（32 量子）的顶点还算"没动过"，留着原来的顶面贴图（A1.1） | `EarthGrid.TURF`、`EarthGrid.undisturbed` |
| 休止角 | 表土 35°、沙 34°、砾石 38°、黏土 40°、泥 20°（设计 4.1 表的估计值）；相邻顶点最大高差 = round(tan θ × 256 / 4)，表土 45 量子 | `Earthwork.repose`、`EarthGrid.step` |
| 坍落轮数 | 每次编辑最多 64 轮 | `EarthGrid.SLUMP_ROUNDS` |

- 顶点高度是绝对高度（方块 y × 256 + 量子），存成 int，不是设计里相对 `y0` 的 int16。
- 一个顶点被几列读，就同时受这几列的上下限约束：下限取各列 `(top0 - 1) × Q` 的最大值，上限取 `(top0 + 3) × Q` 的最小值。
- 每个格子沿 nw-se 对角线切成两个三角形，和 Terrain Smooth 画顶面的对角线一样。内部顶点在 6 个三角形里，所以体积 = 格子面积 × Σh / Q，精确成立。
- 笔刷（`EarthGrid.brush`）是圆形：中心深度 × (1 + cos(π d / r)) / 2，四舍五入到整量子。
- 填土（`Earthwork.fill`）先只留下能动的顶点，再用最大余数法（`EarthGrid.distribute`）把"想填的量"和"身上带的量"中较小的那个分下去，分出来的总和正好等于这个量。
- 扣除和增加都按顶点被夹紧以后实际动了多少来算，所以不会复制，也不会丢。

### 2.3 方块不变式

- 已编辑列的 `top0 - 1` 到 `top0 + 2` 这 4 格：
  - 表皮最低点在格子顶面以上 → FULL（整格土）；
  - 表皮最高点在格子底面以下 → AIR；
  - 其他 → SURFACE（表皮穿过这一格）。
- 一格是土，当且仅当它不是 AIR（`EarthGrid.kind`）。每次编辑后 `Earthwork.settle` 把方块改成和表皮一致：
  - 先从上往下删掉变成 AIR 的土；
  - 再从下往上，在不是 AIR 的空格里放土：用 `topState` 的裸土（草方块、灰化土 → 泥土，其他保持原样，`Earthwork.bare`）。
  - 只换空气、草丛、雪层，不碰别的方块。
- 世界生成、光照、寻路、爆炸和别的模组照常只看方块，所以看到的是整格的近似。
- **别的东西改了这 4 格**（放方块、爆炸、命令）：`Earthwork.blockChanged` 把它记下来。服务端 tick 结束时对账：一格土没了，就把读这一格的顶点降到这一格的底面（能降的才降）。
- **徒手或用工具挖 SURFACE / FULL 的土格会被拦下**（A1 起就这样，A1.1 没改），显示 `message.apocalypse_firstlight.earthwork.needs_shovel`（"这块地得用铲子挖"）。创造模式也一样。要恢复原样，用 `/afl dev earth reset`。

### 2.4 坡度：休止角和坍落（A1.1）

挖和填（`Earthwork.edit` 带坡度）都按 `EarthGrid.Field` 的四步走：

1. **范围：** 这次动到的顶点所在的列，向外再扩 1 列。其中已编辑列的顶点都读进来。
   - 一个顶点只有在读它的每一列都已编辑时才能动；
   - 其他读进来的顶点都是"墙"：不动，土也不进不出。可动顶点旁边还没读到的邻居也读进来当墙。
   - 每个可动顶点的最大高差（step）取读它的各列材料休止角里最小的那个（2.2）。
2. **墙的界限（`Field.bound`）：** 可动顶点不能比相邻的墙低 step 以上，也不能高 step 以上。这个界限沿可动顶点一步一个 step 往里传（多源松弛，顺序固定），再和列的上下限（`top0 - 1` .. `top0 + 3`）取交集。
   - 所以贴着不能编辑的地面挖不出直墙，只能挖出 35° 的坡；挖出来的土也相应变少。
   - 本来就比休止角陡的天然坡不会被推动：已经在界限外的顶点只会往界限里走。
3. **移动（`Field.move`）：** 笔刷的量按界限夹紧。实际动了多少，就记多少土。
4. **坍落（`Field.slump`）：** 相邻两个顶点的高差超过 step 时，高的那个把超出部分的一半（整数量子）给低的那个。
   - 按顶点键的固定顺序做，最多 64 轮；
   - 两个顶点都还"没动过"（草皮阈值内）的天然坡不塌；
   - 谁也不会被塌出墙的界限。
   - 总量不变，所以坍落不改身上带的土。

- 结果：坑是碗形的，窄而深的笔刷挖出来的坑也会塌成浅碗；填土堆成 35° 的土丘，不会是柱子。
- **退回（`reset`）和对账（reconcile）不走坡度**（`edit(..., false)`）：只受列的上下限约束，因为退回要回到原样，对账跟着方块走。
- **和设计 3.11 的差别：** 设计里原状土用"开挖角"（表土 63°），松土用休止角；A1 没有松土层，一律按休止角算。**A2 已经分开**（`earthwork_a2.md` 第 2 节）。

## 3. 数据和存档

- `earthwork/EarthChunk`，挂在 `LevelChunk` 上（`mixin/EarthworkLevelChunkMixin`，接口 `EarthChunkHolder`）：
  - `h[4096]`、`base[4096]`：int，`Integer.MIN_VALUE` 表示这个顶点没有数据；
  - `edited`：256 位，哪些列已编辑；
  - `top0[256]`、`topState[256]`：已编辑列原来的顶。
- 设计 3.1 的 `loose`（松土厚度）和 `mat`（材料）A1 没有做；**A2 加上了**（区块数据版本 2，`earthwork_a2.md` 3.1）。
- 存档：区块 NBT 的 `apocalypse_firstlight:earth`（`Earthwork.TAG`），在 `ChunkDataEvent.Save/Load` 里读写。只存有数据的顶点：
  - `v`（索引）、`h`、`base`：IntArray；
  - `edited`：LongArray；
  - `cols`：列表，每项 `{i, y, s}`，`s` 是 `NbtUtils.writeBlockState` 写的方块状态。
- 区块里所有列都退回、所有顶点都清掉以后，数据整个删掉，区块回到纯 Terrain Smooth。
- **旧存档：** 没有这个标签的区块就是没编辑过，不受影响。

## 4. 渲染和碰撞

### 4.1 表皮

- 已编辑列的 SURFACE 格由 `terrainsmooth/client/EarthSkin` 出四边形，经 `SmoothSurfaceModel`：
  - 放在 `ModelData` 的 `SKIN` 属性里，只进 solid 层；
  - 表皮四边形放在不剔除的列表里（side = null）；DOWN 面保留原版的底面，其他面都不画。
- 每个格子的两个三角形先按这一格的上下面裁剪（`EarthGrid.pieces`，Sutherland-Hodgman），每块三角形变成一个四边形（最后一个点重复一次）。
  - 正好躺在格子底面的平片归这一格；正好躺在顶面的平片，如果表皮还要往上，就归上一格。所以表皮的每一点只由一个格子画。
- 贴图：三个顶点都"没动过"（草皮阈值内，2.2）的三角形用 `topState` 的顶面贴图（草、沙……），否则用裸土（`Earthwork.bare`）。
  - 坡度不超过 45° 的块从正上方投影，方向和原版这个位置的变体一致。
  - **陡于 45° 的块（A1.1）** 像原版方块的侧面那样从侧面投影：按法线在 x、z 里更接近的那个轴，u 沿水平方向，v = 1 - 高度（`EarthSkin.sideUv`）。
    - 从上方投影的拉伸是 1/cos，从侧面投影是 1/sin，45° 两者相等，所以在 45° 切换。
    - 坑壁不再出现竖条纹；两种投影交界的三角形边上能看到贴图接缝。
  - 着色（草色）和倾斜明暗烘进顶点色，tint index 为 -1。
- 光照：斜面平光（不用 AO），走 Terrain Smooth 的 slopedNow 交接。光照值取这一列顶上一格、这一格上面一格、四个侧面里非实心那几格的最大值，烘进四边形。
- **表皮格不给邻居压暗（A1.1 补丁）：** 表皮格在数据里是整块不透明的土，可它里面的地面常常只比格子底面高一点点（土堆边缘那几列只抬高几个量子，也会在 `top0 + 1` 放一块土）。原版和 Embeddium 的平滑光照把它当成一面墙，邻居的草顶在它旁边的角就压暗了，土堆外面一圈都是暗带。
  - 现在客户端副本里的表皮格（`Earthwork.clientSkinCell`：土类方块、所在列已编辑、这一格是 SURFACE）在 `BlockStateBase.getShadeBrightness` 里算 1.0，和空气一样（`TerrainSmoothBlockStateMixin.afl$earthShade`）。FULL 格还是 0.2。
  - 截图实测（绿色通道，用户 2026-10-21 的图）：编辑区里的草和远处的草一样，都在 100–105；压暗的是它外面一圈，只有 65–80。所以编辑区本身没有变亮，看起来"亮一块"是暗圈衬出来的。

### 4.2 Terrain Smooth 怎么看已编辑列

- 服务端和客户端都把已编辑列当成"假格子"：`top0` 及以下是自然地面，以上是空气。所以它周围的坡永远按原来的样子算，不会因为这一列被挖了而变。
- `TerrainSmooth.geometry` / `TerrainSmoothClient.renderGeometry` 对已编辑列返回 -1：这一列不再画 Terrain Smooth 的顶面。

### 4.3 碰撞和选中

- SURFACE 格：碰撞 8×8 柱盒（`SmoothRules.GRID`），选中 4×4 柱盒，每根柱子的高度取表皮在柱子中心的高度。泥巴的碰撞低 2/16。沿 x 方向等高的柱子合成一个盒子，形状按高度缓存（`Earthwork.shape`）。
- FULL 格还是整格立方体。
- **选中框（A1.1 补丁，用户 2026-10-21）：** 天然地面和岩石**一律不画选中框**（`SmoothOutline`）：
  - 范围：Terrain Smooth 的地面名单（`TerrainSmooth.ground`，包括已编辑格）、`minecraft:base_stone_overworld`（石头、花岗岩、深板岩……）、`forge:ores`，以及 AFL 命名空间里以 `_ore` 结尾的矿石。
  - 理由：地面是连续的，以后的挖掘和采矿按体积来，不按方块，方块框在上面没有意义。准星就是目标，挖掘的裂纹照常显示。
  - 道路的地面也算地面（用户 2026-10-21，A1 验收后）：C 的坡面草皮 `apocalypse_firstlight:graded_turf` 和路面 `apocalypse_firstlight:road_surface`（路面网格下面看不见的碰撞块）不画框。C 的代码没改，判断在 E 的 `SmoothOutline` 里。
  - `SmoothOutline` 以 `EventPriority.HIGHEST` 先跑，取消事件后，`MeshHitPicking` 那类贴模型的框也不画。
  - 人放的方块和建筑照常有选中框。桥面 `road_structure`、路缘石、护栏这些工程结构照常有框。
  - 这也取消了 Terrain Smooth P1 E 节的斜面轮廓。同一天先做过一版沿表皮画线框的，用户决定不要选中框以后删掉了。
- 站立高度（`standingTop`）、窒息判断、抬升（`lift`）都认这套形状。

## 5. 同步

- 服务端：每次改动把区块记成脏的。`ServerTickEvent` END 时，对每个脏区块：
  - 标记区块需要保存；
  - 清掉周围 3×3 区块的 Terrain Smooth 几何缓存（`TerrainSmooth.forget`）；
  - 用 `EarthChunkPacket` 把**整个区块**的数据发给所有追踪这个区块的玩家；数据为空时发"删除"。
- 玩家开始追踪一个区块（`ChunkWatchEvent.Watch`）时，补发一次。
- 客户端：`Earthwork.CLIENT` 存每个区块的不可变副本，整个替换。所以区块构建线程读到的永远是一份完整的数据。收到以后清掉周围 3×3 区块的几何缓存，再把受影响的方块范围标记重建（`TerrainSmoothClient.earthChanged`）。
- 区块卸载时删掉副本，离开世界时清空。

## 6. 开发命令

`/afl dev earth`，只在开发环境里有（`src/dev/.../dev/earthwork/EarthCommands`），要 OP 2 级，必须是玩家。瞄准 8 格内准星下的地面，没瞄到就用脚下。输出是英文。

| 命令 | 作用 |
|---|---|
| `dig [radius] [depth]` | 圆坑。半径 0.3–6，深 0.05–3（方块），默认 1.5 / 0.5。挖出来的土记在身上 |
| `fill [radius] [depth]` | 用身上的土填，参数同上。最多填身上带的量 |
| `info` | 瞄准的列：已编辑 / 能编辑 / 不能编辑，**不能编辑时说出第一条不满足的条件**（A1.1，见下）；原来的顶、表皮高低、没动过的顶点数；4 区块内的已编辑列、顶点、净体积；身上的土；快照不一致次数 |
| `reset [radius]` | 半径（方块，0–64，默认 8）内的已编辑列退回原样，不再算已编辑 |
| `check` | 4 区块内的已编辑列：缺顶点的列、方块和表皮对不上的格子、超出范围的顶点 |

- 身上的土（`Earthwork.CARRIED`）只在内存里，服务器关掉就没了。A2 的铲子把土装在铲子里（存档），开发命令的 `dig` / `fill` 还是用身上的土。
- 输出里的"refused"是因为读它的某一列不能编辑而没动的顶点数。
- `info` 里 `fixed:` 后面的原因（`Earthwork.why`，按 2.1 的顺序检查，报第一条不满足的）：
  - 区块或东、南邻区块没载入；
  - Terrain Smooth 在这里关着；
  - 没有天然地表（盖了东西、水、悬垂）；
  - 顶、顶下一格不是土类方块，或顶下两格不是实心方块（报方块 ID）；
  - 顶上 1 / 2 格不空（报方块 ID）；
  - 角点不自由（`SmoothRules.notFree`）：顶不是天然地表、正上方不空、某个邻列（报坐标）不是天然地表（人造或上方不空 / 水 / 低两格以上 / 高两格以上 / 没载入），或某个角被钉住（那里四列高差 2 以上）。

## 7. 离线检查

`gradlew earthworkCheck`（`src/test/.../earthwork/EarthworkCheck`），不启动游戏，只测 `EarthGrid` 的数学。失败时退出码 1。

- **划分：** 20000 个随机列（有些落在块边界上）。所有 SURFACE 格的表皮块从上往下看正好把这一列盖满一次：投影面积带符号求和 = 1，同时说明每一块都朝上。每块都在自己的格子里；格子种类从下往上是 FULL、SURFACE、AIR；碰撞盒在格子内。
- **分配：** 2000 次随机分配，各份之和正好等于总量，没有零份或负份。
- **体积和坡度（A1.1 起用游戏里同一套 `Field`）：** 48×48 顶点的场，边缘是墙（当作和未编辑地面共用的顶点），表土休止角 35°。随机挖、填 400 次，每次界限、移动、坍落：
  - 坍落前后总量相同；
  - 挖出 = 带着 + 填下（按量子）；
  - 场的体积变化 = 顶点量子变化 × 格子面积；
  - 贴着墙的、动过的顶点和墙的高差都不超过 step。
  - 另外打印坍落后场内还比休止角陡的"动过"的相邻对数。

结果：
- 2026-10-21 A1：2357842 项检查，0 失败。
- 2026-10-21 A1.1：2358243 项检查，0 失败。400 次编辑共坍落 1559342 量子；场内 3522 对动过的相邻顶点，没有一对陡于 45 量子（35°）。
- 2026-10-21 A1.1 补丁：2358243 项检查，0 失败，和 A1.1 相同（补丁没有改网格的数学）。

- 第一次跑时，划分检查全部报面积为 -1。原因是 `EarthGrid.projectedArea` 的正负号约定反了，不是绕序错了：(nw, sw, se, ne) 和原版 UP 面的顺序一样，本来就朝上。已改成朝上为正，现在检查同时守住绕序。
- 设计第 11 节写的是"随机笔刷 10 万次"。A1 实际是上面这几组，没有做 10 万次。

## 8. 已知限制（A1）

- **在已编辑列旁边放方块可能露缝：** 旁边一列变成非自然地面后，它的 Terrain Smooth 顶面可能和共用的边缘顶点对不上。
- **挖低以后，上面放的方块和积雪可能悬空：** 方块不会自己掉下来。
- ~~准星的选中框用的是 4×4 柱盒，看得出台阶~~：A1.1 补丁起天然地面不画选中框（4.3）。选中判定本身还是 4×4 柱盒，所以准星指在陡壁边上时，挖到的格子偶尔和看到的面差一点。
- **贴图接缝（A1.1）：** 从上方投影和从侧面投影的三角形相邻处，贴图对不上。
- **挖得浅（A1.1）：** 贴着不能编辑的地面，或用窄而深的笔刷时，休止角让坑变浅，挖出来的土比笔刷要的少。这是有意的。
- ~~不分原状土和松土~~：A2 已分开（原状土按开挖角，松土按休止角）。
- **对账可能把土放回去：** 某格土被别的东西删掉，而边缘顶点又动不了时，下一次 `settle` 会按表皮把这格土补回来。
- **感染者寻路**还是按整格方块算。
- **贴图方向**：一列第一次编辑时，顶面贴图的旋转可能变一下（Embeddium 用它自己的随机数选变体，`EarthSkin` 用原版的）。
- **没有配置开关：** 数据只会由开发命令产生；Terrain Smooth 关掉时不能编辑，已有的数据也不画。
- **身上的土不存档。**
- ~~没有铲子、松土、材料表~~：A2 已做，见 `earthwork_a2.md`。
