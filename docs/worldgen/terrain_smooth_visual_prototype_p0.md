日期：2026-10-11。状态：**用户实机比较过，选定 B 方案**（“B更值得开发”，A 的观感不如 B），坡面美术不再改。之后的 P1 加上了碰撞、选中和交互，并把下文的“地表表 + 轮询”换成了现场计算：见 [terrain_smooth_p1_interaction.md](terrain_smooth_p1_interaction.md)。本文保留 P0 的视觉设计；与 P1 冲突的地方以 P1 为准，已在下文标出。

只用来在游戏里直观比较三种地表：原版、方案 A（45° 单格斜坡）、方案 B（约 27° 的双格缓坡）。只在开发环境、一个有限的测试区域、只在客户端画面上生效。不是正式功能，不接入 Terrain V2 生成，不改群系、道路、方块、物品、掉落、挖掘和碰撞，不写任何世界数据。

前一轮的只读审计（地形数据、四条路线对比、风险）见本轮之前的对话报告；这里只记录原型本身。

## 为什么这样做

- 实测（`AFL_R4_01` 存档，约 116 万列）：天然地表相邻两列 97.59% 等高、2.41% 差 1 格、差 2 格以上为 0；只有约 7.7% 的地表列挨着 1 格台阶。所以平原和丘陵上的“折线”基本都是 1 格等高台阶，只需要改这些方块的顶面。
- 方块和存档都不动，所以原型可以随时关掉，关掉后画面就是原版。

## 怎么实现的

代码全部在 `src/dev/java/com/antaurora/apofirstlight/dev/terrainsmooth/`，发布包按 `build.gradle` 的规则排除整个 `dev` 包，不会进正式 JAR。

| 类 | 作用 |
|---|---|
| `SmoothModels` | 模型烘焙完成时（`ModelEvent.ModifyBakingResult`，只在开发运行）包装原版模型：地表方块 `grass_block`、`dirt`、`coarse_dirt`、`sand`、`gravel`、`stone` 的所有状态；所有小植物（`BushBlock` 子类，睡莲除外）。原型关闭时包装层原样返回原版模型 |
| `SmoothPrototype` | 客户端状态：模式、测试区域、统计（P0 的地表表、测量和轮询在 P1 已删除，规则移到 `SmoothRules`） |
| `SmoothSurfaceModel` | 地表方块的区块模型：斜顶面和侧面带 |
| `SinkPlantModel` | 植物的区块模型：跟着斜面上下移动 |
| `SmoothCommands` | 开发命令和发给客户端的消息 |

### 地表表（P0 的做法，P1 已作废）

> P1 起不再预先测量：画面、碰撞、选中每次都按 `SmoothRules` 现场读周围方块（一块读周围 3 × 3 列、自身下 1 到上 2 格），角点规则不变。挖、放以后斜面立刻按新地形重新成形，不再“保持原版”。下面是 P0 当时的做法，留作记录。

- 打开原型（或换区域）时，在客户端从世界里量一遍测试区域，外加一圈：每列的地表高度 H（顶块 + 1）和类别。
- 测量从世界表面高度往下找，跳过空气、植物、雪层、树叶和原木，所以树冠下面的地面也能量到。
- 类别：
  - **天然地面**：区域内、顶块是上面 6 种之一，且上面是空气、植物或雪层，参与平滑；
  - **其他方块**：人工方块、道路、树根下的那块（上面是原木或树叶）、区域外那一圈，不参与，保持原样；
  - **水**；
  - **未加载**、**空**。
- 测量以后改动过的列（挖、放、淹），每秒左右轮询一次发现，从此按“其他方块”处理，保持原版，并让周围的区段重建。这一轮不平滑玩家改动；草蔓延这类同一高度的变化不算改动。未加载的列在区块载入后补量。

### 角点规则（两种方案的唯一区别）

每个方块角点（4 列交汇的点）只算一个高度，摸到这个点的所有方块用同一个值，所以相邻顶面一定严丝合缝：

- 4 列里有任何一列不是天然地面，或 4 列高差 ≥ 2：**钉住**，每个方块在这一点保持自己的高度（悬崖、树根、水边、人工物和区域边界都保持锐利）。
- **方案 A（45° 单格斜坡）**：取 4 列里最低的。只有台阶上面那块削成斜面，下面那块不动；1 格高的单格小凸起会被削平。
- **方案 B（约 27° 双格缓坡）**：取 4 列的平均。上面那块往下降半格，下面那块往上抬半格（会高出自己的格子）。1 格台阶摊成两格宽、1:2 的坡；单格小坑变成浅碟。

### 画法

- **顶面**：按四个角点画一个斜四边形（渲染时沿西北—东南对角线拆成两个三角形）。贴图按原版顶面的方向从上往下投影；草方块的群系着色照旧。
- **侧面**：只画邻格地表到本块顶面之间露出来的那条带子，贴图从带子的上沿往下排，草方块侧面的那圈绿边跟着斜面走。没露出来的侧面不画（原版本来也剔除），底面用原版的。
- **植物**：站在斜面方块上的草、花、蕨、树苗（包括高草和高花的上下两半），按它自己的随机偏移位置算出斜面高度，整株上下移动，不悬空也不埋进去。
- **光照**：
  - 原版的平滑光照（AO）对不贴格子面的四边形，会从方块自己的格子取光（上一轮从字节码确认）；不透明方块格子里的光约为 0，斜面会发黑。所以斜面方块默认**平面光照**，从上方或侧面的空格子取光。
  - Forge 47 只能按方块状态决定要不要 AO，所以在同一个区块构建线程上，由“取模型数据”把“这块是斜面”传给紧接着的 AO 判断（原版和 Embeddium 都核实过是这个顺序）。
  - `ao on` 可以切到 AO，用来对比。
- **明暗**：没有光影包时，斜面按倾斜方向调暗，模仿原版的方向明暗（朝上 1.0、南北 0.8、东西 0.6，按法线混合）；有光影包时交给光影包按法线算。
- 斜面是普通的区块几何：光影的阴影、Embeddium、F3+T 都按地形处理。Xaero 取地图颜色时不带模型数据，拿到的是原版平顶，地图颜色不变。

## 开发命令

前缀 `/afl dev terrain_smooth`。仅开发运行，需要 OP2，必须由玩家执行。原型在玩家自己的客户端上运行，命令只是把指令转过去。

| 命令 | 作用 |
|---|---|
| `off` | 关闭，恢复原版画面 |
| `a` | 方案 A：45° 单格斜坡 |
| `b` | 方案 B：约 27° 双格缓坡 |
| `here [size]` | 测试区域以你站的位置为中心（边长 32–256，默认 192） |
| `area <x> <z> [size]` | 测试区域以 x z 为中心 |
| `status` | 当前模式、仅视觉、区域范围、各类列数、被平滑的方块数（每列一块）及占比、跟着移动的植物数、改动过的列数、各项耗时 |
| `ao on` / `ao off` | 斜面用平滑光照（可能发黑）/ 平面光照（默认） |
| `refresh` | P0：重新量一遍。P1 起：清空形状缓存并重建区域 |
| `collision on` / `collision off` | P1 新增：斜面碰撞和选中（默认开）/ 只改画面 |

没设区域就直接 `a` 或 `b`，以你当时站的位置为中心。

## 两种方案的差异

| | A：45° 单格 | B：约 27° 双格 |
|---|---|---|
| 1 格台阶 | 上面那块削成 45° 斜面，下面不动 | 上降半格、下升半格，两格宽 1:2 的坡 |
| 单格小凸起 | 削平 | 变成低矮的鼓包 |
| 单格小坑 | 四周往坑里倾斜 | 变成浅碟，坑底也抬起 |
| 是否超出方块格子 | 不超出 | 下面那块会高出自己的格子，最多 0.75 格 |
| 观感（推断，待你判断） | 棱角更多，更像方块世界的倒角 | 更圆滑，接近真实地形 |

## 性能风险（只有估算，没有实测）

- **面数**：被平滑的块仍是一个顶面，侧面只画露出来的部分，所以面数和原版同一量级（推断）。
- **区块构建**：包装层对所有草方块、泥土、沙、砾石、石头都会被调用。原型关闭时只读一次模式就返回；打开时，区域外再多判断一次坐标；区域内查表算角点（一次几十次数组读取）。
- **形状缓存**：同一种几何只生成一次，按“几何 + 渲染层 + 是否有光影包”缓存。
- **主线程**：
  - 量表约 37 000 列（192 + 2 的平方）；
  - 轮询每 tick 1500 列，所以改动大约 1 秒后才被发现；
  - 切换模式时把区域内的区段标记重建，会有一次重建高峰。
- `status` 会报实际的耗时：量表毫秒数、每 tick 轮询耗时、区块构建里的查询次数和平均耗时、生成的斜面块数和形状数、标记的区段数。这些都要你在游戏里看到才算数，没有实测，不标 PASS。

## 已知限制

- **碰撞没改**（P0）：人还是走在原版方块上，台阶处要跳；子弹和箭打在原版方块上。P1 已加上斜面碰撞和选中。
- **光照**：斜面是平面光照，旁边的平地是 AO；交界处亮度可能略有不同。`ao on` 可以对比，但斜面多半会发黑。
- **贴花**：弹孔、焦痕、液体贴花还是贴在原版的面上，斜面上会悬空或陷进去。
- **雪层**不移动。高草等两格植物只按下半截底下的那块算。
- **树、水、人工物、区域边界**周围一格钉住不平滑，那里会保留原版台阶。区域边界有一条明显的接缝线，是预期的。
- 只认上面列出的 6 种方块；粗泥以外的灰化土、泥巴、黏土等不平滑。
- 不区分玩家放的方块（P0：测量以后改动的列不再平滑；P1 起：改动后按新地形同样平滑）。

## 最短实机测试

1. 进 `AFL_R4_01`，飞到 `648 110 32` 附近，等区块加载。
2. `/afl dev terrain_smooth area 648 32 192`
3. `/afl dev terrain_smooth a`，看山包顶、山坡、坡脚、河岸四个点。
4. `/afl dev terrain_smooth b`，同样四个点再看一遍。
5. `/afl dev terrain_smooth off`，对比原版。
6. 无光影和 Sundial 各看一次；开着 Xaero 小地图；按一次 F3+T；退出重进以后原型是关着的，重新 `a` 或 `b`。
7. `/afl dev terrain_smooth status` 看数字；有问题的地方记下坐标。
