# 世界生成建筑和统一 Mesh 构件：C 的评估（2026-10-24，设计同步，没改代码）

来源：用户 2026-10-24 的设计同步任务"AFL 建筑体系长期设计同步 — 全面 Mesh 化与玩家自由建造"。本文只记 C（世界生成）这边的理解、影响和建议，不定实施时间，不改现有功能。

相关：记忆里的"材料不是方块"规定（2026-10-24：建材一概不用方块形式，拆除只掉碎片）；`underground_u3_rocks_ores_design.md`（凿下来的石块就是材料）；`town_buildings_v1.md`（现在的镇建筑生成）。

---

## 1. 理解

- 正式建筑不再逐格堆方块。玩家拿材料、用建筑锤和全息蓝图规划真实尺寸的 Mesh 构件：自由尺寸施工（混凝土、砖、地基）和预制构件安装（梁、柱、墙板、门窗框、屋顶、楼梯）两种方式。
- 世界生成的建筑和玩家建的建筑最终共用一套构件：玩家进 Linden 的房子能直接拆隔墙、补屋顶、换窗、加建车库，不用先拆回方块。
- 局部破坏（裂纹、孔洞、削弱、局部坍塌）是长期目标，分阶段做。
- 方块注册、区块、存档照旧做底层；地形不换成 Mesh。

## 2. C 的哪些内容受影响

| 内容 | 现在怎么生成 | 影响 |
|---|---|---|
| Linden 住宅 A / B | `BuildingKit` 程序化生成器往 `BuildingCanvas` 上画方块格（外墙面材、隔墙、门、台阶），`TownBuildingPass` 按区块写进去 | **最大**：整套输出是方块格 |
| 其他镇建筑 | `WhiteBoxKit` 白模占位（一格厚墙、平顶） | 本来就要重做，可以直接按构件做 |
| 加油站 A1、溪谷老宅 | NBT 模板放置（`gas_station_01.nbt`、`forest_home_b.nbt`），A1 冻结、老宅归 Main | 大：模板是方块；迁移归 Main |
| 公路、桥、隧道、护栏、标志、步道牌 | 路面是方块（沥青 + `road_surface` 碰撞），桥、护栏、标志等已经是"看得见的 Mesh + 看不见的碰撞"（记忆：公路构件全是 Mesh），步道牌和标桩是 `TunnelFixture` | 小：已经是 Mesh 工程构件，接受统一损坏 / 拆除 API 即可 |
| 地形、土方、岩石、洞穴 | 方块 + 土方高度场 | 不受影响（地形不是建筑） |
| 以后的废弃矿井（U7）、研究设施 | 还没做 | 正好按构件做：矿井的木支架、巷道衬砌、设施的混凝土墙 |

## 3. Linden 适不适合用统一构件

适合，而且是最合适的一类：

- 北美的木框架住宅本身就是构件拼的：混凝土基础、楼板、2×4 墙骨（16 英寸间距）、外墙板、桁架屋顶、沥青瓦，和蓝图里的构件一一对应。
- 现在的生成器已经有一层语义：`HousePlan` 在房子自己的坐标系（u 沿正面、w 往里、y 从地板）里算出房间、门、台阶、隔墙，只是最后落成了方块。以后把输出从"方块格"换成"构件列表"，规划部分大多能留。
- 用真实尺寸以后，层高可以是 2.4–2.7 m，墙厚 0.15–0.3 m，不用再受 1 m 格子限制。

## 4. 哪些可以保留

- 镇的规划：街网、地块、地块种子、退线、整平和放坡（`TownPlan`、`TownWorks`），和建筑的表现方式无关。
- 区块写入的规则：每个区块只写自己的列、地块挡住树和地物（`WorldGenRegionRoadGuardMixin`）、版本锁。构件化以后同样需要。
- 公路"Mesh 外观 + 隐藏碰撞方块"的做法：已经验证过性能和碰撞，构件建筑的碰撞、光照代理可以照这个来。
- 地基以下、路基、地形照旧是方块和土方。
- 已经实机 PASS 的方块建筑（住宅 A / B、A1）在迁移以前照常生成，不提前推倒。

## 5. 值得提前预留的构件和数据规则

1. **构件描述**（世界生成和玩家共用的格式）：种类、材料、尺寸（米，非整数）、位置和朝向、连接（哪面墙搭在哪根梁上）、开口（门窗洞的位置和尺寸）、结构角色（承重 / 非承重）、状态（完好 / 损坏 / 拆走）。
2. **生成构件的稳定 id**：地块 id + 构件序号，同一个种子永远一样。生成的房子可以从种子重新算出来，存档只记**玩家改过的部分**（拆了哪面墙、补了什么、哪里有洞），不把整个镇存一遍。这是存档大小和"生成的房子玩家能改"的关键。
3. **跨区块：** 一面 5 m 的墙会跨区块。现在 `TunnelFixture` 要求每个构件落在一个区块里，构件建筑做不到。要定构件挂在哪个区块（按锚点）、别的区块怎么查到它，并且和区块生成的先后无关。
4. **底层代理：** 光照、下雨、刷怪、感染体寻路、方块碰撞查询都按方块格算。Mesh 墙要有对应的隐藏代理（每格或更细），0.2 m 的薄墙、斜着放的墙怎么落到格子上要先定规则。
5. **坐标和尺寸规则：** 建筑自己的坐标系（沿用 u / w / y），米为单位，楼层标高，朝向角度；世界生成和建筑锤吸附用同一套。
6. **材料 id 和物品材料一致：** 混凝土、钢筋、各树种木料（记忆：木材按树种）、U3 的各种岩石石块（毛石墙）。生成的房子拆掉以后返还的材料按这套算。
7. **版本：** 构件格式和每种生成器各有版本号，进世界版本锁。

## 6. 应该交给 Main 或建筑系统工作区的

- 建筑锤、全息蓝图、材料投入、施工完成；
- 构件运行时：渲染（要画进区块网格，不能每个构件一个方块实体渲染）、碰撞和光照代理、存档、网络同步；
- 统一的损坏 API（工具、子弹、爆炸、车辆、感染体共用）、孔洞、支撑和坍塌；
- 预制构件的制造（B 的工作台）、材料经济；
- 通用 Mesh 网格库需求交给 Vextris（记忆：共享网格归 Vextris）；
- A1 和溪谷老宅的迁移（Main 的资产）。

C 负责：世界生成建筑怎么产出构件描述、镇和地块怎么接、生成阶段怎么把构件放进世界、生成建筑的离线检查。

## 7. 最大的设计风险

1. **Mesh 外观和方块底层对不上**（最大）：光照、雨、寻路、刷怪、碰撞都是方块格的。薄墙、斜墙、孔洞如果代理没做好，会漏光、漏雨、感染体穿墙、玩家卡墙。要在阶段 B 的第一面墙上就验证。
2. **性能：** 一个镇上百栋房子，每栋几百个构件。必须画进区块网格并缓存（渲染性能 V1 的经验），Oculus 阴影、Embeddium 晚到的方块实体都踩过坑（记忆）。生成时间也要量，现在深世界一个区块已经 88–131 ms。
3. **存档：** 如果生成的构件也逐个存，存档会膨胀；要"种子重算 + 只存改动"。
4. **过渡期两套并存：** 方块房子和构件房子会同时存在很久，建筑锤、拆除、损坏都要能处理两种，或者明确方块房子不能改。

## 8. 建议

- 阶段 A 的规范里先定第 5 节的 1–5 条，尤其是稳定 id、跨区块和底层代理。
- C 这边在规范定下来以前不动已 PASS 的住宅 A / B 和 A1；新的镇建筑种类（现在是白模的那些）等规范出来再做，避免做两遍。
- 阶段 D 选一栋住宅 A 做试点：同一个 `HousePlan` 输出构件列表，和方块版并排对照。

## 9. 岩体雕刻能不能用到 Mesh 建筑的局部破坏（2026-10-24，用户问）

U3a-3 第 2 轮的岩体雕刻（`underground_u3_rocks_ores_design.md` 第 13 节）实机效果用户认可。能直接带过去的：

- **小格体积数据：** 被打过的构件才存一份小格位图，没碰过的不存；
- **一下打掉一块的算法**（`RockCarve.piece`）：从受击点贴着表面长出去，体积固定、宽比深大、每次形状不同、永远连着表面，不会在里面掏出暗洞；
- **平滑面网格**（`CarveNet`，surface nets）：和旁边没打过的部分严丝合缝（离线检查 0 条缝），画进区块网格；
- **小格碰撞盒**、按体积掉碎料、新断面贴图（混凝土、砖的新断口也偏浅）。

要改的：

- **坐标系：** 岩石的小格对齐世界方块；建筑构件尺寸任意、可能斜放，小格要放在构件自己的坐标系里，跟着构件走。
- **分辨率：** 12.5 cm 对岩石够，对 15–20 cm 厚的墙太粗（一下就打穿），墙要 1/16 m 或按构件定。
- **材料不同，坏法不同：** 雕刻适合混凝土、砖、石头这类脆的材料；木头是劈裂、断成条，钢是弯、变形，玻璃是整片碎，各要自己的坏法。
- **结构：** 打出洞以后承重怎么变、什么时候塌，是另一套系统（第 7 节的结构风险）。
- **归属：** 通用的部分（小格场、surface nets、接缝规则）以后建筑系统要用时，按"共享网格归 Vextris"的规定提给 Vextris 或抽成共用模块；C 现在只在地形里用，不提前搬。
