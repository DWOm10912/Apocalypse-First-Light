## 1. 设计原则（用户要求）

- **六个稳定的内部 ID**：`s1`–`s6`。名称和缩写是显示文字，不写进公共 API。
- **固定指北**：-Z 北、+X 东，没有随机整体旋转。
- **两层分开**：
  - **物理层**：地貌区、气候，决定地形和生态；
  - **政治层**：州界，决定名称、路牌、广播、结构和出生。
  - **州界不决定任何方块或群系**。一个州不等于一个群系，边界两侧连续，不会有生态接缝。
- **复用 Terrain V2**：TerrainPlanV2、河网、生态、平滑、碰撞继续用，不写六套地形生成器。
- **V1 的深度**：只有 S1、S2 深做（城市、道路、结构）。其他四州先只做自然环境。

### `FederalMap`（每个种子一份，确定性，线程安全）

| 查询 | 用途 |
|---|---|
| `stateAt(x, z)` | 陆地点（本土或卫星岛）属于哪个州，海上为 null；岛屿归离它最近的那个州 |
| `governingStateAt(x, z)` | 任何地点（含领海）按州界规则归属哪个州 |
| `sample(x, z)` | `MacroGeographySample`：海陆、陆块、海床高度。这就是 TerrainPlanV2 读的掩码格式，规划器可以原样用它 |
| `physiography(x, z, out[6])` / `dominantPhysiography` | 6 个地貌区权重（和为 1，平滑，与州界无关） |
| `temperature` / `moisture` | 0..1 气候梯度 |
| `cities()` / `city(id)` / `islands()` / `crossings()` | 候选城市、卫星岛、跨海连接候选 |
| `start()` | **M4 集成接口**：开局区（所在州、中心、半径 2000 m） |
| `landBounds()` | 全部陆地的包围盒 |
| `coastRadius` / `mainlandDistance` | 海岸半径、到本土海岸的有向距离 |

- **确定性**：只用 JDK 的算术和三角函数，不依赖哈希顺序。同一个种子和尺度，两次独立构建、以及缓存里的实例，查询结果逐位相同（§6）。
- **查询速度**（i7-12700K，单线程）：
  - `stateAt` 约 1.3–1.8 µs；
  - `physiography` 约 0.6 µs；
  - `sample` 约 1.6 µs。
  - 地图、路牌、结构这类偶尔的查询够用。逐方块的热路径（比如每列的生态）应该在 C2 把州 ID 和地貌权重烘焙进规划网格（每格 1 字节），做到 O(1) 查询。

### 4.3 对六个问题的回答

1. **能否在现有规划域里扩大本土？不能，有意义的扩大做不到。**
   - r1 规划域 22.5 km，本土包围盒 14.4 × 13.8 km，最远陆地 8984 m，外海边距 2280 m。
   - 保持同样的外海边距，联邦模板最多只能放大到 ×0.76，即本土约 15.2 × 12.2 km。这和现在的 r1 本土差不多大。
   - 要 20 × 16 km，网格必须加大。
2. **会破坏外海或卫星岛吗？不会。**
   - N = 1760 时最近陆地离网格边 2384 m，比 r1 的 2272 m 还多。
   - 三座卫星岛都在，面积与 r1 同量级，离本土 ≥ 498 m（16 个种子）。
   - 海床沿用 r1 公式（陆架、陆坡、深海、海盆）。
3. **网格要加大吗？要，从 N = 1408 改到 1760**（28.2 km 见方，格数 +56 %）。
   - 16 个种子里最远陆地 11 798 m，1760 能装下所有检查过的种子。
   - 规划器是正方形网格（全部按 N×N 写的），改成长方形能省约 20 %，但要改动规划器每个数组和循环。不值得，不建议。
   - 1760 = 55 × 32，与指纹的 32 格分块对齐。
4. **排水与高度怎样？没有退化。**
   - 逆坡步仍是 0。
   - 封闭洼地每 km² 从 0.48 变成 0.66，仍然很少，而且规划器会填平。
   - 河流线数随面积增加（37 → 69，面积 ×1.9）。
   - 高度分布与 r1 相近。
   - 注意：r1 规划器按本土的主轴自己摆放 r1 的地貌区（褶皱山带、山麓、海岸平原、冰碛平原），联邦的六类地貌**还没接进规划器**，所以"湖区州"现在是山带，"荒漠高原州"是平原（§4.4）。尺度测试证明的是规划器能在联邦掩码上正确跑完，不是六州地形已经做好。
   - 地貌参数是绝对米数，放大国家不会放大单个山岭。×2.0 时陡坡比例降到 0.38 %，山带只占很小一部分。
5. **构建时间和峰值内存能接受吗？×1.0 可以，×1.3 勉强，×2.0 不行。**
   - ×1.0：10.6–12.3 s（三次运行），与 r1 的 9.8 s 几乎相同（行级并行，海洋格很便宜）；采样峰值 +767–951 MB，实际 512 MB 堆就能跑完（r1 需要 384 MB）；缓存 12 MB；常驻 147 MB（r1 是 88 MB）。
   - ×1.3：28 s、峰值 +1.7 GB。
   - ×2.0：150 s、峰值 +3.4 GB。排水阶段明显超线性：格数 5.4 倍，时间 18 倍。
   - 这些数据来自 20 线程的机器。6–8 线程的机器上，×1.0 估计 20–30 s，只在第一次用某个种子时发生，之后读磁盘缓存。
6. **需要分层规划器吗？对 20 × 16 km 不需要。** 直接复用现有规划器，把 N 改成按实例传入，掩码改成可替换即可。只有国家超过 ×1.3 时，才需要分层或分块排水。

### 4.4 C2 必须先解决的规划器改动

1. **网格与掩码**：TerrainPlanV2 / TerrainPlanSurface / RiverNetwork / EcologyPlan 里的静态 `N`、`ORIGIN` 改成按实例传入；掩码来源改成 `MaskSource`（r1 = MacroGeography，联邦 = FederalMap）。
   - 回归门槛：r1 的规划指纹必须仍是 `8d712b1dd53f3bd3 / 90287ece05fe7a5c`。
2. **地貌区**：用 `FederalMap.physiography` 的 6 类权重，替换 r1 的四类权重（belt / foot / coastal / plain），每类配自己的初始地表：
   - 丘陵：沿用 r1 褶皱山带和山麓；
   - 平原：沿用 r1 冰碛平原；
   - 海岸低地：沿用 r1 海岸阶地、溺谷、潮沼；
   - **新做**山地：高起伏、冰川槽谷、陡岩，高度约 Y 150–260；
   - **新做**高原：顶盖岩、台地、峡谷切割、阶梯崖；
   - **新做**湖区：冰川湖盆。规划器现在会把洼地填平，湖要保留为高于海平面的水体，需要新的水面类型和每个湖的水位，运行期加水位填充。
3. **州界与河流**：S1/S5 的自然边界线改成贴着规划出的一条河（州界依赖规划，仍是确定的）。
4. **烘焙查询**：州 ID、地貌权重、气候烘焙进规划网格。

### 4.5 最小堆

- **方法**：`bench.sh floor` 从 256 MB 起逐档试（256 / 384 / 512 MB …，结果在 `build/federal-worldgen/bench/floor.txt`）。
- **结果**：
  - r1：384 MB 能跑完（12.4 s），256 MB 内存不足；
  - 联邦 ×1.0：512 MB 能跑完（14.8 s），384 MB 内存不足。
- **怎么理解采样峰值**：表里的采样峰值是 GC 宽松时的占用，不是下限。
- **游戏里**：规划在集成服务器里构建，和游戏共享堆。额外的临时需求从约 0.4 GB 增加到约 0.5 GB，常驻增加约 60 MB。

## 8. 国家公路规划（E）

### 8.1 方法

`worldgen/federal/NationalRoadPlan.java`（`national_road_plan_v1_proto`，纯 Java，确定性）。

- **路由**：64 m 代价网格上的 A*，16 邻域，堆按 id 打破平局。
- **单格代价**：长度 × 地貌系数：
  - 山地 +3×、海岸湿地 +1.5×、高原 +0.6×、湖区 +0.3×、丘陵 +0.2×；
  - 离岸 250 m 内再 ×1.6；
  - 海不可通行。
  - 已有走廊用过的格打 0.75 折，鼓励共线，让道路在互通处相会，不并排跑。
- **可选地形**（`Terrain` 接口，传入规划高度）：
  - 坡度 2 % 以上开始加价，5 % 以上急剧加价；
  - 进入水面一次 +600（桥）。
- **几何处理**：
  1. Douglas–Peucker 简化，80 m 容差，在州际保留带之内；
  2. Chaikin 平滑 5 次；
  3. 50 m 重采样；
  4. 曲率松弛到半径 ≥ 300 m（R4 平曲线下限），端点固定。
- **节点**：
  - 城市 / 互通 / 交叉：按到达的道路等级判定；
  - 州界穿越：200 m 内去重；
  - 山口：沿线山地权重最高处；
  - 跨海桥：卫星岛连接；
  - 有地形时还有河流 / 河口桥：每 8 m 取样水面，120 m 内去重。
- **保留带半宽**（森林、地块、结构要避开的范围）：州际 60 m、州道 30 m、岛链 30 m。
- **导出**：`toJson()`，字段顺序固定，坐标保留 0.1 m。预览会写出 `national_roads_<种子>.json`。

### 8.2 网络（用户种子，尺度 1.0）

- **走廊**：10 条走廊规格，展开成 23 段：20 段陆路、3 段岛链。
- **长度**：州际 28.9 km、州道 59.5 km、岛链 10.1 km。
- **节点**：互通 6、交叉 4、普通城市 6、州界穿越 9、山口 3、跨海桥 3（跨度 532 / 556 / 580 m）。
- **连通**：16 个城市和 3 座岛全连通。不是每两个州都直接相邻，路网按城市和节点连。

| 走廊 | 等级 | 途经 |
|---|---|---|
| interstate_ew | 州际 | desert_town（s6）→ county_seat（s2）→ valley_town（s1）→ river_city（s1） |
| interstate_ns | 州际 | industrial_city（s4）→ valley_town（s1）→ port_city（s5） |
| sh_mountain | 州道 | mining_town → pass_village（s3，山口）→ farm_town_north（s2） |
| sh_range_front | 州道 | pass_village → desert_town（沿山前绕行） |
| sh_canyon | 州道 | desert_town → canyon_outpost |
| sh_lakes | 州道 | mill_town → industrial_city → port_town（s4） |
| sh_farm_north | 州道 | farm_town_north → mill_town |
| sh_farm_belt | 州道 | farm_town_north → county_seat → farm_town_south |
| sh_gulf | 州道 | farm_town_south → bayou_village → port_city → shore_town → river_city |
| sh_hills | 州道 | valley_town → hill_village → port_town |
| island_bridge:1–3 | 岛链 | 最近的城市 → 跨海桥 → 卫星岛 |

### 8.3 按规划高度布线（诊断，联邦 ×1.0 + r1 地貌）

- **做法**：把联邦 ×1.0 的规划高度和水面（含河流）传给 `Terrain`，重新布线（`bench/national_roads_federal_1.0.json`）。
- **结果**：
  - 全长：州际 30.6 km、州道 61.4 km、岛链 10.2 km；
  - 半径：每段 ≥ 300 m（最小 323 m）；
  - 桥位：河流 / 河口 28 处，另有跨海 3 处。

**坡度**（σ 40 m 纵断面上的最大值）：

| 情况 | 走廊 | 最大坡度 |
|---|---|---|
| 达到 R4 标准 | interstate_ew 全线、interstate_ns 南段（valley_town → port_city）、海湾州道 | ≤ 3.2 % |
| 越过 r1 褶皱山带 | interstate_ns 北段 industrial_city → valley_town | 27.5 % |
| 同上 | sh_lakes 西段 | 18.3 % |
| 同上 | sh_farm_north | 30.9 % |
| 同上 | sh_range_front、sh_farm_belt 北段 | 约 12 % |

**结论**：
- 超标的都是穿越 r1 褶皱山带的北部路段。在六州设计里，那里应该是湖区低地。C2 把六类地貌接进规划器以后要重新评估。
- 无论地形怎样，最终坡度都要靠 C3 的线形设计（展线、填挖、隧道或桥）来满足，走廊本身不承诺坡度。

### 8.4 R4 正式接入还缺什么（C3）

1. **线形设计**：
   - 走廊只是 50 m 折线加保留带。
   - 正式路线要在保留带内拟合平曲线（直线、圆曲线 R ≥ 300 m、缓和曲线）和纵断面（≤ 3 %，σ 40 m 平滑，与 R4 样板一致）。
   - 还要有填挖方限制。
2. **路基进规划**：
   - 路基标高、填方、挖方最好作为规划器的一个阶段烘焙进规划高度，区块生成时地形就已经平整到位，不必事后挖填。
   - 这要升 `terrain_plan`，或者新增 `national_roads` 子系统。
3. **区块切片配方**：
   - 每个区块按规划数据确定性地放路面、路肩、中央带、边坡、护栏，相当于 R4 样板 `R4Earthworks` / `R4Materials` 的世界生成版本。
   - **不允许常驻加载区块**。
   - R4 V1 样板是开发命令往已加载区块里写方块，不能直接用。
4. **桥梁**：
   - 河流 / 河口桥约 28 处（×1.0 诊断）；
   - 3 座跨海桥，跨度 532–580 m；
   - 湿地路段（s5）要用路堤或栈桥。
   - 旧 Highway V2 的跨海桥几何（`SeaBridgeGeometry` 等）可以评估复用。
5. **互通与交叉**：6 处互通（菱形 / 苜蓿叶占地）、4 处州道交叉。R4 样板里没有互通。
6. **道路等级标准**：
   - 州际用 R4；
   - 州道需要自己的标准（用户已有决定：S6 / U6F），包括山口允许的坡度。
7. **碰撞**：`dev_highway_surface` 只存在于开发资源（`src/dev`），正式需要可行驶的平滑碰撞方块。载具还没有。
8. **冲突避让**：
   - 森林（`ForestPlan` 要跳过保留带）；
   - 建筑地块、城市候选；
   - 老宅开局（M4）；
   - 河流雕刻（桥位）；
   - 地形平滑（路面方块不平滑）。
   - 这些需要一个"到最近走廊的距离"查询。数据已经有了，查询还没写。
9. **版本**：接入时给版本锁加 `national_roads` 子系统 id。
10. **旧代码**：
    - `HighwayRouteGraph`（MacroGeography 时代的两条轴向直线主干）已经不再自然生成（`primary_highway` 修改器是 `forge:none`）。
    - C3 决定复用其中的几何类，还是删除。
11. **路牌**：盾牌、公里桩、英文路牌留到更后面。
