# 声音与感染者听觉

## 1. 系统概述

声音系统把服务器上的玩家行为和爆炸转换为带世界坐标、类型及传播半径的 `NoiseEvent`。感染者位于经方块声学衰减后的有效范围内时，会把调查位置更新为真正的声源位置。

当前事件类型包括 `GUNSHOT`、`EXPLOSION`、`BLOCK_BREAK`、`FOOTSTEP`、`LANDING` 和 `INTERACTION`。系统不额外生成感染者，也不改变声音半径、目标选择或听觉记忆时长；噪声广播循环本身只更新听觉与破障授权状态，不在广播循环中直接执行 `createPath`。

如果声音的传播半径超过 10，感染者会尝试朝声源所在位置移动，并尝试破坏路上的易碎阻碍。

为避免大群感染者在同一 tick 同步寻路，首次调查路径按实体 UUID 稳定错开 `0–9 ticks`；成功路径最短 `20 ticks` 后刷新，失败路径冷却 `30–40 ticks`。距离现有目标不超过 2 格的连续声音只刷新最后事件时间，不重置调查 / 搜索阶段或稳定目标 revision；声音位置明显变化时仍会建立新目标。入口搜索为每实体 `40 ticks` 冷却并带 `0–19 ticks` 初始错峰，每轮只对评分最高的至多 8 个候选建立路径。

## 3. 枪声：Noise System V2

枪声由 TaCZ 服务端射击事件产生，声源位置保持为射击玩家的世界位置。基础半径按以下优先级解析：

1. `GunId` 显式覆盖；
2. 未覆盖枪械使用当前 TaCZ 枪械类别 fallback；
3. 未知类别或无法取得枪械索引时使用通用 fallback `80` 格。

当前共有 **45** 把现实枪械使用显式裸枪半径，完整表见 [[枪械]]。原有五个锚点保持不变：M1911 `64`、UMP45 `72`、AK-47/AKM `96`、Kar98 `112`、M107 `160`。

显式值只表示裸枪基础半径。当前 MUZZLE attachment 的 TaCZ `silence` 结构为 `Pair<Modifier, Boolean>`：左侧 `Modifier.addend` 来自 `distance_addend`，右侧布尔值来自 `use_silence_sound`。AFL 用右侧结构化布尔值识别真正 Suppressor，不读取显示名称，也不把所有 MUZZLE 视为消音器。

```text
taczModified = baseRadius + silence.distance_addend

if use_silence_sound == true:
    suppressedCap = max(8, round(baseRadius * 0.10))
    infectedRadius = max(8, min(taczModified, suppressedCap))
else:
    infectedRadius = max(8, taczModified)
```

真正 Suppressor 因而保证感染者听觉半径至少降低 90%，但 TaCZ 自己更强的负 addend 仍会保留，最终下限始终是 8 格。非 Suppressor 枪口只保留原 TaCZ addend 行为，不获得 90% cap。裸枪 45 项显式值、category fallback 和通用 80 均未改变。RPG-7 和 M320 的显式值只表示发射器发射声；弹头爆炸会在命中位置另行产生独立的 `EXPLOSION` 事件。

### 3.1 Gunshot Tinnitus V1

该系统是服务器权威、确定性的短期听觉暴露，不造成伤害，也不保存到玩家 NBT。TaCZ 每次成功射击产生的服务端 `GunShootEvent` 都会进入现有 `TaczNoiseEvents`；automatic / burst 的每一发因此分别累积一次。声源继续使用当前枪声 Noise Event 的 `player.position()`，不会改成命中点。

服务器仅通过当前 `ServerLevel` 的 `getEntitiesOfClass(ServerPlayer.class, AABB, predicate)` 查询声源周围 16 格包围盒内的玩家，不跨维度或遍历全服。射手距离固定为 `0`；其他玩家使用眼睛位置到声源的真实距离。Creative 会处理，Spectator、死亡或 removed 玩家会排除；距离大于等于 16 格时本次增加量为 `0`。

令 `R` 为 `GunshotNoiseResolver.resolveAcousticRadius` 已应用 MUZZLE `silence.distance_addend`、但尚未应用感染者 90% cap 的独立声学输入，`d` 为 listener 距离：

```text
loudness = clamp((R - 64) / 96, 0, 1)
distanceFactor = clamp(1 - d / 16, 0, 1)^2
shotExposure = loudness * distanceFactor * 0.55

if R >= 128: shotExposure *= 1.25
if R >= 160: shotExposure *= 1.35

shotExposure = clamp(shotExposure, 0, 0.75)
```

真正 Suppressor 在 `TaczNoiseEvents → GunshotExposureTracker` 的 listener 查询与 exposure 应用之前直接短路，因此射手和所有附近玩家本发 `shotExposure = 0`；这不借用约 10% 的感染者半径，也不影响 Explosion Tinnitus。制退器、补偿器等非 Suppressor MUZZLE 继续按上式正常累积。

每名玩家的 transient `acousticExposure` 上限为 `1.5`，按服务器时间惰性衰减 `0.008/tick`；从 `1.0` 完全衰减约需 125 ticks（6.25 秒）。阈值为轻度 `0.35`、明显 `0.60`、强烈 `0.90`。服务端 packet throttle 保留 6 ticks 硬间隔，并只在首次触发、severity 至少提高 `0.15`，或持续射击每 20 ticks 需要延长时发送；发送后保留 `45%` exposure。

Gunshot 与 Explosion 的服务器严重度计算保持独立，但共同发送现有 `ExplosionTinnitusS2CPacket`，并进入同一个客户端 Episode。Episode 首个有效 impulse 才创建并播放一次 `ExplosionTinnitusSound`；后续更强 impulse 只提高 severity 并延长剩余时间，较弱或等强 impulse 只延长，均不 stop、new 或 replay 音频，也不把 Overlay 重置到第 0 帧。音频/视觉时间轴自然归零后 Episode re-arm，下一次独立触发才允许再次播放。时长公式仍为 `round(40 + 120 * severity)` ticks，上限 200 ticks，Explosion 的 severity、音量、距离和淡出参数均未重调。

2026-09-06 隔离 GameTest Server 40/40 通过，覆盖 45/9 枪械半径表、M1911/AKM/M107 的 90% cap、AKM 非 Suppressor 枪口、TaCZ 更强 modifier、8 格下限、12 格感染者响应差异，以及 AKM/SCAR-H/M107 真 Suppressor 全 listener exposure 为 0、AKM/SCAR-H/Deagle/M107 裸枪累积、packet throttle、共享 Episode 单次 START 与 re-arm、Explosion 回归。该结果是无图形客户端的服务器/代码验证，不等于实际试听或 Overlay 画面验收。

## 4. 爆炸：Noise System V2

所有进入 Forge `ExplosionEvent.Detonate` 的真实服务端爆炸都会产生一次 `EXPLOSION` Noise Event。事件位置直接使用 `Explosion.getPosition()`；强度读取 live `Explosion` 的实际 radius/strength 字段，不按 TNT、手雷或弹头类型建立硬编码表。

动态半径公式：

```text
rawRadius = 96 + explosionStrength * 24
roundedRadius = round(rawRadius / 8) * 8
noiseRadius = clamp(roundedRadius, 96, 256)
```

| Explosion strength | Noise radius（格） |
| ---: | ---: |
| 2.0 | 144 |
| 2.5 | 160 |
| 3.0 | 168 |
| 4.0（原版 TNT） | 192 |
| 5.0 | 216 |
| 6.0 | 240 |
| 约 6.67 或更高 | 256（上限） |

仅监听 `Detonate`，因此同一实际爆炸不会因同时处理 `Start` 和 `Detonate` 而重复产生噪声。未来爆炸物只要进入标准 Minecraft/Forge Explosion 流程，就会自动使用同一公式。

Explosion Noise 与 Explosion Tinnitus 是两个独立消费者：前者决定感染者听觉范围 `96–256` 格；后者继续使用自己的玩家距离、严重度、音频与 Overlay 计算。两者可以响应同一个 `Detonate`，但互不借用半径或状态。
