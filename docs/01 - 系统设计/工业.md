### 1. 电力系统

电力单位：FE(Forge Energy)

#### 加工机器能耗规则

- 机器 balance 定义 Energy Capacity、Max Input 与固定 Work FE/t。
- 配方只定义生产输入、输出和加工时间，不保存独立 FE/t 或总能耗字段。
- 每次加工进度成功前进 1 tick 时，机器扣除一次固定 Work FE；能量不足或输出堵塞时不前进且不扣能量。
- 单次配方总能耗是派生值：`Work FE/t × processing ticks`。

#### 能源线缆视觉连接

- 线段端点、转弯、分叉及机器接口处显示 Core 与对应方向的 Arm。
- 仅当一个线缆方块的两个相反方向都直接连接能源线缆、且不存在第三条连接时，使用贯穿整格的直线模型及独立无端盖贴图隐藏 Core。
- 该直线内部显示规则对 X、Y、Z 三轴一致；只改变视觉模型，不改变 FE 网络、连接判定或传输行为。

#### 化学反应器 V1 接口

- Chemical Reactor 背面是 FE 输入口，储能 `60,000 FE`，单 tick 最多接收 `128 FE`。
- 配置中预留 `32 FE/t` 工作功率；V1 没有配方或加工循环，因此只储能、不主动耗能。
- 玩家面对机器正面时，左侧为 `8,000 mB` 输入液槽且仅允许填充，右侧为 `8,000 mB` 废液槽且仅允许抽取；其余面不提供流体能力。
- Fluid Pipe 是无重力、高度无关的工业压力管道；AFL 标准自动流体端口统一为 `25 mB/t`。单个真实端口在同一 tick 内累计成功输入或输出最多 `25 mB`，多个源或多个目标不能叠加突破对应端口预算。
- Fluid Tank 自动化仍只从底部输出、只从顶部输入，水平侧不暴露流体能力；Chemical Reactor 左侧输入口是 fill-only 目标，右侧废液口是 drain-only 自动输出源，四个端口各自独立遵守 `25 mB/t` 预算。
- V1.5 固定接口外观：Fluid Tank 与 Chemical Reactor 不因 Fluid Pipe 连接状态改变接口模型或透明像素；管道直接连接接口表面。储罐外露顶底端固定使用 `fluid_tank_port_idle`，堆叠内部继续使用原 join 模型。储罐不再替代管道起始 Core，紧邻储罐的管段使用现有 Core + Arm；连接属性仍服务自动化逻辑。
- Fluid Tank 与 Chemical Reactor 均由源端服务器 tick 主动 push，复用同一套 capability 驱动的 BFS；路径可向上、向下或同高延伸。
- 管网优先选择当前可接受流体的目标；只有不存在可立即填充的目标时，才会选择容量已满或本 tick 输入预算已用尽、但端口与流体仍兼容的目标作为背压视觉路线。该路线继续刷新与正常输送相同的流体、方向 mask 和 20 ticks 保留状态，但本 tick 实际传输量为 `0 mB`，管道本身不保存流体。
- 当目标重新具备容量或输入预算时，同一路线恢复正常的 `25 mB/t` 输送；源流体耗尽、网络断开或目标端口/流体不再有效时停止刷新，现有视觉状态在 20 ticks 保留期结束后清除。
- V1.4.1：实际传输量大于 0 时使用当前 Fluid 的 FLOWING sprite；合法兼容目标暂时无法接收、实际传输为 0 的背压路线使用 STILL sprite。两者复用 Fluid 的 tint 与 atlas 动画，以 `isFlowing` 原位切换，不清空路线或改变方向 mask、保留时间。视觉同步包增加此布尔值，AFL 网络协议由 `6` 升为 `7`，客户端与服务器须使用匹配版本。
- 玩家手持 Forge 流体容器可从 Fluid Tank 任意成员方块的六个面操作统一逻辑储液槽；该手动容器交互不受自动端口 `25 mB/t` 限制。
- GUI 中液位使用当前 Fluid 的 still atlas sprite、tint 与实际储量比例渲染。FE 与两槽流体均持久化，并随正常机器掉落物保留。

##### 实体交互音效 V1

触发层已实现；空间听感验收仍有素材限制。用户实际文件名为 `industrial_waste_splash.ogg` / `industrial_waste_swim.ogg`（没有附件正文中的 `(1)` 后缀），原样复制到 `src/main/resources/assets/apocalypse_firstlight/sounds/`。注册事件为 `apocalypse_firstlight:industrial_waste_splash` 与 `apocalypse_firstlight:industrial_waste_swim`，`sounds.json` 各引用同名音频；仅这两条新 OGG，无重编码、裁剪、normalize 或 resample。

**已知限制：两条原始 OGG 均为 48 kHz、双声道。** Minecraft 当前 OpenAL 路径保留 stereo buffer；标准多声道 buffer 不执行普通 3D spatialization，不能将“世界坐标广播已实现”当成“3D 定位听感已通过”。遵照保留音频内容的要求，当前不擅自转单声道。完成此项需要用户提供 mono 文件或另行授权转换。依据：[OpenAL 1.1 Specification](https://www.openal.org/documentation/openal-1.1-specification.pdf)。

源码 authority：本地 1.20.1 `Entity.updateInWaterStateAndDoWaterCurrentPushing`、`doWaterSplashEffect`、`move`、`nextStep`、`waterSwimSound`、`playSwimSound` 与 `Player.playSound`。Forge `SoundActions` 只有桶填充、桶倾倒、蒸发三项，没有自动 splash/swim 触发；播放事件只能观察已发生的声音，不能补不存在的触发。

定义加权速度 `Q = sqrt(0.2F × vx² + vy² + 0.2F × vz²)`，随机音高 `P = 1 + (randFloat - randFloat) × 0.4`（原版范围约 0.6–1.4）。

| 场景 | 当前触发 / 参数 |
| --- | --- |
| 入液 | Forge 接触高度从不大于 0 变为大于 0；沿用 firstTick 抑制出生即泡液的 splash，持续浸泡不重复，离开后重入可再触发 |
| 大 splash | 原版 `V = min(1, Q × scale)`，自身 scale=0.2，受控载具取控制乘客速度且 scale=0.9；`V >= 0.25` 为大 splash，volume=V、pitch=P |
| 小 splash | 同一原版分界 `V < 0.25`；复用 splash 事件，volume=`V × 0.65`，pitch=`min(1.45, P × 1.075)`。原版大小分支本身不改变参数，这组轻微变体是 AFL V1 选择 |
| 普通游动 / 涉水 | 读取原版 moveDist（碰撞后有效移动距离 ×0.6，Y 仅在可攀爬时计入）；超过独立音效游标后设为 `floor(moveDist)+1`。仅距离实际增加、允许 movement sound、非乘客、脚下判定非空气时发声，不改原版 nextStep / footsteps / game events |
| 游动音量 | `min(1, Q × 0.35)`；受控载具取乘客速度，scale=0.4。普通实体用 deltaMovement；服务器玩家使用本次碰撞后实际位移，避免客户端位置包不提供可靠水平 deltaMovement。volume=0 不播，停止移动不会继续播 |
| 快速游动 | 原版没有单独 fast-swim 事件或速度阈值；本版以正在移动且 sprinting 选择变体，复用 swim，volume ×1.15（上限1）、pitch ×1.075（上限1.45）；更快移动也会更快跨过距离阈值 |
| 边界保护 | Silent 实体不播；同时接触原版水时优先原版水声音；非潜水船的乘客不额外 splash/swim，避免船内乘客接触误报 |

原版 sound 的速度权重区分自身 / 控制乘客，实体宽度影响其 splash 粒子数量，**不直接乘入音量**；此处没有凭体型另造音量公式，也没有新增水花粒子。

两种声音均只在逻辑服务器触发，通过 `level.playSound(null, x, y, z, event, entity.getSoundSource(), volume, pitch)` 广播。`null` 不排除正在移动的玩家；客户端 hook 直接返回，不再本地预测播放同一自定义声音，避免服务器和客户端各播一次。玩家使用原版 `Player.playSound` 会排除自己，因此本版不走该方法。代价是本地反馈取决于服务器延迟。

覆盖继承 Entity 接触路径的玩家、生物及其它实体；游动仍遵守原版 MovementEmission，未给 Boat / Projectile / ItemEntity 建立特殊系统。桶仍是 `SoundEvents.BUCKET_FILL` / `BUCKET_EMPTY`；既有 Water ambient / drip 行为不变，paddle、bubble、专用水下循环等扩展未做。

新增代码：`src/main/java/com/antaurora/apofirstlight/fluid/IndustrialWasteSounds.java`、`mixin/EntityIndustrialWasteSoundMixin.java`；接入 `AflSounds.java`、`sounds.json` 和 `apocalypse_firstlight.mixins.json`。实体仅增加瞬时入液标志、音效距离游标及单次 move 快照，不写 NBT / Capability。FluidType、补源、流动物理、桶、纹理、机器、管道、配方、世界生成、污染和辐射均未改变。

### 2. 矿石/金属
