# 感染者基础规则

本页集中记录普通感染者的日照、感知、增援与破障规则；听觉半径见 [声音与感染者听觉](声音与感染者听觉.md)。

### 2. 对于原版僵尸的改动
- 普通 `minecraft:zombie` 不因日照燃烧，包括站在完整方块、半砖、楼梯、Power Cable、Fluid Pipe 等非完整方块时；真实火源、熔岩和燃烧武器仍可正常点燃并造成伤害。Husk、Drowned、Zombie Villager 等变种保持各自原版日照规则。
- 现在不会生成小僵尸
- 僵尸现在拥有锥型的视野，因此可以shift躲避
- 僵尸的视野不会被透明方块遮挡
- AFL 禁用 Vanilla Zombie Reinforcement：所有 `Zombie` 及子类（包括 Husk、Drowned、Zombie Villager、Zombified Piglin）均不通过受伤呼叫原版增援；枪声仍会吸引周围已有僵尸，自然生成与明确的结构生成不受此规则影响。

#### 日照燃烧闪烁修复 V1

- `ZombieSunlightMixin` 在服务器端的 `Zombie#isSunSensitive()` 提前关闭普通 Zombie 的日照敏感性，阻止日照点火进入 fire ticks / fire flag 同步流程。已移除原 `LivingTickEvent` 中依赖脚下天空判定和恰好 `160` fire ticks 的事后 `clearFire()`；不修改工业方块碰撞箱、真实火焰状态、伤害或客户端火焰渲染。
- 实机运行与视觉尚未验证；需在开阔白天分别检查完整方块、半砖、线缆、流体管道上的 30–60 秒日照，以及 Fire / Lava 的真实燃烧。已有存档中的燃烧状态保留并自然消退，不根据时长猜测来源后强制清除。

#### 僵尸增援禁用 V1.1

- `InfectedEvents` 在服务器 `EntityJoinLevelEvent` 中清空增援专用属性 `minecraft:zombie.spawn_reinforcements` 的全部 modifier（包括 leader bonus），并将 base 设为 `0.0`；该属性范围为 `[0, 1]`，清理后的 `getValue()` 为 `0.0`。新生成、`/summon` 和区块重新加载均通过此入口处理，且归零先于仅适用于普通 Zombie 的 AI 分支。精确 `minecraft:zombie` 还会关闭 Vanilla `BreakDoorGoal`，避免与 AFL 的受控破障 Goal 重叠。
- 复用原有 `ZombieEvent.SummonAidEvent`，在 `LOWEST` 优先级再次归零并返回 `DENY`，拦截入世界后属性被修改的增援尝试；不添加逐 tick 扫描。只清理增援属性，不改变生命、移速等其它属性或枪声响应范围。
- Zombie 转换为 Drowned 等变种时，原版在新实体加入世界后才调用 `handleAttributes`，可能重新添加 leader modifier；`LivingConversionEvent.Post` 在转换完成后复用同一归零方法，补齐此生命周期路径。三个处理入口均使用 `LOWEST` 优先级。
- 旧实现已经对精确 `minecraft:zombie` 返回 `DENY`，Forge 47.4.22 会直接阻止该次增援；旧实现的缺口是未覆盖 Zombie 子类、未清理属性，而非已证实普通 Zombie 的 DENY 失效。主世界自然敌对生成仍只允许普通 Zombie，其他来源进入世界的子类同样适用增援禁令；它们不会因此获得普通 Zombie 的 AFL 噪声 AI。
- 开发 DEBUG 日志 `[AFL INFECTED] Reinforcement reset` 输出处理后的 base、effective 和 modifier 数量；预期分别为 `0.0`、`0.0`、`0`。可用 `/attribute @e[type=minecraft:zombie,sort=nearest,limit=1] minecraft:zombie.spawn_reinforcements get` 检查有效值。
- 2026-09-06 无图形 GameTest 按隔离条件在 Hard 难度、`doMobSpawning=false` 下让 10 个普通 Zombie 各承受 4 次玩家伤害：40 次真实 `SummonAidEvent` 均被 AFL handler 标记为 `DENY`，前后感染者总数不变；Zombie、Husk、Drowned、Zombie Villager、Zombified Piglin 的有效增援概率与 modifier 也分别验证为 `0.0` 和空。该测试不把关闭自然刷怪本身当作唯一证据，而是同时断言了事件拒绝和最终属性。结果验证服务器逻辑，不等于图形客户端实机观察。

#### 感染者破障 AI 性能整理 V1

- 当前 AFL 感染者实体仍是精确 `minecraft:zombie`；没有独立 Runner 或其它自定义感染者实体。允许破坏的方块范围未扩大，仍只由 `#apocalypse_firstlight:infected_breakable` 决定：玻璃、玻璃板、树叶、木门、木活板门、木栅栏和木栅栏门；木板、原木、石头、机器与工业结构不在此表内。
- `InfectedBreachGoal` 的正前方轻量障碍检查改为每只实体独立错峰：正常间隔 `10–20 ticks`，未找到障碍后 `20–40 ticks`。已经开始破坏时只验证当前方块、授权、距离与 claim，不再每次 Goal 更新重新扫描前方。
- 声音调查的首次寻路按 UUID 稳定错开 `0–9 ticks`；成功路径最短 `20 ticks` 后才刷新，失败路径等待 `30–40 ticks` 后再试。相同位置附近（距离不超过 2 格）的连续噪声只刷新最后事件时间，不重置调查阶段、搜索点或稳定目标 revision。
- 建筑入口候选搜索保持 `40 ticks` 冷却，并增加每实体 `0–19 ticks` 初始错峰。每次搜索仍扫描原有 10 格水平范围和 4 格高度范围，但只对评分最高的至多 8 个候选调用 `createPath`，不再对所有候选逐一建路；入口移动命令最短每 `20 ticks` 刷新一次。
- 每个世界中的同一可破坏方块最多允许 1 个活动 breaker claim；claim 在破坏者死亡、移除、方块失效、Goal 停止或 60 ticks 超时后释放。该限制只减少同点争抢，不改变破坏速度或掉落规则。
- DEV 环境每 `200 ticks` 汇总感染者数量、障碍扫描、寻路尝试、破坏目标获取、活动 claim、失败重试与噪声更新；production 不输出该诊断。2026-09-06 最终无图形 GameTest 的 100-tick 压测结果为：20 / 40 / 80 个感染者分别产生 139 / 257 / 544 次局部障碍扫描，同一测试障碍始终最多 1 个 claim；全部 49 项服务器测试通过。真实帧时间、视觉动作与大型存档体验仍需图形客户端实机验证。
