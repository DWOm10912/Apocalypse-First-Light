# 辐射系统

## 0. 一眼看懂

辐射系统现在已经能形成完整的基础生存压力：世界不同区域有不同环境辐射，建筑可以削弱辐射，玩家会累计 Dose，并随 Dose 升高进入辐射病 I–IV。

本页记录当前 live code，并区分代码接入与实机验证。Contamination Core V1A、V1B 与 V1C 已由用户完成实机验证；Container Radiation V1.1 的 point shielding 已通过用户实机验证，32 格边界与 Lead Chest V1 仍等待世界内验证。

## 1. 三个核心概念

### Environment Radiation

简单理解：**你现在站的这个地方有多危险。**

- 单位：`RU/h`
- 来源：世界辐射场、地表群系、安全区和开局生态区共同决定。
- 建筑屏蔽会降低玩家实际受到的环境辐射。
- 当前自然环境范围是 `0–240 RU/h`。

### Dose

简单理解：**你身体已经累计吃进去多少辐射。**

- 单位：`RU`
- 每秒根据玩家当前真正受到的辐射增加。
- 不会自然下降。
- 死亡后仍然保留。
- Dose 决定辐射病等级。

### Residual

简单理解：**你身上现在残留了多少污染。**

- 当前显示单位：`RU/h`
- 在非 SAFE 区域缓慢靠近环境对应的目标值。
- 在 SAFE 区域缓慢衰减。
- 死亡后清零，正常退出和重新登录会保留。
- 目前只作为独立污染读数显示在 Geiger 上，**尚未计入 Dose**。

### Local Radiation

简单理解：附近方块、物品或随身污染物直接造成的局部辐射。

世界位置接口仍然存在，当前固定返回：

```text
localRadiation = 0 RU/h
```

V1C 不把玩家背包硬塞进这个只有 `Level + BlockPos` 的接口。Container Radiation V1 也需要玩家中心、距离和 source→player 射线，因此同样走 player-aware 结果：

```text
playerEffectiveRadiation
= shieldedAmbient + existingPositionLocalRadiation
  + carriedItemRadiation + nearbyContainerRadiation
```

其中 `worldLocalRadiation = existingPositionLocalRadiation + nearbyContainerRadiation`。玩家背着污染物时会持续受照，但不会把这份随身源强辐射给其他玩家；同一个世界容器则可以按各玩家自己的距离和遮挡分别影响多人。

### Item Contamination V1A

这是物品堆自身的离散污染数据，与玩家的 Residual 是两套独立状态。污染等级保存在 ItemStack NBT 的 `AflContaminationLevel` 字节中。

| 数值 | 等级 | 中文显示 | NBT 行为 |
| ---: | --- | --- | --- |
| `0` | `CLEAN` | 洁净 | 不写入该 NBT；清理后若没有其他 NBT，则恢复为无 Tag ItemStack |
| `1` | `TRACE` | 微量 | 写入 byte `1` |
| `2` | `LOW` | 轻度 | 写入 byte `2` |
| `3` | `MODERATE` | 中度 | 写入 byte `3` |
| `4` | `HIGH` | 高度 | 写入 byte `4` |
| `5` | `SEVERE` | 严重 | 写入 byte `5` |

同一个 ItemStack 整堆共享一个污染等级。相同物品、相同污染 NBT 可以按原版规则堆叠；污染等级不同会因为 NBT 不同而分开。Level 0 不添加无意义 NBT，因此洁净物品与原版堆叠兼容。

代码使用同一个纯映射为 V1B 方块掉落和世界战利品确定目标等级：

| 输入值 | 目标等级 |
| ---: | --- |
| `<= 0.000001` | `CLEAN` |
| `< 1` | `TRACE` |
| `< 10` | `LOW` |
| `< 60` | `MODERATE` |
| `< 150` | `HIGH` |
| `>= 150` | `SEVERE` |

Level 1–5 的物品 Tooltip 会显示现有辐射图标和本地化污染等级；Level 0 不增加 Tooltip。辐射图标源纹理为 `18×18`，Tooltip 按 `14×14` 显示。

V1A 已由用户完成以下实机验证：

- Level 0 不写污染 NBT，能与普通 Vanilla clean stack 合并；
- 同污染等级可以堆叠，不同污染等级会分离；
- ItemEntity 丢出/捡回后污染等级保留；
- 退出并重新进入世界后污染等级保留；
- Level 0–5 Tooltip 和工具类物品 Tooltip 显示正常。

### Item Contamination V1B

V1B 只在 ItemStack 生成时执行一次污染赋值。自然世界方块本身仍然没有污染 NBT，也不会被持续扫描。

#### 方块掉落

- Forge Global Loot Modifier 在最终 block loot 结果生成后处理 ItemStack；
- 使用 `LootContext.ORIGIN` 还原被破坏方块原位置，并通过 `BLOCK_STATE` 确认方块掉落上下文；
- 使用当地未经过建筑屏蔽的环境辐射：包含 biome、启动区和安全锚点约束，不包含 player shielding 或 `localRadiation`；
- 直接复用 V1A `getTargetLevel(...)`，不添加随机偏差；
- 最终等级为 `max(existingLevel, environmentTarget)`，干净环境不会自动洗净已有污染；
- 处理发生在 Fortune、Silk Touch 和爆炸条件完成之后，不改变物品种类、数量、经验或掉落判定；
- 通过标准 block loot table 的玩家/非玩家破坏均可覆盖；绕过 loot table 的自定义销毁路径不在 V1B 保证范围内。

#### 世界战利品

- 只处理存在可信 `LootContext.ORIGIN`、且实际 Loot Table ID 路径为 `chests/*` 的结果；
- 当前位置环境辐射先得到 `baseLevel`；建筑屏蔽和 `localRadiation` 不参与；
- `CLEAN` 不消耗随机数且不 jitter；
- 非 CLEAN 容器使用当前 LootContext RNG，在整次生成中只 roll 一次：`15%` 为 `base-1`、`70%` 为 `base`、`15%` 为 `base+1`，最后 clamp 到 `0..5`；
- 本次生成的所有普通 Stack 使用同一个 rolled level，已有更高污染仍通过 `max` 保留；
- GLM 只在 Loot Table 真正生成 ItemStack 时运行；容器内容保存后，重开、区块重载和重新登录不会重新 roll；
- `/give`、创造栏和普通配方不经过该 `chests/*` 路径，保持 Clean。

当前 Industrial Locker 支持原版 Loot Table 生命周期，因此绑定 `chests/*` 表时会自动覆盖。Retail Shelf 当前是手动库存 BlockEntity，并未使用 Loot Table；未来切换到 `chests/*` 输出后才会自动进入 V1B。

Block Drops contamination 与 World Loot contamination 已由用户明确确认实机正常。未据此追加声称 Fortune、Silk Touch、reload 或每一种容器子路径都已逐项测试。

### Item Contamination V1C

每个污染等级现在有唯一的单件基础辐射源强：

| Level | 单件源强 |
| --- | ---: |
| `CLEAN` | `0.00 RU/h` |
| `TRACE` | `0.01 RU/h` |
| `LOW` | `0.03 RU/h` |
| `MODERATE` | `0.08 RU/h` |
| `HIGH` | `0.16 RU/h` |
| `SEVERE` | `0.32 RU/h` |

整堆源强保持线性：

```text
stackSourceRate = perItemSourceRate(level) × stackCount
carriedItemRadiation = Σ directCarriedStackSourceRate
```

例如 `64×SEVERE = 20.48 RU/h`，刚超过普通 Geiger 的 `20 RU/h` 量程。玩家直接携带范围严格为 Hotbar、Main Inventory 和 Offhand；不包括 Armor、Ender Chest、当前打开的容器、Shulker 内部、Curios、机器槽位或附近 ItemEntity，也不会递归扫描嵌套物品栏。

玩家 actual exposure 为：

```text
effectiveRadiation = shieldedAmbient + existingWorldLocalRadiation + carriedItemRadiation
Dose += effectiveRadiation / 3600    （每秒）
```

安全锚点只压制自然环境，不清除 `carriedItemRadiation`。随身源强不改变 `RadiationZone`，也不会改变 Residual 的增长目标；Residual 仍不进入 Dose。

污染 Tooltip 的第一行仍使用 `14×14` 图标显示等级。玩家 direct inventory 中存在 `apocalypse_firstlight:geiger_counter` 时，第二行显示当前整个 Stack 的精确 `RU/h`；Geiger 不必拿在手里。Geiger HUD 和声音仍要求主手或副手持有仪器。当前 SAFE 仪器读数为 `Residual + carriedItemRadiation + worldLocalRadiation`，非 SAFE 时读取完整 `effectiveRadiation`；`>=20 RU/h` 仍显示超量程并使用最大点击率。

V1C 已由用户明确完成以下实机验证：

- Level→RU/h 映射与 Stack 数量线性计算正常；
- direct inventory 的 carried source 确实进入 actual exposure 与 Dose；
- `32×SEVERE = 10.24 RU/h`，移出玩家 Inventory 后当前辐射约下降 `10.24 RU/h`；
- SAFE 区内 carried source 仍然有效；
- Tooltip 与中文本地化显示正常。

英文环境没有在这轮用户实测中单独验证，因此不标记英文 runtime verified。

V1C 明确没有实现动态物品污染、地面 ItemEntity 空间源、污染生物、污染方块存储、洗消或独立 carried total NBT。普通容器空间源从下一节的 Container Radiation V1 开始实现。

### Container Radiation V1.1

普通容器采用 `0%` 自屏蔽，即 `containerTransmission = 1.0`；Lead Chest 使用专用的 `containerTransmission = 0.50`。容器内部源强只遍历该 BlockEntity 的 direct slots：

```text
internalRadiation = Σ ItemContamination.getStackSourceRate(directStack)

containerContribution
= internalRadiation
  × containerTransmission
  × (1 / max(1, distanceSquared))
  × pointShieldingTransmission
```

- `distanceSquared` 是玩家包围盒中心到容器 BlockPos 中心的欧氏距离平方；最大查询半径为 `32 blocks`，距离 `<=32` 时正常计算，超过后贡献为 `0`；
- source→player 使用一条点源射线，不复用环境辐射的 14-ray 平均；射线从源方块外开始，容器本体不参与 shielding；
- 射线每穿过一层 `apocalypse_firstlight:radiation_shielding`，透射率乘以 `0.35`，降至 `<=0.01` 后提前停止；
- 单条射线中的 shielding BlockPos 使用局部 primitive set 去重，同一坐标最多计算一次；Minecraft DDA 在 face/edge/corner tie 时每步只选择一个确定体素，不向多个相邻体素扩散；player endpoint 在 Tag 检查前停止；
- 多个容器贡献线性相加，不取最大值；
- 根据 `playerCenter ± 32 blocks` 动态计算 min/max chunk，只读取相交的已加载 chunk 中已有 BlockEntity；最坏每轴 5 个、共 25 个 chunk，不加载新区块，也不添加 chunk ticket；
- 扫描优先读取 `Container` 自身 slots，否则才读取 Forge `ITEM_HANDLER`，两条路径不会同时执行；
- Vanilla Chest/Trapped Chest、Barrel、placed Shulker、Hopper/Furnace 等直接库存，AFL Lead Chest、Industrial Locker、Retail Shelf 与带物品槽机器均可进入扫描；Energy Cell 没有 ItemStack 库存，因此不是容器辐射源；
- 双箱按两个 `ChestBlockEntity` 各自真实保存的 `27 slots` 分别计算，不读取会组合为 54 格的 Forge chest handler，因此不会双计；
- 未展开 LootTable 的随机容器保持未生成状态并暂不贡献；辐射扫描不会为了读槽位提前生成战利品；
- 不递归读取容器物品内部库存。Chest 中的 Shulker Box ItemStack 只按该 Stack 自己的污染计算；placed Shulker 的 27 个 direct slots 正常计算；
- 每个玩家的结果使用弱引用、最多 `20 ticks` 的瞬时缓存，使 Dose 结算和 10-tick 同步调用共享同一次约 1 秒扫描。没有持久 NBT、全局 source registry 或 per-container cache。

SAFE 只压制自然环境，不清除 `nearbyContainerRadiation`。因此 SAFE 中 Zone 仍为 `SAFE`，但附近污染容器仍可增加 Dose，并进入 Geiger HUD 与点击声。容器破坏或清空后，下一次扫描不再产生该世界源；掉落 Stack 保留污染 NBT，但地面 ItemEntity 本轮仍不是空间源。

Point-source shielding 已由用户使用直线 fixture 和 debug breakdown 实机验证：无墙为 `0 hits / 1.0`，一层为 `1 hit / 0.35`，两层为 `2 hits / 0.1225 = 0.35²`，三层为 `3 hits / 0.042875 = 0.35³`。命中列表中的 BlockPos 均对应不同的实际墙体方块，没有发现 duplicate-hit bug；现有 DDA traversal、唯一 BlockPos 保护、source/player exclusion 和 `×0.35` 系数全部保留。

### Lead Chest V1

`apocalypse_firstlight:lead_chest` 保留 Vanilla Chest 的开盖状态、开关声音、3-row Generic Container GUI、漏斗与比较器行为，但使用 AFL 自有逐面 UV 模型与 BlockEntityRenderer 渲染箱体、盖子和锁扣。每个 Lead Chest 独立保存 `27 slots`；相邻 Lead Chest 不再自动合并为双箱，也不与 Vanilla Chest、Trapped Chest 或其他容器连接。盖子由现有 opener 状态驱动，在后侧铰链处以 cubic easing 平滑旋转到约 `70°`，锁扣作为盖子的子部件随盖子运动。

Lead Chest 的自屏蔽只作用于自己的 direct inventory：

```text
leadChestContribution
= internalRadiation
  × 0.50
  × (1 / max(1, distanceSquared))
  × pointShieldingTransmission
```

双箱仍按左右两个真实 BlockEntity 分别作为点源：每半边各自读取 `27 slots`、乘以 `0.50`，并使用各自 BlockPos 计算距离和点源屏蔽，不会把 54 格合并到双箱中心。Lead Chest 不降低内部 ItemStack contamination level，不去污，不降低 Dose 或 Residual，也没有 FE、tick 或额外效果。

Lead Chest 没有加入 `apocalypse_firstlight:radiation_shielding`；它不会替玩家遮挡环境辐射，也不会作为 source→player 射线上的额外墙体。普通容器仍为 `1.0`。Radiation Hazard Container 尚未实现，`95%` 自屏蔽仅是后续候选值。

本轮没有实现 Radiation Hazard Container、动态污染、地面 ItemEntity source、living source、placed block contamination 或 decontamination。

## 2. 玩家实际会遇到什么

### 四个辐射区域

| 区域 | 环境场 `F` | 理论环境辐射率 | 玩家感受 |
| --- | ---: | ---: | --- |
| `SAFE` | `< 0.08` | `0 RU/h` | 环境本身不增加 Dose；Residual 会缓慢衰减 |
| `IRRADIATED` | `0.08–<0.62` | `1–<10 RU/h` | 长时间暴露才会形成明显 Dose |
| `HEAVY_FALLOUT` | `0.62–<0.84` | `10–<60 RU/h` | Dose 增长明显，长时间停留很危险 |
| `EXTREME` | `>= 0.84` | `60–240 RU/h` | 极危区域，无遮蔽暴露会很快进入高阶段辐射病 |

区间边界以代码比较规则为准。例如 `F = 0.62` 已经属于 `HEAVY_FALLOUT`，`F = 0.84` 属于 `EXTREME`。

### 为什么焦土特别危险

焦土使用 `EXTREME` 生物群系 Profile。它会把自然场约束到 `F = 0.86–1.00`，对应约 `82.5–240 RU/h`，所以焦土不是只有视觉危险。

在完全无遮蔽、读数恒定为 `240 RU/h` 时：

- 约 `30 秒`累计到 `2 RU`，进入辐射病 I。
- 约 `5 分钟`累计到 `20 RU`，进入辐射病 IV。

建筑屏蔽可以显著延长这些时间，但不会清除已经累计的 Dose。

### 建筑能保护什么

建筑屏蔽只降低实际进入玩家的环境辐射。

简单理解：

```text
玩家当前真正受到的辐射
=
环境辐射经过建筑屏蔽后的部分
+
附近局部放射源
```

当前公式：

```text
finalRadiation
=
ambientRadiation × shieldingTransmission
+
localRadiation
```

因为目前 `localRadiation = 0`，所以现阶段通常等价于：

```text
finalRadiation = ambientRadiation × shieldingTransmission
```

注意：建筑会降低 `finalRadiation`，但通常不会把 HUD 上的区域枚举从 `EXTREME` 改成 `SAFE`。区域表示外部环境类型，屏蔽表示玩家实际吃到多少辐射。

## 3. Dose 怎么增长

服务器每 `20 ticks`（1 秒）结算一次。

简单理解：每秒吸收“每小时辐射率的 1/3600”。

```text
newDose = oldDose + finalRadiation / 3600
```

| 恒定 `finalRadiation` | 每秒增加 Dose | 达到 `2 RU` | 达到 `20 RU` |
| ---: | ---: | ---: | ---: |
| `1 RU/h` | `0.000278 RU` | 2 小时 | 20 小时 |
| `10 RU/h` | `0.002778 RU` | 12 分钟 | 2 小时 |
| `20 RU/h` | `0.005556 RU` | 6 分钟 | 1 小时 |
| `60 RU/h` | `0.016667 RU` | 2 分钟 | 20 分钟 |
| `240 RU/h` | `0.066667 RU` | 30 秒 | 5 分钟 |

当前规则：

- Dose 只使用 `sample.finalRadiation()`。
- Residual 当前不进入 Dose。
- Dose 不会自然下降。
- 正常存档、重新登录和死亡重生都会保留 Dose。
- 尚无正式医疗玩法降低 Dose；管理员命令可以修改或清空。

## 4. Residual 怎么增长和消退

### 在非 SAFE 区域

先根据当前 `finalRadiation` 计算目标值，最高为 `12 RU/h`：

```text
targetResidual = min(12, finalRadiation × 0.05)
```

然后每秒向目标靠近 `0.2%`：

```text
newResidual
=
oldResidual + (targetResidual - oldResidual) × 0.002
```

| `finalRadiation` | `targetResidual` |
| ---: | ---: |
| `20 RU/h` | `1 RU/h` |
| `60 RU/h` | `3 RU/h` |
| `120 RU/h` | `6 RU/h` |
| `240 RU/h` | `12 RU/h` |
| `>240 RU/h` | 仍封顶为 `12 RU/h` |

这是双向逼近：从高辐射区进入较低但仍非 SAFE 的区域后，Residual 会缓慢向更低目标回落。

### 在 SAFE 区域

SAFE 区每秒独立衰减：

```text
newResidual = oldResidual × 0.9995
```

低于 `0.01 RU/h` 时直接归零。

| 情况 | Dose | Residual |
| --- | --- | --- |
| 保存、退出、重新登录 | 保留 | 保留 |
| 非死亡实体 Clone | 保留 | 保留 |
| 死亡后重生 | 保留 | 清零 |

## 5. Radiation Sickness I–IV

辐射病完全由累计 Dose 决定，惩罚由服务端执行。

| Dose | Stage | 移速 | 收到的治疗 | 反胃 | 周期伤害 |
| ---: | ---: | ---: | ---: | --- | --- |
| `< 2 RU` | 0 | 无 | `100%` | 无 | 无 |
| `2–<5 RU` | I | `-5%` | `100%` | 无 | 无 |
| `5–<10 RU` | II | `-10%` | `75%` | 无 | 无 |
| `10–<20 RU` | III | `-15%` | `50%` | 持续 10–12 秒；结束后冷却 45–75 秒 | 无 |
| `>= 20 RU` | IV | `-20%` | `25%` | 持续 16–24 秒；结束后冷却 25–45 秒 | 每 5 秒受到 1 点魔法伤害（半颗心） |

当前细节：

- 移速使用临时 `MULTIPLY_TOTAL` Attribute Modifier。
- 治疗削弱修改玩家实际收到的治疗量。
- III/IV 的反胃持续时间和冷却以 1 秒为随机步长。
- 冷却从上一次反胃结束后开始计算。
- IV 周期伤害和反胃相互独立。
- 自定义 `radiation_sickness` Effect 负责显示阶段，真正惩罚由服务端管理器执行。
- Effect 没有可用的 curative item，因此牛奶不能解除。
- 死亡会清除临时状态，但 Dose 会保留，辐射病随后按原 Dose 恢复。

> 牛奶不能解除辐射病；死亡也不能清除累计 Dose。

### Radiation Atmosphere

空气雾效使用同步后的 `finalRadiation`，在 `10 RU/h` 达到最大目标强度。

```text
x = min(1, finalRadiation / 10)
targetIntensity = x² × (3 - 2x)
```

- 客户端每 tick 向目标强度靠近 `10%`。
- 最大强度时，雾色以 `0.48` 强度向 RGB `(0.43, 0.46, 0.34)` 混合。
- 远裁剪面最多缩短到原来的 `70%`。
- 玩家位于液体雾中时不应用空气雾修改。
- 视觉强度封顶不代表真实辐射封顶。

## 8. 已知问题

### 开局核心边界不连续

开局生态区辐射上限在距离世界坐标原点约 `d=160` 的边界存在一次不连续跳变：

- `d <= 160` 直接使用 `0.079` 上限。
- 刚越过 160 后进入下一段从接近 `0` 开始的 smoothstep。

因此这里目前不是完全连续的平滑过渡。尚未修复。

### Radiation Field 与 biome placement 不是同一个场

辐射使用独立的 `RadiationField`；地表群系使用 Minecraft climate sampler 与 TerraBlender。`BiomeRadiationResolver` 会在群系确定后约束辐射范围，但当前不是“同一个 F 精确决定群系”。

### 当前污染玩法仍是半成品

Residual 已经能记录、持久化和显示，但还不会增加 Dose，也没有正式洗消方式。Item Contamination V1C 已让玩家直接携带的污染 Stack 增加 actual exposure 与 Dose；Container Radiation V1 已让已加载普通容器成为 player-aware 空间点源。世界位置 `localRadiation` 接口仍固定为 0，地面 ItemEntity 和污染方块仍不会成为空间辐射源。

## 10. 技术细节

这一部分主要供开发和调试时查阅。

### 10.1 完整计算顺序

```text
世界种子二维辐射场
    ↓
地表生物群系约束
    ↓
安全锚点压制
    ↓
开局生态区辐射上限
    ↓
环境场 F → ambientRadiation
    ↓
14 方向遮蔽采样 → shieldingTransmission
    ↓
worldFinalRadiation
= ambientRadiation × shieldingTransmission + existingPositionLocalRadiation
    ↓
已加载容器 direct inventory
    ↓
容器内部源强 × inverse-square × 单条点源屏蔽射线
    ↓
playerEffectiveRadiation
= worldFinalRadiation + carriedItemRadiation + nearbyContainerRadiation
```

- `RadiationZone` 根据屏蔽前的有效环境场判断。
- 安全锚点核心内会把自然环境强制为 `SAFE / 0 RU/h`，但不会清除玩家背包的 `carriedItemRadiation` 或附近容器的 `nearbyContainerRadiation`。
- 非主世界维度返回 `SAFE / 0 RU/h`；Residual 按 SAFE 规则衰减。

### 10.2 原始 Radiation Field

`RadiationField` 使用世界种子生成确定性二维 value noise，只依赖 X/Z：

```text
rawF = clamp01(broad × 0.82 + detail × 0.18)
```

| 层 | 空间尺度 | 权重 |
| --- | ---: | ---: |
| Broad | `768 blocks` | `0.82` |
| Detail | `192 blocks` | `0.18` |

### 10.3 生物群系约束

| 地表群系 | Profile | 约束后的 `F` | 约辐射率 |
| --- | --- | ---: | ---: |
| 原版平原 | `SAFE` | `0–0.075` | `0 RU/h` |
| 污染疏林 | `IRRADIATED` | `0.10–0.58` | `1.33–9.33 RU/h` |
| 沉降荒原 | `HEAVY_FALLOUT` | `0.62–0.82` | `10–55.45 RU/h` |
| 焦土 | `EXTREME` | `0.86–1.00` | `82.5–240 RU/h` |
| 未识别/其他群系 | `UNKNOWN` | 保留 `0–1` | `0–240 RU/h` |

`BiomeRadiationResolver` 只读取已加载 chunk；不会为了远处采样强制生成或加载 chunk。每个世界最多缓存 `4096` 个 X/Z 解析结果。

### 10.4 安全锚点

安全锚点初始来自世界出生点；地堡成功生成并绑定后可改为地堡内指定安全点。

| 距离安全锚点 | 压制系数 |
| --- | ---: |
| `d <= 40` | `0` |
| `40 < d < 96` | `smoothstep((d - 40) / 56)` |
| `d >= 96` | `1` |

```text
preStartupF = biomeF × anchorSuppression
```

### 10.5 开局生态区上限

开局生态区以世界坐标 `(0, 0)` 为中心：

| 区域 | 上限行为 |
| --- | --- |
| 核心平原 `d <= 160` | 上限 `0.079` |
| 核心外至噪声化平原边界 | 从 `0` smoothstep 到 `0.079` |
| 平原边界至污染疏林外边界 | 从 `0.10` 过渡到 `0.42` |
| 疏林边界后的 `48 blocks` | 从 `0.42` 交接回原有效场 |
| 交接区之外 | 不施加上限 |

```text
effectiveF = min(preStartupF, startupCap)
```

仅在 `startupCap` 存在时应用。`d=160` 的已知不连续见“已知问题”。

### 10.6 `F` 到 `RU/h`

```text
F < 0.08:
R(F) = 0

0.08 <= F < 0.62:
R(F) = 1 + 9 × (F - 0.08) / 0.54

0.62 <= F < 0.84:
R(F) = 10 + 50 × (F - 0.62) / 0.22

F >= 0.84:
R(F) = 60 + 180 × (F - 0.84) / 0.16
```

换算前把 `F` 限制到 `0–1`，所以自然环境最大为 `240 RU/h`。

### 10.7 14 方向建筑屏蔽

- 6 个正交方向和 8 个空间对角方向。
- 每条射线最多检查 8 个采样位置。
- 每命中一个 `apocalypse_firstlight:radiation_shielding` Tag 方块，透射率乘以 `0.35`。
- 单条射线透射率低于或等于 `0.01` 后停止。
- 14 条射线透射率取平均。
- 结果按玩家 BlockPos 缓存 `10 ticks`。

```text
rayTransmission = 0.35 ^ hitCount
shieldingTransmission = sum(all 14 rays) / 14
shieldingPercent = 1 - shieldingTransmission
```

当前 Tag 内的正式材料是：

| 方块 | Registry ID | 单层透射率 | 单层削弱 |
| --- | --- | ---: | ---: |
| 钢筋混凝土 | `apocalypse_firstlight:reinforced_concrete` | `0.35` | `65%` |

### 10.8 同步与 stale

- 世界 `finalRadiation` 每 `10 server ticks` 同步给主世界玩家，用于环境雾效；背包和容器污染物不会改变空气外观。
- 只有手持 Geiger 时才同步完整仪器数据。
- SAFE 的 Geiger measured rate 为 `Residual + carriedItemRadiation + worldLocalRadiation`；非 SAFE 为 `effectiveRadiation`。
- 容器扫描结果最多缓存 `20 ticks`，所以 10-tick 同步与每秒 Dose 结算会复用最近一次结果，实际库存变化最迟在下一次约 1 秒扫描反映。
- Geiger 快照超过 `40 ticks` 未更新后视为 stale，不继续作为有效读数/声音来源。
