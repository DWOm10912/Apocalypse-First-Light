# 流体系统

AFL 使用 Forge Fluid / FluidStack 构建定向端口、无库存压力管与可堆叠储罐；机器容量与配方见 [机器参数](../../02%20-%20内容设计/方块/机器.md)。

# 1. 流体系统

AFL 使用 Forge Fluid / FluidStack 作为工业流体基础。

当前主要包含：

- Water
- Industrial Waste
- 未来其它工业流体

流体系统与 FE 网络完全独立。

---

# 2. Fluid Pipe

Fluid Pipe 是工业压力管道。

## 基础规则

| 项目 | 当前规则 |
|---|---|
| 标准自动传输速率 | 25 mB/t / 每个真实端口 |
| 高度限制 | 无 |
| 重力限制 | 无 |
| 管道内部储液 | 无 |
| 区块强制加载 | 无 |
| 液体混合 | 不允许 |
| 管道 Tier | 无 |
| Pressure 模拟 | 无 |
| Pump | 无 |
| Filter | 无 |

管道本身不保存 FluidStack。

真正的流体永远存在于：

- Fluid Tank
- Chemical Reactor
- 未来其它机器流体槽

中。

---

## 端口预算

标准自动化端口：

`25 mB/t`

这是：

【单个真实输入 / 输出端口的 tick 预算】

多个来源同时接入同一个端口时，不能突破该端口的 25 mB/t 上限。

不同端口拥有独立预算。

手持桶等玩家手动容器交互不受 25 mB/t 限制。

---

# 3. 流体输送

当前输送方式为：

`Source Endpoint → Fluid Pipe → Target Endpoint`

Source 主动向管网 push。

管路可以：

- 向上
- 向下
- 水平
- 转弯

高度不会改变传输能力。

目标必须：

- 接受对应 Fluid
- 存在可用容量
- 当前端口仍有输入预算

如果存在多个目标，优先寻找当前真正可以接收流体的目标。

---

# 4. 背压

当目标：

- Fluid 类型兼容
- 管路仍有效

但因为：

- 储罐已满
- 本 tick 输入预算已耗尽

暂时不能接受流体时，管道进入背压显示。

此时：

`实际传输量 = 0 mB`

并且：

- 不扣除源端 Fluid
- 管道不保存 Fluid
- 路线仍短暂保持可视状态

目标重新获得容量后自动恢复输送。

---

# 5. 管道流体显示

真实输送时：

`FLOWING sprite`

背压状态：

`STILL sprite`

两者都使用 Fluid 自己的：

- Texture
- Tint
- Atlas Animation

输送停止后，管内视觉最多保留约：

`20 ticks`

之后消失。

---

# 6. 管线隔离

直接紧贴的平行管线不会因为相邻而自动串线。

规则与 Fluid 类型无关。

例如：

- Water / Water
- Water / Industrial Waste

只要属于两条独立管线，就不会因为紧贴而互相连通。

需要主动连接时，应通过明确的转弯或桥接结构完成。

# 7. Industrial Waste / 工业废液

Registry：

| 对象 | ID |
|---|---|
| Source / FluidType / LiquidBlock | `apocalypse_firstlight:industrial_waste` |
| Flowing | `apocalypse_firstlight:flowing_industrial_waste` |
| Bucket | `apocalypse_firstlight:industrial_waste_bucket` |

`1 Bucket = 1,000 mB`

## 当前规则

- 不可无限生成 Source
- 可以使用桶放置和取走
- 可以进入 Fluid Tank
- 可以通过 Fluid Pipe 输送
- 可以作为 Chemical Reactor 废液
- 不属于 `minecraft:water`
- 不属于 `minecraft:lava`

当前没有：

- 接触伤害
- 中毒
- 腐蚀
- 污染伤害
- 辐射
- 毒气

---

## 物理表现

工业废液整体沿用 Water 风格的流动与实体移动基础：

- 可以游动
- 可以溺水
- 可以推动实体
- 支持船
- 可以灭火

但它不是普通水，因此不会被其它系统当作配方水使用。
