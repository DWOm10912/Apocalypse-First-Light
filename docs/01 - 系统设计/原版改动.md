### 2. 对于原版僵尸的改动
- 僵尸现在在白天不会燃烧
- 现在不会生成小僵尸
- 僵尸现在拥有锥型的视野，因此可以shift躲避
- 僵尸的视野不会被透明方块遮挡
- AFL 禁用 Vanilla Zombie Reinforcement：所有 `Zombie` 及子类（包括 Husk、Drowned、Zombie Villager、Zombified Piglin）均不通过受伤呼叫原版增援；枪声仍会吸引周围已有僵尸，自然生成与明确的结构生成不受此规则影响。

#### 僵尸增援禁用 V1.1

- `InfectedEvents` 在服务器 `EntityJoinLevelEvent` 中清空增援专用属性 `minecraft:zombie.spawn_reinforcements` 的全部 modifier（包括 leader bonus），并将 base 设为 `0.0`；该属性范围为 `[0, 1]`，清理后的 `getValue()` 为 `0.0`。新生成、`/summon` 和区块重新加载均通过此入口处理，且归零先于仅适用于普通 Zombie 的 AI 分支。
- 复用原有 `ZombieEvent.SummonAidEvent`，在 `LOWEST` 优先级再次归零并返回 `DENY`，拦截入世界后属性被修改的增援尝试；不添加逐 tick 扫描。只清理增援属性，不改变生命、移速等其它属性或枪声响应范围。
- Zombie 转换为 Drowned 等变种时，原版在新实体加入世界后才调用 `handleAttributes`，可能重新添加 leader modifier；`LivingConversionEvent.Post` 在转换完成后复用同一归零方法，补齐此生命周期路径。三个处理入口均使用 `LOWEST` 优先级。
- 旧实现已经对精确 `minecraft:zombie` 返回 `DENY`，Forge 47.4.22 会直接阻止该次增援；旧实现的缺口是未覆盖 Zombie 子类、未清理属性，而非已证实普通 Zombie 的 DENY 失效。主世界自然敌对生成仍只允许普通 Zombie，其他来源进入世界的子类同样适用增援禁令；它们不会因此获得普通 Zombie 的 AFL 噪声 AI。
- 开发 DEBUG 日志 `[AFL INFECTED] Reinforcement reset` 输出处理后的 base、effective 和 modifier 数量；预期分别为 `0.0`、`0.0`、`0`。可用 `/attribute @e[type=minecraft:zombie,sort=nearest,limit=1] minecraft:zombie.spawn_reinforcements get` 检查有效值。
- 尚未实机验证。隔离测试不能只依赖 `doMobSpawning=false`：原版增援本身也受该 gamerule 限制。清场后需在无其它生成来源的隔离区域将其设回 `true`，再在 Hard 难度反复攻击测试；完成后恢复测试前的世界设置。
