# 第一辆车 V0：老式单排座皮卡（设计）

状态：**V0-a 第一步：车身 Mesh V1 已实现（2026-10-15，按真车结构图重做，第 2.2、2.4 节），未经实机验证。** 用户选了方向 A（第 2.1 节）。现在有能放、能看的车（第 2.2 节）：车身、车内、发动机舱、底盘、车轮、漆色和磨损、开关引擎盖 / 车门 / 尾门、开发命令。平滑法线：分支 `feature/t15-smooth-normals` 上已用 Vextris 0.1.1-alpha.3 的折角平滑（面积加权）打开，未经实机验收（第 2.2 节末）。还没有：驾驶、座位、物理、碰撞、货斗库存、油箱、仪表指针（第 2.3 节）。用户 2026-10-15 让车辆设计和道路开发并行：完整的车辆物理等 C 的统一接地查询定下来再写（第 5、8 节）。

以前的要求（用户 2026-10-12，[溪谷老宅 B V1 计划](../worldgen/forest_start_home_b_v1_plan.md) 第 5 节、[开发顺序](../dev/development_order_v1.md)）：

- 1990–2000 年代常见的北美紧凑型皮卡，AFL 自有的虚构品牌和型号，不用现实车厂的商标；
- 单排驾驶室 2 座，开放货斗能拉木材和物资，离地间隙高，适合林间碎石车道；
- 外观简单、耐用、明显用了很多年；不做复杂改装；
- 它是整个载具系统的模板：以后的轿车、SUV、厢式货车、卡车都复用同一套实体、接地、驾驶、存档、货物；
- 溪谷老宅主人的战前车辆：车棚里已经留了锚点（`tools/afl_minecraft_mcp/forest_home_b_m1.mjs` 的 `VEHICLE_ANCHOR`），车做好后新世界在锚点放真车，油箱见底；
- 顺序：先做可靠的四轮接地、悬挂、低速驾驶，再加发动机、变速箱、损伤。玩家在 Mesh 坡面上走得顺，**不等于车轮接地已经验证**。

## 2. 车

**品牌和型号**：联邦本地的虚构车厂，暂定 **Halstead Motor Company（霍尔斯特德汽车）**，型号 **Tamarack T15（落叶松）**，单排座短货斗。用户 2026-10-15 定：名字先用这个。车标、铭牌、车尾字样都用自己的设计，不像任何现实车厂。

**尺寸**（1 格 = 1 m；按这一级别北美紧凑型单排皮卡的常见范围取，不对应某一款真车）：

| 项 | 数值 |
|---|---|
| 全长 × 全宽 × 全高 | 约 4.7 × 1.69 × 1.75 m（V1 按第 2.4 节的参考车改；原定 4.80 × 1.76 × 1.72） |
| 轴距 | 2.85 m |
| 轮距 | 1.424 m（原定 1.46） |
| 轮胎 | 225/75 R15：外径约 0.72 m，宽 0.225 m（原定 0.74 / 0.24） |
| 离地间隙 | 0.23 m（车桥下） |
| 货斗内部 | 长 1.85 × 宽 1.40（轮拱之间 1.10）× 深 0.42 m |
| 整备质量 | 约 1450 kg |
| 载重 | 约 550 kg（货斗） |
| 油箱 | 60 L（[1 mB = 1 L](../gameplay/fuel_fluids_v1.md)，按升显示） |

**动力**（用户 2026-10-15 定：柴油、分时四驱）：

- 前置纵置 2.5 L 直列四缸涡轮柴油，怠速 750 rpm、红线 4300 rpm，最高车速约 135 km/h；
- 燃油只认柴油 `apocalypse_firstlight:diesel`，和老宅的柴油发电机用同一种油（发电机和车抢油是有意的取舍）；
- 冷车启动先等电热塞预热（天越冷越久，0.5–4 秒，仪表上一盏预热灯），再拧到底打火；
- 分时四驱：平时 2H（后驱），驾驶室地板上的分动箱拨杆切 4H（前后轴硬连，扭矩各一半，没有中央差速）。只有车速低于 20 km/h 才能切。4H 在碎石、泥、雪、陡坡上抓地好；在干沥青上急转弯会有点拖（前后轮转速对不上），提示玩家硬路面用 2H；
- 4 挡自动，玩家只看到 P / R / N / D。**待用户定**：车身 V1 按参考车做的是地板五速手动档杆 + 分动杆（第 2.4 节），和这里的自动档对不上；驾驶做到这一步前要定：改手动档，还是保留自动档（那样档杆模型要改成自动档的 P / R / N / D 杆）。

**样子**：方正的驾驶室、平直的发动机盖、前格栅加两个方大灯、钢制前后保险杠、车斗侧面平板、尾门带铰链和两根拉链。旧：漆面褪色、边角掉漆生锈、轮拱锈穿一点、风挡玻璃一道裂纹、货斗里的划痕和凹坑。按 [贴图密度](../models/wood_furniture_v2.md) 的做法：240 px LabPBR 共用材质，不画装饰图案，靠材质和凹凸。

**漆色和新旧**（用户 2026-10-15 追加：漆色能换，路上就能放破车和各种颜色的车）：

- 车身漆面单独一层。模型贴图分两部分：漆面用一张灰度底色，其余部分（镀铬、黑塑料、轮胎、玻璃、车内）用固定颜色。渲染时漆面乘上这辆车自己的漆色，其余不变。LabPBR 的高光贴图给漆面统一的清漆光泽，褪色越重越哑。
- 每辆车存一个 `Paint`：
  - 主色（RGB）；
  - 第二色，可选：腰线以下或车顶双色，90 年代皮卡常见；
  - 磨损 0–1：褪色、掉漆露出灰色底漆、锈。磨损用一张固定的锈 / 掉漆分布图按阈值显示：数值越大露得越多，锈先出现在轮拱、门槛、车斗边角。只用材质，不画图案。
- 出厂色板约 10 种 90 年代常见色：白、银、黑、深红、森林绿、藏青、米色、棕褐、深灰、浅蓝。每辆车在色板上加一点点偏差，同色的两辆车不会完全一样。
- 老宅的车：一个固定的漆色（概念图时定），磨损中等（用了很多年，但一直有人开）。
- 改漆色：
  - V0 先有开发命令 `/afl dev vehicle paint <颜色> [第二色] [磨损]`；
  - P2 让玩家自己喷漆，和以后木匠台那套油漆共用，用量按车身面积算。
- 路边破车（P1，第 8 节）：同一个车型、同一套漆色，状态是"废弃"：
  - 磨损高；可能少轮胎、少车门、玻璃碎；油箱里随机剩一点；
  - 修好以前不能启动（零件维护 P2）；能搜货斗和驾驶室；
  - 放在哪：公路路肩、停车场、车道。道路沿线的放置点要 C 给（道路生成知道哪里有路肩和停车区），车本身是 Main 的车辆实体。
  - 不动的破车不跑物理，有人推、撞或修好开走才醒过来，所以路上多放一些也不太费。数量和性能等做的时候再量。

概念图里磨损的做法和游戏里计划的一样：同一套模型，只改漆色、第二色和磨损数值。锈从门槛和轮拱长起，掉漆露出底漆，越往上越少。这一版老宅的车先用深红、磨损 0.45，最终颜色等方向定了再说。

### 2.2 车身 Mesh V1（方向 A，2026-10-15，已实现，未实机验证）

用户选 A，要求引擎盖能打开、看到发动机；看了实机的 V0 以后要求精致、不像白模，按真实结构图做、不自己编，车内要细（第 2.4 节）。V1 是整车重做，V0 的生成器 `tools/build-pickup-t15-v0.mjs` 已删掉。

**生成器**：`tools/build-pickup-t15.mjs`（`--check` 只检查输出是否最新，`--fast` 跳过 AO 烘焙，只给预览用）。模块在 `tools/pickup-t15/`：`common.mjs`（尺寸、材质、Mesh 和部件表、骨骼支点、铰链、锚点、平滑设置）、`exterior.mjs`（车身外观）、`wheel.mjs`（车轮）、`cab.mjs`（车内）、`engine.mjs`（发动机舱）、`chassis.mjs`（大梁和底盘）、`shade.mjs`（程序材质）。通用建模工具在 `tools/vehicle-mesh-kit.mjs`（截面放样、圆角、管子、按半径自适应的圆角段数、UV 展开和装箱、AO 烘焙）。在概念坐标系里建模（米，x 向前、y 向上、z 向右，驾驶员在 -z），最后转成游戏坐标（像素 = (z, y, -x) × 16，是旋转不是镜像：车头朝 -Z，驾驶员在 -X）。

**结构**（按第 2.4 节的参考图）：

- 外观：驾驶室向内收（腰线以上内倾 55 mm），车顶前后卷边，风挡和后窗圆角胶条；引擎盖微拱、两条棱线、前后卷边，内侧 X 形加强骨架和隔音棉；通风格栅板是一排长条孔；格栅是框 + 横竖格栅条，四个方灯带灯框和压圈；车门和窗框一体，门胶条、三角座和后视镜；货斗腰线、顶边绑绳孔、轮包、三段尾灯、左侧加油口；尾门上拉把手、两根拉索、下铰链；后保险杠转角半径 0.13 m；
- 车轮：225/75 R15 轮胎（胎侧鼓出、圆胎肩，花纹在贴图里），冲压钢圈 6 孔 6 螺母；左边的车轮转半圈装；
- 车内：仪表台主体 + 上软垫，表罩里的组合仪表（转速表、车速表、油量、水温，静止的指针、指示灯条、透明表罩），两端圆出风口、中间两个出风口、除雾风道，暖风面板（推杆、按键）、收音机、烟灰缸、手套箱、护膝板、T 形手刹拉手、引擎盖拉手；两辐方向盘 + 大喇叭盖，上下两半转向柱护罩、钥匙、两侧拨杆；地胶 + 中间通道、踏板三个、地板五速档杆 + 分动杆、门槛踏板、脚踢板；长条座椅（八条竖压线、两个头枕凸起、侧护板、滑轨、安全带和锁扣）；门内饰板（上下两段、扶手、内拉手、摇窗把手、锁钮）；A 柱和 B 柱饰板、后围饰板、拉手、顶棚、顶灯、遮阳板、车内后视镜；
- 发动机舱：2.5 L 直列四缸柴油机（油底壳、缸体、缸盖、气门室盖、正时罩、皮带轮和皮带、发电机、7 叶风扇、导风罩、散热器和水管），进气侧（进气歧管、喷油泵、4 根油管、喷油器、机油尺、增压管），排气侧（排气歧管、隔热罩、涡轮、下管、空滤和进气管），防火墙一侧（电瓶、副水箱、玻璃水壶、保险盒、真空助力器和刹车总泵、线束、暖风水管），下护板；
- 底盘：梯形大梁（纵梁在后桥上方拱起）、6 根横梁、车身支架、拖钩；前后 5 片钢板弹簧、吊耳、减震器；前整体桥和差速器、转向节、横拉杆、转向机、转向臂、直拉杆、转向中间轴；后桥；变速箱、分动箱、传动轴；排气管、消声器（尾管从右后轮后面出）；左侧油箱和加油管；货斗下的备胎、绞盘和吊索。

**骨骼和交互点**（`pickup_t15.rig.json`，概念坐标，渲染器里换成游戏坐标）：

### 2.3 仪表和指针（计划，用户 2026-10-15 问）

用户问仪表能不能复用柴油发电机组的，并要求指针必须流畅（发电机组的"有点卡卡的"）。

**发电机组为什么卡**（离线按代码算的，不是实测）：服务端的读数（水温、油量、负载、油压）每 tick 都在连续变，但只有取整到 1%（油量 0.5%）以后变了才同步，而且两次同步至少隔 10 tick；客户端的指针按时间常数 5 tick 追新目标（`follow_ticks: 5`）。

- 读数变得快时（暖机初期），指针每 0.5 s 收到一个新目标，速度在 1.9–3.2 %/s 之间来回跳，一顿一顿地走；
- 读数变得慢时（接近工作温度），指针约 1 s 就追到目标停下，等好几秒，下一个 1% 来了再走一小步，像台阶；
- 停住的指针会并进区块网格，下一步再拆出来，区块重建时可能多一帧闪动（没实测）。

**车的仪表**：复用发电机组仪表的做法（指针是动画骨骼、表盘画在贴图上、指针的造型和材质），但表盘布局按 1990 年代皮卡做：大车速表（km/h）、转速表，小表：油量、水温、油压、电压。指针保证流畅：

- 车是实体，每帧都画，不并进区块网格；
- 车速、转速以后由驾驶端的车辆物理每 tick 算出（驾驶员客户端自己算），渲染时按 partialTick 插值；
- 油量、水温这种慢读数：客户端按最近两次收到的值估出变化速度，指针以这个速度匀速走（不再"追上就停"），外面再套一层很短的阻尼，看起来像真表针。

做的时间：驾驶和发动机状态（V0-a 后面几步）有了数据以后一起做。发电机组的指针：用户 2026-10-15 同意一起修，同日已修（同步改成 0.2% 一档，客户端跟随改成平滑连续放出，见 [柴油备用发电机组](../machines/diesel_standby_generator_v1.md)；离线按代码模拟过，未实机验证）。

## 3. 架构（所有车辆共用）

```text
AflVehicleEntity          车辆实体：位置、朝向、速度、车轮状态、座位、存档
  VehicleSpec             每种车的数据：尺寸、质量、车轮位置、悬挂、发动机曲线、油箱、货斗
  VehiclePhysics          纯物理，客户端和服务端同一份代码（不碰世界，只问 VehicleGround）
  VehicleGround           接地查询（第 5 节）：给一个点和高度提示，返回地面高度、法线、路面种类
  VehicleSeats            座位、上下车、驾驶员输入
  VehicleCargo            货斗库存（网格背包的容器面板）
  VehicleFuel             油箱、耗油、加油
客户端：VehicleRenderer（Mesh 车身 + 车轮 + 动画部件）、VehicleCamera（驾驶视角）、VehicleHud（仪表读数）、声音
```

**谁算物理**：和原版船一样，驾驶员的客户端算自己开的车（手感不受网络延迟影响），每 tick 把状态发给服务端；服务端用同一份物理检查合理性（速度、位置跳变、穿墙），不合理就拉回。没人开的车（停着、溜坡）由服务端算。物理代码是确定性的纯函数，两边算出来一样。

**步长**：每 tick 分 4 小步（80 Hz）积分，悬挂才稳；渲染按 partialTick 插值，车身和车轮不抖。

**车辆模型**：一个刚体（质量、转动惯量）+ 四个车轮：

- 每个车轮一根悬挂：从车身上的安装点往下查地面（第 5 节），弹簧 + 阻尼，行程 ±0.12 m；
- 轮胎：纵向（驱动、刹车）和横向（转弯）各一条简单的抓地曲线，按路面种类乘系数（沥青 1.0、碎石 0.75、土 0.7、草 0.6、雪 0.35、冰 0.15，待调）；超过抓地就打滑；
- 转向：阿克曼前轮转角，最大 32°，速度越快能打的角度越小（防止高速一把打死翻车）；
- 发动机：一条柴油机的扭矩曲线（低转扭矩大）+ 自动换挡，怠速 750 rpm、红线 4300 rpm；最高车速约 135 km/h（V0 先限 100 km/h，第 7 节）；
- 驱动：2H 只有后轮出力；4H 前后轴硬连，扭矩各一半，前后轮转速差在高抓地路面上变成拖滞力（简化，不做真的传动系）；
- 刹车：四轮，按住 S 减速，停住以后再按住就挂倒挡；空格是手刹（后轮），停坡用；
- 重心：货斗装的东西按[负重系统](../gameplay/weight_system_v1.md)的质量算进车重和重心，装满了加速慢、刹车距离长、转弯更容易侧倾。

**碰撞**：

- 车身对世界：一组盒子（车头、驾驶室、货斗），和方块的碰撞形状求接触，撞上就停 / 反弹，速度太大时 P2 再算损坏；
- 车对生物：低速推开，高速撞到感染者给伤害（P1，和噪声一起做）；车对玩家：推开，不碾压（V0）；
- 车是实体，不是方块，玩家能站在货斗里（货斗地板是可以站的碰撞面，车动的时候站着的人跟着走，P1）。

## 4. 驾驶和乘坐

- **上车**：对着车门右键 → 门打开（动画）→ 坐进去 → 门关上。驾驶座在左（北美）。货斗不能坐人开车（V0）。
- **下车**：潜行键 → 开门 → 站到门外；门外有东西挡着就从另一边下，两边都挡住就不让下。
- **驾驶视角**：第一人称在驾驶员眼睛的位置（离座垫约 0.75 m），能看到方向盘、仪表、引擎盖；头可以左右看 ±120°、上下 ±60°，车转弯时视角跟着车身转。按 F5 切到车后的跟随视角。D 下一步做"第一人称看得见自己的下半身"，驾驶时的身体姿势和它对接。
- **启动**：坐在驾驶座按住交互键：先拧到预热挡，预热灯灭了再拧到底，起动机转 0.5–1.5 秒着车。V0 看有没有油和气温；电瓶以后加。可以把这一下做成 QTE（[QTE 约定](../machines/portable_diesel_generator_v1.md)），V0 先不做。
- **操作**：W 油门、S 刹车 / 倒车、A / D 转向（方向盘动画，松手自动回正）、空格手刹、R 换挡（P / R / N / D，V0 自动在 D 和 R 之间切，R 键留着）、X 切 2H / 4H（拨杆动画，车速 < 20 km/h）、交互键熄火 / 启动。按键名跟着玩家的按键设置，提示一个词。
- **HUD**：驾驶时只加车速和油量两个读数，放在生存 HUD 那一组里（现代面板风格）。仪表本身在车里看。

## 5. 接地查询（和 C 的接口）

车轮怎么"踩"到地面，是这辆车可靠不可靠的关键。

```text
VehicleGround.sample(level, x, z, yHint, radius) → {height, normal, surface, source, blocking, valid}
```

- `x, z`：轮胎接地点；`yHint`：车轮现在的高度（桥上 / 桥下、隧道这种多层的情况用它挑离车轮最近的那一层）；`radius`：轮胎半径，用来把方块台阶的边抹圆。
- 返回：地面高度（连续值，不是方块格）、法线、路面种类（沥青 / 混凝土 / 碎石 / 土 / 草 / 沙 / 雪 / 冰 / 水 / 未知）、来源（道路、平滑地形、方块）、`valid`（区块没加载、查不到时为 false，车轮按上一 tick 的接触点保持，不掉下去）。
- 只读，不加载、不生成区块；在客户端和服务端都能算，结果一样。

数据从哪里来（按优先级）：

1. **道路**（C）：路面底座的连续路面——C 负责（[Main ↔ C3 契约](../worldgen/main_c3_interface_contract_v1.md)：Mesh 路面底座给载具的路面高度、法线、接地查询；[Highway V2.0 契约](../worldgen/highway_v2_0_design_contract.md) 的 `RoadSurfaceQuery`）。桥面、伸缩缝、涵洞顶上都走这里。
2. **平滑地形**（[地表平滑](../worldgen/terrain_smooth_v1.md)）：自然地面的连续高度和法线，按 `SmoothRules` 的规则算，和玩家看到、踩到的坡面一致。
3. **方块**（兜底）：方块碰撞形状的顶面；车轮在台阶边上按轮胎半径抹圆（一个 0.37 m 半径的轮子能爬上大约 0.15 m 的台阶，一整格 1 m 的台阶爬不上去，这和真车一样）。

Main 写接口、第 2、3 种来源和车辆这一侧；C 提供第 1 种来源，插在最前面。**接口的字段和"多层怎么选"要和 C 先对好**，C 现在在做 C3.3a 的 B–E 组（草皮、填方、涵洞、桥），不打断它：先把这一节作为草案发给 C，等 C 方便时回复。

C 已经计划的"每条路做一遍车轮接地回归"（C3 状态）就用这个接口跑：沿路中心线和车道线每 0.25 m 查一次，检查高度跳变、法线突变、`valid` 断档。

### 5.1 和 C 对好的部分（C 回复 2026-10-15，双方同意）

- **字段**：够用，再加一个 `blocking`。
  - 护栏、翼墙压顶这类 BARRIER（`road_structure`）返回 `valid=true`、`surface=混凝土`、`blocking=true`。车轮不站上去，车身把它当障碍。
  - 其他行车面 `blocking=false`。
- **法线**：道路这一层的法线由道路设计解析算出（纵坡、横坡、超高），不从方块拼，所以是连续的。
- **路面种类对应**：

| 道路部件 | `surface` | 备注 |
|---|---|---|
| 铺装列（PAVED，`road_surface` 碰撞层）、路肩、桥面和桥台上的铺装（DECK / ABUTMENT） | 沥青 | |
| `graded_turf`（中央带、边坡、边沟） | 草 | 高度用方块四个角，按西北—东南对角线分成两个三角形（和画面一致），不用台阶状的象限碰撞盒。由 C 实现，不走 `SmoothRules` |
| 护栏、翼墙压顶（BARRIER） | 混凝土 | `blocking=true` |
| 碎石 | — | 现在没有。C3.3c 的入户碎石路以后再挂 |
| 土、沙、雪、冰、水 | — | 道路不产出，走 Main 的平滑地形和方块兜底 |

  `source=road` 包括铺装、桥面、草皮三类。
- **多层选择**：
  - 道路层列出覆盖 (x, z) 的所有路面候选（主路面、桥面，以后 C3.3b 立交的上下层），取离 `yHint` 最近的一个，并且要求 |候选 − `yHint`| ≤ 1.5 m（数值以后可以调）。
  - 没有一个满足，道路层就返回 `valid=false`，由平滑地形接手，比如桥下的河谷地面。
  - `yHint` 传上一 tick 的车轮接触点高度。
  - 涵洞上面就是路面本身，只有一层。
- **草皮和平滑地形交界**：C3.3a B 组以后，草皮外缘对齐噪声实际做出的地表（`RoadWorks.naturalTop`），原来约 0.6 格的落差没有了。这条随 B 组验收生效，B 组在 C 的分支上，还没合并。
- **位置**：`com.antaurora.apofirstlight.worldgen.network.road.RoadSurfaceQuery`，数据来自 `RoadNetworkRuntime` 绑定的 `RoadWorks`。客户端登录时已经收到整个建成路网（`BridgeMesh` 用的是同一份），所以两端结果一样。只读，不加载区块。
- **时间**：等道路工程定型，也就是 C3.3a 的 C、D、E 组验收以后，C 再写道路这一层。在那之前，Main 按这一节写 `VehicleGround` 接口，道路层先用一个永远返回 `valid=false` 的占位实现，C 以后替换掉。

## 6. 存档和状态

车辆实体存：车型 ID、漆色 `Paint`（主色、第二色、磨损，第 2 节）、状态（正常 / 废弃）、驱动挡（2H / 4H）、位置朝向、速度（卸载时清零）、四个车轮的悬挂状态（不存，加载时落地重算）、发动机开 / 关（区块卸载时熄火）、油量（L）、里程（km）、门 / 尾门开关、货斗库存、车主（不锁车，V0 只记录谁最后开过）、损坏占位（P2）。

- 车所在的区块卸载时车跟着存进区块；开着车跨区块时，驾驶员在车上，区块照常跟着玩家加载。
- 驾驶员掉线 / 死亡：车停下（熄火、手刹）。
- 继任者不知道前任的车在哪（以后可以加"前任的车钥匙在遗体上"）。

**加油**：车的加油口在左后侧（货斗前面）。
- 加油站的加油枪（[加油站](../gameplay/fuel_fluids_v1.md)，`LiquidJet` 喷流）对着加油口右键；
- 油桶（`afl:fuel_can`）对着加油口右键倒进去；
- 只认柴油：汽油的加油枪和油桶对着加油口没反应，提示"柴油"（P2 以后可以做"加错油"故障）。

**耗油**：按发动机负荷算：怠速约 0.6 L/h，平路 60 km/h 约 8 L/100 km，满载上坡、4H 更多。60 L 满箱大约跑 700 km。老宅车棚里的车油箱见底（比如 4 L，够开到最近的加油站附近）。

**货斗**：网格容器（[网格背包 V0](../ui/afl_inventory_grid_v0_plan.md) 的容器面板），站在尾门后面右键打开；大小按货斗面积，V0 暂定 10 × 7 格（以 D 的格子尺寸再定）。货物算进车重（第 3 节）。尾门开着时才能放长东西（原木、长枪）——V0 先不分，P1 再说。

## 7. 性能和世界

- 区块生成：开车比走路快得多，跑到没生成的区块时会卡。V0 限速 100 km/h（约 1.4 格 / tick），以后看区块生成速度再放开；C3 文档也记着"高速移动时的区块生成和路面网格"没测过。
- 渲染：车身和车轮是一个 Pure Mesh 实体，四个车轮、方向盘、仪表指针、门、尾门是动画部件；按 [Mesh 预算](../rendering/mesh_shape_runtime_v1.md) 控制三角形数；第一人称车内可见，所以车内也要建模（[打开能看到的内部](../worldgen/forest_start_home_b_v1_plan.md)）。
- 噪声：发动机响的时候就是噪声源，半径和声音传播距离一样（感染者听觉）；P1 做声音时一起接。
- 光影：Sundial 下调，原版要正常，其他光影不坏。

## 8.1 声音清单（P1，用户 2026-10-15 问）

车是虚构的，不用追求像某一款真车，但要像一台 1990 年代的 2.5 L 四缸柴油机：怠速有"哒哒"的敲击声，带一点涡轮的细啸声。按 AFL 的老做法用 Adobe Firefly 生成（[一条录音切分](../machines/portable_diesel_generator_v1.md)，不自己合成）。网上的免版权音效只用来补漏：来源一多，音色就不统一，许可也要一条条核对。

发动机要连续变化，做法和原版不同：同时放几条不同转速的循环录音，按转速调音高、交叉淡入淡出，按油门负荷混入一点"吃力"的声音。

| 组 | 声音 | 来源 |
|---|---|---|
| 发动机 | 预热继电器"咔"一声；起动机转着车（一条录音：打火 → 着车 → 怠速 → 熄火，切成三段）；打不着（没油）；怠速循环；低、中、高转速循环（带负荷）；松油门滑行循环；涡轮细啸（叠加层） | Firefly，同一台"车"的几条录音 |
| 行驶 | 轮胎滚动循环：沥青 / 碎石 / 土 / 草；沥青急刹尖叫；碎石打滑；悬挂压到底"咚"；车里的风噪（随车速） | Firefly；碎石、土可以试原版方块的脚步声 |
| 碰撞 | 轻撞、重撞（金属 + 玻璃）；刮蹭 | Firefly |
| 车身 | 车门开、关；尾门开（链条）、关；油箱盖开、关；钥匙插入、转动；档杆；2H / 4H 拨杆"咔哒"；手刹棘轮 | Firefly 的短音效 |
| 其他 | 喇叭（不在用户表里，建议加）；转向灯继电器（P2，没有转向灯以前不做） | Firefly |
