# 体温 / Temperature — 设计 V1

状态：**V1 已实现（2026-10-03），编译通过，没有实机验证**。实际行为和全部数值见 `docs/gameplay/temperature_system_v1.md`。本文记录设计目标、用户决定和取舍。

## 用户决定（2026-10-03）

1. 用摄氏度。**环境温度**和**核心体温**分开算。
2. 极端冷热最后可以缓慢掉血，但必须先经过“性能减益”阶段，不直接伤血。
3. V1 用现有护甲保暖，数值放在 JSON 里（thermal insulation）。不做金属装备晒太阳发热。以后的服装系统在这个接口上扩展。
4. AFL V1 主世界的基调是**温带偏冷**，不做永久核冬天。废土比平原略冷，昼夜温差更大。四季以后再做。

## 1. 两层模型

- **环境温度**：这里的空气有多冷。只和地点、时间、天气、建筑、热源有关，跟穿什么无关。以后温度计显示的“环境温度”就是这个值。
- **核心体温**：从 37.0 °C 开始，慢慢追一个由体感决定的**目标体温**。所有阶段都只看核心体温。

体感 = 环境温度 − 湿冷 + 出力产热。保暖只把舒适区的下限往下移，所以 V1 的护甲天然只防冷。

不做热量池、积分器、身体部位温度、风向和日照方向。所有外部因素都折成一个体感温度，约 25 个可调数，全部在一个 JSON 里，`/reload` 生效，和耐力、口渴的写法一致。

## 2. 环境

- 每个群系有日均温、昼夜振幅和水温。05:00 最冷，14:00 最热。
- 废土：日均 9 °C，振幅 9（0–18 °C）；平原：日均 12 °C，振幅 6（6–18 °C）。废土的白天和平原一样暖，因为空气干、升温快；夜里明显更冷。
- 下雨 −3，雷暴 −4，只在有降水的群系生效。废土没有降水，所以不下雨也淋不湿。
- 高处更冷（Y 80 以上每格 −0.05）。地下接近岩温（11 °C 起，越深越暖）。
- 遮蔽：屋顶和墙越完整，空气越接近全天均温；室内没有昼夜变化，也不受天气影响。所以“进屋”本身就能保暖，但废土的无火小屋只有 9 °C，过夜还是偏冷。
- 热源只认白名单里的方块 id（营火、火、岩浆、熔炉、AFL 的炉子和发电机等）。叠加按“最强的一个 + 一半其余”，再有上限，不会无限叠加。岩浆和火是辐射热：贴近非常烫，退几格就没了（用户实测：站在岩浆旁不热，2026-10-03 加强）。室内效果是户外的约 1.67 倍，因为户外有风。售货机等用 lit 表示灯光的方块不是热源。

## 3. 身体

- 舒适区默认 14–24 °C（体感）。体感每超出 1 °C，目标体温偏离 0.15 °C。
- 变坏慢（τ 300 秒，泡水 100 秒），回暖快（τ 120 秒），玩家不会被困住：在营火旁从 33 °C 回到正常约 3 分钟。一个 MC 夜晚只有约 2 个 τ，所以昼夜变化会被身体平滑掉。
- 湿身：淋雨或下水会变湿，湿冷 −6；入水按深度连续计算（用户要求“踩在水里就降温，泡在水里更快”，2026-10-03）：越深越接近水温、湿冷越重（全身入水再 −12）、保暖和干活的热损失越多、体温掉得越快。保暖在湿透时减半，全身入水时完全失效。热源旁边干得更快。泡在冷水里几分钟会冻伤掉血（用户要求，2026-10-03）。
- 干活发热：耐力花得越多越暖（最多 +8 °C），冷的时候干活能抵消一部分寒冷。

## 4. 阶段（先减益，最后才掉血）

| 冷 | 核心体温 | 效果 |
|---|---|---|
| C1 寒冷 | < 36.0 | 耐力恢复变慢，持枪发抖 |
| C2 失温 | < 35.0 | 再加减速、寒战消耗饥饿、不自然回血 |
| C3 严重失温 | < 34.0 | 再加每 15 秒 1 点伤害 |

| 热 | 核心体温 | 效果 |
|---|---|---|
| H1 炎热 | > 38.0 | 口渴变快，耐力消耗增加 |
| H2 中暑 | > 39.0 | 再加耐力恢复变慢、减速、不自然回血 |
| H3 热射病 | > 40.0 | 再加每 15 秒 1 点伤害 |

- 掉血在简单、普通、困难都能致死（2026-10-03 用户要求，和口渴的脱水一致；不能致死就等于可以无视），和平难度不掉血。
- 进入更差的阶段时动作栏提示一次。
- 不做状态效果图标、屏幕滤镜、反胃，不影响阅读和战斗；提示交给体温表盘。

**V1 世界里的预期体验**：废土裸身在户外过夜只会到“寒冷”；皮甲、屋子、营火任意一样都能保持正常；站在岩浆旁约 1 分钟进入“炎热”、几分钟后热射病掉血，退开几格就安全；在冷水里泡 3–5 分钟会冻伤掉血，所以游泳横渡宽阔海面要坐船；满屋机器旁干活只是略热。其它掉血情况只在真正极端的地方出现（其它模组的雪原、极高处的夜里）。这符合“温带偏冷、不做极端机制”。

## 5. 保暖

- 护甲的保暖值（°C）按件写在 JSON 里。皮甲最保暖（全套 12），正好让废土最冷的 0 °C 落在舒适边缘；金属甲护甲高但保暖差（铁 6），形成取舍。
- 以后的服装、背包衬里、饰品槽：注册新的保暖来源即可。厚衣服怕热、防水、金属晒太阳发热都留到服装系统。

## 6. HUD：体温表盘

用户要求（2026-10-03）：
- 体温指示是核心指示，表示**核心体温**，不是环境温度。
- 默认不显示数字。
- 正常是中性灰；冷时连续渐变到冰蓝，热时连续渐变到橙色，没有阈值跳色。
- 正常只有很轻的呼吸感；偏冷或偏热时边缘微微发光；极端时有中等强度的脉动和光效，但不妨碍阅读和战斗。
- 数字（°C）以后由温度计或生存监测仪解锁，显示核心和环境两项；V1 只预留接口。
- 风格要和耐力、口渴、负重的圆形 HUD 统一。

第一版预览后用户的意见：保留位置、尺寸、冷热颜色方向、状态插值框架和极端状态的概念；去掉中间的温度计图形；球体要有真实的层次；外圈更精致；正常状态不能像一块灰色圆饼；冷热过渡更柔和；极端特效减少但提高质量。目标是**像现代生存监测设备上的状态指示灯，而不是圆形温度计图标**。

第二版（金属外圈 + 玻璃球）实机看过后，用户的意见（2026-10-03）：和耐力环、水滴环差太多，不像一个风格。

第三版（和耐力环同样的圆环 + 中间圆点）实机看过后，用户的意见（2026-10-03）：进度涨得慢，不明显；参考了其它模组（Tough As Nails 用状态图标，Cold Sweat 放在快捷栏正中，冬季救援把各项指标拼成一组仪表盘、体温在中间），用户喜欢冬季救援的做法，确认先把下面这版做进游戏，其它 HUD 以后再加。

当前做法（第四版，生存指标组）：
- 体温表盘在中间、最大，耐力环和水滴环在它两边，组成一组，放在红心和饱食度上方。
- 中间图标：正常是圆点；偏冷变成雪花，偏热变成火焰，平滑过渡。不看数字也能一眼读出状态。
- 外圈是 270° 的双向刻度：指针在正上方是正常，偏冷往左，偏热往右。
- 趋势箭头：底部开口里三个箭头连续流动，变冷往下流（蓝），变热往上流（橙）。体温本身变得慢，箭头在目标体温一变时就出现，解决“涨得慢看不出来”。
- 目标框（用户确认加入，2026-10-03）：刻度上一个空心、低透明度的细线框，表示“在这里、穿成这样，体温最终会停在哪里”。环境一变它用约 0.2 秒移过去（快，但不瞬移），实心指针慢慢追它。核心体温始终是视觉主角，目标框必须比它弱。
- 正常时轻微呼吸，偏离时有光晕；极端时光晕更强更宽、缓慢脉动，并有一圈细波纹向外扩散（用户觉得原来的极端光晕偏弱，2026-10-03 加强）。数字仍等测温装备解锁，以后可以显示在表盘中间。
- 细节见 `temperature_system_v1.md` 的 HUD 一节。

## 6.5 屏幕遮罩

第三层反馈：表盘告诉你现在冷不冷，目标框和箭头告诉你环境正在把你推向哪边，屏幕遮罩表示身体已经真的受到冷热影响。
- 只跟核心体温走，只在屏幕边缘，准星和 HUD 始终清楚，不晃镜头、不大幅模糊。
- 冷：原版像素风的雪花霜边（用户要求，参考 Tough As Nails / Cold Sweat 的画法，但不用它们的贴图），从角落往里长。
- 热：暖色泛白加边缘热浪。第一版用了 Cold Sweat 那种暗红压暗，用户觉得像濒死、太红，改成被晒晕的感觉。
- 细节见 `temperature_system_v1.md` 的“屏幕遮罩”一节。
