# 声音与感染者听觉

AFL 的声音系统会将玩家行为、枪械与爆炸转换为具有位置和传播范围的噪声事件。

感染者听到噪声后会调查真实声源位置。

---

# 1. 噪声类型

当前噪声类型：

| 类型 | 用途 |
|---|---|
| `GUNSHOT` | 枪声 |
| `EXPLOSION` | 爆炸 |
| `BLOCK_BREAK` | 方块破坏 |
| `FOOTSTEP` | 脚步 |
| `LANDING` | 落地 |
| `INTERACTION` | 环境交互 |
| `MACHINE` | 机器运行（2026-10-09 加入，没有玩家声源） |

声音系统本身：

- 不生成新的感染者
- 不直接执行寻路
- 只更新感染者的声源目标与调查状态

---

# 2. 感染者听觉

感染者位于噪声的有效传播范围内时，会记录真实声源位置并尝试调查。

当声音传播半径：

`> 10 格`

时，感染者可以进一步：

- 朝声源移动
- 搜索进入建筑的路径
- 尝试破坏允许破坏的障碍物

---

## 调查参数

| 参数 | 当前值 |
|---|---:|
| 首次寻路错峰 | 0–9 ticks |
| 成功寻路最低刷新间隔 | 20 ticks |
| 寻路失败重试 | 30–40 ticks |
| 相近声源合并距离 | 2 格 |
| 建筑入口搜索冷却 | 40 ticks |
| 建筑入口首次错峰 | 0–19 ticks |
| 每轮最大入口候选寻路数 | 8 |

距离当前调查目标不超过约 2 格的连续噪声：

- 刷新最后听到声音的时间
- 不重新建立整套调查流程
- 不重新选择几乎相同的声源位置

如果声源位置发生明显变化，则可以建立新的调查目标。

枪声调查保留真实声源位置。声源超出单次寻路可达范围时，可以先沿至少两个节点、终点确实更接近声源的局部路径移动，再按原有刷新间隔重算。无有效进展的路径仍按失败冷却重试；不提高听觉半径或寻路搜索预算。此局部路径规则仅用于枪声调查，不改变爆炸调查与搜索阶段规则。

# 6. 枪声

AFL 原生枪械的枪声直接进入 AFL 自己的噪声系统。

每把枪的枪声半径由自己的枪械数据定义。

例如：

| 武器 | 枪声半径 | 枪声耳鸣 |
|---|---:|---|
| 制式手枪 | 64 格 | 否 |

只有一次真正成功射击才会产生枪声噪声。

以下情况不会产生枪声噪声：

- 空仓干击
- 被服务器拒绝的射击
- 未真正发射子弹的状态

---

## 枪声传播

枪声会：

- 以射击位置作为声源
- 吸引有效范围内的感染者
- 使用正常的方块声学衰减
- 参与感染者调查与破障逻辑
- 枪声本身（玩家听到的）也传到同一半径（2026-10-09，见第 14 节）

枪声不会直接生成新的感染者。

---

# 7. 枪声耳鸣

枪声噪声和枪声耳鸣是两个独立系统。

一把枪可以：

- 产生很大的感染者听觉范围
- 但不一定让玩家耳鸣

例如制式手枪：

`噪声半径 = 64 格`

但：

`枪声耳鸣 = 否`

较大口径武器后续可以单独启用枪声耳鸣。

---

## 枪声耳鸣内部参数

枪声耳鸣主要用于未来的大口径枪械。

### 基础范围

`16 格`

### 武器响度

根据枪械噪声半径 `R`：

`loudness = clamp((R - 64) / 96, 0, 1)`

因此：

- 64 格及以下基本没有枪声耳鸣响度
- 噪声半径越高，耳鸣潜力越强

### 距离衰减

玩家距离枪声 `d`：

`distanceFactor = (1 - d / 16)²`

16 格以外不产生该枪声的耳鸣暴露。

---

## 大口径倍率

| 枪声半径 | 额外倍率 |
|---|---:|
| `R ≥ 128` | ×1.25 |
| `R ≥ 160` | 再 ×1.35 |

单次暴露强度存在上限：

`0.75`

---

## 累积参数

| 参数 | 当前值 |
|---|---:|
| 累积上限 | 1.5 |
| 每 tick 衰减 | 0.008 |
| 第一阈值 | 0.35 |
| 第二阈值 | 0.60 |
| 第三阈值 | 0.90 |
| 硬冷却 | 6 ticks |
| 延长节流 | 20 ticks |
| 触发后保留累积 | 45% |

该系统主要用于：

- 大口径步枪
- 狙击枪
- 重型武器

普通 9mm 制式手枪当前不会触发。

# 8. 爆炸噪声

所有正常进入 Minecraft / Forge 爆炸流程的爆炸都会产生一次爆炸噪声。

感染者听觉半径根据实际爆炸强度动态计算。

## 公式

`rawRadius = 96 + Explosion Strength × 24`

然后：

`Noise Radius = round(rawRadius / 8) × 8`

最终限制：

`96–256 格`

---

## 爆炸噪声示例

| 爆炸强度 | 噪声半径 |
|---:|---:|
| 2.0 | 144 格 |
| 2.5 | 160 格 |
| 3.0 | 168 格 |
| 4.0 | 192 格 |
| 5.0 | 216 格 |
| 6.0 | 240 格 |
| ≥ 约 6.67 | 256 格 |

原版 TNT：

`Explosion Strength = 4`

因此：

`噪声半径 = 192 格`

爆炸声本身也传到同一半径（2026-10-09，见第 14 节）。

---

# 9. 爆炸噪声与爆炸耳鸣

两者使用同一次爆炸事件，但属于不同系统。

## 爆炸噪声

负责：

**感染者能从多远听见爆炸。**

范围：

`96–256 格`

## 爆炸耳鸣

负责：

**玩家在近距离受到多强的听觉和视觉冲击。**

它使用自己的：

- 距离
- Severity
- 音量
- 持续时间
- Overlay

规则。

因此：

> 爆炸可以被非常远的感染者听见，但只有距离较近的玩家会出现明显耳鸣。

爆炸耳鸣的具体参数见《生存系统》。

|---|---|
| 羊毛 | 每穿过 1 层完整羊毛，有效传播范围 ×0.5 |

多层羊毛按乘法累计。

例如：

原始噪声：

`64 格`

穿过一层完整羊毛：

`32 格`

穿过两层：

`16 格`

# 11. 机器噪声

机器的噪声由方块实体在服务端直接发出（类型 `MACHINE`，声源位置是机器的发声点，没有玩家声源），半径一般取玩家听得见它的距离。

| 机器 | 行为 | 噪声半径 |
|---|---|---:|
| 备用柴油发电机组 | 拧钥匙盘车 | 12 格 |
| 备用柴油发电机组 | 着车 | 24 格 |
| 备用柴油发电机组 | 运行中，每 40 ticks 一次 | 24 格 |
| 便携式柴油发电机 | 拉一下起动绳 | 8 格 |
| 便携式柴油发电机 | 着车 | 32 格 |
| 便携式柴油发电机 | 运行中，每 40 ticks 一次 | 32 格 |

运行中的发电机组超过 10 格，感染者可以为了它破障；机组一直在响，感染者会在它附近反复调查，可以当诱饵。便携式是开架的，没有隔音罩，比带罩的大机组响；拉一下起动绳只有 8 格，不到破障门槛。详见 [备用柴油发电机组 V1](../../../machines/diesel_standby_generator_v1.md)、[便携式柴油发电机 V1](../../../machines/portable_diesel_generator_v1.md)。

盘车、拉绳、着车、停机这几声和运转循环都传到同一半径（2026-10-09，见第 14 节）。

其它机器（取水泵、充电站、冷柜压缩机等）目前还没有噪声。

# 14. 声音传播半径（2026-10-09）

用户 2026-10-09："最近加入的发电机音效，是传播半径和感染者听觉半径对得上的 / 但是之前的绝大部分音效，都不是这样……特别是枪声 / 把他们的半径改成对应的感染者听觉半径"。

**规则**：和感染者噪声对应的声音，玩家听到的范围等于这次噪声的半径。声音随距离线性变小，到半径处听不到。玩家听得见的，感染者也听得见。唯一的例外是装了消音器的枪声（见下）。

**原来为什么对不上**：原版有两道限制。
- 服务端只把声音发给 16 × max(音量, 1) 格内的玩家；
- 客户端在 max(音量, 1) × `sounds.json` 的 `attenuation_distance`（默认 16）处衰减到零。
- 所以用音量 1 播的枪声 16 格就没了，感染者却在 64–128 格都听得到；油罐爆炸用音量 3，只发到 48 格；16 格以下的范围用音量调不出来，音量小于 1 只是变轻，范围还是 16。

**做法**：
- 服务端 `noise/RangedSound.play(level, 位置, 声音, 类别, 半径, 音量, 音调)`：只发给半径内的玩家（`network/RangedSoundS2CPacket`，带随机种子，各客户端选到同一个变体）。
- 客户端 `client/RangedSoundInstance`：解析出声音文件后，把它的衰减距离换成这个半径，音量不超过 1。所以这些事件在 `sounds.json` 里的 `attenuation_distance` 不再起作用。
- 半径用发噪声时的同一个值，不另外写一份。

| 声音 | 半径 | 原来 |
|---|---|---|
| 枪的开火声 | 枪械数据的 `noise.radius`：P9 64、Blackridge 88、Silverwood 104、BR51 112、HR55 128、CAT 6 | 16 格 |
| 装了消音器的开火声 | **16 格**（例外：用户同日定"消音改回16格"，`NativeGunNoise.SUPPRESSED_SOUND_RADIUS`）。噪声还是 max(1, round(R × 0.05))：P9 3、Blackridge 4、BR51 6、HR55 6 | 16 格 |
| 原版爆炸声（所有走原版爆炸流程的爆炸） | 这次爆炸的噪声半径，96–256 格 | 64 格：客户端自己放（音量 4），也只有 64 格内的玩家收得到爆炸包。现在 mixin `mixin/client/ExplosionSoundMixin` 去掉客户端那份，由服务端在 `noise/ExplosionNoiseEvents` 里按半径放，音调和原版一样 |
| 油罐爆炸叠加的那一声 `fuel_explode` | 同一次爆炸的噪声半径 | 客户端算 96 格，服务端只发到 48 格 |
| 备用机组：盘车（没油时） / 着车 / 停机 | 12 / 24 / 24 | 16 / 24 / 24，但服务端只发到 16 格 |
| 便携机：拉绳（着车的和没着的） / 着车 / 停机 | 8 / 32 / 32 | 16 / 32 / 32，同样只发到 16 格 |
| 两台机组的运转循环 | 24 / 32 | 本来就对（客户端循环控制器按半径放） |
| 铅箱开盖、合盖 | 3（开盖的噪声） | 12 格 |
| 原版门、活板门、栅栏门开关 | 声音位置上那个方块的噪声：木门 4、铁门 6、木活板门 3、铁活板门 5、栅栏门 3。AFL 钢门可以徒手开，噪声按木门算（4），声音也是 4（虽然放的是铁门声） | 16 格 |
| 原版箱子、木桶开关 | 3 | 16 格 |
| 放置方块 | 4 | 16 格 |
| 破坏方块 | 这个方块的破坏噪声：软质 4、木质 6、石质 8、玻璃 10、金属 12，不在这些标签里的 6 | 16 格 |
| 玩家脚步 | 潜行 2、走路 4、疾跑 8（看是哪个玩家的脚步、他当时的步态） | 16 格（音量很小） |
| 玩家落地 | 轻摔声 8、重摔声 12；方块的落地声跟着同一下 | 16 格 |

**原版声音怎么缩**（用户同日"原版那些也缩"，`client/NoiseSoundRanges`）：
- 原版是在各处自己播这些声音的（服务端发给 16 格内的玩家，或者客户端本地放），所以在客户端接住：Forge 的 `PlaySoundEvent` 在声音解析之前触发，把它包一层，解析出来的声音文件换成衰减距离等于半径的一份，音量不超过 1，别的照原样转发。
- 怎么认：
  - 门、活板门、栅栏门：声音名以 `door.open/close`、`fence_gate.open/close` 结尾，半径取声音位置上那个方块的噪声（和 `InteractionNoiseResolver` 同一套判断）；那里是空气（门刚被拆）才按声音名；别的方块借用门的声音（加油站泵井盖开关用的是铁活板门声）不缩，2026-10-10 改，原来按声音名把它缩到了 5 格；
  - 箱子、木桶：`block.chest.*`、`block.barrel.*`；
  - 放置、脚步、落地：第一次用到时把所有方块状态的声音类型扫一遍，记下放置声、脚步声、落地声；放置声要是"方块"类别，脚步和落地声要是"玩家"类别（怪物的脚步不动）；
  - 脚步看离声音最近的玩家是潜行、走路还是疾跑；
  - 落地：原版只有会掉血的摔落（超过 3 格）才有落地声，那时噪声是 8 格（3–6 格）或 12 格，所以轻摔声 8、重摔声 12，方块的落地声跟着前面那一下；
  - 破坏方块：原版在 `LevelRenderer.levelEvent` 的 2001 里放破坏声，mixin `mixin/client/LevelRendererBreakSoundMixin` 在这一下前后记下是哪个方块，半径用 `BlockBreakNoiseResolver`。
- 听者在半径外时直接不放：1.20.1 的字幕不看距离，不这样的话听不见也会弹字幕。
- 半径常量提到 `InteractionNoiseResolver`（`WOODEN_DOOR` 等）和 `MovementNoiseEvents`（`footstepRadius`、落地半径）里，噪声和声音共用一份。

**没动的**：
- 没有噪声的声音：储物柜、垃圾箱、收银机、冷柜、配电盘、取水泵、充电站、各种机器循环、换弹拉栓等枪械动作声。它们没有对应的听觉半径，不动。容器翻找声 8 格；翻找噪声目前所有容器都关着（半径 0）。

**消音枪声**：枪械文档原来就写"消音器只改噪声，玩家听到的距离不乘 0.05"。这一轮先按新规则缩到了 3–6 格，用户看了以后定"消音改回16格"，所以保留原来的规定：消音枪声 16 格，噪声 3–6 格。

**太短的声音**（用户同日："有一些音效特别短，比如油罐爆炸，一会就没声音了"）：
- `fuel_explode` 原来的素材只有 3 秒，峰值后 2.15 秒就衰减了 40 dB。同日换成用户新生成的 12 秒录音，`explode.ogg` 11.0 秒，峰值后 9 秒才衰减 40 dB（见 `docs/gameplay/fuel_fire_v1.md`"声音"）。
- 枪声都在 1 秒左右，峰值后 0.5 秒衰减 40 dB，尾巴没有被切；`p9_01_suppressed` 0.33 秒，结尾还在 -30 dB，是被切断的。用户定"枪声尾音先不管，后面我们再重置"，这次不动。

**验证**：`compileJava` 通过，refmap 里有两个 mixin 的映射。没进游戏听过。

**以后**：新声音如果和噪声同时发出，就用 `RangedSound.play`，半径传发噪声用的同一个变量。新加原版式的交互噪声（`InteractionNoiseResolver`、`MovementNoiseEvents`、`BlockBreakNoiseResolver`）时，看 `client/NoiseSoundRanges` 认不认得对应的声音。
