# 流体系统

AFL 使用 Forge Fluid / FluidStack 构建定向端口、无库存压力管与可合并的储罐；机器容量与配方见 [机器参数](机器.md)。

## 0. 计量单位：1 mB = 1 升（2026-10-04 起）

- AFL 所有流体数值统一按 **1 mB = 1 升** 计：一格液体（源方块）= 1 m³ = 1,000 升 = 1,000 mB。
- 容器容量按真实容积定，不按"能装几桶"：

  | 容器 | 容量 |
  |---|---|
  | 立式储罐 | 每格 800 mB；拼成完整长方体的储罐合并，容量 = 格数 × 800 mB |
  | 化学反应器 | 输入槽、废液槽各 200 mB |
  | 热力发电机 | 液体燃料槽 200 mB |
  | 地下油罐 | 30,000 mB |
  | 取液泵出口缓冲 | 250 mB |

  以后的手提油壶约 20 mB，油桶约 200 mB。
- **原版桶要逐步淘汰**：
  - 从 2026-10-04 起，`minecraft:bucket` 的合成配方已禁用（`data/minecraft/recipes/bucket.json`，`forge:false`）；
  - 不能再挤牛奶（对牛、哞菇、山羊用桶没反应），以后做现代的盒装 / 桶装牛奶；
  - 世界里已有的桶暂时还能用。原版桶一桶仍是 1,000 mB，所以单格立式储罐（800 mB）装不下一整桶，合并的大罐才能倒进去。
- **取液泵**（2026-10-05 已实现，没有实机验证，见 [Intake Pump V1](../../../models/intake_pump_v1.md)）代替桶取液：
  - 两格长：后格在岸上，前格伸到液面上；只抽前格正下方那一格的液体源；
  - 抽进流体管道，每 tick 5 mB（每秒 100 升），抽液时 8 FE/t；
  - 水和岩浆要在至少 3 × 3 × 1 的同种液体源池子里才能抽，抽了不会用掉（用户 2026-10-05 定，为了游戏性）；前格下面那格落在任意一个 3 × 3 方阵里就算；
  - 其它液体（汽油、柴油、工业废液）每抽 1,000 mB 用掉一格源方块，不要求池子大小；
  - 高温液体（超过 400 K，岩浆）要用耐热设备：耐热流体管道、耐热流体储罐、耐热取液泵（2026-10-05，见 [耐热流体设备](../../../models/heat_resistant_fluid_set_v1.md)）。普通管道、储罐、取液泵也能装，但会被烧毁（方块消失、不掉落）。两种设备互不相连。
- 以后还要做便携容器（手提油壶、油桶）来代替桶，桶也会从战利品里去掉。
- 液体重量按密度算：水每 mB 1 kg，岩浆 3 kg，工业废液 1.1 kg，汽油 0.74 kg，柴油 0.84 kg（见 [负重](../生存/负重.md)）。
- 管道流速仍是 25 mB/t（每秒 500 升）：管子直径约半米，大口径管道每秒几百升是合理的。

# 1. 流体系统

## 流体光照

- 公共流体层读取 `FluidType.getLightLevel(FluidStack)`：大于 0 使用 full-bright，0 保持环境光；钢框、玻璃和其他模型不使用 full-bright。
- 世界光照按 `round(流体亮度 × 上限 / 15)` 映射，发光流体最低 1；储罐上限 9，管道上限 5。熔岩分别为 9 / 5，水与普通工业废液为 0。标准 Block Light 不提供彩色光。
- 合并的储罐里，每格按自己分到的液体（从下往上灌）发光；空的格熄灭。管道沿用 20 tick 内容保持时间，流动/静止切换不改变亮度；内容过期清除光照。
- 仅光照等级改变才写方块状态，液量小幅波动不反复更新光照。不改流体传输、容量和消耗。
- 实现与验证见 [流体光照 V1](fluid_lighting_v1.md)。

AFL 使用 Forge Fluid / FluidStack 作为工业流体基础。

当前主要包含：

- Water
- Industrial Waste
- 未来其它工业流体

流体系统与 FE 网络完全独立。

# 2. Fluid Pipe

Fluid Pipe 是工业压力管道。

## 基础规则

| 项目 | 当前规则 |
|---|---|
| 标准自动传输速率 | 25 mB/t / 每个真实端口 |
| 高度限制 | 无 |
| 重力限制 | 无 |
| 管道内部储液 | 无 |
| 区块强制加载 | 无 |
| 液体混合 | 不允许 |
| 管道 Tier | 无 |
| Pressure 模拟 | 无 |
| Pump | 无 |
| Filter | 无 |

管道本身不保存 FluidStack。

真正的流体永远存在于：

- Fluid Tank
- Chemical Reactor
- 未来其它机器流体槽

中。

---

## 端口预算

标准自动化端口：

`25 mB/t`

这是：

【单个真实输入 / 输出端口的 tick 预算】

多个来源同时接入同一个端口时，不能突破该端口的 25 mB/t 上限。

不同端口拥有独立预算。

手持桶等玩家手动容器交互不受 25 mB/t 限制。

---

# 3. 流体输送

当前输送方式为：

`Source Endpoint → Fluid Pipe → Target Endpoint`

Source 主动向管网 push。

管路可以：

- 向上
- 向下
- 水平
- 转弯

高度不会改变传输能力。

目标必须：

- 接受对应 Fluid
- 存在可用容量
- 当前端口仍有输入预算

如果存在多个目标，优先寻找当前真正可以接收流体的目标。

---

# 4. 背压

当目标：

- Fluid 类型兼容
- 管路仍有效

但因为：

- 储罐已满
- 本 tick 输入预算已耗尽

暂时不能接受流体时，管道进入背压显示。

此时：

`实际传输量 = 0 mB`

并且：

- 不扣除源端 Fluid
- 管道不保存 Fluid
- 路线仍短暂保持可视状态

目标重新获得容量后自动恢复输送。

---

# 5. 管道流体显示

真实输送时：

`FLOWING sprite`

背压状态：

`STILL sprite`

两者都使用 Fluid 自己的：

- Texture
- Tint
- Atlas Animation

输送停止后，管内视觉最多保留约：

`20 ticks`

之后消失。

---

# 6. 管线隔离

直接紧贴的平行管线不会因为相邻而自动串线。

规则与 Fluid 类型无关。

例如：

- Water / Water
- Water / Industrial Waste

只要属于两条独立管线，就不会因为紧贴而互相连通。

需要主动连接时，应通过明确的转弯或桥接结构完成。

# 7. Industrial Waste / 工业废液

Registry：

| 对象 | ID |
|---|---|
| Source / FluidType / LiquidBlock | `apocalypse_firstlight:industrial_waste` |
| Flowing | `apocalypse_firstlight:flowing_industrial_waste` |
| Bucket | `apocalypse_firstlight:industrial_waste_bucket` |

`1 Bucket = 1,000 mB`（1 mB = 1 升，见第 0 节；原版桶的合成已禁用，工业废液桶以后随桶一起淘汰）

## 当前规则

- 不可无限生成 Source
- 可以使用桶放置和取走（只限世界里已有的桶）
- 可以进入 Fluid Tank
- 可以通过 Fluid Pipe 输送
- 可以作为 Chemical Reactor 废液
- 不属于 `minecraft:water`
- 不属于 `minecraft:lava`

当前没有：

- 接触伤害
- 中毒
- 腐蚀
- 污染伤害
- 辐射
- 毒气

---

## 物理表现

工业废液整体沿用 Water 风格的流动与实体移动基础：

- 可以游动
- 可以溺水
- 可以推动实体
- 支持船
- 可以灭火

但它不是普通水，因此不会被其它系统当作配方水使用。

## 颜色和光影兼容（2026-10-04）

工业废液的颜色放在顶点色里（0x9B936B），贴图存"颜色 ÷ 顶点色"，原版和 Complementary 下看起来不变；汽油、柴油也一样（见 [燃油液体](../../../gameplay/fuel_fluids_v1.md)）。原因是 Sundial Lite 把没登记的半透明方块当彩色玻璃，液体看不见；在它的设置里打开"模组液体检测"后，有顶点色的模组液体会被当成水画出来（颜色取顶点色，不显示贴图花纹）。工业废液桶的液体层也改为跟着顶点色（物品模型 `apply_tint` + `client/AflFluidItemColors`）。原贴图在 git 里有记录。
