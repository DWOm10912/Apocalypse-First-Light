# AFL 木材体系、建筑木材与工匠台：规划 V1

日期：2026-10-11。来源：作者在 Mesh 树木 P0-B 期间给出的三条设计决定。

本文是规划。写下时（2026-10-11）什么都没有注册，没有实现，也没有配方；实施顺序是先等树木系统（[P0-B](../rendering/mesh_trees_p0b.md)）验收，再安排。

**进度（2026-10-12）**：
- 六种原木、树枝、叶材已正式注册（[Mesh Trees P4](../rendering/mesh_trees_p4_formal.md)）。
- 第一批建筑方块已做：[木材建筑方块 V1](../models/wood_building_blocks_v1.md)，六个树种 × 木板 / 圆角方木 / 木梁，共 18 种。代码完成、离线检查和编译通过，用户实机 **PASS**（2026-10-12）。
- 仍然**没有**配方、锯材、台阶楼梯、工匠台（用户这一轮明确排除）。
- 下面第六节的表格加了"现状"一列；其余各节仍是规划原文。

## 一、总体方向：三层

1. **世界里的自然树木**：
   - 用 Mesh 树系统表现：真实外观、风动、多样性；
   - 首批正式树种是白栎和东部白松（P0-A / P0-B）。
2. **砍树**：
   - 只能砍底部树根，砍断后整棵树倒下；
   - 倒树可以是 Mesh 实体或特效；
   - 倒地后统一结算掉落；
   - 架构见 [P0-A L 节](../rendering/mesh_trees_p0a.md)。
3. **玩家得到并用来建造的木材**：
   - **不用**自由形状的 Mesh 物体做主要建筑材料；
   - 走"方块逻辑 + Mesh 外观"：放置、选中、破坏、旋转、结构生成都按方块系统处理；
   - 外观不是原版满方块，而是更写实的木材截面和倒角。

## 二、AFL 自有木材系列

- AFL 的正式树种各有独立的木材系列，例如：
  - 白栎 → 白栎原木 → 白栎锯材 / 木板；
  - 东部白松 → 白松原木 → 白松锯材 / 木板。
- 原版木材继续注册、保持兼容。AFL 的主要生存获取、建筑制作和工业加工逐步改用 AFL 木材。
- 木材的注册、贴图和配方以后单独开发。

## 三、建筑木材

首批围绕白栎、白松。优先的类型：

| 类型 | 说明 |
|---|---|
| **圆角方木**（rounded-square timber，重点） | 逻辑上占满 1 格，视觉上有轻微圆角或倒角；用于木屋、林中小屋、门廊、棚屋、加油站木构细节；要明显比原版原木更真实、更高级 |
| 木梁（beam） | 沿一个轴的梁 |
| 木板（planks） | — |
| 以后扩展 | 半梁、角梁、斜撑、柱子等构件 |

## 四、工匠台：材料清单式制作

- **定位**：
  - 一台独立的工匠台，主要做建筑、家具、大型零件和普通复杂制品；
  - 精密制造台和其他专用机器保留自己的功能，避免重复。
- **不用网格**：
  - 不用原版 3×3 摆格子，也不扩大成 5×5 或 9×9；
  - 配方的数据结构不受网格限制，材料种类和数量可以任意（在合理的数据类型、库存容量和性能限制内）。
- **玩家在界面里**：
  1. 从分类列表选要做的物品；
  2. 看全部所需材料和数量；
  3. 系统自动统计玩家拥有的材料，每种显示"已有 / 需要"；
  4. 不足时明确显示缺什么；
  5. 齐了点"制作"，自动扣料、出物品。
- **例：大型木制储物柜**：

  | 材料 | 数量 |
  |---|---|
  | 白栎木板 | 48 |
  | 结构木梁 | 12 |
  | 钢制螺栓 | 24 |
  | 金属铰链 | 4 |
  | 把手 | 2 |

  不需要把这些材料摆成特定形状。
- **后续要支持**：
  - JSON 数据驱动的配方；
  - 材料标签与同类材料替代；
  - 材料不足提示；
  - 批量制作；
  - 配方分类与搜索；
  - 与 AFL 木材和工业材料兼容。

## 五、树木系统里已经留好的接口

- 树种 id（`white_oak`、`white_pine`；Mesh Trees P3 起还有 `red_oak`、`shagbark_hickory`、`red_maple`、`eastern_hemlock`）就是木材系列的标识，计划的注册名都以它开头。见下面的产品线草案。
- 作者 2026-10-11 定的顺序：先完成六种树的生态体系与正式接入，再集中开发木板、木梁、圆角方木和工匠台（[mesh_trees_p3_species L 节](../rendering/mesh_trees_p3_species.md)）。
- 每棵树的布局按枝的体积算好了三项（`TreeShape.Layout`）：
  - 树干体积，出原木；
  - 粗枝体积（会碰撞的枝），出原木或短原木；
  - 细枝体积，出树枝、柴。

  倒树结算时直接用这三项，不必重新量树。P0-B 实测的 v0：
  - 白栎：树干 2.71 m³、粗枝 2.58 m³、细枝 0.72 m³；
  - 白松：树干 11.08 m³、粗枝 0.73 m³、细枝 1.82 m³。

  每件物品折合多少体积还没定，要和背包、重量一起平衡（AFL 的方块是轻量搬运单位：泥土一块 0.15 kg、石头 0.25 kg，物品接近真实重量）。
  - Mesh Trees P2（2026-10-11，[mesh_trees_p2_felling](../rendering/mesh_trees_p2_felling.md) K 节）先用暂定值：原木 0.5 m³ 一件，树枝 0.1 m³ 一件，叶材按树冠半径算。只在 `FellingRules.drops` 一处计算，平衡时只改这里。
- 倒树后由实体一次性结算；格子本身不掉落（现在就是 `noLootTable`）。
  - P2 已实现：倒树实体落地后结算一次，同一棵树不会掉第二次。
  - P2 已用规划的名字做了开发专用注册，只是普通物品，没有配方：`white_oak_log`、`white_pine_log`、`white_oak_branch`、`white_pine_branch`，以及叶材 `white_oak_leaves`、`white_pine_needles`。正式注册时接管这些 id，并删掉开发注册。

## 六、木材产品线草案

注册名都是计划，`<wood>` 是 `white_oak` 或 `white_pine`。

| 层 | 产品 | 计划注册名 | 来源 / 用途 | 第一批？ | 现状（2026-10-12） |
|---|---|---|---|---|---|
| 原始掉落 | 原木 | `<wood>_log`（物品） | 倒树结算，按树干 + 粗枝体积 | **是** | 已做：六个树种，3D 原木方块（P2.2–P4） |
| 原始掉落 | 树枝 / 柴 | `<wood>_branch` 或通用 `kindling` | 按细枝体积；燃料、引火 | **是** | 已做：`<wood>_branch` |
| 原始掉落 | 树皮 | `<wood>_bark` | 剥皮时得到；白栎树皮可做鞣料，以后皮革用 | 以后 | — |
| 原始掉落 | 橡子 / 松果 | `white_oak_acorn`、`white_pine_cone` | 倒树或落叶时少量；以后种树苗 | 以后（随树苗生长） | — |
| 原始掉落 | 松脂 | `white_pine_resin` | 白松割脂；胶、火把、防水 | 以后 | — |

| 中间产物 | 锯材（粗方材） | `<wood>_lumber` | 原木锯开；做方木、梁、木板的原料 | **是** | 没做（用户 2026-10-12：先不加中间物品） |
| 中间产物 | 木板 | `<wood>_planks`（物品与方块） | 锯材再锯 | **是** | 方块和它的物品已做（V1），没有配方 |
| 中间产物 | 板条 / 木条 | `<wood>_lath` | 家具、隔墙、栅栏 | 以后 | — |

| 建筑方块 | 台阶 / 楼梯 / 板 | `<wood>_planks_slab` 等 | 同材质的变体，挖掘标签和等级与母材同步 | 以后（随第一批之后） | — |
| 建筑方块 | 半梁、角梁、斜撑、柱 | `<wood>_half_beam`、`_corner_beam`、`_brace`、`_post` | 构件 | 以后 | — |
| 加工 | 锯木机、剥皮 | — | 以后的木材加工机器 | 以后 | — |
| 加工 | 工匠台配方 | — | 第四节 | 以后（工匠台本身之后） | — |

第一批建议的最小闭环：
1. 倒树得到原木和树枝；
2. 原木临时用简单配方得到锯材和木板。工匠台以后再接，到时把这一步换掉；
3. 锯材做成圆角方木、木梁、木板方块。

## 七、规则（实施时）

- 按 AGENTS.md，木材和木制建筑方块用斧，挖掘等级按原版木头的方式，不套用工业 Diamond 的默认。台阶、楼梯、门等变体的挖掘标签和等级与母材同步。
- 外观做法按 AFL 的 Mesh 约定：方块逻辑、Mesh 外观，Blockbench 源放在 `src/main/blockbench/`。V1 的三种几何都是程序生成的简单形状，生成器 `tools/build-wood-blocks-v1.mjs` 就是可编辑源，没有 `.bbmodel`。
- 生存挖掘和掉落要在游戏里确认后才算完成。

## 八、顺序

1. 树木系统（P0-B）实机验收。
2. 白栎、白松木材注册和贴图：原木、锯材、木板、树枝；第一批建筑方块：圆角方木、木梁、木板。
3. 整树倒下和掉落结算。
4. 工匠台：界面、JSON 配方、标签替代、批量。
5. 其余中间产物、构件和加工机器。
