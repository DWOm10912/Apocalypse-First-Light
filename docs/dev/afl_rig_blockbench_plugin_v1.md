## 1. 为什么要它

P2 的枪械动画实机 NOT PASS（[player_skeleton_v1_design.md](player_skeleton_v1_design.md) 第 13.9 节），根子在"做的时候看到的"和"游戏里算出来的"不是一回事：
- 片段是对着 Blockbench 里方块手臂摆的；
- 游戏里手臂由 IK 去够目标，手、肘、腕的位置都由 IK 重新算。

插件让 Blockbench 用**游戏同一套算法**摆人：
- 骨架定义：`rigs/afl_humanoid_v1.json`；
- 走路片段里的静止呼吸 `locomotion.idle`；
- 动作片段按遮罩叠上去；
- 道具按运行时的道具关键帧摆放；
- 两只手按同一套两段 IK 去够目标。

所以 Blockbench 里看到的，就是游戏会画出来的。

## 3. 怎么用

**安装**：Blockbench → 文件 → 插件 → 从文件加载插件，选 `tools/blockbench/afl_rig.js`。
- 2026-10-16 我已经通过 MCP 装进用户的 Blockbench，插件列表里叫 `afl_rig`，是本地插件。
- 改了插件文件以后，用 `Plugins.devReload()` 或者重新加载。

**菜单**：工具 → AFL 骨架，下面有：

| 菜单项 | 作用 |
|---|---|
| 新建人物动画工程 | free 格式工程，带 16 块骨头、15 个分段方块、骨架的全部挂点（现在 4 个：`eye`、`armpit_l`、`armpit_r`、`holster`）和枪套参考模型 |
| 从道具定义建道具 | 读 `player_props/<id>.json`（找不到时读测试资源里的）。选「开始时挂在」哪个坐标系和握点。同名道具替换原来的，别的道具不动 |
| 把模型并入道具外观 | 把一个 .bbmodel 并进来当道具的样子；有几个道具时先选哪一个 |
| 重建枪道具外观（游戏网格） | 有枪道具时才出现：重新读枪的 aflmesh，换掉道具组里的枪外观（第 11.4 节） |
| 导入动作 JSON | 读一个已有的动作文件 |
| 导出当前动作 | 写动作 JSON 和片段 |
| 导出道具定义 | 写 `player_props/<id>.json`；有几个道具时先选哪一个；枪道具拒绝（由 `gunPropExport` 生成） |
| 加枪套参考模型 | 旧工程没有枪套模型时加上（第 10.4 节） |
| 设置仓库路径 | 默认 `D:/Minecraft Modding/AFL-survivor-v0` |

**面板**：动画模式右侧的「AFL 骨架」面板。
- 视角：
  - 俯仰：拖动条 −60…60°；
  - 开关：第一人称、下蹲、呼吸（idle 片段随时间播放，默认关，静止更好对姿势）、步枪胸口（胸口按长枪规则跟俯仰）、细手臂（Alex）。
  - 第一人称打开、动作里有枪道具时，预览按游戏的第一人称规则往前伸、手臂画窄（第 12.1 节）。
- 动作设置，存在每个动画上：
  - 动作 ID `group/name`；
  - 片段键：空着时等于 `group.name`；
  - 遮罩、层、优先级、淡入、淡出、第一人称模式、说明。
- 每个道具一张挂点表（第二阶段，第 10.2 节）：
  - 每行是「从」几秒起、「挂在」哪个坐标系、关键帧摆的是哪个「点」、「藏」不藏；
  - 第一行从 0 秒开始，时间不能改；
  - 「+ 当前时间 换挂点」在播放头位置加一行，同时在道具组上钉住两个关键帧，让曲线不变。
- 左右手的目标时间轴：
  - 每行是时间、目标、过渡、转角、肘向；
  - 目标可以选 `pose`、骨架的每个挂点 `socket:<挂点>`，以及每个道具上的每个点 `prop:<道具>:<点>`；
  - 「+ 当前时间」在播放头位置加一行。
- 道具出错时（例如挂在一个没有关键帧的道具上），面板下方用红字说明，这个道具不显示。
- 读数：每只手实时显示下面这些数，超出 ActionCheck 的门槛时标红。

| 读数 | 门槛 |
|---|---|
| 离目标（px） | IK 权重满时超过 0.6 px |
| 伸展比 | — |
| 肘角 | — |
| 腕弯 | 超过 50° |
| 前臂扭转 | 超过 30° |

**一个动作的做法**：
1. 新建人物动画工程，切到动画模式，新建动画。
2. 身体部分在骨骼上打关键帧：胸口、头、腿，以及没有 IK 目标的手臂。
3. 有道具时先「从道具定义建道具」，再在 `prop_<id>` 组上打位置和旋转关键帧，摆道具。
4. 道具要换挂点时（从枪套到手、弹匣离开枪），把播放头放到那一刻，点「+ 当前时间 换挂点」，再改那一行的坐标系。
5. 在面板里给左右手加目标时间轴，手会自己去够。
6. 「导出当前动作」，确认后写文件。

## 4. 坐标和换算

**两个坐标系**：
- Java 模型像素：游戏运行时用。y 向下，前方 −z，右臂在 −x。
- Blockbench free 格式：+y 向上，原点在地面。
- 换算：`B = (−x, 24 − y, z)`，等于绕 z 转半圈再上移 24。正反换算是同一个式子。
- 旋转：四元数 `(qx, qy, qz, qw) ↔ (−qx, −qy, qz, qw)`。

**骨骼关键帧**：
- Blockbench 关键帧数值 (bx, by, bz) 写进 Bedrock 文件时变成 (−bx, −by, bz)。
- 游戏读文件得到 `rotationZYX(bz, −by, −bx)`。
- 位置 (px, py, pz) 写成 (−px, py, pz)。
- 这和 `tools/export-native-gun.mjs` 的约定一样。
- 插件显示一根骨头的结果，和 Blockbench 自己显示同一个关键帧完全一样（MCP 实测，四元数点积 1.000000），所以旋转手柄的方向是对的。

**道具**：
- 每个道具是一个组 `prop_<id>`，按建道具时选的坐标系挂在：
  - `chest` → `chest`；`bone:<骨骼>` → 那根骨头；`socket:<挂点>` → 挂点所在的骨头；
  - 其余（`root`、`shoulder_*`、`prop:`）→ `root`。
  - 这个父级只在道具不在当前动作里时起作用；在动作里时插件按运行时的结果直接放道具。
- 组的原点 G 是建道具时的握点。新道具的握点放在：`socket:` 坐标系时放在挂点上，`prop:` 时放在那个道具的握点上，其余放在静止时的右手掌心。
- 组里有一个 `bounds` 方块，每个点一个定位器。
- 道具内容的编辑坐标 e 换成道具模型系：`Rx180 (e − D)`。D 是物品原点在编辑空间的位置，存在工程设置里。
- 点的物品单位：`(e − D) / (16 × scale)`，和 `PlayerProps` 一致。

**道具组的一个关键帧怎么变成一个运行时 `PropKey`**：
- 设关键帧的位移是 Δ，旋转是 R（ZYX 欧拉）。
- 转角：`turn = Rz180 · R · Rx180`，`rot` 取它的 XYZ 欧拉角。
- 位置：`pos = B2J(G + Δ + R (e_点 − G))`。肩部坐标系再减去静止时的肩关节位置。
- 一般写法：坐标系在静止姿势下的变换是 F，则 `turn = F.q⁻¹ · Rz180 · R · Rx180`，`pos = F⁻¹ · B2J(G + Δ + R (e_点 − G))`。
  - `chest`、`root`、`bone:`：F 是单位变换；
  - `shoulder_*`：F 是移到静止的肩关节；
  - `socket:`：F 是移到静止的挂点；
  - `prop:<道具>`：F 是那个道具在静止姿势下的位置（第 10.3 节）。
- 这个定义按静止姿势算。显示时按运行时的规则重新放道具，所以动作里胸口弯下、肩膀移动时，看到的和游戏一致。

**时间**：
- 道具组的每个关键帧时刻 t_i，以及挂点表里每一行的开始时刻（第一行除外），各变成一个 `PropKey`：`at = t_(i−1)`，`blend = t_i − t_(i−1)`。第一个是 `at 0`、`blend 0`。
- 这个 key 的坐标系、点、`hidden` 取挂点表在它**开始时刻** t_(i−1) 的那一行。
- 也就是相邻两个关键帧之间按运行时的规则过渡：smoothstep 缓入缓出，绕这个 key 的点转。
- 两个关键帧之间 Blockbench 自己的插值方式（线性、平滑）对道具不起作用。
- 导入旧动作时反过来换算：
  - 每个 key 的到位时刻 `at + blend` 放一个关键帧，至少比上一个晚 0.1 ms（`blend 0` 的瞬移变成 0.1 ms 的过渡）；
  - 如果下一个 key 开始得比上一个到位晚 5 ms 以上，就在它开始的时刻补一个保持帧；
  - 挂点表的每一行从这个 key 的前一个关键帧开始；相邻几个 key 的坐标系、点、`hidden` 都一样时合成一行。

## 5. 和游戏一致的范围

**一致**，第 7 节逐点对拍过：
- 骨架和 idle 片段；
- 下蹲；
- 动作片段（按遮罩，线性、catmullrom、step 三种插值）；
- 淡入和淡出的权重；
- 视线俯仰带出来的胸口弯曲；
- 头跟视线，夹在关节范围内；
- 根部平移，把眼睛移到镜头正下方；
- 道具坐标系除了 `anchor:` 以外的全部：`chest`、`root`、`shoulder_*`、`bone:`、`socket:`、`prop:`；
- 多个道具、一个道具骑在另一个上、跨坐标系的过渡、`hidden`；
- 手目标的 `pose`、`socket:`、`prop:<点>`、`prop:<道具>:<点>`，包括过渡时绕手掌转和肘向渐变；
- 肩前伸、IK、肘、扭转、腕的限制。

**JOML 的笔误也照抄了**：
- 游戏用的 JOML 1.10.5，`Quaternionf#getEulerAnglesZYX` 算 x 角时写的是 `0.5 − x² + y²`，正确的是 `− y²`。
- 游戏的 `HumanoidPoser.clampEuler` 经过它，所以只要头相对胸口既有偏转又有俯仰，即使在关节范围内也会被改掉一点。
- 插件的 `clampEuler` 照抄这个笔误，否则预览和游戏对不上：`tool/crowbar_smash` 差 0.11°，根部跟着差 0.02 px。
- 这在游戏里是真问题：头相对胸口偏 30° 加俯仰 60° 时，头的朝向差 10°；偏 50° 时差 27°。修不修是另一件事，见第 9 节。插件自己做坐标换算时用的是正确公式。

**插件里没有**，第一阶段不做：
- 走路、跑、转身步：预览是站着不动的人。
- 动作的 `approach`（走到锚点前）和所有 `block:` 目标：Blockbench 里没有世界锚点。
- `view_anchors`。
- 道具的 `anchor:` 坐标系。导入时用到它的道具（以及骑在它上面的道具）原样保存，导出时按原来的位置原样写回，不能显示也不能编辑。
- 左手玩家镜像（游戏里有，Java 一侧单独检查，第 10.5 节）。
- 原版手臂角度：游戏里手上拿着物品、又没有 IK 目标的手臂，用原版的举物姿势；插件里用片段的手臂。
- 参数片段 `param_clip`：存下来，原样写回。
- 坐姿。

## 6. 导出规则

- **只写插件自己的片段文件**：
  - 片段文件 `animations/player/<组>.animation.json` 的根上有 `"afl_rig"` 标记，才算插件的文件。
  - `item`、`tool`、`machine`、`locomotion` 这些是 `tools/author-player-*.mjs` 生成的，插件拒绝写进去，提示换一个组名（例如 `item_bb`）。
  - 插件文件里只替换导出的那一个片段键，同一文件里别的片段不动。
- 动作 JSON 和道具 JSON 也带 `"afl_rig"` 标记。运行时的解析器不认识这个字段，会忽略它。
- 目标文件已经存在、又不是插件写的（手写的动作），确认框会单独标出来，由用户决定是否覆盖。
- 每次导出都先弹确认框，列出仓库路径、每个文件是新建还是覆盖、注意事项。点「写入」才写。
- 导出时的数值处理：
  - 数值保留 4 位小数；
  - 贝塞尔插值导出成线性，并提示（运行时不支持贝塞尔）；
  - molang 表达式提示"运行时读成 0"。
- 动作 JSON 的字段顺序、一行一个关键帧的写法，和手写文件一致。
- 道具（第二阶段）：
  - 只有一个道具时写成 `prop`（和第一阶段的文件一样），多个时写成 `props` 列表，按工程里道具的顺序；
  - 有关键帧、或者挂点表改过的道具才写进动作；
  - 一个道具挂在 `prop:<别的道具>` 上，而那个道具不在动作里或排在后面时，拒绝导出并说明原因；
  - `hidden` 只在为真时写；`open_from` 每个道具各自写回；
  - 手目标里第一个道具的点写成短的 `prop:<点>`，别的道具写 `prop:<道具>:<点>`。
- 导入时没用到的字段（`approach`、`param_clip`、`view_anchors`、`events`、`check`）存在动画的 `afl.extra` 里，导出时原样写回。
- 存工程时，工程设置（`afl_rig`：仓库、视角、道具列表）和每个动画的 `afl` 设置（含每个道具的挂点表）都写进 .bbmodel（第一阶段 MCP 核对过 `Codecs.project.compile` 的输出）。

## 10. 第二阶段：骨骼和挂点坐标系、多道具、换挂点（2026-10-16 实现，未提交）

用户 2026-10-16 要求：bone 道具坐标系（大腿枪套）、枪套挂点、多道具和弹匣换挂点。这是 P9 重做（从大腿枪套掏枪、收枪，换弹时弹匣离开枪）要用的底层能力。运行时（Java）和插件一起改，两边对拍一致。

### 10.1 动作文件的新写法（运行时 `skeleton/action/PlayerAction.java`）

**多个道具**：
- 新字段 `props`：道具列表，每个是 `{"id", "keys", "open_from"}`，写法和第一阶段的 `prop` 一样。
- 只有一个道具时照旧可以写 `prop`。`prop` 和 `props` 同时写是错误，动作不加载。
- 同一个动作里道具 id 重复也是错误。
- 道具按列表顺序摆放；一个道具只能骑在排在它前面的道具上。

**道具关键帧的新坐标系**：

| `frame` | `pos` 的意思 | 例子 |
|---|---|---|
| `bone:<骨骼>` | 静止模型像素，跟着那根骨头走（和 `chest`、`root` 同一种写法，`chest` 就是 `bone:chest`） | 枪贴着大腿：`bone:thigh_r` |
| `socket:<挂点>` | 从骨架挂点量起的像素，跟着挂点所在的骨头转 | 枪口在枪套口：`socket:holster` |
| `prop:<道具>` | 那个道具自己模型系里的像素，跟着它转 | 弹匣插在枪里：`prop:p9_pistol` |

- 手臂骨头（上臂、前臂、手）不能当坐标系：IK 在道具之后才摆手臂。这样的 key 不摆道具（沿用前一个 key）。
- 检查在加载时做：坐标系只能是 `chest`、`root`、`shoulder_r`、`shoulder_l`、`anchor:*`、`bone:*`、`socket:*`、`prop:<前面的道具>`，否则动作不加载。

**`hidden`**：
- 道具关键帧的新字段，默认 false。
- 从这个 key 开始道具不画（弹匣塞进弹匣包里、枪插回枪套后交给枪套显示）。
- 它的位置照常算：手可以去够它，骑在它上面的道具照常跟着它。

**手目标 `prop:<道具>:<点>`**：
- 去够某个道具上的点。
- 第一阶段的 `prop:<点>` 照旧是第一个道具上的点。

**过渡跨坐标系也连续**：
- 每个 key 从前一个 key **这一帧实际的位置**过渡过来，所以换坐标系那一刻不会跳。

### 10.2 插件里的挂点表

- 每个道具在每个动画里有一张挂点表，每行是：从几秒起、挂在哪个坐标系、关键帧摆哪个点、藏不藏。
- 导出时每个 `PropKey` 用它**开始时刻**所在的那一行（第 4 节的时间规则）。所以：
  - 换挂点那一行开始之前的那段过渡，按旧坐标系算，道具先到位；
  - 从那一行开始，道具跟着新坐标系走。
- 「+ 当前时间 换挂点」在播放头位置加一行（复制当前行），同时在道具组上钉两个关键帧，曲线不变。然后在那一行选新坐标系。
- 每一行可以换点：例如枪在枪套里时摆枪口（`muzzle` 放在 `socket:holster`），拿在手里时摆握把（`grip`）。
- 没打关键帧的道具，只要挂点表改过，也会写进动作（在原地不动，跟着挂点走）。

### 10.3 `prop:` 坐标系在 Blockbench 里怎么摆

- 道具组的关键帧照旧是"身体静止时这个道具在哪"。
- 在 `prop:<被骑的道具>` 那几行里，数值按**被骑的道具在这段开始时（静止姿势）的位置**换算成相对位置。
- 效果：
  - 弹匣不打关键帧时，就停在枪上，跟着枪走（画面里看得到，因为插件按运行时显示）；
  - 换挂点那一刻（插件里的样子）和导出后游戏里的样子一致；
  - 相邻几行都挂在同一个道具上（只是藏不藏不同）时，按最早那一行的开始时刻算，换行不会跳。
- 导入时反过来，用原文件里被骑道具的关键帧算出它在那一刻的位置。

### 11.1 枪道具文件

`player_props/<枪>.json` 比普通道具多三个字段：

这个文件**不从插件导出**，由 `./gradlew gunPropExport --args="p9_01"` 从枪的模型生成（`--args="--check p9_01"` 只核对）。插件的「导出道具定义」碰到枪道具会拒绝并说明。数值来源见 p9 文档第 2.1 节。

### 11.2 `carry` 坐标系

- 道具关键帧的新坐标系 `carry`：枪在它的挂点上，和身上的枪套层画的一样，连大小一起。游戏里用实际挂点，插件和离线检查里用道具文件的 `carry` 预览值（挂在骨头上，跟着骨头走）。

- 挂点表里可以选 `carry`（只有带 `carry` 的道具才有这一项，标签“枪在枪套里，和身上画的一样”）。建枪道具时默认「开始时挂在」`carry`，组放在 `thigh_r` 下，握点放在预览挂点上。
- `carry` 那几段导出时 `pos`、`rot` 都写 0：枪就在挂点上，道具组在这几段的关键帧只决定时间。导入时 `carry` 的 key 按预览挂点换算成静止姿势下的位置显示。

### 11.3 握把锁手

- 手的目标是有 `grips` 的点（`prop:grip_r`、`prop:<枪>:grip_l`）时，手的位置和朝向都跟着枪（运行时 `ActionPose.gripTarget`，和 `GunStance.handTarget` 同一个算法；插件的 `gripTarget` 逐行移植）。作者只摆枪，手自己跟着。
- 没有 `grips` 的点照旧：手掌放在点上，朝向跟前臂。
- 注意：工程里的枪道具在建道具时把 `grips` 复制进了工程配置（`Project.afl_rig.props[].grips`）。
  - 道具文件重新生成以后（比如改了 `GunStance.Kind` 的握法），工程里的不会跟着变。
  - 现在要手动换：在控制台把道具的 `grips` 换成新文件里的，然后保存工程。
  - 2026-10-17 P9 改正握时就是这样换的（[p9_stance_loops_v1.md](p9_stance_loops_v1.md) 第 4.1 节）。
  - 导出不受影响：导出只写关键帧，Java、对拍读的是道具文件。只是预览和截图会用旧握法。

### 11.4 外观：枪的游戏网格

- 建枪道具时，插件读枪的 Vextris 网格 `meshes/<枪模型>.aflmesh.json`（P9 是 `p9_01_v2_native`），按 geo 的绑定姿势把每个部件放进道具组，锁定、不导出。跳过的骨骼和游戏一样（`MaintenanceGunRendering` 不画的 `reload_magazine`、`additional_magazine`、手臂、镜头等，以及 `empty_old*`）。
- 所以 Blockbench 里看到的枪就是游戏画的那把，不用再「把模型并入道具外观」。
- 菜单「重建枪道具外观（游戏网格）」：枪的网格改了以后重新读一遍，换掉旧的 `gun_*` 网格。
- 网格的颜色可以在 Blockbench 里随便改（只为看得清），不影响导出。

### 11.5 导出

- P9 掏枪、收枪是用插件「导出当前动作」写进仓库的（2026-10-17，我通过 MCP 操作；用户还没自己用过）。
- 导出把每段过渡写成“从上一个关键帧起”（第 4 节的时间规则），第一个关键帧在 0 秒时会多出一个 `at 0` 的保持 key（例如 `at 0, carry, blend 0.12`）。和手写的效果一样，不用删。
- 身体片段写进插件自己的片段文件 `animations/player/gun.animation.json`（新的组 `gun`，根上有 `afl_rig` 标记）。

## 12. 姿势循环和跟视线（2026-10-17 实现，未提交）

运行时一侧（循环权重、`view` 怎么算、三个字段的作用）写在 [p9_stance_loops_v1.md](p9_stance_loops_v1.md) 第 2、3 节；这里只写插件。

- **循环**：动作面板「循环」选 `time`（按时间，待机）或 `stride`（按步伐，冲刺），导出 `loop` 和 `length`（= 动画长度）；预览里动画循环播放。导入时用文件的 `length`。
- **`view` 坐标系**：挂点表里的 `view`，标签“跟视线：眼睛前方，随抬头低头转”。
  - 静止时从骨架的 `eye` 挂点量起，朝正前方；道具组放在 `head` 下。
  - 预览时跟着面板上的视线俯仰转。
  - 核心算法：`viewFrame`、`easedPitch`、`actionView`，和 Java 的 `ActionPose.viewFrame`、`eased`、`actionView` 逐行对应。
- **三个设置**：
  - 「腰射」勾选框 → `hip_fire`（只在循环动作上）；
  - 「侧身」度数 → `chest_twist`（只在循环动作上），预览按它转胸口；
  - 「视线俯仰」上、下两个数 → `view_pitch`（两个都填、上小于下才写，空着就是一直跟随）。
- **`solveFrame`** 多了 `yaw`（视线偏航）和 `chestYaw`；不给 `chestYaw` 时用动作的 `chest_twist`。
- **导出往返**（我通过 MCP，Blockbench 5.2.2）：P9 待机导入再导出，和原文件只差格式。`rot` 差 0.0001°（4 位小数），手目标写成短形式 `prop:grip_r`。
- 用户还没在 Blockbench 里用过这些设置。

### 12.1 第一人称前伸、窄手臂（2026-10-17 第三轮，未提交）

**2026-10-17 晚起游戏不再用这条规则**：第一人称拿着枪时画的是枪的旧视图模型（[first_person_gun_view_v1_design.md](first_person_gun_view_v1_design.md) 第 8 节）。插件「第一人称」开关下带枪道具的预览**不再代表游戏画面**；代码和对拍先留着，确定不用以后和 Java 一起删。

游戏一侧的规则见 [p9_stance_loops_v1.md](p9_stance_loops_v1.md) 第 4.2、4.3 节；插件照着做，预览和游戏的自己第一人称一样。

- 只在面板「第一人称」打开、当前动作带枪道具（道具定义里有 `gun`）时生效。
- **前伸**：`solveFrame` 的新参数 `fp`。`view` 坐标系的关键帧沿视线往前 `firstPersonReach(俯仰)` 像素，肩膀往前送同样多（`protraction`）。核心函数 `firstPersonReach`，和 Java 的 `GunStance#firstPersonReach` 对应（5 px，低头 15° 起减少，45° 为 0）。
- **窄手臂**：`solveFrame` 多返回 `arms`（= `firstPersonArm(前伸量)`，满前伸时 0.62）。画面上上臂、前臂、手的方块（`upper_arm_*`、`forearm_*`、`hand_*`）只把 x 缩到这个倍数，围绕方块中线；关掉第一人称时恢复。只是显示，骨骼和导出不变。
- 实现细节：Blockbench 的 `Canvas.adaptObjectPosition` 会把网格缩放重置成 1，所以先调用它再设缩放；缩过的网格记在 `mesh.userData.aflThin`，恢复时只碰这些。
- 对拍：`AflRigParity` 加了第一人称前伸的场景（共 1027 个，全部一致）。
