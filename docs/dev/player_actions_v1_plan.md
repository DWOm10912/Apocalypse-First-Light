## 2. 动作层的架构

### 2.1 数据放哪（和第 10 节的一处不同）

- 动作定义放 `assets/apocalypse_firstlight/player_actions/<组>/<名>.json`，**不放 `data/`**。服务端和客户端都直接从模组 jar 读，和 `CrowbarSmashTimeline` 读片段的方式一样。
- 原因：客户端画动作需要定义，而数据包不会自动发给客户端，要发就得另写同步包。V1 不支持用数据包覆盖动作定义，以后真有需要再加。
- 物品映射 `item_actions/<物品>.json`、物品锚点 `item_anchors/<物品>.json` 同样放 `assets/`。
- 第 10 节的路径相应改掉，并注明原因。

### 2.2 纯计算部分（`skeleton/` 包，不引用客户端类，离线检查直接用）

| 类 | 作用 |
|---|---|
| `PlayerAction` | 解析后的动作定义：片段、层、遮罩、优先级、进出过渡、锁定、每只手的目标时间线、道具、事件、打断方式 |
| `PlayerActions` | 从 jar 读全部定义；按 id 查；检查格式错误 |
| `ActionState` | 第 6.1 节的状态：动作 id、开始 tick、变体、标志、对象（方块位置、主手或副手） |
| `ActionTimeline` | **外观是时间的纯函数**（第 10.6 节第 2 条）：给出状态和当前时间，算出每只手当前的目标和过渡进度、每个道具挂在哪里、显示还是隐藏 |
| `HandTargets` | 目标解析器的注册表：`clip`、`clip_ik`、`pose`、`held:`、`socket:`、`block:`、`object:`。`entity:` 只留名字，V1 不实现 |
| `HandBlend` | 两个手部目标之间的过渡：**绕手掌插值**（位置按手掌中心插值，旋转用最短路径的四元数插值，最后再换回手臂根部的坐标系）；进度用缓入缓出曲线，不用线性 |

`HandBlend` 直接吸取 BR51 第一轮的教训：换弹结束时插的是手臂根部的坐标系，手掌在 5 tick 里划了一段弧（参考文档 4.5 节）。

### 2.3 分层（第 10.5 节的 V1 子集）

每帧从下到上求一遍：
1. **移动层**：已有的 `locomotion.*` 片段。
2. **持握姿态层**：拿着这件东西平时怎么拿，循环。V1 只有油桶提着（`stance_item.carry_can`）和加油枪拿着（`stance_item.hold_small`）两个。
3. **动作层**：一次性动作，遮罩可以是 `upper`、`arm_r`、`arm_l`。
4. **视线层**：已有（胸和头分摊视线）。
5. **IK 层**：每只手按"当前主人"给出的目标去够。每只手每帧只有一个主人，就是遮罩覆盖它、优先级最高的那一层。
6. **收尾**：关节限制、对准镜头、写回原版部件，已有。

实现方式：`HumanoidPoser` 已经拆成 `solveBody` 和 `solveArms`（P2）。动作层插在两者之间：先用 `solveBody` 解出身体，再由动作层给两只手设目标和权重，最后 `solveArms`。拿枪时 `SkeletonGunStance` 仍按现在的方式占用两只手；V1 的五个动作都不会和拿枪同时发生。

### 2.4 身体挂点

挂点写进骨架定义 `rigs/afl_humanoid_v1.json` 的 `sockets`，现在只有 `eye`。V1 只加用得到的：

| 挂点 | 挂在 | 用途 |
|---|---|---|
| `armpit_l`、`armpit_r` | chest | 温度计夹在腋下 |
| `hip_r` | pelvis | 油桶提着时手的自然位置参考（可选，片段能做到就不加） |

位置按 Classic 和 Slim 分别给（Slim 手臂窄 1 px）。

### 2.5 目标的解析（每帧实时算，所以手跟着移动的物体走）

| 目标 | V1 怎么解析 |
|---|---|
| `clip` | 片段里手臂骨骼的旋转，不用 IK |
| `clip_ik` | 片段里 `ik_hand_r` / `ik_hand_l` 的位置和朝向（相对胸），手用 IK 去够 |
| `pose` | 交给下层（移动层的摆臂、放松下垂） |
| `held:<锚点>` | 主手物品的锚点：物品画在哪里 × 锚点在物品模型里的位置。锚点来自 `item_anchors/<物品>.json` |
| `socket:<挂点>` | 自己身上的挂点 |
| `block:<锚点>` | 动作对象方块上的锚点。V1 由方块类自己提供（一个 Java 接口 `HandAnchors`，方块实体按当前状态和网格动画返回锚点），**先不扩展 `mesh_shapes` 的 JSON**。拉绳的拉手位置直接用现在的 `PortableDieselGeneratorBlock.handle(...)`，所以手和拉手永远对得上 |
| `object:<道具>:<锚点>` | 动作里出现的道具（油桶盖）上的锚点 |

### 2.6 道具和挂接事件

**2026-10-16 实际做法不同**（本节下面是原方案，没有实现）：
- S2 改成"道具摆位"：动作定义的 `prop` 段，见第 10.1 节第 4 条。
- AFL Rig 插件第二阶段（[afl_rig_blockbench_plugin_v1.md](afl_rig_blockbench_plugin_v1.md) 第 10.1 节）加了多个道具 `props` 和换挂点：每个道具关键帧自己写挂在哪（`bone:`、`socket:`、`prop:<别的道具>` 等），换坐标系的那一刻从道具当时的实际位置过渡过去，不跳；`hidden` 代替 `show` / `hide`。没有单独的 `attach` 事件。
- 2026-10-20（伐木斧挥砍）：道具关键帧加了 `ease`，管这一段过渡怎么走：`smooth`（默认，慢-快-慢，和以前一样）、`in`（从静止加速，到这个关键帧时最快：斧头全速砍进木头）、`out`（一开始最快，慢慢停在这个关键帧上）。`in` 接 `out` 可以让一个中间关键帧不停顿。游戏（`ActionPose.keyEase`）和 AFL Rig 插件的预览都认；插件的编辑界面不显示、也不写回 `ease`，从 Blockbench 重新导出会丢掉它。

原方案：
- 动作定义的 `objects` 列出道具，例如油桶盖：`{"id": "cap", "from": "held:cap"}`，表示它本来是手持物品模型上的 `cap` 骨骼。
- 事件 `attach`（`{"tick": 30, "type": "attach", "object": "cap", "to": "hand_l"}`）：在这一 tick 把道具改挂到左手。**换挂的那一刻保持它在世界里的位置和朝向不变**，只换父级，所以不跳。
- `detach`、`show`、`hide` 同理。
- 画的时候：手持物品照常画，但它的 `cap` 骨骼按道具当前的挂点重新放。这用的是现有 GeckoLib 和 `GeckoMeshRenderer` 的骨骼变换，不新增网格能力。

### 2.7 触发和同步

两种触发方式，都满足"同一个状态在任何客户端算出同样的姿势"：

| 触发 | 用于 | 同步 |
|---|---|---|
| **物品使用映射** `item_actions/<物品>.json` 的 `use` | 温度计；以后的吃喝 | 不加包：原版已经同步"谁正在用哪只手的什么物品、用了多久" |
| **服务端启动** `PlayerActions.start(player, id, context)` | 拉绳、插枪、砸玻璃、倒油 | 新包 `ActionState`，S2C，发给 `TRACKING_ENTITY_AND_SELF`，只在变化时发；开始追踪一个玩家时补发一次。协议号 47 → 48（**S1 没做**：拉绳和插枪用各自已有的同步，见第 9.1 节） |

- 这四个动作现在**本来就由服务端决定**（握拉手、插枪、砸玻璃的预约、倒油开始），所以只是在它们已有的判定点上多调一次 `PlayerActions.start` / `stop`，**不改游戏规则和时机**。
- `commit`（真正改变游戏状态）V1 仍由各系统自己做：砸玻璃在 `impact_tick`、出油在 `POUR_DELAY` 之后、着车由发电机算。动作定义里写同样的 tick，检查工具核对两边一致（第 10.6 节第 5 条）。
- 砸玻璃的时机现在读自第一人称动画文件 `crowbar_first_person.animation.json` 的 `afl_timing`。迁移后改为读新的动作定义，旧文件在骨架改默认开、旧视图模型删除时一起删。

### 2.8 第一人称

- 骨架开着、做这五个动作时，第一人称**不再画旧的视图模型和假直臂**，手只来自身体（和现在空手、拿 BR51 一样）。
- 镜头效果（砸玻璃命中的小抖、拉绳的晃动、倒油的视角转动和蹲下）**原样保留**（S2 第 2 轮改动：骨架开时倒油不再转视角，只保留蹲下，见第 11 节），它们只动镜头，和身体无关（第 10.7 节）。油桶视图模型里的相机骨骼改成动作片段里的 `camera` 通道，只作用于本地镜头。
- 油流起点（`FuelCanPourJets` 的喷口）改从"手持油桶在身体上的位置"取，第一、第三人称一致。

### 2.9 手持物品怎么画

- 拿着这五样东西时，物品画在手上：手的坐标系 × `item_anchors` 里的握点的逆变换，所以握点正好在手心。
- 用物品现在的模型（静态网格、GeckoLib 网格），不新做模型。
- 原版 `ItemInHandLayer` 在骨架画这件物品时不再画一份（和 BR51 的 `ItemInHandLayerSkeletonMixin` 一样）。

## 3. 片段怎么做

- 用脚本生成：`tools/author-player-actions.mjs`，和现在的 `tools/author-player-locomotion.mjs` 一样，支持 `--check`，输出 `assets/apocalypse_firstlight/animations/player/<组>.animation.json`（Bedrock 1.8.0）。
- 片段大多只写 `ik_hand_*` 的路径和少量身体骨骼（躯干前倾、侧弯、头低一点），手的落点由目标解析器定，所以片段很短。
- 关键帧默认 catmullrom，撞击时刻用 step 加一个很短的回弹（参考文档 4.6 节的节奏规则）。
- 以后改用 Blockbench 手工做时，片段名和动作定义不变，只换片段文件。

## 4. 五个动作的新做法

### 4.1 温度计 `item/thermometer_armpit`

- 触发：`item_actions/clinical_thermometer.json` → `{"use": "item/thermometer_armpit"}`。
- 层：动作，遮罩 `upper`。
- 右手（拿温度计的手）：0–8 tick 从 `pose` 过渡到 `socket:armpit_l`（横过胸口，和现在的意图一致），停到使用结束。
- 左手：上臂向里收、夹住（片段里 `upper_arm_l` 内收 10–15°），前臂自然下垂。
- 第一人称：低头才看得到手在胸前，平视时手不在画面里，自然取代现在"手移出画面"的处理。
- 事件：无；读数仍由物品使用结束时服务端算（不变）。
- 左手拿温度计时左右镜像。

### 4.2 发电机拉绳 `machine/generator_pull`

- 触发：服务端握住拉手时 `start`，松开、着车、关界面时 `stop`。拉一下不新开动作，用变体加开始 tick（`variant: pull`，`start` = 这一拉的开始 tick），所以别人看到的拉的时机一致。
- 层：动作，遮罩 `full`（身体要配合：重心后移、躯干扭转）。
- 右手：`block:pull_grip`，跟着网格通道 `pull` 实时走，拉出去时手跟着飞出去再被带回来。

## 9. S1 实现记录（2026-10-16）

### 9.1 和方案不同的地方

1. **没有 `ActionState` 包，协议号不变（仍是 47）。** S1 的三个动作都能从客户端已有的状态读出来（`client/skeleton/SkeletonActions`）：
   - 温度计：原版同步的物品使用（`item_actions/clinical_thermometer.json`）。开始时间 = 现在 − 已用 tick。
   - 拉绳：发电机方块实体已同步的握住者和拉动者（`PortableGeneratorPull.heldSet`），拉手的行程来自网格通道 `pull`。
   - 加油枪：加油机已同步的插枪口和插拔时间（`NozzleFillView.anchors`）。
   - 后两个的开始时间是这个客户端第一次看到的时刻。这两个动作的外观由实时锚点决定，不依赖开始时间，所以各客户端看到的一样。S2 的砸玻璃有服务端定的时机，到时候再决定要不要加包。
2. **`block:` 锚点由客户端类提供**，不是方块实体上的 `HandAnchors` 接口：`PortableGeneratorPull.anchors`（`pull_grip`、`handle_rest`、`brace`）、`NozzleFillView.anchors`（`nozzle_grip`、`opening`）。锚点每帧按世界坐标给出，再换到模型坐标。
3. **新加"走近"（`approach`）。** 玩家离拉手最远可以有 2.2 格（`PULL_REACH`），离加油口 2.5 格，手臂够不到。于是身体在画面上走到锚点前：
   - 站在离锚点 `distance` 格、向自己左边偏 `side` 格的地方，最多离玩家实际位置 `max` 格，并转身正对锚点。
   - 只是画法，玩家实际位置不动。
   - 头按 `pitch` 低头。`pitch` 可以写成 `[参数 0 时, 参数 1 时]`，按动作参数插值。
   - 圆形影子跟着走近后的身体走（`mixin/client/EntityRenderDispatcherShadowMixin`）：影子取样的位置和画的位置都挪同样的距离，所以落在身体下面的方块上。挪动量由 `SkeletonActions#bodyOffset` 每帧给出，只对这一帧真正走近的玩家生效。2026-10-16 起影子 mixin 改问镜头导演 `CameraDirector#bodyOffset`，走近是它登记的一个身体偏移来源（`client/camera/CameraSources`，[camera_director_v1_plan.md](camera_director_v1_plan.md) D3），效果不变。2026-10-21 修：挪影子的 `pushPose` 原来在 `renderShadow` 的 RETURN 里弹回，但 Embeddium 的快速影子会在 `renderShadow` 开头取消整个方法，RETURN 走不到，姿态栈留下一层，实体画完就报 “Pose stack not empty” 崩溃（工作台锯木头的走近第一次碰上）。现在改在 `EntityRenderDispatcher#render` 里 `renderShadow` 调用之后弹回，取消与否都会走到。
   - 第一人称时镜头放在姿势里的眼睛上，朝向是身体正面加这个 `pitch`，按动作权重缓入：
     - 镜头：`mixin/client/PortableGeneratorCameraMixin`。
     - 身体照画：`FirstPersonBody.shown` 接受镜头在姿势眼睛上的情况。
4. **手的朝向等于 IK 给出的、不扭转的前臂朝向**（`HumanoidPoser#forearm` 返回前臂的整个朝向），所以手腕不折、前臂也不扭，再按 `roll` 绕前臂转。
   - 最早按"肩到目标的连线"摆，发电机左手腕折到 60° 的上限。
   - 第二版只对齐了前臂的方向、没管绕轴的转角，量体温时前臂扭了 90°（顶到上限），方块前臂拧成麻花。见第 9.7 节。
5. **骨架画的玩家，手持物品画在手骨上。** `ItemInHandLayerSkeletonMixin` 重定向 `translateToHand` 到 `PlayerSkeleton.translateToHand`（手骨坐标系，Slim 也按原版偏 0.5 px），所以手肘弯曲时物品跟着手走。
   - 这对骨架开时的所有手持物品都生效。
   - 直臂时和原来一样。
6. **没做（留到 S2 或以后）**：
   - 持握姿态层（`stance_item.*`），以及 `held:`、`clip_ik`、`object:` 目标。
   - 道具和事件。
   - Slim 单独的挂点（S1 用一套）。
   - 逐 tick 的手速检查、首尾衔接检查、tick 一致检查（S2 的砸玻璃和倒油才需要）。
   - 左手镜像的离线检查（代码有镜像，没出检查）。
7. GUI 里的人物预览（物品栏）只套用片段，不走近、不用方块锚点。

### 9.7 实机第 1 轮（2026-10-16）

用户评价：
- 这一轮"还不错"，动作基本不穿模，也挺流畅。
- 量体温时方块手"拧成麻花"。用户问这是不是还没支持 mesh 手臂造成的技术限制。

量过以后发现，主要不是技术限制：
- 量体温时右前臂扭了 90°（扭转上限），多出来的约 40° 落在手腕上。
- 拉绳和加油枪的前臂也扭了 30°–50°。
- 原因：当时手的目标只对齐了前臂的方向，没管绕轴的转角，IK 把转角分给了前臂和手腕。
- 真正的技术限制只在这一层：方块前臂表现不了扭转，扭一点就像拧绳子；真人的前臂扭转是两根骨头交叉，外形几乎不变。所以动作要避免前臂扭转，需要转手的时候用 `roll`，并控制在小角度。

修法：
- 手的目标朝向直接用 IK 给出的、不扭转的前臂朝向（`HumanoidPoser#forearm`）。

### 10.1 和方案不同的地方

1. **（已过时，第 11 节改为两个动作都用 `body`）第一人称保留视图模型**。动作定义新字段 `first_person`：`body`（S1 的三个动作，第一人称的手来自身体）或 `view_model`（撬棍、油桶：自己第一人称时骨架不做这个动作，照旧画 `CrowbarFirstPerson` / `JerryCanFirstPerson` 的视图模型）。理由：这两个视图模型是用户 PASS 过的动画（拧盖、命中顿挫、相机骨骼），身体上的版本还没进游戏看过；先让别人和第三人称看到动作，第一人称换不换由用户决定（第 10.6 节第 1 条）。改回方案的做法只要把 JSON 里的 `first_person` 改成 `body`。
2. **没有加 `ActionState` 包，协议号仍是 47**。两个动作都用已有的同步：

3. **没有挂接事件（`attach`）**。第三人称的油桶盖不拧下来：左手伸到壶嘴上做拧的样子，盖子画面不动（第 10.6 节第 2 条）。
4. **道具不用 `held:` 骨骼，而是"道具摆位"**。新文件 `player_props/<id>.json`（`skeleton/action/PlayerProps`）：哪些物品、画多大、包围盒、对称轴、命名点（物品模型自己的方块单位）。动作定义新段 `prop`：按时间的关键帧，每帧写"道具的哪个点放在哪、转多少"；手用新目标 `prop:<点>` 去抓。这样道具的位置由动作定，手去够它，换手、松手都不会让道具跟着手抖。物品照常用它的物品模型画（`ItemDisplayContext.NONE`），不需要 GeckoLib 骨骼。
5. **撬棍的手位不用 `block:glass_impact`**，而是"视角锚点"：动作定义新段 `view_anchors`，从眼睛按视角放两个点（举起：右肩上方；砸下：沿视线前下方）。售货机的命中点在服务端，客户端拿不到别人瞄准的点；砸的方向本来就是视线方向。左手和躯干用新片段 `tool.crowbar_smash`（关键帧，catmullrom）。
6. **油桶的时间来回走**：倒油时动作时间 = 已倒的刻数 / 20（封顶 3.2 秒，正好过了倾倒的最后一帧）；停下后以两倍速倒回 0，桶摆正、放低、回到身侧。提着不倒时时间是 0。所以混入改为按"开始显示多久"算（`ActionPose.Moment#age`），不再按动作时间，否则提着的姿势永远混不进来。
7. 左手持（主手在左）的玩家：道具摆位沿身体中线镜像，同时道具沿它自己的对称面翻一次（油桶的厚度方向），两次翻转合起来是一次旋转，所以画出来的油桶不是反的。

## 12. S2 第 3 轮：倒油视角锁定、撬棍双手斜握（2026-10-16）

### 12.1 用户实机反馈（第 3 轮，附截图和三段录像）

- 旧的倒油动作像是没删：视角不锁定，可以 360° 转圈，还能看到方块手臂的动作。

### 12.2 原因

- 倒油时屏幕被手臂糊满：第一人称镜头放在姿势里的眼睛上，倒油弯腰低头时，头的俯仰把眼睛带到了胸口前面，镜头离前臂只有 0.05 格（离线检查：遮挡 67–85%）。

- 撬棍静态手持：第 2 轮只把砸玻璃改成身体动作，平时拿着仍是 `CrowbarFirstPerson` 的视图模型。
- 看不见手：第一人称用的是第三人称的视角锚点，举起时手在屏幕外上方，砸下太快。

### 12.3 改了什么

1. **第一人称镜头不跟头的俯仰**：新的 `ActionPose.cameraEye(pose)` = 脖子 + 眼睛的静止偏移按身体根部朝向转，不算头的俯仰。身体被动作带着走时，第一人称镜头放在这里（`SkeletonActions#cameraEye`、检查工具同样）。头照样跟着视线低下去，别人看到的不变。
2. **倒油视角锁定**：骨架开时 `JerryCanPourView` 每帧把视角从镜头眼睛转向加油口上方 0.1 格（最多往下 50°），用原来的平滑转向（每帧 `TURN_RATE` 5 的指数缓动），鼠标拉不走；停下后恢复。骨架关时仍是原来的壶嘴对准逻辑。
3. **只有低的加油口才蹲**：壶嘴离脚低于 0.75 格才蹲（地面油罐盖、大柴油发电机）；便携发电机（壶嘴 0.84 格）站着倒。站着时弯腰按多高 0.35 格算。
4. **倒油走位和手**：走到离加油口 0.5 格，身体在它右边 0.15 格（`approach.side`，左手持时镜像），左手才够得到倾斜后的壶嘴一端；弯腰最大 40°。右手握后提手（2.0 秒起），左手 0.4 秒去壶嘴、2.0 秒起握中提手。
5. **撬棍双手斜握，平时拿着就是身体动作**：新动作 `item/crowbar`（手臂层，优先级 30，第一人称 `body`）。左手在腹部左侧握直的一端（末端），撬棍斜向右上、向前，右手在它上面 0.3 格处、右胸前，弯钩在右肩前上方（第 4 轮按用户实机意见改为左手在下、右手在上，见第 12.9 节；第 3 轮原来是右手在下）。骨架开时不再画 `CrowbarFirstPerson` 的视图模型。普通挥击（原版攻击）按挥动进度 × 0.3 秒播放：两手把撬棍提到胸口右前方（棍子朝右上），向前砸下，回到斜握。新道具定义 `player_props/crowbar.json`（0.53 倍，约 0.91 米，36 英寸撬棍）。
6. **砸玻璃改双手**：`tool/crowbar_smash` 从 `item/crowbar` 的斜握开始、回到斜握（两个动作的混入都是 0，切换时不跳）。左手一直握末端 `grip_end`；右手蓄力时顺着棍子滑到左手上面的 `grip`，1.4 秒起滑回 `grip_high`。
   - 第三人称：双手举到脸前偏右，棍子朝右上；沿视线砸下，停在玻璃上到 1.05 秒，再回到斜握。
   - 自己第一人称：视角锚点有自己的 `first_person` 偏移。蓄力时双手在画面右下方，棍子从画面右上方伸出去；砸下时双手在画面中下方。全过程都能看到手。
   - 为什么第一人称不举过头：Minecraft 的手臂从肩到手心只有约 8.5 像素，双手够不到头顶的同一点；手臂又有 4 像素粗，双手在眼睛高度时一定挡住镜头（离线检查遮挡 45–60%，离皮肤 0.05 格）。
