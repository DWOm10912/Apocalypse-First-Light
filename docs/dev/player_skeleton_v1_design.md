## 0. 为什么不能在原来的系统上修

用户的视频（2026-10-15）里，往右转头时右肩直接顶到镜头前。原因有两层：

1. **身体朝向**【原版】：原版身体朝向最多落后头 50°，第一人称身体按身体朝向画。往右转 50° 时，右肩在眼前方约 0.27 格、下方约 0.21 格，画面右下角就出现一大块袖子。
2. **第一人称的枪是按"假镜头"摆的，不是给真身体拿的**【已测】。`tools/check-skeleton-arm-reach.mjs` 把 6 把枪所有片段的手部锚点算到镜头坐标里（站立、平视、不含晃动 / 后坐 / ADS），再跟真身体的肩膀比：

| 枪 | 第一人称长度 | 第三人称长度 | 实物长度（枪架） | 待机时右手锚点离右肩 | 待机时左手锚点离左肩 |
|---|---|---|---|---|---|
| silverwood_12 | 1.31 | 1.09 | 1.00 | 0.48 | 1.03 |
| br51_01 | 1.54 | 1.28 | 1.05 | 0.47 | 1.06 |
| cat | 0.84 | 0.74 | 0.90 | 0.68 | 1.03 |
| hr55 | 1.14 | 1.00 | 1.40 | 0.57 | 1.11 |
| p9_01_v2_native | 0.41 | 0.36 | 0.20 | 0.72 | 0.83 |
| blackridge_50 | 0.50 | 0.44 | 0.27 | 0.72 | 0.82 |

单位是格。肩膀取原版手臂的转轴：眼下 0.330、左右各 0.293。手臂从肩轴到手末端是 10 像素，**最多够到 0.586 格**。

结论：
- **左手**：6 把枪待机时全部够不到，差 1.4–1.9 倍；
- **右手**：两把手枪和 CAT 也够不到；
- **枪的大小**：手枪在第一人称里是实物的 1.8–2 倍，BR51 是 1.47 倍。第三人称也偏大（BR51 1.22 倍，P9 1.8 倍），而背上、枪架上已经是实物大小（`CarriedWeaponsLayer`、`WoodGunRackRenderer.LENGTH`）。

现在的第一人称手臂（`NativePlayerArmRenderer`，展示比例 0.62 / 0.78 / 0.62）其实是"从画面外伸进来的两根直棍"，从来不连着肩膀。所以统一身体后，每把枪都要重新定位置和大小，这不能在旧系统上打补丁解决。

**按实物大小，两只手的距离是合理的**【已测】。待机时两个手部锚点的距离：

| 枪 | 两手距离（格） | 说明 |
|---|---|---|
| silverwood_12 | 0.31 | 真实步枪握把到护木约 0.3–0.35 米 |
| br51_01 | 0.32 | 同上 |
| cat | 0.22 | |
| hr55 | 0.54 | 长枪 |
| p9 | 0.02 | 双手合握 |
| blackridge | 0.03 | 双手合握 |

也就是说，**锚点本身没问题，错的是枪在身体上的位置和大小**。这是"保留现有锚点和动画，只重新挂点"可行的依据。

`br51 shoot`、`hr55 static_bolt_caught` 这类片段只带几根骨骼，是叠在待机之上播放的。上面的工具单独采样它们，结果不代表实际位置，迁移时按运行时的混合规则另外检查。

## 1. 骨架层级与骨骼数量

### 1.1 骨骼：16 根

```
root（渲染原点，脚底，跟实体走）
└─ pelvis（骨盆：腰以下的躯干）
   ├─ chest（胸：腰以上的躯干）
   │  ├─ head
   │  ├─ upper_arm_r ─ forearm_r ─ hand_r
   │  └─ upper_arm_l ─ forearm_l ─ hand_l
   ├─ thigh_r ─ shin_r ─ foot_r
   └─ thigh_l ─ shin_l ─ foot_l
```

关节都在整数像素上，**直立时贴图逐像素和原版一样**。尺寸用原版模型像素，1 像素 = 0.0586 格。

| 部位 | 原版盒子 | 切分（从部位顶端量） | 骨骼长度 |
|---|---|---|---|
| 躯干 8×12×4 | `body` | 腰 6：上 6 像素归 chest，下 6 像素归 pelvis | — |
| 手臂 Classic 4×12×4 / Slim 3×12×4 | `rightArm` / `leftArm`，转轴在顶下 2 像素 | 肘 6、腕 10 | 肩→肘 4 像素（0.234），肘→腕 4 像素（0.234），腕→手末端 2 像素 |
| 腿 4×12×4 | `rightLeg` / `leftLeg`，转轴在顶端 | 膝 6、踝 10 | 髋→膝 6 像素，膝→踝 4 像素，脚 2 像素 |
| 头 8×8×8 | `head` | 不切 | — |

说明：
- **为什么肘在第 6 像素**：手臂侧面贴图是 4×12，切在第 6 像素上下各 4×6，正好对半，不重采样。
- **好处**：上臂和前臂的 IK 骨长相等（各 4 像素），两段 IK 最稳。
- **手掌是最后 2 像素**：腕关节能转，让手的方向对上锚点的方向。Curios 腕部物品原来挂在 `WRIST_Y = 8.5`，改挂到前臂末端（腕关节处）。
- **腰**：用户要求胸跟视线转、腿慢一拍（第 5 节），所以躯干必须在腰处分成两段，原版的躯干是一整块。

### 1.2 挂点：不是骨骼，是骨骼上的固定偏移

| 挂点 | 挂在 | 用途 |
|---|---|---|
| `eye` | head | 和镜头对齐（第 5 节）；第三人称视线 |
| `grip_r` | hand_r | 右手握持点（手部锚点的位置），普通物品和枪 |
| `grip_l` | hand_l | 左手握持点 |
| `back` | chest | 背着的主武器（现在 `CarriedWeaponsLayer` 的背部位置） |
| `holster` | thigh_r | 手枪套（现在的右大腿位置） |
| `wrist_l` | forearm_l 末端 | 腕部温度计等 Curios |
| `chest_rig` / `backpack` | chest | 胸挂、背包（现在 `WornMeshRenderer.Part.BODY`） |
| `ears` | head | 耳罩 |

挂点数据写成 JSON，Steve 和 Alex 各一套参数。Alex 的区别只有两处：手臂宽 3、肩轴 y 2.5（原版就是这样，`NativeHandBinding.centreX` 已经区分）。

### 1.3 和原版 ModelPart 的关系（兼容的关键）

- **其他模组画的东西都挂在原版的 6 个 ModelPart 上**：渲染层、Curios、护甲。所以原版 ModelPart **继续存在，并且由 AFL 写回变换**：
  - `body` ← chest
  - `head` ← head
  - `rightArm` / `leftArm` ← upper_arm
  - `rightLeg` / `leftLeg` ← thigh
- 前臂、手、小腿、脚、骨盆是 AFL 自己的骨骼，原版看不到。
- **顺序**：原版 `setupAnim` 先照常跑（别的模组可能在它前后改姿势）→ AFL 读出原版结果当"建议"（比如原版挥手的 attackTime）→ AFL 求出姿势 → 写回 6 个 ModelPart → 渲染层照常跑。
- **数量对比**：原版 6 根，审计时估的约 15 根，本设计 16 根（加了腰）。

## 2. 原版皮肤与关节变形方案

### 2.1 网格：C-min（关节处一圈共享顶点）

- **每段一个盒子**，侧面 UV 是原版皮肤里对应的那一截。直立时和原版逐像素一致【待原型：用"直立渲染和原版逐像素对比"的检查确认】。
- **关节处的接缝**：上一段的底边和下一段的顶边是**同一圈顶点**，这圈顶点按两根骨骼变换的一半来放（两段旋转的中间姿态）。弯曲时不会裂开，也不会断肢。
- **不画关节内部的端盖**。只有肢体末端（手底、脚底、肩顶、头顶）画原版的端面。
- **折角上限**【原版审计结论，待原型】：

| 关节 | 范围 |
|---|---|
| 肘 | 0–145° |
| 膝 | 0–150° |
| 腕 | 屈伸 ±60°，左右 ±30° |
| 腰 | 扭转 ±45°，前屈 −15…+30° |
| 踝 | −30…+45°（正值脚尖朝下；P1 蹲姿后脚踮脚 40°，见第 12.6 节） |

  超出范围时内侧面会折进去，所以姿势求解时就夹住。
- **贴图拉伸**【审计时推算】：90° 弯曲时，外侧每段从 6 像素拉到约 8 像素，内侧压到约 4 像素。最近邻采样下仍是清楚的像素，只是关节附近不是正方形。这是关节真弯的必然代价。如果实机看着难受，再在关节加一圈顶点把曲率分开（每个关节多 4 个四边形）。
- **法线**：接缝那圈顶点用两侧面法线的平均，光影下关节处不会有一条硬线。其余面用面法线，和原版一样。
- **头和躯干不做倒角**，四肢倒角也不进 V1（审计第 5 节：倒角会把皮肤边缘像素拉成描边，用户不喜欢）。

### 2.2 皮肤

| 情况 | 做法 |
|---|---|
| Steve（Classic） | 手臂 4 宽，肩轴 y 2 |
| Alex（Slim） | 手臂 3 宽，肩轴 y 2.5，其余一样 |
| 第二层（袖子、裤腿、外套、帽子） | 同一套骨骼和接缝环，外扩：四肢和躯干 0.25 像素，帽子 0.5 像素（原版数值）。接缝环外扩稍微加大，免得弯曲时内侧第二层压进底层【待原型，Sundial 下也要看】 |
| 旧版 64×32 皮肤 | 原版加载时就转成 64×64，AFL 拿到的总是 64×64，第二层区域透明 |
| 幸存者皮肤库（以后） | 同样是 64×64 原版格式，不需要特殊处理 |
| 皮肤贴图的读取 | `AbstractClientPlayer#getSkinTextureLocation` 和 `getModelName`（"default" / "slim"），和原版一样 |

### 2.3 护甲和装备

| 东西 | 做法 | 状态 |
|---|---|---|
| 原版式护甲（`ArmorItem` + 64×32 护甲贴图） | AFL 用同一套分段几何和护甲贴图（`layer_1` / `layer_2`，UV 排布和皮肤一致）画，外扩 1.0 / 0.5 像素，跟着关节弯 | 设计，P4 做 |
| 自带模型的模组护甲（Forge `getHumanoidArmorModel`） | 回退：照常用原版护甲层画，跟着写回的上段走。弯曲时护甲是直的，这是已知限制。不为它限制玩家弯角 | 回退方案 |
| AFL 的 Curios 装备（胸挂、背包、耳罩、枪套） | 改挂到第 1.2 节的挂点：胸挂 / 背包 → chest，耳罩 → head，枪套 → thigh_r。网格不变 | 迁移，P4 |
| AFL 腕部温度计 | 挂 `wrist_l`（前臂末端），跟着前臂转 | 迁移，P4 |
| 别的模组的 Curios / 渲染层 | 跟着原版 ModelPart 走（也就是上臂、大腿、胸、头），挂在这几段的都对。挂在手腕、手上的会在弯肘时偏开，这是已知限制 | 回退方案 |
| 披风、鞘翅 | 挂 chest，原版逻辑 | 不变 |

## 3. 第一人称与第三人称统一渲染方案

### 3.1 一个身体

- **本地玩家在第一人称时，就是把自己的整个身体在世界那一遍里画出来**。走的是和第三人称完全相同的 `PlayerRenderer`，同一个姿势、同一份网格。
- **第一人称只做"隐藏"，不做"另一个姿势"**。要隐藏的有：
  - head、帽子层、头盔；
  - 头部 Curios（耳罩）；
  - 自定义头颅（`CustomHeadLayer`）。
  
  这些都在眼睛附近，会挡镜头。其余都照画，包括手臂和手里的东西。
- **原版第一人称手持物品那一遍（`renderHandsWithItems`）在骨架开启时整个关掉**。以下几样都由身体上的挂点画，不再单独存在：
  - 枪：`ConfiguredGunFirstPerson`、`NativePlayerArmRenderer`；
  - 撬棍、油桶、加油枪、发电机拉绳的第一人称手臂；
  - 原版物品的第一人称手。
- **可沿用的挂钩**：第一人称身体分支已有让世界那一遍画出本地玩家的挂钩。
  - 具体是：`LevelRendererFirstPersonBodyMixin` 重定向 `isDetached`，以及渲染层跳过表、护甲隐藏。
  - 它们的判断条件（第 3.4 节）可以沿用。
  - 这个分支的后仰、颈部后让、手滑出画面、限制手臂这几个补丁不再需要。

### 3.2 画在哪一遍

**选世界那一遍**，这是用户"一个身体"的直接结果。

| | 世界那一遍（选这个） | 原版手持那一遍 |
|---|---|---|
| 和第三人称是不是同一份几何 | 是 | 否，相当于又画一个身体 |
| 视野 | 跟游戏视野走；ADS 放大时枪跟着放大，和真实一样 | 固定 70° |
| 穿墙 | 会穿，要靠第 4.6 节的贴墙姿势 | 永远在最前面 |
| 光影（阴影、光照） | 和世界一致 | 光影包单独处理 |

它的代价也写在这里，都要在原型阶段实机看：
1. **视野大时手臂变形**【待原型】：玩家把视野调到 90–110° 时，手和枪会显得更远、边缘拉伸。真身体就是这样，不另外补偿。
2. **Sundial 的 TAA 拖影**【待原型】：手臂原来在手持那一遍，现在进了世界那一遍，快速转头时可能有拖影（之前转枪时 Sundial 体积云就出过类似的拖影）。
3. **近裁剪面 0.05 格**【原版】：枪托抵肩、瞄准时眼睛到后照门约 0.08–0.12 格，在近裁剪面外面。第 5.4 节的镜头净空检查会覆盖。

### 3.3 阴影那一遍

- 同一帧的姿势只算一次，主画面和阴影共用。缓存键是"实体 + 帧序号"。
- 阴影里**画头**：第一人称看自己的影子应该有头。所以"隐藏头"只在主画面那一遍。
- 现有的 `FirstPersonBody.Draw{MAIN, SHADOW}` 判断（`AflShaderCompat.activeShadowPass()`）沿用。`NativeGunShadowSkip` 的规则改成"阴影里画身体上的枪"【待原型：看 Sundial 阴影里枪和手的效果】。

### 3.4 什么时候不画第一人称身体

沿用第一人称身体 V1 的条件，和原版保持一致：
- 镜头分离（第三人称）时，本来就画身体；
- 旁观者、隐身、睡觉、死亡；
- 游泳、鞘翅、激流时不画第一人称身体，回到原版（这几种姿势 V1 不做骨骼动作）；
- 骑乘：坐在实现了 `SeatedRiderHost` 的载具座位上时照样画，坐姿和上下车见 [seated_rider_v1_plan.md](seated_rider_v1_plan.md)（2026-10-16 用户实机试过，有已知问题，之后归 Main）；别的载具还是原版的骑乘腿。

开关：客户端配置 `[skeleton] enabled`，原型期默认关，验收通过后默认开（2026-10-16 起默认开，见文首状态）。关掉时一切回到现在的样子，原型期间不影响正常游戏。

## 4. 枪械动画与双臂 IK 的接口

### 4.1 原则

1. **枪的资产不动**：网格、骨骼、片段、`right_hand_anchor` / `left_hand_anchor` / `camera` / `root` 骨骼都照用。
2. **一把枪一个大小**：第一人称、第三人称、背上、枪架上都是实物大小。
   - 缩放比例 = 枪架长度 ÷ 模型最长边。
   - 结果【已测】：

| 枪 | 实物缩放 | 现在第一人称 |
|---|---|---|
| silverwood_12 | 0.345 | 0.45 |
| br51_01 | 0.307 | 0.45 |
| cat | 0.480 | 0.45 |
| hr55 | 0.551 | 0.45 |
| p9 | 0.261 | 0.53 |
| blackridge | 0.244 | 0.45 |

   - **这是要你拍板的一点**：手枪在第一人称里会比现在小一半左右，BR51 小三分之一；HR55 反而大 22%，CAT 基本不变。我建议按实物，原型阶段你实机看过再定。
3. **枪挂在身体上**：枪的位置由"持枪姿势"给出，相对胸，不再相对镜头。现在每把枪 `*_in_hand.json` 里的 `firstperson_righthand` / `thirdperson_righthand` 显示变换不再用于手持。
4. **手去抓枪**：手臂用两段 IK 去够枪上的锚点，手不再是画在锚点上的独立模型。

### 4.2 一帧的顺序

```
1. 下半身：移动（站 / 走 / 跑 / 蹲），给出 root、pelvis、腿
2. 视线分配（第 5 节）：给出 chest 和 head 的朝向
3. 持枪姿势：按枪类（手枪 / 步枪 / 霰弹枪）和状态（持枪 / ADS / 冲刺低位 / 贴墙）
   给出枪的 root 相对 chest 的位置 → mount
4. 枪的片段：照原样采样，给出枪内部各骨骼（拉栓、弹匣、root 的后坐）
   → 锚点在世界里的位置 = chest · mount · 枪片段
5. 右臂 IK：肩 → 肘 → 腕，目标是 right_hand_anchor
6. 左臂 IK：目标是 left_hand_anchor，按左手权重（4.4）和放松姿势混合
7. 叠加：呼吸、受击抖动（只动身体，不动镜头）
8. 写回原版 ModelPart，画
```

ADS 时，第 3 步的 mount 由瞄准对齐来求：
- 枪的瞄具线（`NativeSightMount`）对准镜头的视线；
- 后照门放在眼前 `eye_relief` 处（初值 0.10 格）【待原型】。
- 然后第 5、6 步的手照样去够锚点。也就是说，**ADS 是枪对准眼睛，手跟着枪走**，不是手带着枪凑到画面中间。

### 4.3 两段 IK

- **解法**：余弦定理解析解，肩→肘→腕三点。
  - 腕的目标是锚点沿手的方向往回退一个手掌长（2 像素）；
  - 手的朝向取锚点的旋转，腕关节吸收差值，超出腕的范围就夹住。
- **肘的朝向（极向量）**：右臂朝下、朝外、略朝后，左臂镜像。可以按持枪姿势调。肘角夹在 0–145°（第 2.1 节），所以**不会反折**。
- **够不到时**，按顺序处理，**手臂从不拉长**：
  1. 肩前伸：肩轴最多前移、内收 1.5 像素（约 0.09 格，相当于锁骨），持步枪时默认用一部分。
  2. 持枪姿势里胸可以带一点转（步枪站姿左肩在前），这是姿势数据，不是临时补救。
  3. 还是够不到：**右手**是持枪手，枪跟着右手往回收（枪服从手）；**左手**按权重淡出，回到放松姿势。
  
  第 2、3 种情况都会被检查工具记录下来，算作资产问题，要改片段或姿势。
- **手臂快伸直时**（目标距离超过 98% 臂长）：平滑过渡到直臂，免得肘在接近伸直时左右甩。

### 4.4 左手权重

- 默认值按物品类型：

| 物品 | 默认 |
|---|---|
| 步枪、霰弹枪、长枪 | 1（一直双手） |
| 手枪 | ADS 和举枪时 1；冲刺、放下时 0 |
| 普通物品 | 0 |

- **片段可以覆盖默认值**：每个动作的两只手各有一条目标时间线，写在动作定义里（第 10.2、10.4 节），可以随时切换目标，比如左手从护木到弹匣包再回护木。
- 权重切换都有 0.1–0.2 秒的过渡。
- 这实现了用户的"一般不用左手，只在需要双手的动画再抬手"。

### 4.5 片段时间的来源

- 枪片段的"开始时刻"来自同步的动作状态（第 6 节），不是本地 GeckoLib 控制器各自计时。这样本地第一人称、第三人称、别的玩家看到的是同一个时刻。
- 现有 `NativeGunActions` 的 Session 已经有片段 id 和开始时刻，直接用。
- **镜头骨骼**（`camera`）照旧只给镜头（`NativeCameraBoneConsumer`），不动身体（第 5.3 节）。
- **后坐**：分两部分。枪 root 的后坐动画让枪往后顶，手跟着枪走，所以手臂会被带回来；镜头的后坐照旧只动镜头。

### 4.6 贴墙姿势

在世界那一遍画，枪会穿进墙里。处理办法：
- 每帧沿枪管方向从肩膀打一条射线（用碰撞形状，不用视觉网格）。
- 枪口会进墙时，持枪姿势混到"贴墙"：枪口上抬、往回收。
- 这在第三人称也一样，别的玩家看到的也是贴墙的样子。

### 4.7 拔枪和收枪

- 现在的 draw / put_away 片段是"从画面下方出现、往下消失"。
- 骨架下改成从 `back` / `holster` 挂点出来、回去：先插值到挂点，再进片段。这和背枪、枪套的显示正好接上。
- 原型阶段先保留原片段，P2 再改。
- **P2 第一段已实现（BR51、P9）**：路径是挂点 → 中间点 → 持枪位置，片段的整枪位移由钉住的骨骼换掉，机械部分照常播放。见第 13.3 节。

### 4.8 迁移策略（回答用户 2026-10-15 的问题）

- **现在不修**：第一人称身体分支上枪的问题先不管，这个分支不合并。
- **原型（P1）只迁 BR51**，并且只做持枪和 ADS，不做换弹。
- **P2 迁剩下的**：
  1. 先按第 4.1 节的规则自动换过去：实物缩放、挂到胸、IK；
  2. 用检查工具跑全部片段，找出够不到、肘角超限、镜头净空不够的；
  3. 列清单，批量改片段或姿势。
  
  不是每个动作从头重做。
- **P2 第一段（2026-10-15）**：BR51 全套动作和 P9 已经迁过去，第 1、2 步完成，检查结果见第 13.7 节。另外四把还没迁。

## 5. 摄像机、身体朝向与脚步转向规则

### 5.1 镜头是权威

- **镜头位置和原版完全一样**：实体位置加眼高（站立 1.62，蹲下 1.27，原版插值）。从不从头骨计算。
- **身体去对准镜头**：每帧求出姿势后，算出 `eye` 挂点和镜头的水平差，整个 root 水平平移把它抵消，夹在 0.25 格以内【待原型】。
  - 例子：低头时头绕颈部前倾，眼睛会往前跑，身体就往后让。第一人称身体 V1 的"颈部后让 0.13 格"是这个规则的特例。
  - **这个平移第三人称也做**，所以两边是同一个姿势。别人看到你低头时屁股略往后，真实的人也这样。
- **竖直差不平移**：眼高按原版，头骨的高度只用于显示。第一人称看不到头，没有问题。

### 5.2 视线怎么分到身体上

| 骨骼 | 规则 | 初值【待原型】 |
|---|---|---|
| head | 承担剩下的偏航和俯仰 | 相对胸：偏航 ±70°，俯仰 −60…+50° |
| chest | 偏航跟视线，落后量有上限；俯仰承担一部分 | 空手落后 ≤ 15°；持枪、ADS、双手动作时 0（完全跟视线）；俯仰取视线俯仰的 30%，夹在 −25…+20° |
| pelvis / 腿 | 偏航见 5.3 | 胸相对骨盆扭转 ≤ 45°（腰的上限） |

**P1 实际用的值和上表不同**，以第 12.3 节为准：
- 持枪时胸转到视线右边 20°（左肩在前），不是 0；
- 持枪时胸的俯仰是视线俯仰的 50%，夹在 −25…+30°；
- 头相对胸的俯仰上限是 −70…+60°；
- 胸相对骨盆的扭转在髋部完成，整个躯干一起转，见第 12.6 节。

为什么胸要紧跟视线：右肩在眼右侧 0.293 格。胸落后 θ 时，右肩往前移 0.293·sin θ。15° 时是 0.076 格。肩在眼下 0.33 格，所以它在视线下方 77°，而平视时画面下沿只到视线下方 35°，看不到。视频里的 50° 落后会让肩前移 0.22 格。这一条【待原型】用第 5.4 节的工具扫一遍确认。

### 5.3 脚步转向

- **移动时**：骨盆朝移动方向。侧走、斜走时，骨盆最多偏离视线 ±45°，腿按移动方向播放；后退时骨盆朝前，腿倒放。
- **站着不动时**：
  - 视线偏航在胸的扭转上限以内：骨盆不动，只有胸和头转；
  - 超过上限：触发一次"踏步转身"，骨盆在约 0.25 秒内转到胸的方向，腿播放小碎步片段（P1 起叠加在当前腿姿上，蹲着也能踏步，见第 12.6 节）；
  - 转得太快时（一帧超过上限），骨盆直接被拖着走，不让腰扭过 45°。
- **数据来源**：
  - 用原版同步的头部偏航（`yHeadRot`）和移动；
  - 骨盆的朝向由每个客户端按同样的规则自己算，不另发包；
  - 别的玩家的转身时刻可能和本人差一两帧，可以接受。
- **镜头摇晃**：原版的走路摇晃（view bobbing）作用在镜头上。骨盆的上下起伏用同一个 `walkDist` 公式、同一个相位，所以镜头和身体一起动，手和枪在画面里是稳的【待原型】。

### 5.4 镜头净空

骨架要保证以下几条（P1 实测后改过两处，原因见第 12.4 节）：
- **镜头附近**：除了被隐藏的头，任何可见顶点离镜头不近于 0.12 格（近裁剪面的 2.4 倍）。
  - "可见"指在视锥里，视锥放宽 1.25 倍留余量。镜头旁边、身后的顶点不算。
  - **持枪时改为不近于 0.055 格**（近裁剪面 0.05 加 10%）。第 3.2 节写过，ADS 时后照门本身就在眼前 0.08–0.12 格，握把上的右手就在它旁边，0.12 做不到。要保证的是没有可见的东西被近裁剪面切开。
- **肩膀**：视线俯仰在 ±45° 以内时，肩膀不进入画面上方三分之二。
  - 低头超过 45° 时，看的就是自己身上，画面上方是胸前的地面，肩膀出现在画面两侧是正常的。原来写的"任意俯仰"在正下方看时没有意义。
  - 转头时肩膀挡镜头的问题，靠 ±45° 内这条判定来查。

检查工具（P1 写）的做法：
- 扫视线偏航（相对骨盆 −90…+90°）、俯仰（−90…+90°）；
- 扫状态：空手、持枪、ADS、蹲、走；
- 对每种组合算最近顶点和肩膀在画面里的位置，超标就报。

这是用户说的"肩膀穿过摄像机"的数值检查。

## 6. 动作状态和多人同步方案

### 6.1 动作状态

```
ActionState {
  action   // 动作 id：idle / gun_hold / ads / reload / inspect / draw / put_away /
           //          melee / use_item / pull_cord / pour / ...
  clip     // 片段 id（枪片段或人物片段）
  start    // 开始时刻：服务端 gameTime（tick）
  variant  // 变体（例如空仓换弹、哪把枪）
  flags    // ADS、左手模式等
  context  // 动作对象：目标方块位置和锚点、目标实体 id 和骨骼（开门、拉绳、驾驶）
}
```

- **身体的每一层都只读这个状态加上原版已同步的量**，所以同一个状态在任何客户端求出的姿势相同（除了 IK 目标里跟本地世界有关的部分，比如贴墙射线）。
- 片段时间 = (当前 gameTime − start + partialTick) ÷ 20。

### 6.2 同步

| 量 | 来源 |
|---|---|
| 位置、视线偏航和俯仰、姿势（站 / 蹲）、冲刺、手里物品、正在使用、挥手 | 原版已同步 |
| ActionState | AFL 新包，S2C，发给 `TRACKING_ENTITY_AND_SELF`，**只在变化时发**；开始追踪一个玩家时补发一次当前状态 |
| ADS 开关 | 合进 ActionState 的 flags |

- **本地玩家先走**：按键时客户端立刻切换，不等服务端回包。服务端确认的状态回来时，如果和本地一致就忽略；不一致（例如服务端拒绝换弹）再纠正。
- **枪动作**：`NativeGunActions` 本来就是服务端决定的，它开始一个 Session 时顺手发 ActionState。
- **流量**：每次动作变化一个几十字节的小包，跟枪的射击包同一量级。

### 6.3 协议

新包注册时协议号 +1（现在是 "46"）。按多会话规则，合进 master 前通知受影响的会话【规则见 project-multi-session-rules】。

| 其他模组的渲染层 | 跟着原版 6 个 ModelPart | 胸、头、上臂、大腿上的东西都对；手腕和手上的弯肘时偏开 |
| **Oculus / Sundial** | 身体用原版实体 RenderType（`entityCutoutNoCull` + 皮肤贴图）发顶点，光影包按实体处理（`gbuffers_entities`） | 不需要自定义着色器（这也是不做 GPU 蒙皮的原因）。TAA 拖影、阴影里的手和枪【待原型，以 Sundial 为准，原版必须正常，其他光影不能坏】 |
| **Embeddium** | 它优化原版 ModelPart 的立方体渲染 | AFL 自己发顶点，不走那条路径，不冲突；头还是原版 ModelPart 画 |
| 第一人称身体 V1 的挂钩 | `isDetached` 重定向、渲染层跳过、护甲隐藏、`WornMeshRenderer` 跳过隐藏部位 | 沿用；其余补丁删除 |

## 8. 性能风险和分阶段验收标准

### 8.1 性能

| 项 | 估计 | 状态 |
|---|---|---|
| 顶点 | 底层约 72 个四边形，加第二层约 144 个（约 576 顶点），原版是 72 个四边形。约 2 倍原版 | 【待原型，JFR 实测】 |

| 远处的玩家（以后的 NPC、感染者） | 32 格外不做 IK、片段隔 2–3 帧采样一次；64 格外用不分段的原版刚体 | 设计 |

1. 世界那一遍的手臂在 Sundial 下的 TAA 拖影；
2. 高视野下的手臂透视变形；
3. 贴墙姿势在狭窄室内是否频繁触发；
4. 模组护甲和手腕挂件的回退效果；
5. 枪按实物大小后第一人称的观感（手枪明显变小）；
6. 动作切换时的过渡穿插（手穿过身体）。

前 5 项都要你实机看。第 6 项靠检查工具。

**P1 的验收标准**：

## 10. 人物动画制作工作流（长期标准）

用户 2026-10-15 要求：这一节是 AFL 以后所有人物动作的制作标准。新增站立、行走、持枪、掏枪、收枪、换弹、吃喝、包扎、机器操作、驾驶这些动作，应当主要靠**新增动画资源和配置**完成，而不是每次改人物渲染代码。以后加一把枪、一台机器、一辆车，要复用现有骨骼、动作模板和 IK。

本节全部是设计，下面提到的文件、工具、命令都**还不存在**，标【计划】的在哪个阶段做见第 11 节。

**V1 落地方案**：[player_actions_v1_plan.md](player_actions_v1_plan.md)，动作层 V1 子集 + 现有五个 AFL 动作迁移。
- 2026-10-16 S1 已实现：动作定义、目标时间线、`socket:` 和 `block:` 目标、走近、手掌插值过渡、离线检查、`/aflc action`。三个动作是温度计、拉绳、加油枪。还没有实机检查。
- 和本节不同的地方：
  - 动作数据放 `assets/` 不放 `data/`；
  - S1 没有同步包；
  - `block:` 锚点由客户端类给出。
  - 详见那份文档第 9 节。
- 本节下面的其余部分（模板生成器、`clip_ik`、道具、事件、叠加层等）仍是计划。

### 10.0 四类资源和一条规则

| 资源 | 位置【计划】 | 谁写 | 内容 |
|---|---|---|---|
| **骨架定义** | `assets/apocalypse_firstlight/rigs/afl_humanoid_v1.json` | 定一次，很少改 | 骨骼名、父子、关节位置（Classic / Slim 两套）、关节范围、挂点 |
| **动画片段** | `assets/apocalypse_firstlight/animations/player/<组>.animation.json`；Blockbench 源文件在 `src/main/blockbench/player/` | 动画制作 | 骨骼旋转、手的路径、标记 |
| **动作定义** | `data/apocalypse_firstlight/player_actions/<组>/<名>.json` | 配置 | 用哪个片段、哪一层、两只手抓什么、事件、过渡、锁定 |
| **物体锚点** | 物品 geo 的锚点骨骼、`item_anchors/<物品>.json`、`mesh_shapes` 的 `anchors`、载具模型骨骼 | 做物体的人 | 手抓哪里、手掌朝向 |

**规则**：
- 加一个新动作 = 一个片段 + 一个动作定义 + 物体上的锚点。如果它改变游戏状态（喝水加水分、换弹加子弹），再加一行服务端调用 `PlayerActions.start(player, id, context)`。
- **人物渲染、IK、混合代码不动**。
- 只有出现一种**新的目标类型**或**新的事件类型**时才改代码。它们都是注册表里的扩展点（第 10.3、10.6 节），加一种类型不改已有的。

### 10.1 Blockbench 16 骨骼人物模板

**唯一来源**：骨架定义 JSON 是唯一来源，Blockbench 模板由脚本从它生成，不手画。所以模板、运行时、检查工具永远一致。
- 生成脚本【计划，P1】：`tools/build-player-rig-template.mjs`
- 生成结果：`src/main/blockbench/player/afl_humanoid_v1_template.bbmodel`

**格式和坐标**：
- 格式：Blockbench 的 GeckoLib / Bedrock 动画模型，和现有 Native 枪完全相同。
- 单位：像素，1 像素 = 1/16 格（运行时再乘原版玩家缩放 0.9375）。
- 方向：+Y 向上，原点在两脚中间的地面上，朝向和原版 Bedrock 玩家模型（`geometry.humanoid.custom`）相同，右臂在 x = −5。
- 运行时换算和枪一样（`tools/audit-player-arm-presentation.mjs#aflScene`）：pivot 的 x 取反，旋转的 x、y 取反，按 Z→Y→X 顺序。
- 【待原型】模板生成后，在 Blockbench 里核对一次正面朝向和左右，写进模板说明。

**骨骼**（Classic；Slim 只差手臂宽 3、肩轴低 0.5，见第 1.2 节）：

| 骨骼 | 父 | 关节位置（px） | 盒子 y 范围 | 说明 |
|---|---|---|---|---|
| `root` | — | 0, 0, 0 | — | 整体位移、朝向；只有它和 `pelvis` 可以有位移通道 |
| `pelvis` | root | 0, 12, 0 | 12–18 | 躯干下半；蹲下、起伏 |
| `chest` | pelvis | 0, 18, 0 | 18–24 | 躯干上半；腰在 y 18 |
| `head` | chest | 0, 24, 0 | 24–32 | 第一人称隐藏 |
| `upper_arm_r` / `_l` | chest | ∓5, 22, 0 | 18–24 | 肩 |
| `forearm_r` / `_l` | upper_arm | ∓5, 18, 0 | 14–18 | 肘 |
| `hand_r` / `_l` | forearm | ∓5, 14, 0 | 12–14 | 腕 |
| `thigh_r` / `_l` | pelvis | ∓1.9, 12, 0 | 6–12 | 髋 |
| `shin_r` / `_l` | thigh | ∓1.9, 6, 0 | 2–6 | 膝 |
| `foot_r` / `_l` | shin | ∓1.9, 2, 0 | 0–2 | 踝 |

**模板里的辅助骨骼**（不画，可以做动画）：

| 名字 | 父 | 用途 |
|---|---|---|
| `ik_hand_r` / `ik_hand_l` | chest | 片段里"手该在哪"的目标点，位置加朝向。动作定义写 `clip_ik` 时，手用 IK 去够它（第 10.3 节）。用它做动画比转三根手臂骨骼省事，也不受 Slim 影响 |
| `ik_pole_r` / `ik_pole_l` | chest | 可选，片段想指定肘朝哪时用 |
| `prop_r` / `prop_l` | hand | 手里道具的预览挂点，不导出 |
| `socket_*` | 见第 1.2 节 | 挂点位置预览：枪套、背、弹匣包、嘴、腰带。只读，动画里不能动 |

**关节范围**：写在骨架定义里，用解剖方向（屈 / 伸 / 外展 / 旋转）表示，每个关节一个局部轴和正负号。检查工具按它报错，运行时按它夹住。

| 关节 | 范围 |
|---|---|
| 肘 | 屈 0–145° |
| 膝 | 屈 0–150° |
| 腕 | 屈伸 ±60°，偏 ±30° |
| 腰（chest 相对 pelvis） | 扭 ±45°，屈 −15…+30°，侧弯 ±15° |
| 肩 | 前举 −60…+180°，外展 −20…+180°，旋 ±90° |
| 髋 | 前屈 −30…+120°，外展 ±45° |
| 踝 | −30…+45° |
| 头（相对 chest） | 第 5.2 节 |

**模板里的预览件**（不导出，只给制作的人看）：
- 一把实物大小的 BR51 和一把 P9，挂在 `prop_r` 上；
- 胸挂、背包、枪套的外形；
- 一个第一人称视野框：从 `eye` 挂点出发、70° 视野的线框，看动作在第一人称里能不能看到；
- 一个 Slim 手臂切换组，看 Alex 皮肤会不会穿模。

**导出格式**：
- 用 Blockbench 的"导出动画"，得到 Bedrock 动画 JSON（`format_version` 1.8.0），和现有枪一样；关键帧支持 linear、catmullrom、step。
- 一组动作一个文件，片段键名 `<组>.<名>`，例如 `locomotion.walk`、`stance_rifle.ads`、`item.drink_bottle`。

允许的通道（检查工具强制，违反就是错误）：

| 通道 | 允许在哪些骨骼上 |
|---|---|
| rotation | 所有身体骨骼和 `ik_*` |
| position | 只有 `root`、`pelvis`、`ik_*` |
| scale | 身体骨骼上禁止（会把皮肤拉变形） |

**片段里的标记**：用 Bedrock 的 `timeline` 写标记（Blockbench 的"效果"轨道），例如 `"0.55": "grab hand_l"`。标记只给制作者对时间用，**权威时间写在动作定义里**，检查工具核对两者相差不超过 1 tick（第 10.6 节）。

**Blockbench 自带的 IK**：Blockbench 动画模式的空对象 IK 可以帮助摆手，但导出前要烘焙成骨骼旋转，或者改用 `ik_hand_*` 记录【待原型：核对所用 Blockbench 版本的 IK 烘焙方式】。

### 10.2 动作定义

例子（喝水，完整版见第 10.10 节）：

```json
{
  "format_version": 1,
  "clip": "apocalypse_firstlight:player/item.drink_bottle",
  "layer": "action",
  "mask": "upper",
  "priority": 50,
  "blend": { "in": 0.15, "out": 0.25 },
  "loop": false,
  "locks": { "sprint": true, "attack": true, "use_other": true, "move_speed": 0.6 },
  "hands": {
    "right": [ { "at": 0.0, "target": "held:grip_r" } ],
    "left":  [ { "at": 0.0, "target": "pose" } ]
  },
  "events": [
    { "tick": 12, "type": "sound", "sound": "apocalypse_firstlight:drink_sip" },
    { "tick": 24, "type": "commit", "server": "finish_use" }
  ],
  "cancel": { "before_commit": "blend_out", "after_commit": "finish" }
}
```

| 字段 | 意思 |
|---|---|
| `clip` | 片段；可以为空，纯靠 IK 的动作（比如握方向盘）不需要片段 |
| `layer` | `stance`（持握姿态，循环）、`action`（一次性动作）、`additive`（叠加）、`full_body`（全身，盖过移动层） |
| `mask` | `full` / `upper` / `arms` / `arm_r` / `arm_l` / `head` / `legs`，或者逐骨骼写权重 |
| `priority` | 同一层、同一部位上谁说了算 |
| `blend` | 进出的过渡时间 |
| `locks` | 动作期间限制什么：冲刺、攻击、使用别的东西、移动速度倍数、视线范围 |
| `hands` | 两只手各自的目标时间线（第 10.4 节） |
| `objects` | 动作中出现的道具，比如新弹匣（第 10.6 节） |
| `events` | 事件时间线，用 tick（第 10.6 节） |
| `cancel` | 被打断时怎么收场 |

**物品默认用哪个动作**：写在映射表里，不写进代码。
- 文件【计划】：`data/apocalypse_firstlight/item_actions/<物品>.json`，也可以按物品标签写。
- 例子：`{"stance": "stance_unarmed.hold_small", "use": "item/drink_bottle"}`。
- 一个新饮料只需要加一行映射；原版食物按 `#minecraft:...` 标签统一给"吃"。

**谁启动动作**：
- **改变游戏状态的动作**：一律由服务端启动，服务端检查条件后发 ActionState（第 6 节）。本地玩家先走，服务端否决时再纠正。
- **纯外观的动作**（以后的表情动作之类）：可以只在客户端，但同样要发给周围玩家。

### 10.3 IK 目标和锚点规范

**目标类型**（每种是一个注册的解析器，加类型不改已有的）：

| 目标 | 意思 | 例子 |
|---|---|---|
| `clip` | 不用 IK，按片段里手臂骨骼的旋转 | 挥手、摆臂 |
| `clip_ik` | 用 IK 去够片段里 `ik_hand_*` 的位置和朝向 | 手伸到嘴边、从胸挂掏东西的路径 |
| `pose` | 交给下面一层（放松、走路摆臂） | 平时的左手 |
| `held:<锚点>` | 主手物品上的锚点；`held_off:<锚点>` 是副手物品 | `held:grip_r`、`held:grip_l`、`held:magwell`、`held:bolt` |
| `object:<道具>:<锚点>` | 动作里出现的道具上的锚点 | `object:new_mag:grip` |
| `socket:<挂点>` | 自己身上的挂点 | `socket:holster`、`socket:back`、`socket:pouch_mag_l`、`socket:mouth` |
| `block:<锚点>` | 动作对象方块上的锚点（`mesh_shapes` 的 `anchors`，按方块当前状态） | `block:door_handle`、`block:pull_grip` |
| `entity:<骨骼>` | 动作对象实体上的骨骼 | `entity:steering_l`、`entity:door_handle_l` |

**锚点 = 位置 + 朝向 + 握法**：
- 朝向就是手掌的坐标系，约定和现有 `NativeHandBinding` 一致：锚点是手末端盖的中心，手的方向取锚点的旋转。
- 握法（`power` 握紧、`pinch` 捏、`flat` 手掌推）V1 只记录、不影响画面；手指以后再用（第 10.8 节）。

**各类物体的锚点写在哪**：

| 物体 | 锚点写法 |
|---|---|
| Native 枪（已有） | geo 里的骨骼。`right_hand_anchor` = `grip_r`，`left_hand_anchor` = `grip_l`，用别名，**不改名、不改资产**。以后需要再加 `magwell`、`bolt`、`pump` 等 |
| 新的 geo 物品 | geo 里的 `anchor_<名>` 骨骼 |
| 没有骨骼的物品（静态网格物品、普通物品） | `assets/apocalypse_firstlight/item_anchors/<物品>.json`，物品模型坐标里的位置和旋转；没有文件时用默认握点（物品第三人称挂点） |
| 方块 | `mesh_shapes` 的 `anchors` 扩展成 `{"pos": [...], "rot": [...], "hand": "right"}`；旧的只有三个数的写法照旧有效（只当提示框位置） |
| 载具 | 载具模型骨骼 `anchor_steering_l/r`、`anchor_gear`、`anchor_handbrake`、`anchor_door_l`；座位是 `anchor_seat_driver`，骨盆的目标 |

**一个目标在 IK 前怎么变成世界坐标**：
1. 找到锚点所在的物体，取它这一帧的变换。物体本身可能在动：枪在片段里动，门在开。
2. 乘上锚点的局部变换。
3. 得到手的目标（位置 + 朝向）。

每帧都重新算，所以手会跟着移动的物体走。

### 10.4 手部目标切换

IK **不是**永远锁在一个点上。每只手一条时间线，每个关键点写"从此刻起手去哪里"：

```json
"left": [
  { "at": 0.00, "target": "held:grip_l" },
  { "at": 0.40, "target": "clip_ik",              "blend": 0.12 },
  { "at": 0.60, "target": "socket:pouch_mag_l",   "blend": 0.10 },
  { "at": 0.85, "target": "clip_ik",              "blend": 0.08 },
  { "at": 1.30, "target": "held:magwell",         "blend": 0.10 },
  { "at": 1.80, "target": "held:grip_l",          "blend": 0.15 }
]
```

上面是 BR51 空仓换弹左手的示意：从护木离开 → 沿片段路径 → 到弹匣包 → 抓起新弹匣沿片段路径 → 到弹匣井 → 回护木。时间是示意，真实数值 P2 按片段定。

规则：
- **切换是过渡，不是跳**：在 `blend` 时间内，手的目标从"上一个目标这一帧的位置"平滑过渡到"新目标这一帧的位置"，两个目标每帧都实时算。所以枪在动的时候换目标，手也不会掉队。
- **绕开身体**：两个目标之间如果直线会穿过身体（比如从护木到腰后），中间放一段 `clip_ik`，由片段画出绕过去的路径。
- **权重**：每个关键点可以带 `weight`（0–1），0 就是交回 `pose`。第 4.4 节"平时只用右手、需要双手才抬左手"就是权重的默认值。
- **手里拿着东西时**：拿起道具（第 10.6 节的 `attach` 事件）以后，道具跟着手走，手的目标可以是任何东西。
- **检查工具**（第 10.11 节）：
  - 沿时间线逐帧检查够不够得到、肘角、手腕角；
  - 检查手的路径是否穿过躯干（躯干按胶囊体算）；
  - 检查相邻切换之间的速度不超过上限，避免手瞬移。

### 10.5 动作分层与融合

每帧从下到上求一遍，结果按骨骼混合：

| 层 | 内容 | 默认遮罩 | 例子 |
|---|---|---|---|
| 1 移动 | 站、走、慢跑、冲刺、蹲走、起步、停步、原地转身、跳、落地 | 全身 | `locomotion.*` |
| 2 持握姿态 | 拿着什么、怎么拿，循环 | 上半身 | 空手、手枪低位、步枪双手、ADS、搬箱子 |
| 3 动作 | 一次性的：换弹、掏枪、吃喝、拉绳 | 按动作，可以单手 | `action` 层 |
| 4 叠加 | 呼吸、受击抖动、后坐的身体反应、转身倾斜 | 按部位 | `additive` 层 |
| 5 视线 | 胸和头按视线分配（第 5.2 节） | 胸、头 | — |
| 6 IK | 两只手按时间线去够目标；以后加脚接地 | 手臂、腿 | — |
| 7 收尾 | 关节范围夹住、身体对准镜头（第 5.1 节）、写回原版 ModelPart | 全身 | — |

**上下半身分开**：
- 移动层管腿和骨盆，持握姿态和动作层管胸以上。所以"走路 + 持步枪""冲刺 + 手枪低位""蹲走 + 换弹"都是自动组合出来的，**不用为每种组合做一套动画**。
- 胸的朝向由视线层决定，所以腿在走时上半身瞄准不晃。

**两只手各自独立**：
- 每只手每帧只有一个"主人"：遮罩覆盖它、优先级最高的那一层。
- 例子：拿着步枪时右手被"步枪持握"占着；换弹动作只申请左手（`mask: arm_l`），右手照旧握枪。
- 例子：搬箱子（双手）期间，不能开始需要手的动作。

**过渡**：
- 层内换片段用交叉淡化，时间来自动作定义的 `blend`，缓入缓出。
- 移动层不同速度的片段共用一个步伐相位（走到跑不会换脚）。
- 首尾衔接：上一个片段结尾和下一个片段开头姿势一样时（掏枪 → 持枪），`blend` 可以是 0。检查工具比较首尾姿势差。

**冲突**：
- 两个动作抢同一只手时，高优先级的占用，低的等待或被取消（动作定义里写 `on_blocked`）。
- 游戏规则上的冲突（换弹时不能开火）仍然由服务端判定，动画只是表现。

### 10.6 动作事件时间线

**事件类型**（注册表，可扩展）：

| 事件 | 作用 | 谁执行 |
|---|---|---|
| `sound` | 播放声音 | 服务端广播（和现有枪的 `sound_effects` 一样，`NativeGunAnimations.cues` 已经这样做） |
| `attach` | 把一个物体挂到某处：手、身体挂点、物品锚点。例：新弹匣挂到左手 | 客户端外观 |
| `detach` / `show` / `hide` | 物体放开、显示、隐藏 | 客户端外观 |
| `grab` / `release` | 手抓住 / 松开（以后给手指和握法用；V1 等同于 `attach`） | 客户端外观 |
| `commit` | 改变游戏状态：子弹进枪、喝完、包扎生效、发电机启动 | **只有服务端** |
| `require` | 检查条件，不满足就取消动作（例：弹匣还在背包里吗） | 服务端 |
| `fx` | 粒子 | 客户端 |
| `camera` | 镜头叠加晃动 | 本地客户端，只动镜头（第 5.1 节） |

**和真实游戏状态不脱节的规则**：
1. **时间是 tick**：事件按 tick 写。服务端在 `start + tick` 执行 `require`、`commit`、`sound`。
   - 已有先例：`NativeGunActions` 在 `start + magInTick` 时转移子弹，BR51 的 `mag_in_tick` 是 52；声音按片段的 `sound_effects` 时间播放。
2. **外观是时间的纯函数**：任何客户端在任何时刻（包括中途才看到这个玩家）都能从 `(动作, start, 当前时刻, context)` 算出"现在手里拿着什么、弹匣在哪"。所以不需要同步每一帧，也不会有人看到不一样的东西。
3. **外观只用道具**：动作里出现的东西（手里的新弹匣、水瓶）是外观道具，不是真的物品，不会被复制。真的物品数量只在 `commit` 时由服务端改。
4. **打断**：
   - `commit` 之前被打断：游戏状态没变，外观按 `cancel.before_commit` 收场（比如弹匣回到弹匣包，或者淡出）。
   - `commit` 之后被打断：状态已经变了，按 `after_commit` 快速收尾，外观要和新状态一致（子弹已经进枪，就不能再看到弹匣掉回包里）。
5. **一致性检查**（检查工具）：
   - 片段里 `timeline` 标记的时间和动作定义里事件的 tick 相差不超过 1 tick；
   - `commit` 前后的道具状态和游戏状态对得上；
   - 物品使用时长（原版 `getUseDuration`）和 `commit` 的 tick 一致。

### 10.7 第一、第三人称共用

- 动作定义、片段、IK、事件里**没有任何"第一人称专用"的字段**。检查工具发现就报错。
- 第一人称和第三人称只有两处不同：
  1. 第一人称隐藏头和头上的东西（第 3.1 节）；
  2. 片段里的 `camera` 骨骼和 `camera` 事件只作用于本地镜头。
- 制作时用模板里的第一人称视野框看效果。
- 检查工具可以导出一张第一人称投影图给人看，不需要进游戏。
- 旧的第一人称假手臂（`NativePlayerArmRenderer`、`CrowbarFirstPerson` 的手臂、`JerryCanFirstPerson`、`PortableGeneratorPull` 的手）迁移完以后删除，不再保留（第 11 节 P2）。

### 10.8 以后的扩展

骨架定义带版本号。为以后预留，但 V1 **不做**：

| 预留 | 用途 |
|---|---|
| 骨骼名 `finger_*` | 手指，握法 |
| `jaw`、`eye_*` | 面部 |
| `spine_mid`、`neck` | 更多脊柱和颈部关节 |
| `clavicle_r/l` | 锁骨，现在用第 4.3 节的肩前伸代替 |

规则：
- 加骨骼不能改已有 16 根的名字和关节位置，所以旧片段永远有效（片段里没写的骨骼保持原样）。
- 感染体、NPC 用**自己的骨架定义**，骨骼可以多、可以少、比例可以不同（第 11 节）。动画引擎、蒙皮、IK、事件、工具链共用；片段原则上不跨骨架共用，同名骨骼的片段可以试着复用。
- 布娃娃不是骨架自动带的功能，以后单独规划（第 11 节）。

### 10.9 现有 Native 枪械怎么接进来

**默认原则**：枪的机械关键帧保留，手部锚点接 IK，人物全身姿态重做。

| 内容 | 处理 |
|---|---|
| 枪栓、弹匣、套筒、抛壳、枪身后坐、`sound_effects` | **保留**，不批量重做 |
| `camera` 骨骼 | 保留，只给镜头 |
| `right_hand_anchor` / `left_hand_anchor` | 保留，作为 `held:grip_r` / `held:grip_l` 的别名 |
| `*_in_hand.json` 的第一 / 第三人称显示变换 | 不再用于手持（物品栏、地上照旧） |
| 人物身体姿态 | **新做**，按枪类共用：`stance_pistol.*`、`stance_rifle.*`、`stance_shotgun.*`，每类有持枪、ADS、冲刺低位、贴墙 |
| 掏枪、收枪 | **新做**，按挂点共用：`draw.from_back`、`draw.from_holster`、`holster.to_back`、`holster.to_holster`。枪自己的机械部分（比如 P9 首次掏枪拉套筒）叠在上面 |
| 换弹、检视 | 枪片段不动；自动生成的动作定义让两只手全程跟锚点；检查工具报出够不到、穿身体的段，只把那几段改成身体空间的目标（弹匣包等） |

**自动生成**【计划，P2】：`tools/build-gun-actions.mjs` 读每把枪的片段和枪类，给每个片段生成一个默认动作定义（两只手跟锚点，左手权重按枪类），写到 `player_actions/gun/<枪>/<片段>.json`。人只改检查工具报出来的那几段，重新生成时不覆盖人改过的段。

**代表枪**（用户 2026-10-15 指定）：
- **BR51-01** 验证双手长枪：持枪、ADS、换弹、从背上掏枪；
- **P9-01** 验证单手 / 双手切换：平时单手低位，举枪和 ADS 时左手上去合握，从枪套掏枪。

两把都通过以后，再批量迁另外四把。

**P2 第一段的实际做法**（2026-10-15，第 13 节）：
- 身体姿势先写在代码里：`skeleton/GunStance.Kind` 按枪类给出持枪、瞄准、低位、掏收枪路径。还没有拆成 `stance_*` 数据文件。
- 手直接跟两个锚点走，还没有生成动作定义文件。`tools/build-gun-actions.mjs` 没做。
- 检查工具是 `PlayerSkeletonCheck` 的"每个片段"一节。

**加一把新枪以后要做什么**：
- geo 里放 `right_hand_anchor` / `left_hand_anchor`（或 `grip_r` / `grip_l`），做枪自己的机械片段，在 `native_guns` 里写枪类；
- 持枪、ADS、掏收枪的身体动作按枪类自动复用；
- 换弹的动作定义自动生成，再按检查结果改局部。

**不用写任何手臂渲染代码。**

### 10.10 完整示例：喝纯净水瓶

用来说明以后每个新动作的流程。物品 `purified_water_bottle` 已存在。

**第 1 步：物体锚点**
- 写 `item_anchors/purified_water_bottle.json`：
  - `grip_r`：瓶身中段，手掌朝瓶；
  - `spout`：瓶口。

**第 2 步：Blockbench 制作**
1. 复制模板（**不改模板本身**）为 `src/main/blockbench/player/actions/item_drink_bottle.bbmodel`，把瓶子模型挂到 `prop_r` 预览。
2. 新建动画 `item.drink_bottle`，长度 1.6 秒：

| 时间（秒） | 动作 |
|---|---|
| 0.00 | 和持握姿态 `stance_unarmed.hold_small` 的最后一帧一样（首尾衔接） |
| 0.35 | `ik_hand_r` 移到瓶口对着嘴（`socket:mouth` 的预览件帮助对位置） |
| 0.45–1.20 | `head` 后仰 20°，`chest` 后仰 5°，瓶身倾斜 |
| 0.60、0.90 | `timeline` 标记 `sip` |
| 1.20 | 标记 `commit` |
| 1.20–1.60 | 手放回持握位置 |

3. 打开第一人称视野框检查：0.35 秒以后瓶子应当从画面下方进入，不挡住画面中间太久。

**第 3 步：导出**
- 导出动画，合并进 `assets/apocalypse_firstlight/animations/player/item.animation.json`。合并脚本【计划】`tools/merge-player-clips.mjs`，只替换同名片段。
- `.bbmodel` 留在 `src/main/blockbench/player/actions/`。

**第 4 步：动作定义**

`data/apocalypse_firstlight/player_actions/item/drink_bottle.json`，内容如第 10.2 节的例子，其中：
- 右手：开始是 `held:grip_r`，0.30–1.25 秒是 `clip_ik`，之后回 `held:grip_r`；
- 左手：`pose`；
- 事件：tick 12、18 喝水声；tick 24 `commit`，执行物品原本的"用完"（加水分、换空瓶）。

物品映射 `item_actions/purified_water_bottle.json` 写 `{"use": "item/drink_bottle"}`。物品的使用时长要等于 commit 的 tick（24），检查工具核对。

**第 5 步：检查工具**【计划】：`node tools/check-player-actions.mjs item/drink_bottle`。检查内容：
- 关节范围；
- 够不够得到；
- 手是否穿过身体；
- 首尾姿势衔接；
- 标记和事件 tick 一致；
- 使用时长；
- 第一人称投影图。

**第 6 步：游戏内测试**：
1. 开发命令【计划】`/afl dev action play item/drink_bottle`：循环播放，不消耗物品。
2. `/afl dev action speed 0.25`：慢放。
3. 第一人称看一遍，按 F5 看第三人称，有条件时用第二个客户端看。
4. 真正喝一瓶：确认 commit 时水分才变化；喝到一半被打断不加水分。

**第 7 步：以后怎么复用**：
- 脏水瓶、开水瓶：只加物品映射，动作完全复用；
- 罐头、军用水壶：复用片段，换物品锚点；
- 拧阀门、拉拉杆：新做一个片段，手的目标用 `block:<锚点>`，方块那边在 `mesh_shapes` 里加锚点。

## 11. 骨骼框架完成后的玩家与感染体动画重制路线图

| 吃喝 | 物品映射 + `clip_ik` + `commit` |
| 包扎 | 双手、身体挂点（伤口部位） |

| 砍树、劈柴 | 双手工具、`block:` 锚点、命中时机事件；接树木 P2 的砍伐 |

**载具**（P3，等皮卡）：
- 坐姿：骨盆目标 `anchor_seat_driver`，腿用固定片段；
- 握方向盘：两手 `entity:steering_l/r`，方向盘转动时手跟着走，转大角度时一只手松开换手（手部目标切换）；
- 上车、下车：车门锚点和座位之间的全身片段。

皮卡 V0 设计（Main 工作区 `docs/vehicles/first_pickup_v0_design.md`）的 `VehicleSeats` 是对接点。**这一轮只预留目标类型和锚点命名，不实现。**

### 11.3 感染体

**目标**：感染体要有自己的站姿、游荡、警觉、追逐、奔跑、扑抓 / 攻击、踉跄受击、死亡，不是给原版僵尸换一张贴图。

**共用的**（框架）：
- 动画引擎：分层、混合、过渡、优先级；
- C-min 蒙皮；
- IK：扑抓时手够目标，以后脚接地；
- 事件时间线：攻击命中帧、声音；
- 工具链：Blockbench 模板生成、检查工具、开发命令；
- 动作状态的同步方式。

**独立的**：
- **骨架定义**：感染体用 `rigs/infected_<类型>.json`，骨骼可以和玩家不同。例如加一节脊柱让驼背更自然，手臂可以更长，可以有下颌。**不强制和玩家同为 16 根。**
- **动作风格**：自己的片段，不借玩家的走路。
- **AI 状态映射**：服务端 AI 目标决定状态（游荡 / 警觉 / 追逐 / 攻击 / 受击 / 死亡），映射到动作。每次状态变化同步一次，客户端按时间播放，和玩家一样**不同步每帧骨骼**。
- **攻击的游戏判定**：命中时机由服务端 AI 按事件 tick 决定，动画只是表现。

**配套机制**（P4）：
- AFL 自己的感染体实体类型；
- AI 目标；
- 命中判定（现在是 AABB 加头盒）；
- 刷新规则；
- 声音和噪声半径（按已有规则：声音范围 = 噪声半径）。

**性能**：感染体数量远多于玩家，LOD 是必须的：
- 32 格外不做 IK、隔帧采样；
- 64 格外用不分段的刚体；
- 先测 50 个同屏的帧时间，再决定数量上限【待原型】。

**布娃娃**：不是骨架自动提供的。P5 之后单独规划，先做"程序化死亡姿势 + 贴地对齐"（审计第 9 节的 R1）。

### 11.4 Native 枪械的衔接

### 12.2 做了什么

**数据**
- 骨架定义 `assets/apocalypse_firstlight/rigs/afl_humanoid_v1.json`：
  - 16 根骨骼，Bedrock 坐标；
  - 皮肤分段、第二层外扩 0.25；
  - `eye` 挂点在头上 Java (0, −3.63, −2.5)；
  - 关节上限。
  - Alex 的手臂转轴和 Steve 一样，因为原版 `HumanoidModel.setupAnim` 每帧会把它重设到 y=2，所以只有手臂宽度（3）不同。
- 移动片段 `assets/apocalypse_firstlight/animations/player/locomotion.animation.json`：
  - 由 `tools/author-player-locomotion.mjs` 生成，支持 `--check`；
  - 片段有 idle、walk、run、crouch_idle、crouch_walk、turn_step；
  - idle 时两只手自然下垂，有 4 秒一次的呼吸起伏；
  - crouch_idle 是前后脚蹲（左脚在前，右脚在后踮脚），crouch_walk 两脚并排，见第 12.6 节。

**纯计算**（`skeleton/`，不引用客户端类，离线检查直接用）
- `SkeletonRig`：读骨架定义。
- `SkeletonClips`：读 Bedrock 片段，支持 linear、catmullrom、step 三种插值。
- `SkeletonPose`：骨骼的局部和世界矩阵，以及关节的半程矩阵。
- `SkinMesh`：C-min 网格。
  - 关节环取半程旋转；
  - 面、顶点顺序和 UV 跟原版 `ModelPart.Cube` 一致；
  - 弯曲后的四边形改从另一条对角线拆三角形，避免折叠。
- `HumanoidPoser`：
  - 混合移动片段；
  - 骨盆、胸、头分摊视线；
  - 根部水平平移，让眼窝对准镜头，最多 4.27 px；
  - 双臂两段 IK，带肩前伸、支撑手沿枪后滑、肘和腕的限制。
- `GeoAnchorSampler`：从枪的 geo 和动画里读手部锚点，采用 GeckoLib 约定。
- `RifleStance`：BR51 相对眼睛的位置和手的目标。P2 改名为 `GunStance`，分枪类，见第 13.6 节。

**客户端**（`client/skeleton/`、mixin）
- `PlayerSkeleton`：每 tick 更新骨盆朝向（含踏步转身）、胸的落后量，以及蹲、跑、眼高的平滑。
  - 每次画玩家时，在原版 `setupAnim` 之后解一次姿势，再把结果写回原版的 6 个部件。所以护甲、Curios、手持物品这些 layer 都跟着骨架动。
  - 身体换成 C-min 网格来画，头仍然是原版的。
- `SkeletonGunStance`：BR51 按实物大小（模型的 0.307 倍）贴着眼睛摆，双手用 IK 握住 `static_idle` 片段里的锚点。
  - 第一人称加上视图模型的晃动和后坐，手跟着枪动。
- `SkeletonPackets`：ADS 状态同步，服务器转发给周围玩家。网络协议版本 46 → 47。
- `LivingEntityRendererSkeletonMixin`：替换 `renderToBuffer`。
- `ItemInHandLayerSkeletonMixin`：骨架自己画 BR51 时，原版手上不再画一把。
- 第一人称：
  - 空手，或只拿 BR51：取消原版画手那一遍，手只来自身体，所以平视时画面里没有手；
  - 其他情况：保留旧的第一人称视图模型，身体的手臂隐藏，和第一人称身体 V1 一样。
  - 第一人称身体 V1 的后仰、颈部后让、手滑出画面、限制手臂这几个补丁，在骨架打开时都不再生效。

**骨架画哪些姿势**：只画站立和蹲，其余（游泳、鞘翅、睡觉、死亡、旁观）仍是原版。骑乘时腿用原版角度。

### 12.4 离线检查 `./gradlew skeletonCheck`

`src/test/java/com/antaurora/apofirstlight/skeleton/PlayerSkeletonCheck.java`，用的是游戏里同一份网格和姿势代码。没有挂进 `check`，要单独跑。设环境变量 `AFL_DEBUG=1` 会多打印各关节在镜头里的位置（cm）和按俯仰角分开的距离。2026-10-15 的结果：**全部通过**。

1. **直立贴图**：Steve、Alex 各 132 个四边形，和原版立方体逐个比对位置、UV、覆盖面积，一致。
2. **关节**：52 个姿势 × Steve/Alex，网格闭合、不折叠、不翻面。
   - 姿势包括：肘 45/90/120/145° 配前臂扭转 −90/0/90°，腕 ±60/±30°，膝 90/150°，踝 −30/+45°，腰的组合。
   - 最斜的面相对骨骼转了约 54°（余弦 0.582），出现在肘 145° 加扭转 −90° 时。
   - 第一次跑时，肘 120° 以上、膝 150°、前臂扭转 ±90° 都有四边形折叠。原因是弯曲后四边形不再共面，原版固定的 0-2 对角线拆出的两个三角形朝向相反。现在每个四边形挑一条不折的对角线。
3. **BR51 够枪**：站 / 蹲 × 平端 / ADS × 俯仰 −60…+60，Steve/Alex。
   - 两手都在臂长以内（≤ 0.99）。
   - ADS 时右肘弯 29–82°（蹲姿往下看 60° 时最直），左臂接近伸直（约 23°）。
   - 左手往后滑：平视 ADS 0.5 px，蹲姿平视 1.8 px，抬头 60° 时 2.4–3.0 px。
4. **镜头净空**：FOV 70、16:9，视线偏航相对骨盆 −60…+60，俯仰 −90…+90。

| 状态 | 最近可见皮肤（格） | 肩膀进入画面上方 2/3（±45° 内） | 手开始出现的俯仰 |
|---|---|---|---|
| 站 / 走 / 跑 | 0.25 / 0.25 / 0.25 | 0 | +60 / +40 / +20（往下看） |
| 蹲 / 蹲走 | 0.23 / 0.20 | 0 | +60 / +50 |
| BR51 平端 / 走 | 0.088 / 0.090 | 0 | 在枪上 |
| BR51 ADS / 蹲 ADS | 0.060 / 0.057 | 0 | 在枪上 |

### 12.6 实机第一轮反馈后的修改（2026-10-15）

用户实机看过 P1（录像 2026-10-15 20-52、20-53）后，大体没问题，提了三点。改动如下；改完后用户实机复看 **PASS**（2026-10-15）。

**1. 蹲姿改成前后脚**
- 原来两脚并排，膝盖都朝前，像亚洲蹲；两条大腿都相对骨盆前抬 64°，大腿顶部插进躯干下半。
- 现在 `crouch_idle`：
  - 左脚在前，脚掌放平，踝在髋前 3 px；
  - 右脚在后，踝在髋后 3.5 px，脚跟抬起 40°（以鞋底前沿为支点，踝抬高约 0.8 px）；
  - 上身和原来一样：骨盆前倾 10°、胸再前倾 20°、髋下沉 2.94 px、后移 3 px，眼高仍对上原版的 1.27。
  - 角度（大腿 / 膝 / 脚，相对父骨骼）：前腿 −64.1 / 81.9 / −27.8，后腿 −14.7 / 91.0 / −46.3。后腿大腿接近竖直，不再插进躯干；前腿和原来一样。
- `crouch_walk`：两脚并排，髋后移 1.5 px（大腿 −55.7 / 膝 90.0 / 脚 −44.3），再叠加原来的步幅摆动。站着的前后脚和走路的并排脚由速度混合过渡。
- 试过上身前倾 15° + 25°、15° + 15°、髋后移 0.5–2 px，都会让镜头净空不通过：蹲着往下看 40° 时肩膀进入画面上方，蹲姿 ADS 时右臂离眼睛只有 0.042–0.049 格。所以上身保持原值。
- 骨架定义里踝的上限从 ±30° 放宽到 −30…+45°，关节检查在 +45° 时网格仍然闭合。
- 数据来源：`tools/author-player-locomotion.mjs` 的 `CROUCH`（`front` / `rear` 是踝相对髋的距离，`heel` 是踮脚角度），`plantedLeg` 多了 `heel` 参数。

**2. 蹲着转头时的抽搐**
- 原因：`turn_step` 片段是按站立的腿做的，`HumanoidPoser.locomotion()` 用它**整个替换**腿的旋转和位移。蹲着转头超过 40° 时，腿会在约 0.5 秒里跳成站立踏步的样子再跳回去。
- 现在：踏步片段只取它相对第一帧的变化，叠加到当前混合好的腿上（旋转右乘、位移相加），权重仍是 1 − 移动量。蹲着就蹲着踏步。

**3. 转身时身上装备穿模**
- 原因：胸挂、背包等穿戴网格挂在胸骨骼上（写回原版 `body` 部件），躯干下半的皮肤跟骨盆。胸相对骨盆扭转（最多 45°）时，躯干上下错开，胸挂下沿就切进下半身。
- 现在：`HumanoidPoser.solve()` 把胸的扭转放到髋部做（`HIP_SHARE = 1`）：
  - 骨盆绕它自己的竖直轴转，转轴穿过腰的转轴点，所以胸的位置和朝向与原来完全一样（离线检查数值一致），只是躯干上下半不再错开；
  - 站着时大腿跟着转一半（`LEG_SHARE = 0.5`），走路时大腿不跟转，保持步幅方向；
  - 骨盆和大腿之间有了相对转动，大腿顶面和躯干底面在髋部错开，只有从正下方才看得到。
- 没有做装备蒙皮：穿戴网格按骨骼权重变形属于 Vextris 的共享能力，AFL 不做替代实现。

### 13.1 拿在手上的大小

- 手上按实物大小，模型倍数等于枪架长度除以模型最长边：
  - BR51：0.307；
  - P9：0.261。
- 地上、枪架、背上的枪不变，本来就是实物长度。维护台是放大的工作视图，物品栏用的是图标，都不变。
- 枪套里的 P9 也不变，仍是第三人称手上的旧尺寸。枪套外壳是按这个尺寸做的，用户已 PASS（[afl_inventory_grid_v0_plan.md](../ui/afl_inventory_grid_v0_plan.md) 第 14 节）。
  - 掏枪时，枪沿路径从枪套尺寸平滑缩到实物大小（`GunStance.blend` 对缩放做插值）；收枪时反过来。

### 13.2 每个片段都在骨架上播放

- **每帧先算枪的骨骼**：画枪之前，让 GeckoLib 先算一次枪的骨骼（`client/skeleton/GunBones`）。
  - 做法和 `NativeCameraBoneConsumer` 一样：同一个模型、同一个动画管理器、同一个帧时间。
  - GeckoLib 对同一实例、同一 tick 不会重复计算，所以手握住的锚点就是画出来那把枪上的锚点。
- **手跟着枪动**：两只手用 IK 去够 `right_hand_anchor` / `left_hand_anchor` 在当前帧的位置。开枪、换弹、检视、掏枪、收枪时，手都跟着枪的机械动作走。
- **第三人称也播放**：包括别的玩家看到的，不再是冻结的 idle。
  - `NativeGunContextRenderer.skeletonDraw` 打开时，第三人称走带动画的渲染。
  - 片段由服务器触发，GeckoLib 会同步给周围的玩家，所以别人看到的是同一个片段。
- **第一人称**：和 P1 一样在世界那一遍画，旧的浮空手臂不画。
- **片段没写的骨骼**：由常驻的 `baseline` 控制器补上（`static_idle`，空仓时是 `empty_idle`）。
  - 例如 BR51 的 `shoot` 片段没有写手的位置，手的位置来自 `static_idle`。
  - 离线检查也按这个方式分层采样（`GeoAnchorSampler.frame(..., base)`）。

### 13.3 掏枪和收枪

**挂点**
- BR51 从背上掏出（`CarriedWeaponsLayer.backFrame`），P9 从右大腿的枪套掏出（`thighFrame`）。
- 挂点用当帧已经解好的身体来算，所以走路、蹲着时也对得上。

**路径**：挂点 → 中间点 → 持枪位置。
- 长枪的中间点在身体右侧：枪口朝上，握把在右髋旁边（胸前坐标）。
- 手枪的中间点在枪套上方 0.2 格。

**时间**（`GunStance.draw / putAway`，f 是片段进度，从 0 到 1）

| 时段 | 掏枪 | 收枪 |
|---|---|---|
| 0–0.1 | 右手伸向挂点 | 左手离开枪 |
| 0.1–0.3 | 右手伸向挂点、握住 | 左手离开枪（到 0.25）；枪开始送回挂点 |
| 0.3–0.7 | 枪沿路径拿出 | 枪送回挂点（到 0.7） |
| 0.7–1 | 枪拿出（到 0.9）；左手合握：长枪 0.65–0.95，手枪 0.75–1（只在举枪时） | 右手松开（0.75–1） |

**片段自己的整枪位移被换掉**
- 原片段里枪是从画面下方升上来的。现在换成上面的路径。
- 做法：从 `right_hand_anchor` 往上找，`draw` 片段动到的最高一根骨骼钉在绑定姿势。
  - BR51 是 `root`，P9 是 `handling`。
  - 这根骨骼下面的机械部分照常播放，比如 P9 首次掏枪时拉套筒。

**切枪**
- 切走的那把枪继续画，右手带着它回到挂点（"收枪残影"）。这段时间里挂点上不画它。
- 新拿的枪先在自己的挂点上等着，残影结束后再掏出来。
- 残影最长 `min(收枪片段, max(0.15, 掏枪片段 − 0.25))` 秒；掏枪仍按原定时间结束。

**其他规则**
- 第一次看到某个玩家时（进服、进入视距），他手上已有的枪不播放掏枪。
- 只看主手：副手拿着东西或正在使用物品时，枪不走骨架姿势，但也不算收枪。

### 13.4 P9：平时单手低位，需要时双手举枪

**低位（平时）**
- 单手握枪，握把在胸前坐标 (0.17, −0.12, −0.17) 格，枪口朝下 50°；左手垂下。

**举起（双手）**
- 什么时候举起：瞄准时、开枪后 1.5 秒内、换弹时、检视时。
- 举起和放下每 tick 走完剩下距离的 40%。

**胸的方向**
- 扭转：长枪 20°（左肩在前）；手枪 0°（正对前方）。
- 跟随俯仰：长枪和举起的手枪都按长枪的比例。

**瞄准距离**
- 手枪瞄准时，准星在眼前 **0.34 格**（`Kind.sightDistance`），双臂几乎伸直。
- 为什么不用旧值：P1 沿用旧视图模型的 eye relief 换算，0.47 × 0.261 / 0.53 = 0.23 格。那样手离眼睛只有 15 cm，左肘弯到 132°，手臂皮肤离镜头只有 2–4 cm，离线检查不通过。

**手够不着时把枪往回收**
- 仰头、蹲下，或片段把枪转开时，手会够不着。
- 这时手枪沿视线往回收，直到两只手都够得着（`GunStance.inReach` + `HumanoidPoser.shortfall`），但不会近于 **0.27 格**（`MIN_SIGHT`）。所以直着仰头时，手可能还差一点。
- 长枪不收：枪托顶在肩上，P1 的姿势不变。

**肩**
