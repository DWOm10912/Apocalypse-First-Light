### 2.3 空仓换弹 `reload_empty`（2.0 s）

### 2.6 第一人称的限制（旧视图模型，方块手臂）

- 两只手是没有手腕的方块（[gun_handling_reference_v1.md](gun_handling_reference_v1.md)、`NativePlayerArmRenderer`），所以：
  - 左手的方块只能从**画面下方、左下**进来，不能横在枪前面；

### 2.11 手调关键帧的战术换弹（2026-10-22）

起因：用户看 BR-51 和 P9 重制版时说动作「还是有点僵硬」，B 站做 TACZ 枪包的评论说缺缓冲（慢-快-慢、冲过一点再回来），弹匣没跟着手。按评论里的动画原则做，没有照抄别的模组的东西。旧片段量出来的问题：

- 枪的路径是同一种加速曲线，举到位时急停：0.30 s 前后 266°/s 直接停住，回位 1.30–1.35 s 也一样；
- 左手 0.20–0.30 s、0.85–0.90 s 停死，0.40 s 前后一下转 1367°/s（弹匣从屏幕外"跳"到手上）；
- 每段节奏一样，位置都是直线插值；
- 弹匣自己走一条弧线，手只是追着它。

现在的做法：

- **手调的通道**：`handling`（旋转、位置）、`lefthand`（旋转、位置）、`camera`（旋转）是 `src/main/blockbench/p9_01_v3_native.bbmodel` 里 `reload_tactical` 的贝塞尔关键帧，每个通道 13–21 个键，在 Blockbench 里可以直接改。`lefthand` 的键是相对片段的 `lefthand_pos` 预转（[0, 90, 0]）的局部值。
- **推算的通道**（`tools/author-p9-01-v3-native-animations.mjs` 的 `reloadKeyed`，从手调键算出来）：
  - 新弹匣（`mag_out`）对准之前一直长在左手上（`magOnHand`，`onMag` 的反解），所以弹匣从包里拿出来到弹匣井下面都跟着手；
  - 0.56–0.62 s 左手从手调键过渡到弹匣井约束，0.62–0.92 s 插入、掌心离开、拍到底照旧按弹匣井算（`seatDepth` / `slapGap`），0.92–0.98 s 再过渡回手调键，1.08–1.18 s 落到移动中的枪的握把上，之后跟枪；
  - 旧弹匣下落（g = 520）、`magazine` / `reload_magazine` 显示、`follower`、右手握把滑移（滑移量按枪的偏航算：偏航 / 40°）、四个声音。
  - 所以在 Blockbench 里预览时，左手在 0.56–1.18 s 是手调键的近似值（键是按约束算好放上去的），游戏里用的是推算的结果。
- **烘焙**：`tools/bb-keyframes.mjs` 按 Blockbench 5.2 自己的算法求值（`BoneAnimator#interpolate` + `Keyframe#getBezierLerp`：三次贝塞尔取 201 个点，找 x 最近的两点再插值），和 Blockbench 的 `interpolate()` 在 8 个时刻、5 个通道上逐位一致（差 0）。运行时仍是 60 Hz 线性键（GeckoLib），游戏代码没改。
- **工作流**：在 Blockbench 里改这三个骨骼的键 → 保存 → `node tools/author-p9-01-v3-native-animations.mjs --write-source --write-runtime`。`--write-source` 原样保留手调键，只重写推算的骨骼；手调键缺了会报错，不会退回脚本生成。哪些片段、哪些通道是手调的写在脚本的 `HAND_KEYED`。初始键由一次性的种子脚本按下面的节拍放（会话临时目录，不进仓库）。
