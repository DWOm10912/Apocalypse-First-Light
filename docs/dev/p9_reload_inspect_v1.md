### 2.6 第一人称的限制（旧视图模型，方块手臂）

- 两只手是没有手腕的方块（[gun_handling_reference_v1.md](gun_handling_reference_v1.md)、`NativePlayerArmRenderer`），所以：
  - 左手的方块只能从**画面下方、左下**进来，不能横在枪前面；
  - 右手握着枪转，转的是整只前臂。
- 检视给右侧面时，只转枪会让枪口正对镜头、看到的是套筒尾部。现在的做法：枪口转向右（偏航 −60°）、向里滚 10°，右手方块绕握把转，让前臂沿视空间方向 (0.35, −0.6, 1) 从右下进画面，相当于弯了手腕（`bentRight`）。用户 2026-10-17 同意必要时画面里可以出现少量弯曲的手臂；如果游戏里看起来像"捏着枪"，再改成手掌 + 前臂两段。
- 检查：每帧算左臂方块在画面上盖住枪的面积，超过枪画面面积 25% 的帧报出来；右手前臂的方块不能穿过枪（结果见第 7 节）。

### 2.7 瞄准时换弹 `reload_tactical_ads` / `reload_empty_ads`（2026-10-17）

- 触发：瞄准时（`NativeGunAds#bodyProgress` > 0.5，服务器从 `SkeletonPackets.Aim` 知道）按换弹，服务器放 `<换弹片段>_ads`（枪有这个片段时）；不瞄准、或枪没有 ADS 片段，照旧放腰射片段。
- 瞄准不断：ADS 片段不挡瞄准（`NativeGunAds`），按住右键就一直在 ADS（FOV、准星位置都保持）；中途松开右键，枪按普通的瞄准退出回到腰射位，片段照放。瞄准时按换弹也不再先挡 3 刻瞄准。
- 节拍、长度、声音、子弹入枪时刻和腰射片段完全一样（第 2.2、2.3 节），服务端时间不变。
- 画面（和用户说的一样：手在下面操作，不需要看见）：
  - 眼睛一直看目标：枪只往下沉一点、往右侧倾约 10°，准星离开中心约 9% 屏高；
  - 弹匣、左手全程在画面外，靠枪的小动作交代过程：按卡笋一顿、旧弹匣掉、新弹匣碰到弹匣井被顶一下、掌拍到底，空仓时拇指放套筒一跳；
  - 插好后枪直接回到准星上：战术 0.9–1.16 s、空仓 1.04–1.3 s，比腰射早；之后片段剩下的时间枪停在瞄准位（还不能开枪，服务端换弹时间没到）。
- 第三人称：枪留在眼睛下方约 4 px、前方 7 px（view 坐标系，跟着视线；向上最多跟 32°、向下最多 25°，再往下枪会碰到脸），往下沉一点、侧倾着换；弹匣还是从左前腰的弹匣包拿。动作在第一人称回到准星的时刻结束（战术 1.16 s、空仓 1.3 s），淡出 0.2 s 回到瞄准姿势。
- 限制：第三人称的起止位只是接近瞄准姿势（瞄准姿势是程序算的，`GunStance#inReach`，手臂几乎伸直），靠动作的淡入 0.12 s / 淡出 0.2 s 过渡；双手在 view 坐标系里只有贴近脸、几乎不侧倾的位置在各个视线角度下都够得到。

### 2.8 取下弹匣 `unload` / `unload_empty`（2026-10-20）

- 触发：弹匣系统里没有更满的弹匣、枪里的弹匣没装满时按换弹键（`docs/native_guns/magazine_system_v1.md` 3.1）。枪里一发都没有（空仓挂机）时放 `unload_empty`，滑套保持在后；否则放 `unload`。
- 1.3 s，节拍（`tools/author-p9-01-v3-native-animations.mjs` 的 `UNLOAD`）：
  - 0–0.3 s 枪抬起、像检视弹匣那样转向左手（`MAG_CHECK` 姿势），左手从下方进来托到弹匣底；
  - 0.35 s 拇指按卡笋（`p9_01_magazine_release`），0.38 s 弹匣顺着弹匣井往下滑，0.39 s `p9_01_magazine_out`，0.52 s 离开枪；
  - 0.55–0.85 s 左手拿着弹匣往左下出画面；
  - 0.62–1.0 s 枪收到下方出画面（`p9_01_put_away` 在 0.62 s）；1.05 s 服务器把弹匣交到手上，之后换成手里的弹匣。

### 2.11 手调关键帧的战术换弹（2026-10-22）

起因：用户看 BR-51 和 P9 重制版时说动作「还是有点僵硬」，B 站做 TACZ 枪包的评论说缺缓冲（慢-快-慢、冲过一点再回来），弹匣没跟着手。按评论里的动画原则做，没有照抄别的模组的东西。旧片段量出来的问题：

- 枪的路径是同一种加速曲线，举到位时急停：0.30 s 前后 266°/s 直接停住，回位 1.30–1.35 s 也一样；
- 左手 0.20–0.30 s、0.85–0.90 s 停死，0.40 s 前后一下转 1367°/s（弹匣从屏幕外"跳"到手上）；
- 每段节奏一样，位置都是直线插值；
- 弹匣自己走一条弧线，手只是追着它。

现在的做法：

- **手调的通道**：`handling`（旋转、位置）、`lefthand`（旋转、位置）、`camera`（旋转）是 `src/main/blockbench/p9_01_v3_native.bbmodel` 里 `reload_tactical` 的贝塞尔关键帧，每个通道 13–21 个键，在 Blockbench 里可以直接改。`lefthand` 的键是相对片段的 `lefthand_pos` 预转（[0, 90, 0]）的局部值。
- **推算的通道**（`tools/author-p9-01-v3-native-animations.mjs` 的 `reloadKeyed`，从手调键算出来）：
  - 新弹匣（`mag_out`）对准之前一直长在左手上（`magOnHand`，`onMag` 的反解），所以弹匣从包里拿出来到弹匣井下面都跟着手；
  - 0.56–0.62 s 左手从手调键过渡到弹匣井约束，0.62–0.92 s 插入、掌心离开、拍到底照旧按弹匣井算（`seatDepth` / `slapGap`），0.92–0.98 s 再过渡回手调键，1.08–1.18 s 落到移动中的枪的握把上，之后跟枪；
  - 旧弹匣下落（g = 520）、`magazine` / `reload_magazine` 显示、`follower`、右手握把滑移（滑移量按枪的偏航算：偏航 / 40°）、四个声音。
  - 所以在 Blockbench 里预览时，左手在 0.56–1.18 s 是手调键的近似值（键是按约束算好放上去的），游戏里用的是推算的结果。
- **烘焙**：`tools/bb-keyframes.mjs` 按 Blockbench 5.2 自己的算法求值（`BoneAnimator#interpolate` + `Keyframe#getBezierLerp`：三次贝塞尔取 201 个点，找 x 最近的两点再插值），和 Blockbench 的 `interpolate()` 在 8 个时刻、5 个通道上逐位一致（差 0）。运行时仍是 60 Hz 线性键（GeckoLib），游戏代码没改。

  - `action()`：拿着枪、枪的片段是 `reload*` / `inspect*`、片段没放完，且有 `gun/<枪>_<片段>` 动作时，返回它（开始时间 = 片段实例开始时刻，速度 1）；

  - 动作比片段短时（ADS 换弹），到动作长度就停，淡出到瞄准；`_ads` 片段不算"在做动作"（不强制举枪、手不跟片段的锚点）。
