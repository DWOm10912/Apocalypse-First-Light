## 规则（用户原文的条目）

1. 所有开发任务继续维护相关项目文档，明确已完成、待验证和已验收状态。
2. 只有影响其他模块的接口、架构、数据格式、存档、网络协议、世界生成、共享渲染或关键玩法规则变更，才主动通知受影响的 Claude 会话。
3. 普通模型、贴图、本地化、局部配置、单模块内部修复，不需要逐项发送通知。
4. 判断通知必要性时看实际影响范围，不按文件扩展名判断。资源 ID、骨骼名、结构锚点和配置语义发生变化时，仍属于需要通知的变更。
5. 通知只发送给实际受影响的会话，不要求每次向所有 Claude 广播。
6. 通知必须说明：
   - 修改了什么；
   - 影响哪些模块；
   - 当前 Git 分支与 Commit；
   - 是否已合并 Main；
   - 对方需要采取什么行动。
7. 发现跨模块阻塞或重大冲突时，立即通知，不要等整轮开发完成。
8. 正式合并 Main 后，向需要同步新基线的会话发送简短通知。
9. 技术细节允许 Claude 之间自行协调；重大玩法取舍、破坏性存档变更、大范围重构及正式发布仍由用户批准。
10. 跨会话通知不代替 Git 同步、编译、实机验收和正式文档。
