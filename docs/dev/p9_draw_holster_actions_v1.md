## 1. 改之前怎么掏枪

- 拿枪时 `client/skeleton/SkeletonGunStance` 接管两只手，动作系统完全不启动（`PlayerSkeleton.solve` 里 `gun` 为真时 `action = null`）。
- 掏枪、收枪是程序算的：枪从挂点（`CarriedWeaponsLayer.thighFrame`）沿“挂点 → 中间点 → 持枪姿势”三点路径走（`GunStance.path`），两只手什么时候上枪由 `GunStance.draw` / `putAway` 的固定比例决定。
- 时长取枪自己的片段：P9 `draw` 0.5 s、`put_away` 0.5 s。服务器在 `draw` 片段期间锁住这把枪（`NativeGunActions.operation`），掏完才能开火。
- 枪套里的 P9 画成第三人称手持大小（物品模型 `thirdperson_righthand` 0.49467），是骨架手上真实大小（`GunStance.Carried#scale` 0.261）的 **1.895 倍**；枪套外壳按这个大小做的（用户 2026-10-15 PASS）。程序路径在路上把枪从大缩到小。2026-10-17 起手上也画成这个大小（[p9_stance_loops_v1.md](p9_stance_loops_v1.md) 第 1 节），不再缩。
- 没有动作文件的枪（现在是 BR51）照旧走这条程序路径。

## 2. 枪怎么接进动作系统

### 2.1 枪是动作的道具

- 道具文件 `player_props/p9_01.json` 多一个字段 `"gun": "p9_01"`（枪的 id path）：
  - 这个道具就是手上（或正在收回去）的那把枪，由枪自己的渲染器画（片段照常播放，`still` 骨骼照旧停住），不按物品模型画；
  - 道具的坐标：枪的 GeckoLib 原始坐标（方块）绕 x 转半圈，和物品道具一样（`PlayerProps.Prop#local`）；
  - `scale` 等于枪在手上的大小 `GunStance.Carried#scale × carryScale`（P9 0.49467，和枪套里一样大；2026-10-17 放大前是 0.261）；
  - 点：`grip_r`、`grip_l`（枪的 `right_hand_anchor`、`left_hand_anchor` 在 `static_idle` 第 0 秒的位置）、`muzzle`。
- 这个文件由 `./gradlew gunPropExport --args="p9_01"` 从枪的模型生成（`src/test/java/.../skeleton/GunPropExport.java`），不手写、不从插件导出；`--args="--check p9_01"` 只核对不写。数值来源：
  - 点和握把：`GeoAnchorSampler` 读 `geo/p9_01_v3_native.geo.json` 和动画的 `static_idle`（2026-10-17 前是 v2；骨骼和动画与 v2 相同）；
  - 包围盒：枪的 Vextris 网格 `meshes/p9_01_v3_native.aflmesh.json`（只算画出来的骨骼，跳过 `MaintenanceGunRendering` 不画的那些；2026-10-17 换成 v3 网格后重新生成过）；
  - 枪套预览（`carry`，第 2.3 节）：枪套公式 + 物品模型的 `thirdperson_righthand` 大小。
- 拿枪时动作系统只放枪的动作（`gun/…`），别的动作照旧不启动；不拿枪时枪的动作不放（`PlayerSkeleton`）。

### 2.2 握把：手锁在枪上

- 道具文件的 `grips` 表：`grip_r`、`grip_l` 各一个手的坐标系（锚点在 `static_idle` 第 0 秒的位置 `pos` 和朝向 `quat`，加 P9 的握法角度 `grip`，就是 `Kind.PISTOL.gripRight` / `gripLeft`）。
  - 现在（2026-10-17 第三轮，等腰式）：右手 (−5, 15, −10)，左手 (−35, 15, 30)。点 `grip_r`、`grip_l` 是锚点往下移以后的位置（`GunStance.Carried#handDrop` 1.6 px、`#supportDrop` 2 px，方块手的顶才在套筒下面）。
  - 之前：正握版右手 (0, 0, 0)（`Grip.NONE`），左手 (−25, 0, 15)；再之前是枪械重做第 1 轮加的右手 (−30, −10, −30)，手相对枪管歪 38°，看起来像从侧面抓着枪。
  - 左手仍是 (−25, 0, 15)。
  - 道具文件由 `./gradlew gunPropExport` 从 `Kind` 生成。
- 手的目标指向有 `grips` 的点时（`prop:grip_r`、`prop:p9_01:grip_l`），手**整个锁在枪上**（位置和朝向都跟枪），算法和 `GunStance.handTarget` 一样（`ActionPose.gripTarget`）；所以作者只摆枪，手自己跟着，和持枪姿势交接时手不会拧一下。
- 没有 `grips` 的点照旧：手掌放在点上，朝向跟前臂。
- 镜像时（左手玩家）`grips` 退回点的写法。枪的动作从不镜像（4.8），这只是让规则完整。

### 2.3 `carry` 坐标系：枪在枪套里

- 道具关键帧的坐标系 `carry`：枪在它的挂点上，**和身上的枪套层画的完全一样**（手枪：右大腿枪套，`CarriedWeaponsLayer.thighFrame`；长枪：背上），**连大小一起**（P9 现在 1 倍：手上和枪套里一样大；放大前 1.895 倍）。`pos` / `rot` 是在这个位置上再偏一点（P9 的动作里都是 0）。
- 运行时由 `SkeletonGunStance` 把这一帧的实际挂点交给动作（`ActionPose.Moment#carry`，`SkeletonGunStance.carryPlacement`）。
- 两个关键帧之间位置、转角之外**大小也插值**（绕关键帧的点缩放）：手上和枪套里大小不同的枪，拔出来的路上会变大小。P9 放大以后两边都是 1 倍，不再变。
- 没有实际挂点时（插件、离线检查）用道具文件里的 `carry` 预览值：`{"bone": "thigh_r", "pos", "quat", "scale"}`，P9 是 `pos` (−5.162, 15.374, 2.131)、`scale` 1.0（放大前 1.895287；`ActionPose.carryPreview`）。开发环境里第一次用到时，如果实际挂点和预览值差超过 0.05 px（包围盒 8 个角），日志里写一条警告（`SkeletonGunStance.checkCarry`）。

### 2.4 什么时候放哪个动作

`SkeletonActions` 里的“枪”来源排在最前面（`SkeletonGunStance.action`）：
- 正在收枪（收回挂点的“残影”）：`gun/<id>_holster`，时间从残影开始算；
- 正在掏枪（`SkeletonGunStance` 的掏枪时间窗）：`gun/<id>_draw`，时间从手空出来（`drawBegin`）算；
- 播放速度 = 枪片段的长度 ÷ 实际时间窗：收枪被后面的掏枪截短时，收枪和那次掏枪都加快播完，动作总在窗口里放完；
- 不镜像；
- 动作文件不存在的枪（BR51）照旧走程序路径。

### 2.5 交接：动作和持枪姿势之间

`w` = 动作的显示权重（`ActionPose.weight`：淡入、淡出）。
- 枪：`持枪姿势` 和 `动作里的枪` 之间按 `w` 混合（位置、转角、大小，`GunStance.blend`）。
- 手：持枪姿势给的目标、权重、肘向和动作给的（满权重算）按 `w` 混合（`SkeletonGunStance.Acted#mix`）；肩的前送和左手的滑动乘 `1 − w`。
- 掏枪：淡入 0（第一帧枪就在枪套里），淡出 0.15 s，淡出时混进**当时的**持枪姿势（待机、举枪、冲刺低位、瞄准都行）。动作最后一帧是待机的位置（2026-10-17 起，见下）。
- 收枪：淡入 0.12 s，从当时的持枪姿势混进动作；最后在 `carry` 上，残影结束后由枪套层接着画；右手在 0.4–0.5 s 放回垂手。
- **2026-10-17 起平时的姿势是待机循环**（[p9_stance_loops_v1.md](p9_stance_loops_v1.md)）。第四轮起 P9 的待机是第三人称胸前预备（`chest` 坐标系，不跟视线）。
  - 掏枪的最后一帧、收枪的开头就是待机的位置：`chest` 坐标系，握把 (−1.3, 6.6, −7.4)，枪口朝前、向下 23°、向左 6°，左右肘向和待机一样。
  - 所以淡出、淡入时枪不再从别处移过去。
  - 第三轮的 `view` 坐标系结尾、`view_pitch` [−50, 20]、侧身（`chest_twist`）都去掉了。
- 掏枪途中又切走一把枪：收枪动作从持枪姿势淡入，而不是从掏到一半的样子开始，可能跳一下（改之前的程序路径也一样）。

### 2.6 长度

动作按枪片段的长度做：P9 掏枪 0.5 s、收枪 0.5 s，和服务器锁枪的时间一致。要加长就得一起改片段长度（影响能开火的时刻），这一版不改。

### 3.3 为什么胸口要下沉、转肩

方块人的手臂比腿短：垂手时手掌在静止模型 y 10.5，枪套里的握把在 y 14.9，伸直手臂还差约 1.2 px（肩可以往目标送 1.5 px，已经算进去了）。只转肩（绕竖轴）几乎没用，必须让右肩下沉、往后。用 (8, 18, −10) 时手掌离握把 0.21 px（俯仰 20° 时，ActionCheck 的场景）。改成正握以后用 (8, 18, −14)：蹲着时手掌离握把 0.30 px。

代价：骨架让眼睛保持在镜头下面（`HumanoidPoser` 的 `eyeTarget`），胸口一歪，整个身体（连脚）往左挪约 1.3 px、往后约 0.9 px，0.1 s 内挪过去再挪回来。第三人称可能看得出脚滑了一下，要游戏里看。更大的下沉手更贴，但身体挪得更多；(12, 10, −14) 手完全贴上、身体挪 1.6 px。

### 4.2 已知的不完美

- **手碰到枪套里的枪时，手会陷进大腿侧面**最多约 1.3 px：枪套离腿只有 1.26 px，手的方块中心就在握把上。持枪姿势的双手预备本身也有前臂角陷进肚子约 1.2 px，程度相当。
- ActionCheck 的“前臂和手中线离胸口方块 ≥ 2 px”这条在拔出途中（0.16–0.28 s，最小 1.65 px）和最后的双手预备（0.3–0.4 px，持枪姿势本身）达不到，所以 ActionCheck 的场景挑在各段到位的时刻；更细的分上下半身检查是通过的。
- 离线检查都是站着不动的；走路、跑步时掏枪只有游戏里能看。
- 左手搭上、松开的途中会擦到胸口：掏枪 0.4 s 左前臂离胸口 0.75 px（改之前是 0.29 px），收枪 0.04–0.08 s 约 1.5 px。左手是从垂手直线插值到握把的。
- `GunStance` 代码驱动的举枪、瞄准（ADS）右腕：第三轮平视 39–41°（正握版 54–58°，斜握时 17–26°）。这部分之后由插件做的瞄准、开火动作替换，这一版先这样（[p9_stance_loops_v1.md](p9_stance_loops_v1.md) 第 7 节）。
