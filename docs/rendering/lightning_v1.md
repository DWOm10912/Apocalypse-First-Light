# 闪电 V1：写实闪电（2026-10-18）

**状态**：已实现，编译通过，GameTest 和开发版探针测过（见第 6 节）；**用户 2026-10-18 实机 PASS**。

声音：用户之后自己补。现在还是原版的雷声和炸裂声，只是改成按距离延迟。

## 1. 为什么改

原版闪电是一根粗直线加几根短叉，每次重闪都换一个形状（`seed` 每闪一次就变），雷声和闪光同时到。这些在雷雨天视频里都不像真的。

用户要求：
- 换成现实里的闪电；
- 被雷劈中就是死（"现实中被雷劈了也不可能活下来吧"）。

## 2. 参考的现实特征

概念图和模拟动画在 `design/rendering/lightning/`：
- `sim-lightning.mjs`：离线模拟器，用的是和游戏同一套通道算法；
- `concept_1_shapes.png`、`concept_2_first_stroke.png`、`concept_3_timeline.png`；
- `lightning_sim.mp4`、`lightning_sim_slow4x.mp4`。

| 特征 | 现实数据 | V1 怎么用 |
|---|---|---|
| 通道折线 | 先导一段段直线下行，单段约 N(20 m, 10 m)，偏离方向约 N(16°, 11.5°)，方位随机 | 每段长 = 高度 / 88 左右（对数正态），偏 \|N(16°, 11.5°)\|，大方向缓慢漂移、始终向下；每段里再有 3 个小抖动 |
| 分叉 | 梯级先导下行时分叉，上部多；多数分叉在空中断掉 | 主通道分叉概率随高度平方增大；分叉更细更暗、末端变细；约四成闪电有一根分叉也落地 |
| 多次回击 | 约 80% 负地闪有后续回击，间隔 35–60 ms（多通道 90–200 ms），一次闪电平均约 0.37 s | 共 2–5 次回击，间隔 35–120 ms |
| 后续回击走老通道 | 箭式先导沿已电离的通道下来，基本不分叉，比第一次弱 | 后续回击只亮主通道，亮度 0.4–0.8 |
| 回击之间变暗 | 两次回击之间可见亮度基本降下去 | 每次回击满亮一帧，保持一半亮度，再按 12 ms 衰减（分叉 10 ms） |
| 持续电流 | 部分回击后持续发光 30–170 ms | 每次后续回击有 1/4 概率持续发光 80–180 ms |
| 雷声 | 声速约 343 m/s，约 3 s/km | 雷声从通道离镜头最近的点出发，炸裂声从落点出发，各按距离 / 343 m/s 延迟 |

- arXiv 1004.3203：闪电通道的分形建模；
- AMS 词汇表 "Ground discharge"；

## 3. 现在的行为

### 3.1 服务器（`world/LightningStrikes.java`，`mixin/LightningBoltLifeMixin.java`）

**雷击伤 V1（[lightning_injury_v1_plan.md](../gameplay/lightning_injury_v1_plan.md)，D 分支 `feature/lightning-injury`，未合并、未实机）改了落点和伤害，下面两条是那个分支上的行为；master 上仍是"原版落点、1000 伤害必死、着火 8 s"。**

- **落点**：避雷针仍最优先；其余改成"先劈最高的东西"（`mixin/LightningTargetServerLevelMixin`）：活物只有头顶不低于周围 3 格内最高的方块时才被直击，否则雷劈到那片最高的方块上。原版的点火、铜块除锈照旧。
- **伤害**：原版"5 点伤害 + 着火、每闪一次再劈一次"对所有活物取消，换成 `health/LightningInjury` 每道闪电统一分类一次（直击、侧闪、地电流，室内和关好门的 T15 驾驶室挡住）：玩家按方式掷死亡、扣生命、昏迷、双腿麻痹、鼓膜穿孔、雷击后遗，其他活物只扣生命（直击 1000）。被劈的人不着火，被直击或侧闪的人身边 2 s 内的火会被扑灭（第一轮实机后改，2026-10-21）。
  - 创造和旁观模式不受伤。
  - 非活物（掉落物、车）还是原版的 5 点和着火。
  - 原版生物被劈后的变身（猪 → 僵尸猪灵等）不再发生。AFL 没有原版生物，所以不受影响。
- **实体寿命**：原版最早 5 tick 就移除闪电实体，这会把客户端的闪光截断。现在服务器至少保留 `LightningStrikes.MIN_TICKS` = 20 tick（1 s）；客户端放完闪光后自己先移除。

### 3.2 客户端（`client/lightning/`，`mixin/client/LightningBoltClientMixin.java`）

- **`LightningBoltClientMixin`**：
  - 客户端闪电实体不再走原版 tick，改走 `AflLightning.clientTick`。
  - 剔除框盖住整条通道，所以落点被山挡住时，Embeddium 也不会把闪电剔掉。
- **`LightningFlash` 和 `LightningChannel`**：
  - 形状由实体 UUID 决定，所以多人游戏里每个玩家看到的是同一道闪电。
  - 通道顶就是出云的位置：
    - 不开光影：高出落点 150–230 格（`MIN_HEIGHT` / `MAX_HEIGHT`，原版云在 y = 192）；
    - 开光影（2026-10-18，用户同意 Aureveil A 的提议）：通道顶在世界 y = 768 + 0–40（`PACK_CLOUD_Y`，即 Aureveil 的 `CLOUD_ALTITUDE` 默认值），通道高 = 通道顶 − 落点 y，至少 60 格（`PACK_MIN_HEIGHT`）；
    - 闪电产生时按当时开不开光影决定一次；分段长度和水平偏移照旧按高度缩放。
    - 用户在 Aureveil 里改了云高（可调 256–1536）时，AFL 不知道，仍按 768。
  - 通道顶在落点旁边水平偏开最多约 0.25 × 高度，主通道的末端正好是落点。
- **时间线**：
  - 闪电实体出现后，先有 30 ms 很暗的梯级先导从云里往下走；
  - 然后是第一次回击，主通道和全部分叉一起亮；
  - 之后是后续回击（见第 2 节）；
  - 最后一次回击熄灭后，客户端移除实体。
- **`LightningRenderer`**（替换原版闪电渲染器）：
  - 每条通道画成对着镜头的光带，三层：
    - 白色内芯：0.32 格宽，至少 1.6 px；
    - 蓝紫光晕：2.6 格宽，至少 9 px，亮度 0.42；
    - 很宽的淡雾光：16 格宽，至少 40 px，亮度 0.07，表示雨里的散射。
  - 通道顶有一片横向椭圆的云底光：半径 0.38 × 高度，亮度 0.28 × 主通道亮度。
  - 叠加混合，不写深度。原版的距离限制（64 × 视距系数）去掉了，客户端知道的闪电都画。
- **天空闪**：某个 tick 里回击亮度超过 0.3，就设 `skyFlashTime = 2`。这是原版那种全世界变亮的效果，所以会一下一下地闪。尊重原版"隐藏闪电闪烁"选项。
- **照地**：亮着的闪电往 `DynamicLights` 加一个光源。
  - 光源位置：主通道 0.3 × 高度处；朝下的整个下半球，不切角。
  - 亮度：射程 280 格，20 格内满亮 15 级，0.7 射程处 6 级；颜色偏冷白，乘以当前亮度。
  - 影子来自动态光源的方块网格（镜头周围 128 格内）。
  - **只在不开光影时加**，由 AFL 自己逐像素画。
  - 开光影时不加（Aureveil A 建议，用户 2026-10-18 同意）。理由：
    - Aureveil 本来就用闪电实体位置（`lightningBoltPosition`）照地面、天空和云，再加一个会照两次；
    - 这个光源要让整屏每个像素都走一遍阴影步进，alpha.57 下闪光期间帧时间 6.3 → 8.9 ms；
    - 它还会混进按车灯锥形做的光柱和阴影。
  - 320 格外的闪电不加光源。打开"隐藏闪电闪烁"时也不加。
- **雷声**：用 `SoundManager.playDelayed` 按距离延迟（见第 2 节）。声音还是原版的 `LIGHTNING_BOLT_THUNDER`（音量 10000，全图听得到）和 `LIGHTNING_BOLT_IMPACT`。

### 3.3 光影

- **开光影时**：同样的四边形走光影包的闪电程序。AFL 的渲染类型外面包一层 Oculus 的 `LightningRenderStateShard`，用 `InnerWrappedRenderType` 反射构造。
  - 构造失败就退回 Oculus 的 `IRIS_LIGHTNING`；再失败，就用 AFL 自己的类型。
  - 光影包里的 `lightningBoltPosition` 之类的统一变量照常能拿到闪电实体。
- **顶点格式**：`POSITION_COLOR`，Oculus 不会换这个格式；顶点通过 `VertexConsumer` 一个个写入，没有按字节写。
- **回击亮度贴图**（`LightningShaderData`，2026-10-18，接口由 Aureveil A 定，Aureveil alpha.61 起读取）：
  - 用途：让光影的天空和地面闪光与 AFL 的回击同步。看不见的闪电（视野外、被山挡住）也写进去。
  - 名字 `apocalypse_firstlight:dynamic/afl_lightning`，注册在 TextureManager（客户端初始化时就注册），光影包当作 custom texture 读取。
  - 格式：RGBA32F，4 × 5，nearest。只在开光影时，每帧 `AFTER_SKY` 写一次（阴影 pass 跳过）。
  - 位置都相对 `Camera#getPosition()`（含 partial tick），单位米。
  - 第 0 行 texel 0 = (闪电数 n, 0, 0, 4243)。4243 是检查值；没装 AFL 时光影读不到它，会退回自己的随机闪光。
  - 第 1–4 行：每道闪电一行，最亮的在前，最多 4 道。
    - texel 0 = (落点 xyz, 通道高度)；
    - texel 1 = (k_main, k_branch, 距第一次回击的秒数（先导时为负）, 先导时 1 否则 0)。k 就是渲染器这一帧乘在白芯上的亮度；先导时两个都是 0.08；
    - texel 2 = (通道顶 xyz, 0)；
    - texel 3 = 0（预留）。
  - 没有闪电时 n = 0，只在闪电停下后上传一次。

## 4. 已知限制

- 客户端只看得到服务器同步给它的闪电：实体追踪范围是 min(16 区块, (视距 − 1) 区块)。视距 10 时 220 m 外的闪电看不到，也听不到。远处闪电的同步放到 V2。
- 车：雷击伤 V1 分支里，T15 驾驶室两扇门都关着时挡住雷击（只读车门状态）；master 上车里的人仍不受保护。
- 金属吸引雷、劈树都是 V2。"先劈最高的东西"在雷击伤 V1 分支里。
- 雷声还是原版录音，用户会补。
- 不开光影时，闪光期间帧时间约 4.5 → 4.7 ms（开发版探针，测试机）。开 Aureveil alpha.57 时测到 6.3 → 8.9 ms，那次闪电光源还在光影的灯表里；拿掉之后没有重测。
- Aureveil alpha.59 及之前：AFL 的光带被光影当成普通实体表面打光。用户录屏里画面变成白天，落点周围的树发绿，闪电通道被云盖住。
- Aureveil alpha.60（2026-10-18，等用户实机测试）的处理：
  - 只画白芯：rgb 三个分量都 > 0.95 就当白芯，亮度按 alpha；
  - 光晕、雾光、云底光都丢弃，光晕改由光影的泛光给；
  - 闪电像素不被云盖住；
  - 光影自己的天空和地面闪光是随机回击，和 AFL 的回击不同步。
- **和 Aureveil 的约定**：白芯 rgb 保持 (1, 1, 1)，光晕、雾光、云底光保持偏蓝，明暗只放在 alpha 里。改颜色会让 Aureveil 认错（`LightningRenderer` 注释里也写了）。
- 开光影时通道顶在 y ≈ 768–808，离镜头可能有七八百米，超出原版远裁剪面（约 视距区块 × 64 m）。Aureveil alpha.61 把闪电程序里超过 0.98 × 远裁剪面的顶点沿视线拉近、屏幕位置不变，所以在 Aureveil 里不会被切掉。其他光影包可能会切掉通道上段。
- 回击亮度贴图从 Aureveil alpha.61 起读取：天空和地面闪光跟着 AFL 的回击亮度，通道照明用落点到通道顶的线段；读不到校验值时退回光影自己的随机闪光。alpha.61 只过了 Aureveil 的合成探针（按接口手写的贴图），和 AFL 联合实机还没测。
