## 1. 目标

第一人称下低头能看到自己的身体：胸口、腰、腿、脚，以及穿在身上的东西：
- 胸挂、背包肩带；
- 枪背带；
- 大腿上的枪套和里面的手枪；
- 衣服和裤子（皮肤）。

别的玩家看到的、F5 第三人称、物品栏里的人物预览，都和以前一样。

## 2. 以前为什么看不见（量过）

- **原版：** `LevelRenderer.renderLevel` 的实体循环里有一条判断：实体是摄像机实体、摄像机不是第三人称（`camera.isDetached()` 为假）、人没在睡觉，就跳过不画。整个 `LevelRenderer` 只有这一处调用 `isDetached`（1.20.1 / Forge 47.4.22 源码第 1201 行）。
- **Oculus 阴影：** 阴影 pass 不走上面那条判断。`ShadowRenderer.renderEntities` 遍历全部实体、不排除自己（光影包关了实体阴影时，用 `renderPlayerEntity` 单独画自己），都经过 `LevelRenderer.renderEntity`。所以开光影时，第一人称下地上本来就有自己完整的影子（头和手臂都在）。
- **Embeddium：** 不接管这个实体循环。
- 开发环境的依赖里，没有别的模组的 mixin 碰 `Camera.isDetached`、`RenderLayer.render`、`HumanoidArmorLayer.setPartVisibility` 这几处（2026-10-15 查过）。

## 3. 怎么画（已实现）

### 3.1 让自己进入实体循环

- `mixin/client/LevelRendererFirstPersonBodyMixin`：`@Redirect` 上面那处 `isDetached`，改成 `isDetached() || FirstPersonBody.shown(camera)`。第一人称、这一帧该画身体（见 4.3）时，自己就像别的实体一样在正常的实体阶段画出来。
- 走的是原版实体渲染那条路：光影下用实体程序（`gbuffers_entities`），光照、PBR、雾都和别的实体一致，不在某个渲染阶段手动补画。

### 3.2 只在“世界里的自己”上改

- 同一个 mixin 在 `LevelRenderer.renderEntity` 的 HEAD / RETURN 调 `FirstPersonBody.begin(entity)` / `end()`：只有画摄像机实体、而且 `shown` 为真的那一次打开标记。标记分两种：
  - `AflShaderCompat.activeShadowPass()` 为真：阴影 pass，只后仰，不藏东西；
  - 否则：主画面，后仰并且藏东西。
- 物品栏人物预览、维护台、F5、别的玩家都不经过这个标记，不受影响。
- 每帧开始时（`RenderTickEvent`）标记清零，防止某次绘制被取消后标记留到下一帧。

### 3.3 显示什么、藏什么（主画面）

| 部分 | 第一人称 | 怎么做 |
|---|---|---|
| 头、帽子层 | 藏 | `RenderPlayerEvent.Pre` 把模型部件设为不可见，`Post` 还原 |
| 两只手臂、袖子层、护甲的手臂部分、手上拿的东西 | 看手上（骨骼关着见 3.4，开着见 3.5） | 骨骼关着：空手或普通物品画；拿枪、撬棍、倒油的油桶，或正在使用物品藏。骨骼开着：两手都空、收枪、P9 预备姿势低头时画，其余藏 |
| 头盔 | 藏 | `HumanoidArmorLayerFirstPersonBodyMixin`：`setPartVisibility` 末尾把头、帽子（手臂藏时连两臂）设为不可见 |
| 头部物品、披风、鞘翅、身上插的箭 / 蜂刺、肩上的鹦鹉、三叉戟旋转特效、deadmau5 耳朵 | 藏 | `LivingEntityRendererFirstPersonBodyMixin`：`@Redirect` 层循环里的 `RenderLayer.render`，这几类层跳过（手上物品层只在手臂藏时跳过） |
| Curios 头部网格（耳罩） | 藏 | `ClientEquipmentSlots.WornMeshRenderer`：所在部件不可见就不画 |
| 身上着火的火焰（`EntityFlames`） | 藏 | `EntityRenderDispatcherFireMixin` 里判断；第一人称已有屏幕上的火焰效果 |
| 躯干、腿（含外套层、裤子层）、胸部和腿部护甲、鞋 | 画 | |
| 胸挂、背包、枪背带、枪套和手枪、背上的长枪（`CarriedWeaponsLayer`） | 画（背上的枪：用户决定照画） | 跟着身体动；背上的枪在身后，低头看不到 |
| 脚下的圆形影子（不开光影时） | 照旧 | |

- 别的模组的 Curios 头部渲染器不一定看部件可见性，这个管不了，记为已知限制。

### 3.4 手（第二轮，用户 2026-10-15 确认）

`FirstPersonBody#bodyArms` 按手上的东西决定用哪双手。这一节是骨骼关着（`[skeleton] enabled = false`）时的规则；骨骼打开（2026-10-16 起默认）时见 3.5。

| 手上 | 身体的手臂 | 第一人称的手 |
|---|---|---|
| 空手、方块、普通物品 | 画，垂在身体两侧，东西拿在身体的手里（原版 `ItemInHandLayer`） | 低头 25° 开始往下滑，45° 滑出画面（`ItemInHandRendererFirstPersonBodyMixin`，最多 0.7 格，平滑曲线。在 `renderHandsWithItems` 里每次调用 `renderArmWithItem` 的前后压栈并下移；不挂在 `renderArmWithItem` 自己的开头和结尾：Oculus 会在开头取消它，出栈就跑不到了） |
| 枪（`NativeGunItem`）、撬棍、倒油的油桶（自己有第一人称手臂） | 藏 | 照旧（它们取消 `RenderHandEvent`，自己画） |
| 正在使用物品：吃喝、拉弓、举盾、温度计；手持已上弦的弩 | 藏 | 照旧（这些动作的手臂会指向视线方向，伸进摄像机） |

- **手臂前摆限制**（`HumanoidModelFirstPersonBodyMixin` → `FirstPersonBody#limitArms`）：原版走路手臂往前摆可达 49°，跑步 57°，低头 16–22° 就会在画面底角露出身体的手，和第一人称的手同时出现。第一人称身体画手臂时，前摆限制在 20°（0.35 rad，真人走路摆臂的幅度），身体手臂要到低头 45.6° 才进画面，正好接上第一人称的手滑完的 45°。
- **挥手：** 低头不到 45° 时第一人称的手还在，身体手臂的挥击也按 20° 限制，只看到第一人称的手挥；45° 以后第一人称的手已经滑走，身体手臂完整挥击，低头挖脚下的方块时由它给反馈。
- 阴影 pass 不限制手臂摆动。

### 3.5 骨骼打开时的手（2026-10-16 起默认）

`FirstPersonBody#bodyArms` 改成 `PlayerSkeleton#firstPersonHands` 或者 `FirstPersonBody#gunOnBody`（3.5.1）。3.4 的手滑出画面（`handDrop`）、手臂前摆限制在骨骼打开时不起作用。

| 手上 | 身体的手臂 | 第一人称的手 |
|---|---|---|
| 两手都空；收枪动作（`gun/p9_01_holster`，身体把枪送回枪套） | 画（骨骼的手） | 原版画手那一遍取消，平视时看不到手 |
| 身体做的动作（`first_person: body`，比如压弹 `gun/p9_01_mag_load`） | 手里的东西滑出画面以后画 | 先 0.15 s 滑出画面，再取消；动作淡出完后 0.15 s 滑回来（3.5.2） |
| P9，在预备姿势上（待机、走路、冲刺），没在做别的 | 低头 45° 起画，枪拿在身体手里，姿势和别人看到的第三人称一样 | 旧视图模型（枪和两只刚性手臂），低头 25° 开始往下滑，45° 滑出画面（3.5.1） |
| P9 在瞄准、开火、换弹、检视、掏枪等（3.5.1 的例外） | 藏 | 旧视图模型，任何俯仰都不滑 |
| 普通物品（弹匣、方块等），没在用（2026-10-20） | 低头 45° 起画，手里拿着它，抬回 42° 以上收起 | 低头 25° 开始往下滑，45° 滑出画面并取消（3.5.3） |
| BR51 和其他枪；撬棍、油桶；正在使用物品 | 藏 | 照旧，任何俯仰都不滑 |

#### 3.5.1 持枪低头交给身体（2026-10-19）

用户（2026-10-19）：持 P9 走路看着怪；第三人称已经有 P9 的跑步和待机姿势，第一人称镜头往下时没交接过去（参考空手的两种安排）。截图里低头看到自己的身体，右下角仍是平视时的旧视图模型。

- **哪些枪**（`SkeletonGunStance#atReady`）：骨骼认得的枪（`GunStance.carried`）里有待机循环 `gun/<枪>_idle` 的，现在只有 P9-01（`gun/p9_01_idle`、`gun/p9_01_sprint`，胸前预备挂在 `chest` 坐标系，不跟视线）。BR51 没有待机循环，骨骼姿势的枪管顺着视线，低头时也在画面中间，不交接；以后做了待机循环的枪自动适用。
- **平视**：完全照旧（旧视图模型、腰射和 ADS 位置、枪自己的第一人称片段）。这是用户的规则：第一人称持枪的手臂不用骨骼 / IK 重摆。
- **俯仰**：和骨骼关着时空手的手一样的数（`FirstPersonBody` 的 `HAND_FROM` 25°、`HAND_TO` 45°、`HAND_DROP` 0.7 格）：
  - 低头 25° 起，视图模型整个（枪和两只手臂）在镜头坐标里往下移，平滑曲线，45° 移完 0.7 格，在画面外；
  - 低头到 45° 的那一帧起，身体画手臂（含袖子层、护甲手臂）和枪，手臂的姿势、枪的位置和第三人称一样；
  - 身体拿着枪以后，抬头回到 42° 以下（`GUN_KEEP` 3°）才放手，免得在 45° 附近来回闪；42–45° 之间视图模型保持在画面外；
  - 平视、抬头不动。
- **不交接**（保持视图模型；已经交给身体的，身体的手臂和枪当帧藏起来，视图模型 0.12 s 升回来，`GUN_BACK`）：
  - 瞄准：ADS 进度（`NativeGunAds#bodyProgress`）超过 0.02，或按着右键；
  - 按着开火键、换弹键；
  - 枪自己的动作片段在播：掏枪、第一次掏枪、开火、换弹、检视（骨骼上次解姿势时看到的 `action` 控制器片段）；
  - 骨骼姿势把枪举着：开枪后 1.5 s（`RAISED_AFTER_SHOT`）、换弹、检视；
  - 掏枪、收枪的过程中，或者刚换了一把枪；
  - 野外改装视角（`FieldAttachmentViewState`）、望远镜、正在使用物品；不在站立 / 蹲下。
  - 这些都结束以后再过 0.25 s（`GUN_FREE`），视图模型才重新往下滑，滑完交给身体。
- **为什么这样分**：第一人称的掏枪、换弹、检视、开火只做在视图模型上，身体在第一人称不播这些动作（动作文件 `first_person: view_model`），交给身体会丢掉动作；瞄准和开火后骨骼会把枪举到眼前，身体的枪会挡在画面中间。
- **两套枪、两套手臂不会同时出现**：身体只在视图模型滑完（45°）那一帧起才画手臂和枪；视图模型要升回来时，身体的手臂和枪先藏。两边按同一帧算一次的结果（`FirstPersonBody#gunHandOver`，每帧第一次用到时算），世界那一遍和画手那一遍一致。代价是 25–45° 之间和例外开始的那 0.12 s 里，视图模型在滑、身体没有手臂，这和骨骼关着时空手一样。
- **视图模型交接后照样画**（在画面外，不取消 `RenderHandEvent`）：开火的枪口闪光、弹道起点、抛壳都取自视图模型画出来的位置（`NativeShotVisualSnapshot`、`NativeGunFx`），取消了第一枪就没有弹道。所以低头、身体拿着枪时开第一枪，弹道从画面下方（滑下去的视图模型的枪口）出来，闪光在画面外，然后视图模型升回来。
- **只在自己第一人称的主画面**：阴影 pass 本来就不画骨骼的枪（`PlayerSkeleton#draw`），手臂照旧画进影子；F5、环绕镜头、别的玩家看到的你都不变（身体姿势本来就按第三人称算，`SkeletonGunStance#hold` 的 `firstPerson` 总是 false）。
- **光影**：视图模型的下移做在枪自己的 `RenderHandEvent` 画法里（`ConfiguredGunFirstPerson`，在复制出来的姿态栈上第一个平移），不压 / 弹原版的姿态栈，不受 Oculus 在 `renderArmWithItem` 开头取消的影响；Oculus 分两遍画手时两遍用同一帧的值。
- **代码**：
  - `client/FirstPersonBody`：`#gunHandOver`（每帧一次：能不能交接、按时间缓动的 `gunFree`、视图模型下移比例、身体是否拿枪）、`#gunDrop`、`#gunOnBody`、`#armsShown`；`#bodyArms` 骨骼打开时加上 `gunOnBody`。
  - `client/skeleton/SkeletonGunStance#atReady`：枪在预备姿势上、没在做别的。
  - `client/skeleton/PlayerSkeleton#draw`：自己第一人称身体的枪改成"手臂显示时就画"（`FirstPersonBody#armsShown`；以前只看 `firstPersonHands`）。
  - `weapon/client/ConfiguredGunFirstPerson`：视图模型下移 `FirstPersonBody#gunDrop`。
- **状态**：用户 2026-10-19 实机 PASS（和地上物品、空枪一起提交）。
- **要进游戏看**：
  1. 低头时身体的枪什么时候进画面。我手算的（P9 胸前预备，握把在胸口坐标前 7.4 px、下 6.6 px，胸口跟着低头前倾 0.3 倍，身体往后让到眼睛对准镜头）：视野 70° 时大约低头 45° 枪口到画面底边，正好接上；这个数很粗。视野调大（比如 90°）时身体的枪更早就在画面里，45° 交接时会在画面下部突然出现。要是明显，就把交接角度调早，或者改成按身体的枪在画面上的位置来交接。
  2. 走路、冲刺（P9 冲刺循环上身左右扭）、蹲下时低头，身体的手臂和枪看着对不对，和第三人称是否一样。
  3. 低头时按右键瞄准、开枪、换弹、检视：视图模型升回来是否自然，0.12 s / 0.25 s 合不合适；低头开第一枪时弹道从画面下方出来是否别扭。
  4. 在 42–45° 来回慢慢转，看会不会闪。
  5. Sundial 开着看一次：手臂的影子、身体的枪有没有拖影。

#### 3.5.2 身体动作的进出：镜头渐变和手的交接（2026-10-20）

用户（2026-10-20，看了压弹录像）："为什么说了这么多次你就是记不住，凡是有第一人称额外动画的，都需要做镜头渐变"。录像里压弹一开始，手里的弹匣模型一下子没了、身体的手一下子出来，镜头不动，弹匣在画面边上；停下时反过来一下子跳回去。

规则（`client/skeleton/FirstPersonActionView`，只管自己的第一人称、骨骼开着、身体画手臂时）：
- **镜头**：动作文件写了 `first_person_pitch`（度，向下为正）时，动作开始就开一个导演镜头请求（`CameraDirector`，id `skeleton_action_look`，优先级 `PRIORITY_BODY_EYE`，游戏时钟）：0.45 s 平滑（smoothstep）把视角压到至少这个俯仰，鼠标还能往下看、往上压不过它；动作停止时 0.45 s 平滑抬回玩家原来看的方向。只转镜头，玩家本身的朝向不变。这段时间自己的身体按镜头的俯仰摆（`PlayerSkeleton#solve`，头、颈、胸跟着低头，身体照旧往后让到眼睛对准镜头），所以不会看进身体里。
- **手**：动作开始时，手里东西的第一人称模型（原版画手那一遍）先往下滑出画面，0.15 s 滑完（`FirstPersonBody#handDrop`，和 3.4 一样下移 0.7 格），之后身体才画手臂和手里的道具（`PlayerSkeleton#firstPersonHands`）。动作停止后，身体的手臂按动作的淡出放下，淡出完了才让第一人称模型 0.15 s 滑回来。两套手不会同时出现。
- 动作开始后很快又停：滑到一半的模型停在那里，等动作淡出完再滑回来。
- 导演镜头的请求在淡出时又被打开（比如停了马上又开始压弹），从当时的权重接着淡入，不会跳回平视（`CameraDirector#open`、`CameraFade#open(now, weight)`，所有镜头请求都这样）。
- 现在用的：`gun/p9_01_mag_load`，`first_person_pitch: 55`（弹匣在眼睛下方约 60–73°，离线算的）。别的身体动作不写这个字段就只做手的交接，不低头。
- 字段名和 D 分支（`feature/survival-health-v1a` 的绷带、酒精）一样，但那边是直接把玩家视角往下拉（`SkeletonActions#lookDown`），合并时要统一成一套。D 分支还有普通物品低头交给身体（`FirstPersonBody#itemHandOver`），合并时要和这里的 `handDrop` 合在一起。
- **状态**：用户 2026-10-20 实机 PASS（压弹的低头和手的交接）。
- 第三轮补充（2026-10-20）：压弹动作以前在身体上根本没播（`PlayerSkeleton#solve` 按 id 把 `gun/` 开头的动作当成持枪动作，手上没枪就丢掉），现在按来源判断（`SkeletonActions#gunAction`）。开始压弹时如果已经低头到身体拿着弹匣（3.5.3），直接由身体的手接着做，不再滑一次。

#### 3.5.3 普通物品低头交给身体（2026-10-20，master）

用户（2026-10-20 截图）："拿着弹匣也没有镜头渐变"：拿着弹匣低头，画面下方是身体，右下角还是平视时的弹匣模型。D 分支的生存与健康 V1a 已经做了同样的规则（`FirstPersonBody#itemHandOver`，用户 2026-10-19 PASS），这里按同样的代码、同样的数补到 master：
- 适用：主手或副手有东西，不是枪、撬棍、倒油的油桶，没在使用物品，也不是装好箭的弩；两手都空和身体动作由骨骼自己的手负责。
- 低头 25° 起第一人称手里的东西往下滑（和 3.4 一样，`HAND_DROP` 0.7 格），45° 滑完，原版画手那一遍取消，身体画手臂，手里的东西由 `ItemInHandLayer` 画在身体手上；抬回 42° 以下（`ITEM_KEEP` 3°）才还回去，免得在边上闪。
- 身体动作的低头镜头开着时，按镜头的俯仰算（3.5.2），所以动作结束、镜头抬回时，弹匣先在身体手里，抬过 42° 后第一人称模型再按俯仰滑回来。
- 和 3.5.2 的滑出取较大的那个（`FirstPersonBody#handDrop`）。
- 合并 D 分支时这段代码和 D 的是同一份，只多了镜头俯仰和 3.5.2 的取大。
- **状态**：用户 2026-10-20 实机 PASS（拿着弹匣低头）。

## 4. 怎么避免穿模

### 4.1 量出来的位置（原版尺寸）

- 玩家模型：缩放 0.9375，1 模型像素 = 0.0586 格，模型顶（脖子）在渲染原点上方 1.407。眼睛离脚 1.62（站）/ 1.27（蹲）。
- 摄像机在实体正中（前后方向），躯干前后各 2 像素，所以原版躯干前沿在眼睛竖直线**前方 0.117 格**。低头时往下看会看到躯干的顶面、甚至在躯干里面。

### 4.2 绕渲染原点后仰（已实现）

`RenderPlayerEvent.Pre` 里在姿态矩阵上乘 `Ry(-身体朝向) · Rx(-后仰) · Ry(身体朝向)`，整个模型绕渲染原点往后仰，让躯干前上角落在眼睛竖直线**后方 0.03 格**。渲染原点站着时在脚底，蹲着时原版把它下移 0.125（`PlayerRenderer.getRenderOffset`）。

角度按姿势算一次（`FirstPersonBody#lean`，用原版站 / 蹲的躯干位置和倾角），不是每帧量模型：`Pre` 事件发生在 `setupAnim` 之前，那时模型里还是上一个被画的玩家的姿态。

`tools/check-first-person-body-geometry.py` 的输出（2026-10-15）：

| 姿势 | 后仰 | 躯干顶面在眼睛下方 | 躯干最高处前沿 | 身体离眼睛最近的角 |
|---|---|---|---|---|
| 站立 | 5.98° | 0.208 格 | 眼睛竖线后 0.030 | 0.315 格（近裁面 0.05 的 6.3 倍） |
| 蹲下 | 6.52° | 0.139 格 | 眼睛竖线后 0.247（蹲姿躯干前倾，最高处是后沿） | 0.328 格（6.6 倍） |

- 外套层大 0.25 像素，站立时前上角在眼睛竖线后 0.017。
- 方案里蹲下写的是 7.3°，那是按“绕脚”算的；实际转轴是下移了 0.125 的渲染原点，力臂更长，算出来是 6.52°。
- 胸挂网格比躯干往前凸，低头时会看到它的上沿在眼睛竖线前面一点（没有量具体数）。
- 走路时腿前后摆，离眼睛 0.75 格以上，不会靠近摄像机。
- 上面这张表是平视时的位置；低头时还有 4.5 的颈部前屈，身体离眼睛只会更远。

### 4.3 什么时候不画身体（`FirstPersonBody#shown`）

- 设置关了；摄像机实体不是自己；
- 旁观模式、隐身、睡觉（原版本来就画睡觉，不加后仰）、正在死亡；
- 姿势不是站立或蹲下（游泳 / 爬行、鞘翅、三叉戟旋转），或者 `isVisuallySwimming` / `isFallFlying` / `isAutoSpinAttack`；
- **摄像机离眼睛太远：** 水平超过 0.3 格，或者上下超过 0.6 格（上下放宽，是因为蹲下时眼睛高度有过渡）。维护台锁定视角、发电机拉绳都会挪摄像机，用这一条统一处理，以后新的锁定视角也自动适用。
- 骑乘照常画（坐姿腿往前）；以后皮卡上车时单独看。

### 4.4 其它

- 原版视角摇晃作用在整个世界上，身体跟着世界一起动。
- 原版站着转头时，身体最多落后头 50° 才跟上；第一人称下表现为“转头时身体没马上转”，保留。

### 4.5 颈部前屈（第二轮，用户 2026-10-15 确认）

真人低头是脖子往前弯，眼睛往前移到胸口前面，看到的是胸口正面，看不到肩膀顶。我们不动摄像机（不影响瞄准和点方块），改成身体往后让：`RenderPlayerEvent.Pre` 里先沿视线的水平方向往后平移 0.13 × sin(低头角)，平视和抬头时不动，正下方看让 0.13 格。主画面和阴影 pass 一起挪。

`tools/check-first-person-body-geometry.py` 第二部分的输出（站姿，屏幕纵坐标 -1 = 底边，+1 = 顶边；第一轮没有前屈时，90° 的躯干顶前沿在 -0.21，肩膀顶面铺满下半屏）：

| 低头 | 躯干顶前沿 | 胸挂翻盖上沿 | 腰带前沿 | 脚尖 |
|---|---|---|---|---|
| 45° | -5.46（画面外） | -1.21（画面外） | -1.55 | -1.39 |
| 60° | -2.98（画面外） | -0.75 | -0.95 | -0.82（被胸挂挡住） |
| 75° | -1.81（画面外） | -0.36 | -0.50 | -0.39（被胸挂挡住） |
| 90° | -1.10（画面外） | +0.01 | -0.12 | -0.01（被胸挂挡住） |

- 肩膀顶面在任何低头角度都不再进画面。
- 穿胸挂时脚被挡住：Minecraft 的脚尖只在身体中线前 0.117 格，胸挂口袋凸到 0.25 格。不穿胸挂时，正下方看能看到脚尖。

身体手臂第一次进画面的低头角（同一脚本）：原地垂着 59.4°；前摆 20°（限制后的上限）45.6°；不限制时前摆 40° 是 30.4°、57° 是 16.0°。

## 5. 光影怎么处理

- **不开光影：** 正常的实体光照，只有脚下的圆影子。
- **Oculus 主画面：** 走实体程序，和别的玩家一样。第一人称的手和枪照旧在手部 pass 里最后画，叠在身体前面。
- **Oculus 阴影 pass：** 头和手臂照旧画进阴影；后仰也画进阴影，和主画面一致，自己身上的阴影才对得上。F5 时两边都不后仰。
- **Sundial / 其它光影包：** 没有在游戏里看过。要看：身体光照是否和别的玩家一致；开着体积云时身体边缘有没有拖影。其它包只要求不出错。

## 9. 已知限制

- 别的模组的 Curios 头部渲染器、别的模组加的层，不一定会被藏（只跳过了原版那几类层）。
- 拿枪、撬棍、油桶，或正在使用物品时，身体没有手臂（第一人称的手另外画）。骨骼打开时，P9 在预备姿势上低头到 45° 起例外（3.5.1）；BR51 和其他枪还是没有。
- 持枪低头交给身体（3.5.1）：交接角度是固定的俯仰，不看视野设置；身体拿着枪时开第一枪，弹道从画面下方出来。
- 穿胸挂时低头看不到脚（4.5）。
- 低头 25–45° 之间、拿着普通物品时，第一人称的手正在滑走；跑动中身体手臂被限制在 20° 前摆，不会和它同时出现，但挥击动作在这个区间只有第一人称的手。
