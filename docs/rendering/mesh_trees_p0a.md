## A. 当前 AFL 和 Vextris 的可用能力（读源码得出）

| 能力 | 在哪 | 对树木的结论 |
|---|---|---|
| Mesh 读取、热重载 | Vextris `MeshLoader`（`.vxmesh.json`，无 Minecraft 依赖，服务端和工具也能读）、`VextrisMeshes`（按资源世代整体替换） | 以后正式树种由 Blender/Blockbench 做成 `.vxmesh.json` 可以直接读；服务端也能读同一文件算格子布局 |
| 不可变网格容器 | Vextris `MeshModel`/`MeshPart`（骨骼分组、CUTOUT/TRANSLUCENT 两层、`Builder` 可在代码里建网格；每部件上限 16384 三角形，每模型 128 部件） | 树干 / 枝 / 叶可按骨骼分组；128 部件上限意味着**不能**一格一个部件，格子分配要 AFL 自己算 |
| 即时绘制 | Vextris `MeshRenderer`（实体 / 方块实体用，每帧提交） | 只适合"正在倒下"的那一棵树，不适合静态森林 |
| 区块网格烘焙 | AFL `AflStaticMeshModel` + `AflMeshChunking`：方块实体静止部件转成区块四边形，经模型数据交给区块构建 | 证明了"Mesh 进区块网格"可行；但它挂在方块实体上，树不该每棵带方块实体 |
| 几何越格上限 | `AflStaticMeshModel.REACH = 1.1` | 依据见下表，树沿用 |
| Terrain Smooth 的树判定 | `TerrainSmooth.cell()`：`minecraft:logs` → TREE，`minecraft:leaves` → LEAF | 新树方块进这两个标签，地表平滑一行不改就能识别 |
| 光影查询 | `AflShaderCompat`（IrisApi 反射：是否有光影包、是否阴影通道） | 区块里的树不需要它；只用来选烘焙的明暗方式 |

**区块几何的硬限制**（反编译 Embeddium 0.3.31 和 Oculus 1.8.0 得出）：

| 限制 | 来源 | 数值 | 含义 |
|---|---|---|---|
| 区段视锥盒 | Embeddium `OcclusionCuller.isWithinFrustum`：`CHUNK_SECTION_SIZE = 9.125` | 区段外只留 1.125 格余量 | 伸出区段超过 1.125 格的几何在屏幕边缘会被整段裁掉 |
| 顶点位置编码 | Oculus `XHFPModelVertexType`：`MODEL_ORIGIN 8`、`MODEL_RANGE 32` | 相对区段原点 -8 到 24 格 | 一块方块的几何不可能覆盖一整棵树 |
| 方块中心偏移 | Oculus `ExtendedDataHelper.packMidBlock`：每轴 ×64 存一个字节 | 离方块中心不到 2 格 | 超出会溢出，用 `at_midBlock` 的光影包（Complementary 的体素化）会把顶点算到错的格子 |
| 材质 ID | Oculus `MixinChunkRenderRebuildTask` 在取模型前按**方块状态**设一次 `BlockContextHolder.blockId` | 一个方块的所有面同一个 ID | 树干和树叶必须由不同的方块带，才能一个不动一个摆 |

所以一棵树的几何必须分散到**很多个格子**里，每个格子只带它附近 1.1 格以内的面。这就是本轮的核心设计。

## B. 推荐的静态森林渲染架构

### 对比的三种做法

| | ① 根锚点 + 整棵 Mesh（一个方块带整棵树） | ② 独立实例化（自建 VBO / 实例缓冲，世界渲染事件里画） | ③ **格子体积 + 区块网格（推荐，本轮样板）** |
|---|---|---|---|
| 进 Embeddium 区块网格 | 否：超出编码范围和视锥余量 | 否：自己的绘制调用 | 是：每个格子是普通方块模型 |
| Draw Call | 1 棵 1 次或更多 | 每种树每档 LOD 一次（理想情况） | **0 额外**：和地形同一批区段绘制 |
| 光影阴影 | 只有锚点区段的阴影 | 要自己在阴影通道再画，Oculus 阴影通道也派发 `AFTER_SOLID_BLOCKS`（R4 踩过的坑） | 光影包自己的阴影通道画区段，**主画面和阴影同一份几何** |
| 树叶风动 | 整棵一个材质 ID，树干也会摆 | 顶点格式要伪造 Oculus 扩展格式（`mc_Entity`、`at_midBlock`、切线），强依赖内部类 | 树干格、树叶格是不同方块，ID 分开，见 D |
| Voxy / 地图 | 只看到锚点一格，**远景森林消失** | 完全看不到 | 看到树冠体积，见 Q |
| 每帧 CPU | 无 | 需要裁剪、排序、提交 | 无（区段构建时一次） |
| 改一棵树（砍倒） | 重建一个区段 | 改实例表，最便宜 | 重建这棵树覆盖的 2–8 个区段 |
| 距离 LOD | 无法 | 最灵活 | 区段重建（见 J），有成本 |

结论：**③**。它是唯一同时满足"不开新渲染框架、阴影和风动跟着光影包走、Voxy 能看到、零额外 draw call"的做法。缺点是 LOD 切换要重建区段，以及每棵树占几百个方块格。② 只在将来需要"万棵树动态"时再考虑（例如强风整林摆动），本轮没有这个需求。

### ③ 的具体规则

- 一棵树 = **树根格**（树的身份：位置、变体、朝向）+ **木格**（树干和主枝）+ **树冠格**（带叶片的格子）+ **树冠体积格**（不带面、只占体积）。
- 每个四边形归到一个格子：树枝管面归到它的轴线经过的格子，叶片卡片归到它中心所在的格子；中心落在木格里的卡片挪到最近的非木格（最多约 1 m）。
- 每个面离所属格子不超过 **1.1 格**（同 `AflStaticMeshModel.REACH`），也就离格子中心不到 1.6 格：同时满足视锥余量、编码范围和 midBlock 字节。
- 格子只存方块状态，几何从"树根状态 + 格子离树根的偏移"推出来。客户端有一份**树根索引**（每个已加载区块里的树根），区块构建线程查它：这个格子被哪几棵树覆盖、各取哪一份面。两棵树的树冠重叠时，同一个格子带两棵树的面，不会互相挤掉。
- 不需要方块实体，不 tick，不存每格数据。

### 跨区块

树冠最多伸出树根 ±8 格，常常跨 2×2 个区块。格子都是普通方块，属于它们各自的区块，跨区块显示天然正确。唯一的顺序问题：树冠格所在区块先到、树根所在区块后到时，那些格子先什么都不画；树根区块到达时把这棵树覆盖的所有区段标记重建。区块卸载时从索引里删掉。

## C. 树木模型分层与数据结构

| 层 | 内容 | 方块 | 渲染层 | 光影材质 ID |
|---|---|---|---|---|
| 树根 | 树干最下一格（含根部外扩），树的身份 | `dev_tree_root`（`facing` 4 × `variant` 4） | solid | 别名为 `oak_log` |
| 树干 / 主枝 | 管状网格（树干 12 边、主枝 6 边、侧枝 4 边） | `dev_tree_wood`（`girth` 0–8） | solid | 别名为 `oak_log` |
| 树冠 | 叶片卡片（双面） | `dev_tree_foliage` | cutout_mipped | 别名为 `oak_leaves` |
| 树冠体积 | 无面，只给体素视图 | `dev_tree_canopy` | 无（代理模式除外） | 别名为 `oak_leaves` |

为以后预留的数据（本轮只是数据，没有状态机）：

| 预留 | 现在在哪 |
|---|---|
| 树根坐标 | 树根方块的位置 |
| 朝向 | 树根 `facing`（四个 90°） |
| 变体 / 尺寸 | 树根 `variant`；尺寸由变体的布局定（`TreeShape.Layout` 的边界） |
| 树冠包围范围 | `Layout.minX..maxZ`（客户端再扩 2 格得到重建范围） |
| 碰撞 | 树干格 `girth`（半宽，1/16 格）；侧枝格 girth 0 不碰撞；树冠不碰撞 |
| 倒树旋转轴 | 树根格底面中心 (0.5, 0, 0.5) 的水平轴，方向垂直于倒向（见 L） |
| 唯一身份 | 维度 + 树根坐标（确定性，不需要 UUID） |
| 砍伐状态 | 预留给 L 节的倒树实体，树根方块本身不加状态 |

几何来源：本轮是 `TreeShape` 的程序化白栎（纯 Java，服务端、客户端、离线检查同一份代码，同种子结果完全相同）。正式树种以后由美术网格（`.vxmesh.json`）提供同样的"分骨骼的四边形列表"，格子分配算法不变。

## D. Sundial 树叶风动兼容（结论）

**结论：可行，不改 Sundial、不改 Oculus 文件，不写 AFL 自己的风动着色器。** 代码路径都读过；实机效果没看过。

1. **Sundial 怎么认树叶**（`shaders/block.properties` 和 `programs/gbuffers/Terrain.vert`，Sundial Lite 1.2.0）：
   - 原版树叶是 `block.16896`（二进制 0100 0010 0000 0000：特征位 + 植物位，"像树叶那样连续摆动"，叶片次表面散射）；
   - 顶点着色器读 `mc_Entity.x`，再按顶点的世界坐标和时间算一个平滑噪声位移，最大约 0.1 格（雨天约 0.15）；
   - 不读 `at_midBlock`，也不读 `mc_midTexCoord`。原木不在列表里，ID 是 -1，不摆。
2. **阴影**：`programs/gbuffers/Shadow.vert` 用同一个公式、同一个世界坐标做同样的位移，所以阴影和主画面的树叶位置一致。
3. **Mesh 进区块后保不保留 ID**：Oculus 在区块构建时，每个方块取模型之前，按这个方块的状态从 `WorldRenderingSettings.getBlockStateIds()` 设一次材质 ID，这个方块的所有顶点都用它。AFL 的模组方块不在 Sundial 列表里，ID 是 -1，**用了树叶贴图也不会摆**。
4. **样板的做法**：把光影包自己给 `oak_leaves` 的 ID 复制给树冠格和树冠体积格，`oak_log` 的 ID 复制给树根格和木格（`TreeShaderIds`）。
   - 换任何光影包，AFL 的树叶都按那个包的原版橡树叶处理：Sundial 是 16896，Complementary 是 10009，并且都会摆。
   - 光影包自己列了 AFL 方块的，以光影包为准。
   - 开发版用反射：发现光影包的新表时，替换成加了别名的副本，并整体重建一次区块，所以区块构建线程永远不会读到正在改的表。
   - 正式版建议改成一个只在 Oculus 存在时生效的 mixin（`@Pseudo`），在 `setBlockStateIds` 开头加别名，免掉那次重建。
5. **树干稳定、树根不动**：树干和主枝在木格里，木格的 ID 是 `oak_log`（Sundial 是 -1，不摆），所以树干、树根、主枝完全静止。
6. **树枝**：主枝和侧枝都在木格里，不动。规格允许"非常轻微"的动，本轮不做。
   - 原因：同一根枝如果一半在木格、一半在树冠格，接缝处会被拉开最多 0.1 格。
   - 树叶相对静止的细枝滑动不超过 0.1 m，和原版树叶相对原木的效果一样。
7. **不是"整棵树像橡皮"**：位移只跟顶点世界坐标有关，而噪声的空间尺度是几格到十几格，所以同一张叶片卡片的四个角几乎一起平移，不会变形；不同叶团之间相位不同。
8. **CPU**：零。全部在光影包的顶点着色器里算。
9. **其他光影包**：别名让它们按自己处理原版橡树叶的方式处理 AFL 树叶。
   - 不做风动的包：AFL 树叶就是静止的，和那个包里的原版树叶一样。
   - Complementary 的 `NO_WAVING_INDOORS` 按天空光衰减风动；树冠格让天空光减 1，和原版树叶相同。
   - 找不到 Oculus 内部类时（别的 Oculus 版本），别名不生效，树叶不摆，**不会崩溃**，`status` 会写原因。
10. **Voxy**：Voxy 也读同一张 ID 表（`IrisVoxyRenderPipeline` 调 `setCustomBlockStateMapping(WorldRenderingSettings.getBlockStateIds())`）。
    - 正式 mixin 加的别名对 Voxy 远景同样生效；
    - 开发版是事后替换，Voxy 可能拿到的是旧表。

## E. 无光影时的表现

- 原版没有风动，树叶静止，和原版树叶一样。
- **光照**：
  - 平面光照，每个面取它所属格子的光（格子不遮光，所以有真实光值），不用平滑光照：平滑光照把角点夹进格子里，对伸出格子的面是错的。
  - 树冠格让天空光减 1，和原版树叶一样，所以树下地面会暗一点。
- **明暗**：
  - 树冠深处的遮蔽（越靠里越暗，底部再暗一点）烘进顶点色；
  - 原版的方向明暗按法线混合（朝上 1.0、南北 0.8、东西 0.6、朝下 0.5，同 Terrain Smooth）；
  - 叶片只做轻微的朝上更亮。
- 群系着色：树叶贴图是灰度，用群系树叶颜色着色，和原版橡树叶同一个颜色来源。
- 有光影包时：顶点色只留遮蔽，方向明暗交给光影包按法线算（和 AFL 其他 Mesh 方块同一约定）。

## F. 树冠透明与 LabPBR

- **镂空，不用半透明**：树叶走 `cutout_mipped`，alpha 只有 0 或 255。半透明要排序，会和水、玻璃抢渲染顺序，而且 Sundial 没有 `gbuffers_block_translucent`。有 mipmap，远处不闪。
- **双面卡片**：区块绘制开着背面剔除，所以每张卡片写正反两面（法线相反）；三角形预算按两面计。
- **贴图**（`tools/mesh-trees/build-tree-textures.mjs`，确定性生成）：

  | 贴图 | 尺寸 | 用途 | 覆盖率 |
  |---|---|---|---|
  | 树皮 | 16 × 16 | 四方连续，每米重新起一次 | 100% |
  | 叶团 LOD0 | 32 × 32 | 1.5 m 卡片，约 21 像素/米 | 40% |
  | 中距 LOD1 | 32 × 32 | 更密，3 张代替 5 张 | 54% |
  | 远距 LOD2 | 32 × 32 | 叶团块 | 71% |
  | 体积代理 | 16 × 16 | 方块面，给 Voxy 和地图 | 79% |

  - 尺寸都是 2 的幂：不压低全局 mipmap 等级。
  - 卡片边缘留透明，没有方形轮廓；孤立像素已去掉，避免 mipmap 吃掉。
  - 像素密度按"自然方块暂用原版密度"的约定。
- **共享资源**：
  - 四个变体、四个朝向共用这 5 张贴图和同一个生成器；
  - 变体之间只差种子；
  - LOD 之间共享树干，只是边数少。
- **LabPBR：本轮没做**。树皮和树叶没有 `_n` / `_s`，Sundial 按默认粗糙材质处理，几乎不反射。树叶的次表面透光来自"橡树叶"ID，不靠贴图。以后的做法：

  | 贴图 | 内容 |
  |---|---|
  | 树皮 `_n` | 沟纹 |
  | 树皮 `_s` | 低光滑度，雨天 porosity |
  | 树叶 `_s` | 低光泽，SSS 通道 |
  | 树叶 `_n` | 可选，极轻 |

  按"平铺法线不要细碎线条"的教训，先看掠射光预览再定。只加贴图，不用改代码，也不用重新编译。

## G. 单树技术样板内容

白栎（White Oak），程序化，4 个变体 × 4 个朝向，技术验证质量，不是最终美术。
- **形态**：
  - 短粗树干：根部半径约 0.44 m，向地面外扩到 0.64 m，分叉高 3.4–4.3 m。
  - 5 根主枝：3 根低枝接近水平（10–20°），末端上弯，长 6.4–7.6 m；2 根高枝爬升（30–42°）。
  - 每根主枝 3 根侧枝向上向外。
  - 一根短中央主干带 3 根侧枝，撑起冠顶。
  - 树冠宽而圆、不对称，约 11–13 m 宽、10–12 m 高。
- **叶团**：55 个（其中 34 个在树冠外侧），挂在枝端和外侧枝段上。叶团只是摆卡片的位置，不是球形树冠。
- 离线预览图：`node tools/mesh-trees/check.mjs` 写到 `build/mesh-trees/`（不进仓库），一张是变体 0 的三档 LOD + 体积代理 + Voxy 第 2 级，另一张是四个变体。

每棵树（4 个变体数字基本一样，变体 0）：

| | 数值 |
|---|---|
| 格子 | 381：木 78，树冠 303，其中 142 格带叶片，其余为体积格 |
| 三角形 LOD0 / LOD1 / LOD2 | 2548 / 992 / 492（叶片两面都算；LOD2 在 T 节的修改前是 380） |
| 挪动过的叶片卡片 | 341（中心落在木格里），丢失 0 |
| 范围 | x −7..4，y 0..10，z −6..7（相对树根） |

| 命令 | 作用 |
|---|---|
| `place [variant 0-3] [turns 0-3]` | 树根放在你站的那一格，下面要是实心地面 |
| `grove [count 2-16]` | 你周围 12 格间距的网格，自动贴地表，混合变体和朝向（默认 9 棵） |
| `clear` | 清掉所有样板树，按日志还原每格原来的方块 |
| `lod auto` / `0` / `1` / `2` / `proxy` | 只影响你的客户端：按距离（默认）/ 全部用一档 / 全部显示体积代理（Voxy 和地图看到的样子） |
| `status` | 服务端：样板树数量、写入格数；客户端：树根索引、各档数量、区块构建查询次数和平均耗时、重建标记、光影 ID 别名状态、Embeddium 是否加载 |

安全规则：
- 每格只写进空气或可替换的植物，日志记下原方块。
- 树干、树枝格碰到别的东西就拒绝整棵树。
- 树冠格碰到另一棵样板树的树冠就共用，碰到别的东西就跳过并计数。
- 全世界最多 32 棵。
- 写入用 flags 18：不触发邻居更新、不掉落。
- 日志存在 `data/afl_dev_mesh_trees.dat`。

## I. 性能预算与估算依据（只有估算，没有实测）

**树木数量**按 Terrain V2 生态 V1 的群系表加权：
- 陆地平均每区块约 3.5 棵，坡地混合阔叶林约 11 棵（规划值，不是实测）。
- 32 区块视距的圆形区域约 3200 个区块，约 1.1 万棵；密林区 3 万棵以上。

按 AFL 的 LOD 距离（J 节）分档，平均密度、32 视距：

| 档 | 距离 | 约多少棵 | 每棵三角形 | 小计 |
|---|---|---|---|---|
| LOD0 | < 64 m | 约 180 | 2548 | 0.46 M |
| LOD1 | 64–160 m | 约 930 | 992 | 0.92 M |
| LOD2 | > 160 m | 约 1 万 | 492 | 5.0 M |
| 合计 | | | | **约 6.4 M** |

对照：原版橡树约 60 片树叶方块 × 6 面 × 2 三角形 ≈ 720 个三角形（高画质树叶之间不剔除），1.1 万棵约 8 M。所以平均密度下 Mesh 森林的三角形仍**少于**原版森林；密林区约 ×3。

| 项 | 估算 | 依据 |
|---|---|---|
| 显存 | 6.4 M 三角形 ≈ 13 M 顶点：有光影约 510 MB，无光影约 260 MB | Oculus 扩展顶点 40 字节，Embeddium 原版格式 20 字节；与原版森林同量级或更低 |
| Draw Call | 0 额外 | 树和地形在同一批区段里画 |
| 主线程 | 每 tick 遍历一次树根索引算距离档，1 万棵约 0.1 ms 级（估算）；区块到达时扫描区段调色板（`maybeHas` 先筛） | — |
| 区块构建 | 每个格子一次索引查询（2×2 区块、几棵树的包围盒比较）加一次缓存表查找；体积格直接跳过 | `status` 报实际平均微秒数 |
| 每棵树格子 | 约 380–430 | 原版橡树约 65、大橡树约 150；体积格是给 Voxy 的代价 |
| 缓存 | 每个（变体、朝向、档、明暗）一份烘焙面片，按需生成，模型重载时清空；一个变体的全部组合约几 MB（估算） | — |
| 阴影 | 光影包阴影距离内的树再画一遍（同一份区段网格），树越多阴影越贵；Sundial 的阴影距离由它自己的设置定 | — |
| LOD 切换的重建 | 冲刺时（5.6 m/s）平均密度下约每秒 15 棵跨 64 m 圈、约 50 棵跨 160 m 圈；每棵标记 2–8 个区段，有重叠，约每秒 100–300 次区段重建（估算） | 实际次数看 `status` 的重建标记 |

要避免的都避免了：
- 没有常驻实体、没有 tick；
- 每帧不在 CPU 上重算网格，也没有动态渲染对象；
- 风动在 GPU 上算。

## J. LOD 方案（AFL 自己的视距 LOD，与 Voxy 无关）

| 档 | 距离（水平，相机到树根） | 几何 | 贴图 |
|---|---|---|---|
| LOD0 | < 64 m | 树干 12 边、主枝 6 边、侧枝 4 边；每叶团 5 张 1.5 m 卡片 | 叶团 |
| LOD1 | 64–160 m | 树干 6 边、主枝 3 边、无侧枝；外侧叶团 3 张（水平、朝外、横向），内侧 2 张，1.55 m | 中距（更密） |
| LOD2 | > 160 m | 树干 4 边到分叉为止，主枝和中央主干的内侧两段 3 边（环距 2 m）；全部叶团：外侧水平 + 朝外，内侧只朝外，散开范围和 LOD0 相同 | 远距（叶团块） |
| 体积代理 | `lod proxy` 时；以及 Voxy、地图 | 每个树冠格一个叶块立方体，相邻的面互相剔除；木格一根树皮柱 | 代理叶 |

- 一棵树的所有格子用同一档，所以树冠里不会有接缝。档位按树根距离算，滞后 8 m 防止来回跳。
- 换档时把这棵树覆盖的区段标记重建，Embeddium 重建完一次性替换，不会两份同时画。
- 阴影通道画的是同一份区段网格，所以阴影的档位和主画面一致。
- **AFL 的 LOD0/1/2 是 AFL 自己的模型设计，Voxy 不会读取或切换它们。** Voxy 只在原版视距以外工作，用的是体积代理（Q 节）。

## K. Terrain Smooth 树根兼容

- 样板的树根格和木格在 `minecraft:logs`，树冠格和体积格在 `minecraft:leaves`（开发资源里的标签，条目都是 `required: false`）。Terrain Smooth 的 `cell()` 因此把它们识别为 TREE / LEAF，**一行代码不改**。
- 树根下面那块地：上方是 TREE（不是空气或植物），所以不是可平滑的地表，保持整格；碰到这一列的共享角点也被钉住。树干底面因此正好落在整格顶面上，不会悬空，也不会陷进去。
- 旁边的地面照常平滑，只是在树根这一列的角点保持原高度。根部外扩（0.64 m 半径）会把这个小过渡盖住。
- 树冠下的地面照常平滑：地表扫描从 `WORLD_SURFACE` 往下，越过 LEAF / TREE 找到真正的地面。
- 碰撞：树干格用 girth 的盒子，地形碰撞由 Terrain Smooth 管，两边互不干扰。
- **不需要新的"树根锚点"类别。** 正式版如果不想把 AFL 树方块放进原版标签（原版树叶衰减、鹦鹉生成等会读这两个标签），可以改成 AFL 自己的标签，Terrain Smooth 的 `cell()` 多认一个标签。这只是分类，不动核心算法。

## L. 未来整树倒下的转换方案（本轮不实现）

现在的结构可以安全转换，P0 没发现阻碍。设计：

1. **砍伐**：玩家砍树根格（以后可以扩大到底部 1–2 个木格的命中区）。服务端从树根状态得到变体和朝向，按布局列出这棵树的所有格子，逐格确认还是这棵树的（防止别人改过）。
2. **转换**：同一 tick 内：
   - 生成一个"倒树"实体，带树根坐标、变体、朝向、倒向；
   - 删掉这棵树独占的格子；和别的树共用的树冠格保留；
   - 树根格换成树桩（可选）。
   客户端收到树根消失，从索引删掉这棵树、标记区段重建；实体在第一次重建完成前就开始画整棵树（Vextris `MeshRenderer`，同一份 `TreeShape` 网格，不按格子拆），所以最多重叠一两帧，不会缺帧。AFL 的 `AflMeshChunking.confirm` 已经有"区块确认画了才让渲染器停画"的机制，可以照搬。
3. **倒下**：绕树根格底面中心的水平轴旋转，轴的方向垂直于倒向；倒向由砍的方向决定。只做关键帧式的旋转加落地检测，不做刚体物理。
4. **落地 / 结算**：实体到终点后在服务端一次性结算原木、枝、少量叶类资源，再移除自己。实体存档时带"已结算"标记，区块卸载再加载不会重复结算；结算只由实体做，格子删除时不掉落（现在就是 `noLootTable`）。
5. **重复绘制**：静态几何只来自格子，动态几何只来自实体，两者以树根格的存在与否切换。
6. 状态 STANDING / CHOPPING / FALLING / LANDED / REMOVED：STANDING 是格子，CHOPPING 是树根上的砍伐进度（可以用方块破坏进度），FALLING / LANDED 是实体，REMOVED 是实体移除。

## P. 尚未解决的技术风险

1. **全部没有实机**：外观、风动、阴影、LOD 跳变、性能、显存都要看了才知道。
2. **区段重建成本**：LOD 换档和砍树都要重建区段，冲刺、快速飞行或密林里可能出现重建高峰。没测过；`status` 会报标记数。
3. **每棵树约 400 格**：存档变大，区块构建要查的格子多（体积格已经直接跳过）；是原版大橡树的 2–3 倍。
4. **ID 别名依赖 Oculus 内部类**（`WorldRenderingSettings`）：别的 Oculus 版本可能改名，那时树叶不摆但不出错。正式版用 `@Pseudo` mixin，加 `require = 0`。
5. **正式化还缺方块变化钩子**：样板的客户端索引靠区块到达时扫描，以及服务端在树根放下、移除时发的消息。正式版需要像 Terrain Smooth 那样挂在方块变化上（`Level#onBlockStateChange`），而且要记住 `ServerLevel` 覆盖了它。
6. **原版标签副作用**：样板进了 `minecraft:logs` / `leaves`。正式版要么接受（原版树叶衰减、鹦鹉生成会读），要么改 AFL 自己的标签（见 K）。
7. **树冠格不能放方块**：树冠格不可替换、不可选中，玩家不能在树冠里放东西，也拆不掉单个树冠格，只能用 `clear`。正式版要定树冠的交互规则。
8. **光照斑块**：每个面取它所属格子的光，同一片树冠里相邻卡片的亮度可能有一格之差。
9. **纯 Forge（没有 Embeddium）的原版区块路径没有核对视锥余量**；AFL 默认运行 Embeddium。
10. **LabPBR 没做**（F 节）。
11. **群系树密度**：现在的森林密度是按原版小橡树定的（每区块最多约 11 棵），Mesh 白栎的树冠更大，正式接入时要重新定每个群系的树数和间距。

## Q. Voxy 1.20.1 Forge 技术兼容性（只读源码审查，未实机）

审查对象：Neo Voxy 多版本仓库（CH4ACKO3/neo-voxy-multiversion，`editions/forge-1.20.1-client`，`mod_version 0.3.5-alpha.2`，提交 1031a43，2026-09-26）。前身是 MCRcortex 的 Fabric 版 Voxy，原作者明确不做 1.20.1，这是社区移植。只在客户端运行，需要 Embeddium / Oculus。没有下载 jar，也没有运行。

1. **远景数据怎么来**：
   - Voxy 把客户端已收到的区块段转成体素（`WorldConversionFactory`），每格存方块状态 ID、生物群系和光照；
   - 每种**方块状态**的外观只烘焙一次（`SoftwareModelTextureBakery`）：
     - 用 `ModelData.EMPTY` 和固定随机数取模型的所有面（6 个方向和无方向）；
     - 从 6 个方向正交投影到单位立方体，每面 16 × 16（`MODEL_TEXTURE_SIZE = 16`）；
     - **立方体外的几何被裁掉**。
   - 树叶由 `BlockTags.LEAVES` 或 `LeavesBlock` 识别，走"树叶 LOD 模式"（快速 / 平衡 / 质量）。群系颜色是否随群系变，由方块颜色处理器判断。
2. **降采样**（`common/world/other/Mipper`）：
   - 8 个子格合成 1 个父格时，只有这几种情况父格才是实心：
     - 8 个都一样；
     - 实心子格多于 4 个；
     - 正好 4 个且在底层（平面）。
   - 少数占用一律变空气，注释原话是 "Do not return an arbitrary solid child when minority occupancy rounded to air"。
3. **AFL 的 Mesh 树能不能被认出**：Voxy 只看方块状态的烘焙外观，不看 AFL 的区块网格。
   - 本样板没有模型数据时给的是体积代理：树冠格是叶块立方体，木格是树皮柱；
   - 树冠格在 `minecraft:leaves`，所以 Voxy 把它们当树叶。
4. **只有根锚点会怎样**：离线模拟（`TreeCheck` 用 Neo Voxy 的降采样规则，32 种网格对齐取平均），各级保留的侧面 / 顶面轮廓面积：

   | 表示方法 | Voxy 第 1 级 | 第 2 级 | 第 3 级 |
   |---|---|---|---|
   | 只有根锚点 | 0% | 0% | 0% |
   | 只有带叶片的格子（稀疏载体） | 61% / 65% | 13% / 14% | 0% |
   | **本样板：树冠体积格** | **83% / 82%** | **48% / 45%** | 0% |
   | 原版橡树（对照） | 67% / 64% | 0% | 0% |

   根锚点 + 整棵 Mesh 的树在 Voxy 里会让远景森林**完全消失**；稀疏载体到第 2 级也基本没了。所以树冠必须是一团密实的格子。样板用叶团球体并集，再做 2 格的闭运算填缝，得到的体积比原版橡树还经得起降采样。单棵树到第 3 级（8 格一个体素）都会消失，这对原版树也一样；远处森林靠相邻树冠连成一片才留得住。
5. **要不要专门的低成本 LOD 代理**：要。就是树冠体积格本身加上"没有模型数据就给代理立方体"，不需要另做一套代理方块或改 Voxy。
6. **高度、冠幅、树种颜色、轮廓怎么保留**：
   - 高度和冠幅：体积格就是树冠的真实范围（叶团球体并集 + 闭运算），树根到冠顶的格子都在。
   - 树种颜色：每个树种用自己的树冠方块和代理贴图，群系着色走同一个颜色处理器。
   - 轮廓：外轮廓保持叶团的不规则形状，没有做成圆球。
7. **Sundial + Oculus + Voxy 同时启用**：
   - Sundial Lite 自带 Voxy 程序（`voxy.json`、`voxy_opaque.glsl` → `VoxySolid.frag`），按 `parameters.customId` 取方块 ID 决定材质。树冠格在别名生效后就是树叶 ID（见 D 第 10 条），远景树冠按树叶着色。
   - `voxy.json` 没有阴影程序，远景体素不进阴影图（阴影距离本来就有限）。
   - `excludeLodsFromVanillaDepth: true` 由 Voxy 和光影包处理深度合成。
   - 透明层：树叶是镂空，不进 Voxy 的半透明层。
   - 1.20.1 版不支持原版区块和远景之间的圆形过渡（README 功能表），所以交界处是硬边。
   - 以上都只是读代码，**没有实机，不标 PASS**。

## R. 远景树冠代理、近远景切换和后续成本

- **代理方案**（已在样板里）：
  - 树冠体积格加上没有模型数据时的叶块立方体；
  - AFL 自己的视图在 `lod proxy` 时显示同样的东西，可以对比 Voxy 将看到的样子。
- **近远景的三段**：
  - 原版视距以内是 AFL 的 LOD0 → LOD1 → LOD2（卡片树冠）；
  - 原版视距以外是 Voxy 的体素树冠（方块化的叶块）。
- **切换风险**：
  - 原版视距边界上，卡片树冠突然变成方块化的叶块树冠，且 1.20.1 没有过渡带。轮廓、高度、颜色一致（同一个体积、同一个群系颜色），所以是"风格跳变"，不是"树消失"。
  - LOD2 和体素树冠的密度不同：LOD2 有空隙，体素树冠是实心块。
  - 要再减小跳变，可以让 LOD2 在接近视距边界时改用代理立方体，代价是 LOD2 的三角形更多（每棵约 700，与原版橡树相当）。本轮不做，等实机看了再决定。
- **不为 Voxy 降低近景质量**：近景 LOD0 完全不受 Voxy 影响。Voxy 只决定了"树冠要有体积格"这一点，而体积格对近景没有视觉影响。
- **后续兼容开发成本（估算）**：

  | 工作 | 估算 |
  |---|---|
  | 正式 ID 别名 mixin | 小，一个类 |
  | 代理贴图按树种做 | 每树种 1 张 |
  | 实机验证 Voxy | 要装 Neo Voxy jar（可选模组，**不做硬前置**），在 Sundial 下看边界和远景 |
  | LOD2 靠近边界时改用代理（如果实机证明需要） | 中，改 `TreeCellModel` 的选档规则 |
  | 圆形过渡 | 只能等 1.20.1 版 Voxy 支持 |

## S. Terrain Smooth B 和 Highway R4 的远景风险（只记录，本轮不修）

- **Terrain Smooth B**：斜坡几何来自模型数据（`SmoothSurfaceModel.getModelData` 按位置算）。没有模型数据时退回原版模型，所以 Voxy 远景里的地形是原版的台阶方块。地形不会丢，但视距边界以外不平滑，交界处台阶感会重新出现。
- **Highway R4**：
  - 路面和标线是在世界渲染阶段画的 Mesh，不是区块几何，Voxy **完全看不到**。
  - 开发碰撞层 `dev_highway_surface` 的模型只有粒子贴图，没有面，Voxy 里也是空的。
  - 远景里的公路因此只剩下面的路基方块，加上 `graded_turf` 的近似外观：`graded_turf` 的斜顶按方块状态烘焙，会被裁进单位立方体。
- 正式接全国路网时，路面要么进区块网格，要么给路面方块一个没有模型数据时的代理外观（同树木的做法）。

## T. 实机反馈 1：LOD2 掉细节（2026-10-11）

- **判断**：近看本来就该粗，但要看的是它在 160 m 以外的样子。离线模拟 64 / 160 / 320 m 的屏幕尺寸（2000 × 1125 窗口、70° 视角，高分辨率渲染后按像素面积缩小；工具：会话临时目录里的 `DistanceProbe.java`，没放进仓库），发现 LOD2 在 160 m 和 320 m 也有真问题：
