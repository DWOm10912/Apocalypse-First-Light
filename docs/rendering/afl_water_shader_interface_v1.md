# AFL 水面 ↔ Aureveil：光影接口 V1（AFL 提议，布局 1）

2026-10-28。AFL C（水体归 C，2026-10-26 起）提出，等 Aureveil 定格式。用户 2026-10-27 看了河流 R2 第 1 轮：不开光影时清水能看到河床；开 Aureveil 时水面发暗、不透明，看不到河床（截图）。

**状态（2026-10-28）**：
- AFL 这边已实现，在 C 工作区（`feature/c-worldgen`），未提交，compileJava 通过。
- Aureveil alpha.77 已接上，格式原样采用布局 1。Aureveil 的记录在它仓库的 `docs/afl-interface-water-alpha77.md`。还没实机看。
  - 包是 `Aureveil-Shaders-0.2.0-alpha.77.zip`，SHA256 18a23c3e…abb6c。已拷进 C 工作区的 `run/shaderpacks`，开发客户端的 `oculus.properties` 也切到了它。
- 包里没有 `AFL_WATER` 选项时，AFL 照旧画普通半透明水面，所以 AFL 先合进去也不影响现在的画面。

**Aureveil alpha.77 的做法（它的回复）：**
- 认水：只认布局 1、校验值 4245，看顶点自己的 UV。
- 水色按种类取 texel 2 / 3，浑浊度乘在散射系数上，吸收不变。
- 顶面流速 > 0.05 m/s 按流水画。8 位颜色的 0.5 解出来约 ±0.016 m/s，低于这个门槛，不会把静水误判成流水。
- 泡沫取包的泡沫和 b 中较大的那个；a 乘在水面的 alpha 上。
- 眼睛上方水深 > 0 时，整包按“眼睛在水里”画：水下雾、从下面看水面、云、体积光。
- 关掉写实水面时，用 AFL 的水色画普通水面，不透明度 0.6 × a。
- 没有的：AFL 的水不进阴影图，所以河床上没有焦散，水下的阳光不随水深变暗。以后要做，AFL 得在阴影 pass 里也画水面，到时再定格式。

本文替代 `water_visual_v1_design.md` 5.1 里方块 id 53/54/55 的设想。AFL 的水面不在区块网格里，是 AFL 在 `RenderLevelStageEvent AFTER_TRANSLUCENT_BLOCKS` 里用自己的 BufferBuilder 立即画的，没有方块 id（`mc_Entity` = -1），所以 id 的路走不通。改用和植被接口（Aureveil alpha.70，`docs/afl-interface-vegetation-alpha70.md`）一样的办法：按贴图在图集里的矩形认，数据放在顶点和一张按名字查的动态贴图里。

## 背景：开光影时 AFL 的水现在怎么画

- 代码：`client/liquid/ClientLiquid#draw`。用原版 `RenderType.translucent()` 的状态和程序画（Oculus 换成包的 `gbuffers_water`），BLOCK 顶点格式，坐标相对相机，按距离排序。
- 包现在拿到的是：
  - 颜色 (0.30, 0.42, 0.46)，透明度 0.38–0.82（按水深）；
  - 贴图 `apocalypse_firstlight:block/liquid/water_surface` 上的普通 UV；
  - 法线 (0, ±1, 0)。
- 包按非水的半透明面处理，所以水发暗、看不到底。
- 包要的东西其实都在：水后面的不透明画面（`colortex15`）、厚度（`depthtex1`）在 `gbuffers_water` 里照样能用，只差“认出这是水”和水的数据。

## ① 选项 `AFL_WATER`

- 布尔选项，名字固定，建议 Aureveil 默认开，放在 AFL 页。AFL 用 `ShaderPackOption.on("AFL_WATER")` 读，和 `AFL_RAIN`、`AFL_VEGETATION` 同一套。
- 选项为真时：
  - AFL 每帧开头（`RenderTickEvent START`）写 ②；
  - 水面顶点改成 ③ 的格式。
- 选项为假或包里没有这个选项（别的包、旧版 Aureveil）：AFL 照旧画普通半透明水面，顶点和现在一样。

## ② `apocalypse_firstlight:dynamic/afl_water`

RGBA32F，4 × 1，最近邻，1 层，clamp。FMLClientSetupEvent 时注册。

| texel | 内容 |
|---|---|
| 0 | (布局 1, 眼睛上方的 AFL 水深 m（0：眼睛不在 AFL 水里）, 0, 校验值 4245) |
| 1 | 水面贴图 `water_surface` 在图集里的矩形 (u0, v0, u1, v1) |
| 2 | 河水：(r, g, b, 浑浊度)，现在是 (0.32, 0.50, 0.52, 1.0) |
| 3 | 地上的静水（雨水、水坑、挖开的坑里的水）：(0.46, 0.42, 0.32, 3.0) |

- 颜色是显示值，相当于原版生物群系的水色（包现在拿顶点色当水色的那个位置）。
- 浑浊度：1 = 包自己的水，更大 = 散射更多、更浑。这是 AFL 的建议，包可以按自己的光学模型换算或忽略。
- 眼睛上方的水深：AFL 的水不是原版水，眼睛在里面时 `isEyeInWater` 是 0。包可以用这个值走水下的画法（雾、从下面看水面）。值是相机所在那一列的水面高度减相机高度。
- 含义变了，AFL 把布局号加 1 并通知 Aureveil。包只认识的布局；不认识时建议按普通水画（id 50）。

## ③ 水面顶点（选项为真时）

所有 AFL 水面四边形（水面、水面背面、侧面、河边延伸到岸上的那一圈）：

| 通道 | 内容 |
|---|---|
| 位置 | 相对相机，和现在一样 |
| 颜色 r、g | 流速 x、z：`0.5 + v / 8`（v 是 m/s，世界坐标轴，水流去的方向，夹在 ±4 m/s）。0.5 = 不流 |
| 颜色 b | AFL 算的白水 0–1（快水、水流进潭、坡度突变处；薄水膜在坡上也有一点） |
| 颜色 a | 淡入 0–1：很浅的水（0.8–2 cm）从无到有淡入，河边延伸面是 1 |
| UV | 在 ② 的矩形里：u 的比例 × 4 取整 = 水的种类（0 地上的静水，1 河水，2、3 保留），v 在矩形中间那一半 |
| 光照 UV2 | 和现在一样（水面那格和上面一格中更亮的） |
| 法线 | 面自己的法线：水面按四角的真实高度（急流、浅滩的水面是斜的），背面朝下，侧面水平 |

- 侧面和背面的流速是 0，白水 0。
- UV 在每种水的那一格里占中间一半，跟着面铺开，所以切线方向是确定的；四个顶点的 UV 中点（`mc_midTexCoord`）也在同一格里。
- 流速的数值：河水 0–1.5 m/s（`RiverFlow.MAX_SPEED`），雨水在坡上流的薄水膜也有流速；白水从 0.6 m/s 起出现，2 m/s 满。

## ④ 建议 Aureveil 怎么用（由 Aureveil 定）

- **认水**：在 `gbuffers_water` 的顶点着色器里，中点 UV（没有时用顶点自己的）落在 ② texel 1 的矩形里 → AFL 的水。种类 = clamp(int((u − u0) / (u1 − u0) × 4), 0, 3)。
- **流动**：流向直接用颜色 rg，不再从贴图方向反推。顶面流速 > 约 0.05 m/s 时按包的流水（51）画，速度用真实流速；否则按静水（50）。
- **白水**：颜色 b 叠在包自己的泡沫量上（取大值）。包的岸边泡沫照常。
- **淡入**：颜色 a 乘在水面上（a = 0 时等于没有水面），避免极浅的水突然出现。
- **水色、浑浊度**：按种类取 texel 2 或 3。
- **从水下看**：texel 0 的 g > 0 时，眼睛在 AFL 水里。AFL 的水面背面法线朝下，可以走 `avWaterUnderside` 和水下雾。
- **阴影**：AFL 的水面不在阴影 pass 里画（和现在一样）。

## 不在这一版里的

- AFL 的落水（水柱、水帘、水滴，`ClientFalls`）：开光影时用实体半透明类型画，不在 `gbuffers_water`。照旧，以后单独商量。
- 雨后地面变湿（`drawDamp`）：照旧。
- 水面网格不进阴影图。

## 实机第 1 轮（2026-10-28，Aureveil alpha.77）

用户：“不行，我感觉是那边也碰到我们之前的问题了”，还说“不知道为什么掉帧严重”。截图：水已经清了，能看到河床；但整片河面的条纹和泡沫被拧成沿三角形边走的锯齿折线。

**1. 条纹拧成折线（Aureveil 那边）**
- 原因：`lib/water_detail.glsl` 的 `avWaterStreakSlope`、`avFoamPattern` 用 `dot(q, flow)` 建条纹坐标，q 是世界坐标对 1024 取模。AFL 的流向是逐顶点插值的，方向稍一变，几百米外的坐标就甩开。和 AFL 自己 `afl_water.fsh` 白水条纹的问题是同一类（河流 R2，`river_lake_v1_design.md` 13.4）。
- 已把原因和改法发给 Aureveil：用 16 个固定方向，取流向两侧最近的两个各算一次再混合，坐标系不跟着流向转。等它出新版本。

**2. 掉帧（AFL 这边，已改）**
- 原因：开光影时 AFL 的水面走立即绘制，每帧把 160 m（`RANGE`）内所有水格重新生成并按距离排序。河宽 1.6 倍以后水格成倍增加。昨天开 Aureveil 的截图就只有 34 FPS，不开是 593。
- 改法：开光影且包认 AFL 水（`AFL_WATER`）时，也按区块缓存成顶点缓冲（`drawCached`），只在区块的水位变化时重建；画的时候用包的半透明程序，按区块设置 `ChunkOffset`（`drawPack`）。包的写实水输出是不透明的，不用排序。顶点格式在两条路径之间切换时整批重建。
- 雨后湿地标记原来是每帧生成水面时顺便刷新的，现在由 `dampAll` 单独刷新。这个效果只在地面变暗开着时才有，默认是关的。
- 编译通过，还没进游戏看帧数。

**Aureveil alpha.78（2026-10-28）**：
- SHA256 0ede2965…b8893a078，已拷进 C 工作区的 `run/shaderpacks`。
- 修了什么：
  - AFL 水面的条纹和泡沫改成用 16 个固定方向混合（`avWaterStreakSlopeFixed`、`avFoamPatternFixed`），原版水不变；
  - 0.05–0.25 m/s 之间，静水波纹渐变成流水条纹。
- Aureveil 看了截图，结论修正为：六边形同心环也是流向剪切造成的。浅滩慢水的流向在 8 位编码下接近随机，每个三角形里的等值线是直线，一圈三角形合起来就是同心多边形。所以环和折线会一起消失。岸边泡沫没动。

## 实机第 2 轮（2026-10-28，Aureveil alpha.78 + AFL 按区块缓存）

用户：“正常了，但是这个大片白色，不知道是什么，原版没有……我感觉不像是云呢”。
- 折线、同心环没了；帧数正常（按区块缓存生效）。
- 新问题：快水段的河面上有大片硬边的白斑，俯视时上游一整段河面像铺了一层泡沫。不开光影时同一段只有零星的白水细条纹。
- AFL 的判断：两边对颜色 b 的理解不一致。AFL 的 b 是“白水强度”（smooth((流速 − 0.6) / 1.4)，浅滩、急流 1–1.5 m/s 时约 0.3–0.6），自己只用它画顺流的细条纹，透明度最多 白 × b × 0.55。Aureveil 按 max(包的泡沫, b) 当泡沫覆盖量，0.3–0.6 就成了大片不透明白斑。
- 已发给 Aureveil：建议把 b 当细条纹白水的强度，覆盖量取 b × 0.2–0.3，只在条纹形状里出白、半透明；可以先临时把 b 当 0 确认。等它出新版本。
- AFL 这边暂不改 b；如果 Aureveil 需要单独的“覆盖量”通道，再加布局号。
