# AFL 中文文案与 Wiki 风格基准（GPT 审校样本 V1）

**目的：** 将 `zh_cn_AFL_GPT审校版.json` 作为中文表达的参考基准。此文件是针对用户 2026-10-19 提交的中英对照快照进行的审校稿，**不是自动覆盖当前仓库的指令**；Claude 必须按 Key 合并，并先核对当前实际游戏数据。

## 1. 核心风格

自然、准确、具体、克制，保留正常现代中文的语序与句子节奏。不要为了避免“AI 腔”而将所有用语改得粗俗、口语化，也不要为了显得专业而大量堆砌书面语。以场景、写作者和读者为依据决定文风。

- **状态效果 / HUD：** 快速传达机制，统一「耐力」「生命值」「移动速度」「疾跑」。例如「耐力恢复减缓，移动速度降低，无法自然恢复生命值」。普通体感消息另用口语，如「手脚冻得发麻」。
- **交互 / 错误提示：** 直接解释动作或原因。例如「离加油口太远，已停止倒油」。短交互动词可用「开门」「取下」，不必每条加“请”。
- **武器和配件 Tooltip：** 是装备资料，不是电商广告，也不是酒桌聊天。说明结构、用途、成本及代价，合理使用技术术语。例：「BR-51 专用的 50 发双弹鼓。弹药储备充足，但空仓换弹更慢」。不要无依据保证“一枪致命”。
- **生存 / 特质 / 成长：** UI 标签简短、规范；人物背景允许有生活感。例：「过去常年跑长途，修车的本事没丢，烟却一直没戒掉」。不得在玩家文案中混入「动画还在做」之类开发注释，正式上线前由开发工作区决定是否展示开发状态标记。
- **工业 / Jade：** 选用准确行业术语，读数优先；避免「设备有问题」这种无信息量提示。若没有验证机制，不应凭语言润色猜测技术原理。
- **音效字幕：** 优先识别声音来源、动作和方向；有来源时可用「对象：动作」，没必要强制所有音效都套格式。例「皮卡：起动机转动」「水沸腾」「急促的喘息声」。
- **世界观 / Wiki：** 用户打开阅读的内容像真实文档：公司通告像公司、事故报告像事故报告、幸存者手记像个人手记。不要一味模仿《赛博朋克2077》的讽刺语气。品牌与地名仅使用已批准设定，不擅自杜撰采购史、年表、疗效或背景。

## 2. 语言与数值不可变原则

1. 保留全部 JSON Key、占位符 `%s`、`%1$s`、`%%`、控制码及语义绑定；不得凭空新增游戏功能。
2. 不改动伤害、射速、时间、数量、比例和业务逻辑；若文本与代码冲突，提出需要确认的清单，由负责功能的工作区决定。
3. 固定术语优先级：项目已批准术语表 > 当前游戏已确定设计 > 本审校示例；冲突时不要直接覆盖。
4. **Wiki 数据**从游戏 JSON/Java 实际输出生成；**解释性文字**由相应开发工作区维护；区分「已实机验收」「已集成」「测试中」「规划中」。
5. Wiki 的未发布剧情、内部角色和敏感设计不得直接推送到公开站或公开 R2；非公开页面必须经过权限控制。
6. 界面宽度、折行、字形和中文显示需要游戏内 LQA；JSON 解析与占位符一致不等于实机合格。
7. 中文和数字、英文之间一般留半角空格，型号原样（如 P9-01、7.62×51mm）；不要机械对所有符号补空格。短按钮和状态标签通常不加句末句号。

## 3. Claude 新增内容时的工作方式

1. 先识别页面的**类型、读者、文本用途**和显示长度限制。
2. 优先复用已经验收的表达与术语。新增产品/公司/地名先核对世界观文件。
3. 编写或变更 `en_us.json`、`zh_cn.json` 时进行 Key/占位符一致性检查；文本属于成长和医疗时，必须核对对应 JSON 和实际机制。
4. 新增 Wiki 页面不允许将候选设计写成已经实装。变更后由 Main 负责校验与部署。
5. 每次新增中文文案，抽查实际游戏画面；如果出现明显“AI 说明书腔”“词不达意”“过度口语”问题，要针对具体文本修正，而不是堆叠全局禁用词。

## 4. 审校样例（原文 → 建议）

| 文本用途 | 旧文 | 审校风格 |
|---|---|---|
| 严重失温 | 走路慢，不会自己回血，一直掉血 | 移动速度降低，无法自然恢复生命值，并持续失去生命值 |
| 背景描述 | 以前跑长途，车坏了自己修，烟戒不掉 | 过去常年跑长途，修车的本事没丢，烟却一直没戒掉 |
| 角色死亡 | 旅程随 %s 一同结束 | %s 的旅程到此结束 |
| 大型弹鼓 | 增加弹匣容量，提升持续射击能力，但空仓换弹更慢 | 弹药储备充足，但空仓换弹更慢 |
| 红点瞄具 | 瞄点清晰，便于快速瞄准目标 | 提供清晰的瞄准点，便于快速瞄准目标 |
| 柴油机字幕 | 起动机转动 | 皮卡：起动机转动（明确声源时） |
| 存档规则 | 死后身上的东西都留在遗体上，保留物品栏也没用 | 死亡后，随身物品全部留在遗体上，不受保留物品栏规则影响 |

## 5. 合并方法和审查重点

- `zh_cn_AFL_GPT审校版.json`：完整参考语言文件（1,488 Key）。
- `AFL_中文本地化_修改对照.csv`：逐键列出建议变更、原文、英文与原因。
- 用**逐 Key 的三方合并**，不要直接覆盖当前 `zh_cn.json`：若当前游戏 Key 新增、删除或当前值已经发生修改，则仅把审校建议作为参考并列入冲突清单。
- 本批重要复核项：角色背景与特质名是否对应实际属性、属性倍率的正负方向、字幕音效来源、健康系统是否已经重做、枪械全自动模式是否保持不变、HUD 宽度与断行。
- 本文和中文审校稿属于文案质量基准，而非新的游戏设定。正式纳入仓库须由 Main 校验并经用户实机验收。
