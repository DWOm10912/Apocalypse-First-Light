# AFL 简体中文本地化规范 V1

**状态：V1 已冻结**（用户 2026-10-18 通过并冻结）。所有会话新增或修改中文文本，都按本文执行；已同步给 Main、C、D 等工作区。研究范围不再扩大，以后只做增量修订：术语表加词、润色批次的记录、用户新的决定。修订写进对应小节，并在报告里说明。

**怎么用这份规范（用户 2026-10-18）：** 规范里的"不要用"和禁用词是**提醒复查**，不是机械替换。改写不能为了口语化牺牲专业性、语境或机制准确性：枪械、电力、医疗、车辆的行业术语照用；说明里写清楚机制的句子，宁可书面一点也要准确。

用户决定（2026-10-18）：

1. 整体风格通过：冷静、具体、克制，使用自然的现代中文；不写广告腔、说明书腔，不做不必要的文艺化表达。
2. Stamina 暂时叫**「耐力」**。D 的「体力上限 / 体力恢复 / 移动耗体力 / 干活耗体力」驱动的是同一个资源（`PlayerStamina`），统一改为「耐力」。D 的「体能」是身体属性（fitness），不受影响。
3. 中文与英文、数字之间**继续加空格**，格式统一（第 2.4 节）。
4. **游戏世界里的道路、隧道、标牌用英文**；中文界面、物品名称和玩家提示用中文（第 2.6 节）。
5. 电力系统暂用**「线路互连」**，不改成「串电」。
6. 驾驶按键**单独分一类**，代码改动另排。
7. 音效字幕**不强制**全部写成"主体：动作"，按 Minecraft 官方中文的做法，**分声音类型定规则**（第 2.8 节）。
8. 人物死亡、幸存者背景、无线电和以后的剧情文本**单独做叙事审校**，不和普通界面文案混在一起（第 2.9 节）。

用户决定（2026-10-18，第二轮，看过 2077 文本研究以后）：

9. **核心原则：每种文本都像它真实所属的文本。** 这是 AFL 中文本地化和叙事写作共同的第一条原则（第 2.0 节）。

    - 人物可以有自己的幽默感：幸存者可以吐槽、自嘲、苦中作乐；战前广告可以有商业幽默。

## 2. 风格指南

### 2.0 核心原则：每种文本都像它真实所属的文本（用户 2026-10-18）

动笔之前，先回答三个问题：

1. **这是什么文本？** 界面提示、物品说明、报纸、便条、广告、公告、短信、说明书、广播、日记……
2. **谁写的？** 游戏界面、一家公司的市场部、镇政府、一个卡车司机、一个十几岁的孩子……
3. **写给谁看？** 玩家、顾客、居民、家人、自己……

**然后照那种文本在现实里的样子写：**

- 加油站促销就写成促销；
- 停电通知就写成停电通知，有时间、地点和电话；
- 卡车司机留的便条，就是一个卡车司机随手写的；
- 界面提示就是界面提示，一个动词就够（第 2.2 节）。

三个问题答不上来，就先不写。

下面各节的规则都服从这一条：

- 第 2.1 节的"不写广告腔"，说的是界面和说明不要写成广告；战前广告本身就是广告，就该写成广告。
- 第 2.2 节的语域表，是这条原则在界面文本上的具体写法。

### 2.1 总基调

- **冷静、具体、克制。** 末日感来自具体细节（"手脚冻得发麻""管线里没有油"），不靠形容词（"恐怖的""绝望的"）。
- **说人话。** 写法像一个干过活的成年人：会修车、会劈柴、知道配电盘。界面和说明不写说明书腔，不写广告腔，也不写文艺腔。游戏世界里的广告、说明书、公告这些文本，按第 2.0 节写成它们本来的样子。
- **克制不等于没有幽默。** 人物可以有自己的幽默感，战前广告可以有商业幽默。程度由人物、来源和情境决定（第 2.11 节）。
- **不堆梗、不堆脏话、不用网络流行语。** "貌似""给力""yyds""卧槽"一律不用。角色台词将来需要粗口时，按人设少量用，并由用户定。
- **玩家是"你"**，不用"您"。能省的代词就省。
- **专业名词按真实行业说法**（分闸、脱扣、卸油口、分动箱、制止力、运动霰弹枪）。名称和读数里一定用行业词；提示要短，用大白话；说明里说机制的地方，行业词比口语更准时就用行业词，不换成意思走样的俗话（2026-10-18 补：用户要求不为了口语牺牲专业性）。

### 2.2 按文本类型分语域

| 类型 | 键前缀（举例） | 写法 | 例子 |
|---|---|---|---|
| 方块 / 物品名 | `block.` `item.` `entity.` | 书面、行业标准名、成体系；不加"一款""一个" | 白栎原木、白栎木板、白栎台阶 |
| 交互提示 | `hint.` | 一个动词短语，2–4 字，不加读数、括号、"·"、"："；数值放到 Jade 或屏幕上 | 开门、添柴、拔下插头 |
| 按钮 / 菜单 | `screen.` `gui.` `survivor.*.newworld` | 2–4 字动词，和原版一致 | 取消、返回、创建世界 |
| 状态名 | `hud.*.status.*` | 名词或形容词，2–4 字 | 失温、热衰竭、湿透 |
| 状态效果 | `*.effect` | 短语用"，"并列，主语省略，口语；最多三项 | 耐力恢复更慢，走路慢，不会自己回血 |
| 读数 / Jade | `jade.` `screen.*.distribution_panel` | 状态词 + 读数，行业说法，不加感叹号 | 柴油 120 / 200 L、过载脱扣 |
| 物品说明 | `tooltip.*.description` | 一到两个短句，先说是什么，再说手感或代价；不写营销词 | 见 4.3 |
| 操作说明 | `tooltip.*.use` | 条件 + 动作，按"；"分步，最多两步；更多细节交给 Wiki | 见 4.3 |
| 体感消息 | `message.*.temperature` 等 | 第二人称体感，短，不报数字 | 你冷得发抖 |
| 事实消息 | `message.*.fuel_*` | 直接说结果或原因，不说"操作失败" | 油壶是空的、离加油口太远 |
| 字幕 | `subtitles.` | 按声音类型写，见第 2.8 节 | 储物柜：开门、喘气、雷鸣 |
| 死亡消息 | `death.attack.` | 沿用原版句式（X 被 Y 用 Z 杀死了 / X 饿死了 / X 在与 Y 战斗时……） | %1$s 冻死了 |
| 叙事 / 人物 | `survivor.` 死亡页、背景，无线电，剧情 | 单独审校，见第 2.9 节 | 以前跑长途，车坏了自己修，烟戒不掉 |
| 开发 / 命令 | `command.` `gui.*.hud_layout` | 可以书面、可以留术语，但不夹英文单词 | 被污染的物品：%2$s 组 |

### 2.3 翻译腔和 AI 腔清单

| 不要写 | 改成 | 说明 |
|---|---|---|
| 一款……的…… | 直接说名词 | 广告腔。全部 13 条物品说明都以"一款"开头 |
| 可显著提升 / 大幅降低 / 有效 | 说具体效果：打得更久、传得更近 | 营销词，空泛 |
| 能够、可以……的 | 能 / 会 | 冗长 |
| 进行 / 对……进行 | 直接用动词 | 弱动词 |
| 将 X 均分到 | 把 X 平均分到 | "将"是书面腔 |
| 被压倒的、被……所 | 主动句；名称里的"被"可以保留 | "被被不绝" |
| 的的的 | 拆成短句，或省掉一个"的" | 长定语 |
| 请不要……、请重试 | 别……、再试一次 | 太客气，不像在末日 |
| 暂无、当前、未…… | 没有、现在、还没…… | 系统腔，只在读数和标签里保留"无" |
| ……。（短句末尾） | 不加句号 | 原版和 AFL 的现行规则 |
| ……！ | 去掉感叹号 | 状态是事实，不是喊话 |
| 英文语序（X 的 Y 的 Z、定语后置） | 按中文习惯重排；拼接句用 `%1$s` 换位 | |
| 夹英文（Stack、HUD、QTE） | 中文：物品堆、界面、按键判定 | 品牌、型号和单位除外 |
| 貌似、给力、整活 | 好像、厉害 / 不错、（删掉） | 网络流行语 |

### 2.4 标点和排版

- **标点用全角**："，""：""（）""？""！"，引号用 `“”`。不用半角 `,` `:`。
- **短句、标签、按钮、提示、说明末尾都不加"。"。** 一条里要写两个独立的意思时，中间可以用"。"，末尾仍不加；更长的就分成两条。
- **空格：** 中文与数字、拉丁字母之间加一个半角空格（`最多 4 人`、`LED 壁灯`、`HR-55 战斗步枪`）。全角标点前后不加空格。占位符照常处理：`%s` 代入数字或英文名时两边加空格，代入中文词时不加（`和%s冲突`）。
  > 原版 Minecraft 中文的中英文之间不加空格（`%1$s被%2$s杀死了`）。AFL **有意和原版不同**，继续加空格（用户 2026-10-18 确认）。
- **单位：**
  - 数字和单位之间加空格：`20 L`、`5 kg`、`30 秒`、`20 °C`、`120 FE/t`；
  - `%` 和 `×` 例外，不加空格：`10%`、`×1.35`；
  - 口径是型号，不拆开：`9×19mm`、`7.62×51mm`、`12.7×55mm`、`.50 AE`、`12 号`。
- **省略号：** 界面上表示"进行中"或"打开新界面"的，用一个 `…`（同原版 `选项…`、`正在开始…`）；叙事里用 `……`。不用 `...`。
- **分隔符：**
  - `·` 只用在屏幕读数和创造模式标签页名里（`黎明启示录 · 枪械`、`第 3 路 · 绿`）；
  - 多选项之间用 ` / `（`两驱 / 四驱 / 低速四驱`）；
  - `|` 只用在开发命令里。
- **括号：** 名称里只用来区分变体（`垃圾箱（蓝色）`、`油桶（200 L）`）；提示里不用；说明里尽量不用。

### 2.5 和原版对齐的词

玩家在原版界面里天天看到的词，AFL 里同一个机制要用同一个说法。

| 原版 | AFL 现在 | 统一为 |
|---|---|---|
| 疾跑（`key.sprint`） | 冲刺 | **疾跑**（第一批已改） |
| 潜行 | 潜行 | 潜行（不用"蹲下"指代按键；"蹲下倒油"是描述动作，可以保留） |
| 物品栏 | 背包栏位 | 原版那 36 格叫"物品栏"；AFL 自己的格子叫口袋 / 胸挂 / 背包 |
| 标题屏幕 | 标题画面、标题 | **标题屏幕** |
| 允许作弊 | 允许命令（D） | **允许作弊** |
| 台阶 / 楼梯 | 台阶 / 楼梯 | 不变 |

### 2.7 占位符和键（任何润色都不能碰）

- **键名不改，也不增删。** en_us 和 zh_cn 逐行对齐，按段分组；新键放进对应的段。
- **占位符的个数、类型和编号不变**：`%s`、`%1$s`、`%%`。中文需要换语序时，只能用带编号的 `%1$s` 换位置，不改编号的含义。
- **`%%` 是字面百分号**，不能写成 `%`。
- **数值的含义不变。** 说明里不写代码里没有的效果，也不删掉原有的代价（比如"空仓换弹更慢"）。
- **按钮和 HUD 不能超出原有宽度。** 新文本比原文长 30% 以上的，要在游戏里看一眼有没有被截断。

### 2.8 音效字幕（按声音类型）

原版 1032 条中文字幕里，988 条（约 96%）写成"主体：动作"。剩下的有固定规律：

- 玩家自己的动作写成动词，如"进食""啜饮""游泳""划船""暴击"；
- 环境声写成名词，如"风声""脚步声""怪异的噪声"；
- 没有具体来源的事件也写成名词，如"雷鸣""电闪""爆炸"。

AFL 照这个规律写：

| 声音类型 | 写法 | 例子 |
|---|---|---|
| 某样东西发出的声音，或被操作的东西（门、柜、机器、车、枪、开关） | **东西：动作** | 储物柜：开门、柴油机：启动、断路器：跳闸、皮卡：鸣笛 |
| 持续运转的声音 | 东西：运转 / ……作响 | 冷柜压缩机：运转、炉火：噼啪作响、充电站：嗡嗡作响 |
| 玩家自己的身体或手上动作，没有明确对象 | **只写动作** | 喘气、呼吸、翻找、倒油 |
| 环境声、天气、没有明确来源的事件 | **只写名词** | 雷鸣、爆炸、风声 |

- **主体写玩家认得的那样东西。** 写"柴油机""皮卡""收音机"，不写"活塞""继电器线圈"。只有那个部件本身就是玩家听到的声音时，才写部件（油枪、断路器、分动杆）。
- **枪声写枪种，不写型号**：手枪：开火、步枪：消音射击。玩家靠字幕判断方向和威胁，不靠型号。
- **动作用 2–4 字。** 拟声词跟着"作响"（嘎吱作响、噼啪作响），不写"一响""了"。
- **优先用主动动词**："木桶：打开"，不写"被打开"。只有主动说法读着不对时才用"被"（同原版"物品：被拾起"）。

### 2.9 叙事文本（单独审校）

人物死亡、幸存者背景、开局场景、无线电，以后的剧情和对话，以及玩家打开来读的文件（第 2.6 节），都是**叙事文本**。它们和界面文案分开审：不放进 HUD、提示、名称这些批次，单独排一轮，由用户单独验收。

- **范围（键）：** `survivor.*.death.*`、`survivor.*.background.*`、`survivor.*.scene.*`、`survivor.*.mode.*` 的说明行、`survivor.*.trait.*` 的描述；以后的 `radio.*`、剧情和对话键；报纸、便条、日记、说明书、通知、短信、邮件和广播字幕的键。
- **语气：** 克制，不煽情。死亡页只说事实，不写"命运""终章"这类词。
- **人物口吻：** 背景描述用人物自己的口吻，按身份区分：卡车司机说话粗一点、直一点，店员细一点。人物可以有自己的幽默感（第 2.11 节）。少用俚语。粗口只在人物需要时用，每处都要用户定。
- **无线电：** 用应急广播的口吻：短句、时间、地点、指令，书面但不官僚。和玩家界面的口语是两种语域，不要混。
- **审法：** 放在游戏里的上下文里读，大声读一遍；看同一个人物前后口吻是否一致。叙事文本可以比界面长，但一屏之内要读完。

### 2.10 枪械背景文字（叙事类，建议稿）

枪的背景文字（lore）**和功能说明分开**：

- 功能说明（`.description`）只有一行，写这把枪是什么、怎么用、有什么代价；
- 背景文字写厂牌、手感、谁在用。

背景文字归入第 2.9 节的叙事审校。写法参考了《赛博朋克 2077》简中版的枪械描述，按 AFL 的克制基调收紧。完整规则和草稿见 [zh_cn_gun_flavor_text_v1.md](zh_cn_gun_flavor_text_v1.md)，要点如下：

- 60–120 字，现在时；
- 必须写厂牌、一个具体手感、一个代价；
- 结尾**不强制**冷幽默。这把枪、这家厂的口吻里有，就写；没有，就平实地收尾（第 2.11 节）；
- 不写年份、采购史、政治事件、粗口、网络梗；
- 不写会因平衡改动的数值，比如弹匣发数、伤害、射速；
- 同一家厂的枪按同一种性格写。

### 2.11 幽默和叙事风格（用户 2026-10-18 确认）

**AFL 的整体基调克制、写实，但不禁止幽默。**

《赛博朋克 2077》的黑色幽默是整部作品统一的讽刺腔：叙述者在笑这个世界。AFL 不用这种统一的腔调。AFL 里的幽默**属于文本里的人和文本的来源**，不是叙述者硬加上去的。研究和示例见 [cyberpunk2077_zh_study_v1.md](cyberpunk2077_zh_study_v1.md)。

**幽默的程度由三样东西决定：**

| 决定因素 | 怎么看 | 例子 |
|---|---|---|
| 人物性格 | 这个人平时会不会开玩笑，开什么样的玩笑 | 一个卡车司机在便条里吐槽路况和老板；一个护士的值班记录一个笑话也没有 |
| 文档来源 | 这种文本在现实里有没有幽默 | 汽水广告可以俏皮；停电通知一般不会；店员贴在柜台的手写告示可以带点脾气 |
| 情境 | 写的时候发生了什么事 | 日常琐事可以吐槽、自嘲；写给家人的最后一张字条通常不会开玩笑，除非这个人一辈子都这样 |

**按文本类型：**

| 文本 | 幽默 |
|---|---|
| HUD、提示、读数、按钮、功能说明 | 没有。个别彩蛋例外，比如 C.A.T |
| 物品、枪械、载具的背景文字 | 看厂牌和口吻：有就写，没有就平实收尾。**不强制每篇都加冷幽默** |
| 战前广告、包装、促销 | 可以有**商业幽默**：俏皮话、双关、夸张的推销语，就像真实的北美广告那样 |
| 战前公告、通知 | 一般没有。官方、具体、真诚。来源本身随意的除外，比如店员手写的告示 |
| 战后便条、日记、短信、无线电 | 按人物：可以**吐槽、自嘲、苦中作乐**；也可以一点都不好笑 |

**边界：**

- **不要叙述者统一的讽刺腔。** 不要每篇都去嘲讽世界、公司或者读者。讽刺可以出现在人物嘴里，比如一个对公司不满的员工在发牢骚，那是他的态度，不是 AFL 的立场。
- **死亡和灾难不轻佻。** 人物可以用黑色幽默扛事，那是他的性格；文本不能把死者当道具来逗乐。
- **企业不强行安排阴谋，但可以有现实中的矛盾：** 经营失败、产品召回、质量争议、劳资纠纷、管理混乱。写这类内容按企业档案第 0 节。重大政治事件、军事采购历史仍然不擅自补充。
- **不用网络梗，也不用带中国特定场景的俗语。** 通用俗语可以用。
- **夸张只出现在本来就夸张的文本里**，比如广告和人物吹牛。叙述性文字保持物理上站得住。
- **动植物名用中文正式名，不图好听。** 比如 coyote 是郊狼，不是野狼。
- **粗口、性内容、宗教讽刺**默认没有，每一处单独问用户。

## 6. 增量维护规范

1. **中英同时写。** 加新键时 en_us 和 zh_cn 在同一个任务里写好，放在同一段、同一行号。不要先写英文，以后再补中文。
2. **先查术语表。** 新词不在第 5 节里，就当场补进去（中文、英文、不要用），并写进任务报告。
3. **按第 2.2 节的语域写。** 先确定这条是哪一类：名称、提示、读数、说明还是叙事。
4. **自检清单**（提交前对改动的每一行）：
   - 占位符个数、编号和 `%%` 都和 en_us 一致；
   - 没有句末"。"、没有"！"、没有半角 `, :`、没有 `...`；
   - 中文与数字、拉丁字母之间有空格，单位格式符合 2.4；
   - 出现"一款、可显著、能够、进行、将、暂无、您、貌似"时复查一遍：多数是广告腔或翻译腔，要改；但它们在句子里准确、自然时可以留（比如"将"表示把，"暂无"在空列表里），不机械删；
   - 交互提示是一个动词短语，不带读数和括号；
   - 新文本比原文长 30% 以上的，或者是按钮或 HUD 文本，在游戏里确认没有截断。
5. **严重度**（参照 MQM）：
   - **致命**：占位符错了或少了；意思反了，误导玩家对机制或数值的理解；界面截断导致读不出来。不修不能提交。
   - **严重**：术语和表不一致；行业名称用错；字幕句式不对。当次修。
   - **轻微**：语气、标点、空格。可以攒着在润色轮一起改。
6. **原文改了，中文跟着改。** en_us 的某行意思变了，同一任务里改 zh_cn。改不了的，在任务报告里列出键名，标为"中文待复核"。
7. **只能自动查的就交给脚本（规划见 [lang_validation_plan_v1.md](lang_validation_plan_v1.md)，尚未实现）：** `tools/lang-lint.mjs` 检查以下几项。键、占位符、文件格式是错误级，必须修；风格类只出警告，由人判断：
   - 键对齐和行对齐；
   - 占位符一致；
   - 禁用词；
   - 句末句号；
   - 半角标点；
   - 数字空格；
   - 术语表里的"不要用"列。
8. **跨会话：** 本规范确认后发给所有会话。各会话新增中文都按本规范写；术语表要加词时，在报告里写明，由 Main 合进本文。
