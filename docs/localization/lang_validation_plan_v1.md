# 语言文件自动校验 · 规划 V1

- **状态：** 只是规划，**还没实现**（2026-10-18）。实现要等用户看过这份规划。
- **目的：** 把规范里能机器判断的规则交给脚本，人只看需要判断的地方。用户 2026-10-18 的要求：
  - 键、占位符、格式要自动校验；
  - 禁用词表不机械执行，所以风格类检查**只出警告、不拦提交**，由人判断。
- **依据：** [zh_cn_style_guide_v1.md](zh_cn_style_guide_v1.md) 第 2.4、2.7、5、6 节；批次 1 和批次 2 用过的手工检查（JSON 解析、行对齐、占位符、CRLF）。

## 1. 检查对象

| 文件 | 说明 |
|---|---|
| `src/main/resources/assets/apocalypse_firstlight/lang/en_us.json` | 基准。键集合、行号、占位符都以它为准 |
| `src/main/resources/assets/apocalypse_firstlight/lang/zh_cn.json` | 和 en_us 逐行对齐 |
| `src/dev/highway_mesh_resources/assets/afl_highway_demo/lang/*.json` | 开发演示，只做错误级检查 |
| 其他工作区（D 的 `feature/gun-proficiency` 等） | 用 `--root <工作区路径>` 检查那个工作区自己的文件，不跨工作区比较 |

现在的规模：1276 个键，1320 行（44 行是首尾括号和分段空行），两份行对齐；工作区里是 CRLF（仓库里存 LF，`core.autocrlf=true`），没有 BOM。

## 2. 错误级（必须修，退出码 1）

| # | 检查 | 怎么判断 | 为什么是错误 |
|---|---|---|---|
| E1 | JSON 解析 | 严格解析，不接受尾逗号、注释 | 解析失败整个语言文件不加载，全游戏显示键名 |
| E2 | 重复键 | 逐行扫描键名（`JSON.parse` 会静默保留最后一个，查不出来） | 后一个覆盖前一个，改了前一个看不到效果 |
| E3 | 键集合一致 | zh_cn 和 en_us 的键一一对应：缺的、多的都报 | 缺了显示英文或键名；多的是残留 |
| E4 | 行对齐 | 同一行号上是同一个键；分段空行的位置也相同；行数相同 | 规范第 6 节第 1 条：中英同段同行，方便对照和审校 |
| E5 | 占位符一致 | 抽出 `%s` `%d` `%n$s` `%%`：<br>• 带编号的：编号集合相同；<br>• 不带编号的：个数相同；<br>• `%%` 个数相同 | 少一个参数会显示错的数值；多一个会显示键名或报错。规范第 2.7 节 |
| E6 | 孤立的 `%` | `%` 后面不是 `s` `d` `%` 或 `数字$` | Minecraft 格式化失败时整条显示成键名 |
| E7 | 格式码一致 | `§` 格式码的个数和种类相同 | 颜色或样式错乱 |
| E8 | 空值 | 值是空字符串，或只有空白（白名单里登记过的除外；现在两份文件都没有空值） | 界面上出现空行或空标签 |
| E9 | 文件格式 | UTF-8 合法、没有 BOM、一个文件里不混用 LF 和 CRLF、缩进两个空格、文件末尾有换行 | BOM 和混合换行会让对齐检查和 diff 失真；Git Bash 的 `sed -i` 会悄悄把 CRLF 改成 LF（批次 1 遇到过） |

## 3. 警告级（提醒复查，不拦提交）

只检查 zh_cn。每条警告都写明规范出处，复查后觉得没问题的，登记进豁免表（第 4 节）。

| # | 检查 | 规则 | 规范 |
|---|---|---|---|
| W1 | 中英、数字之间的空格 | 汉字紧挨拉丁字母或数字；`%s` 紧挨汉字时只提醒（代入中文词时不加空格是对的） | 2.4 |
| W2 | 句末句号 | 值末尾是"。"（叙事类键前缀 `survivor.*.background` 等可以整体豁免） | 2.4 |
| W3 | 半角标点 | 汉字旁边的 `,` `:` `;` `(` `)` `!` `?` | 2.4 |
| W4 | 省略号 | `...`；以及界面键里的 `……`、叙事键里的 `…` | 2.4 |
| W5 | 感叹号 | 读数、提示、状态类键里的"！" | 2.2 |
| W6 | 术语"不要用" | 术语表（第 5 节）"不要用"一列的写法出现在值里，比如"草原加油站""冲刺""标题画面""HR55" | 5 |
| W7 | 需要复查的词 | "一款""可显著""能够""进行""暂无""您""貌似"等。**只提醒，不要求改**：这些词在句子里准确时可以留（批次 2 第 10 节有例子） | 2.3、6 |
| W8 | 口径和单位写法 | `毫米` 跟在口径数字后面；数字和单位之间没有空格（`20L`、`5kg`、`20°C`）；`%` 和 `×` 前后多了空格 | 2.4 |
| W9 | 长度 | 中文比英文长很多（按显示宽度，汉字算 2），或者按钮、HUD、提示类键超过设定宽度 | 6 第 4 条 |
| W10 | 字体覆盖 | 值里有游戏字体 `assets/apocalypse_firstlight/font/afl_sans_sc.ttf` 里没有的字。字体是按语言文件取字的子集（`tools/build-afl-sans-sc.py`），GB2312 以外的新字要重新构建字体 | `docs/ui/afl_font_v1.md` |
| W11 | 中英内容不同步 | en_us 的这一行在本次改动里变了，zh_cn 同一行没变（只在 `--changed` 模式下查） | 6 第 6 条 |
| W12 | 世界字样被翻译 | 术语表里登记的世界字样（路名、隧道名、城镇名、品牌字样 PRAIRIE / HALSTEAD 等）在标牌类键里被写成中文 | 2.6 |

## 4. 豁免和配置

- 配置文件：`tools/lang-lint.config.json`。JSON 不能写注释，所以每条豁免都要带 `reason`。
- 内容：
  - `exempt`：按键名或键名通配符（`survivor.*.background.*`）豁免某几条规则，例如：
    - `survivor.*.death.place` 豁免 W3（坐标用半角逗号）；
    - 叙事类键豁免 W2、W4 的界面规则；
    - 只有符号的值（`tooltip.*.stat.separator` 是"："，`tooltip.*.gun_ammo_row` 是 `%s`）豁免 W2、W3 这类标点规则。
  - `terms`：W6、W12 用的"不要用"和世界字样列表。**来源是规范第 5 节的术语表**；配置里的列表是它的机器可读副本，规范和配置改一处就改另一处（和企业档案第 6 节 ↔ 规范第 5.9 节一样）。
  - `review_words`：W7 的复查词。
  - `width`：W9 按键前缀设的宽度上限（按钮、HUD、提示）。
- **基线：** 现有的 1276 条里肯定有很多警告。第一次运行生成 `tools/lang-lint.baseline.json`，记下已有警告；以后默认只报新出现的。每改完一个润色批次，重新生成一次基线。

## 5. 运行方式

```bash
node tools/lang-lint.mjs
```

| 参数 | 作用 |
|---|---|
| （无） | 查 master 的两份语言文件：错误全报，警告只报基线以外的 |
| `--root <path>` | 查另一个工作区，比如 D 的 `D:/Minecraft Modding/AFL-survivor-v0` |
| `--changed` | 只查和 `git HEAD` 相比改过的行；加查 W11 |
| `--all-warnings` | 忽略基线，列出全部警告（润色批次挑条目时用） |
| `--update-baseline` | 重新生成基线 |
| `--json` | 机器可读输出，给其他脚本用 |

- **输出：** 每条一行：`文件:行号  键  规则编号  说明`，最后一行是错误数和警告数。只有错误级会让退出码变成 1。
- **依赖：** 只用 Node 自带模块（仓库的 `tools/*.mjs` 都是这样，本机 Node v24）。W10 读字体的 cmap 表，自己解析 TTF，不加 npm 依赖。
- **不加进 `build`、`runClient`：** 校验失败不能挡住开发版启动。

## 6. 接入点

| 接入点 | 怎么做 | 建议 |
|---|---|---|
| 手动 / 会话的完成标准 | 改了语言文件的任务，报告前跑一次，结果写进报告。写进 AGENTS.md 的 Chinese Localization 一节 | **先做这个** |
| Gradle | 加一个 `langLint` 任务，挂在 `check` 下面（不挂 `build`），调用 `node tools/lang-lint.mjs` | 第二步 |
| Git pre-commit 钩子 | 放一个 `tools/hooks/pre-commit` 示例，只在暂存区里有语言文件时运行，只拦错误级 | 只提供，不替用户装：提交由用户自己管，装不装由用户决定 |
| 代码引用检查 | 扫 Java 里 `Component.translatable("…")` 的字面量键，报语言文件里不存在的键（警告级；拼接出来的键查不到，只能查字面量） | 第三步，可选 |

## 7. 实现分步

1. **P1 错误级：** E1–E9，加 `--root`。用当前 master 的语言文件跑，应该是 0 个错误（批次 1 手工检查过对齐和占位符）。另做几份故意出错的小样例文件，确认每条规则都能报出来。
2. **P2 警告级 + 配置 + 基线：** W1–W9、W11、W12，生成第一份基线。顺便把全部警告按规则列出来，交给下一个润色批次挑条目。
3. **P3：** W10 字体覆盖、代码引用检查、Gradle `langLint` 任务。
4. 每一步做完，更新本文和规范第 6 节第 7 条的状态。

## 8. 不做的事

- 不自动改文本。没有 `--fix`：标点、空格看上去机械，但占位符旁边、坐标、型号里的写法都要人看。
- 不检查语气、不打分。风格交给人和润色批次。
- 不检查原版的语言文件，也不检查第三方模组的文件。
