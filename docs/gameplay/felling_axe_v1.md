- **状态（2026-10-20）：** 已实现，在分支 `AFL-Workbench`（B 的工作区 `D:/Minecraft Modding/AFL-vanilla-rework`），没有合并。只能从创造模式物品栏拿，没有配方（配方重做之前不加配方）。

  - 第二版（同日）：按玩家比例放大，加骨骼挥砍，接入砍树，砍口每一斧开在玩家砍的那一面。`compileJava --offline` 通过，生成脚本 `--check` 通过，离线姿势检查见第 6 节；**没进游戏看过**。

## 1. 参考

美国密歇根款伐木斧（Michigan pattern）：3.5 磅（约 1.6 kg）锻钢斧头，32 英寸（81 cm）弯曲山核桃木柄。新斧出厂时斧头涂黑漆，刃口磨亮。

挥法按现实里双手劈砍的做法：左手一直握在柄尾，右手举起时握在柄上部，往下劈的时候滑到左手旁边；从右肩上方斜着向左下劈进树干，身体先往右转、往后仰，再转过去、往前压。没有另外找视频。

## 2. 模型

`tools/build-equipment-meshes-v1.mjs` 的 `fellingAxe()`，和撬棍同一个坐标系（柄沿 +Y，刃朝 −X，z 是厚度方向），比例 1 px = 1.25 英寸。

- **柄**（`handle`）：长 25.5 px，椭圆截面，宽面朝刃的方向。
  - 半宽 / 半厚：底端柄尾 0.72 / 0.5，鼓起处 0.62 / 0.43，中段 0.5 / 0.36，靠近斧头处加宽到 0.62–0.7，斧眼里 0.7 / 0.3。
  - 中段向斧背方向弯 0.25 px，底端的鹿蹄形柄尾向刃的方向勾 0.3 px；穿过斧眼的那段是直的。
  - 顶端穿出斧头 0.18 px，端面颜色更深，中间一条浅色楔子。
- **斧头**（`head`）：从斧背平面到刃口，每个 x 站点一个竖直的透镜形截面（每侧 8 个点，上下边倒角 0.1），14 个站点放样。
  - 斧背 x = 1.52，刃口中部 x = −4.08，刃线向外弯 0.14 px（弧形刃）。
  - 高度：斧眼一段 ±0.92 px；往刃口展开，上沿升到 +1.52，下沿（斧胡）降到 −2.08（以斧眼中心为准）。
  - 厚度：斧背半厚 0.5，斧眼 0.52，两颊凸面从 0.52 收到 0.09，最后 0.58 px 是磨出来的刃口斜面，收到 0.008。
  - 斧背平面倒角，颜色是磨掉漆的钢。
- **材质**（LabPBR）：

| 材质 | 部位 | Base Color | 光滑度（开放 / 棱边） | F0 |
|---|---|---|---|---|
| `enamel` | 斧头 | [46,46,48] 黑漆 | 112 / 132 | 22 |
| `bit` | 刃口斜面 | [150,152,156] 磨亮的钢 | 140 / 160 | 230 |
| `poll` | 斧背平面和倒角 | [108,110,112] 磨掉漆的钢 | 96 / 118 | 230 |
| `hickory` | 柄 | [158,122,82] 上过油的山核桃木，沿柄长的木纹 ±8 %，细纹 ±3 % | 108 / 120 | 20 |
| `endgrain` | 柄顶端面 | [118,84,52]，年轮线平行于刃，中间楔子 [150,116,78] | 70 / 80 | 20 |

- 1038 个三角面，512 贴图集（每 px 20 个贴图像素），尺寸 5.734 × 25.92 × 1.04 px，共面 0。
- 输出：`src/main/blockbench/felling_axe.bbmodel`、`geo/felling_axe.geo.json`、`meshes/felling_axe.aflmesh.json`、`models/item/felling_axe.json`、`textures/item/felling_axe{,_mesh,_mesh_s,_mesh_n}.png`、HUD 近战剪影 `textures/gui/melee/felling_axe_hud.png`（侧视，斧头在左、刃朝上，和撬棍一样）。
- 显示变换：从撬棍的改来，第一人称、第三人称的比例乘 1.48（第一人称 0.75 → 1.1，第三人称 0.7 → 1.03），和骨骼道具的放大一致；只有不走骨骼的地方用得到。地上、展示框不变。物品栏图标是同一个模型渲染出的 64×64 平面图（2026-10-22 合并进 master 时从 B 分支的 256×256 改成 master 的画法，见 [材料网格](../models/material_meshes_v1.md)「物品栏图标」）。
- 渲染：`client/AflStaticMeshItemClient` 绑定 `felling_axe` / `felling_axe_mesh`，竖直偏移 −0.31（0.5 − 25.92 / 32）。

## 3. 物品

`item/FellingAxeItem`（继承 `AxeItem`），注册 `AflItems.FELLING_AXE`，创造栏"近战与装备"，放在撬棍后面。

| 项目 | 值 | 说明 |
|---|---|---|
| 材料等级 | 自定义 `FellingAxeItem.TIER`：速度 6，等级 2，耐久 800，附魔值 0，不能修理 | 速度 6 = 砍树力度 1（`FellingRules.power` = √(速度 / 6)），和原版铁斧一样 |
| 砍树 | `AxeItem` 自带 Forge 的 `AXE_DIG`，`tree/FellingServer` 认它是斧头 | 每砍一下消耗 1 点耐久；一斧 1 秒（第 5 节） |
| 近战 | 伤害 8（玩家基础 1 + 7），每秒 0.8 下（基础 4 − 3.2，25 tick 一下） | 加进 `tags/items/weapons/melee.json`，快捷栏近战位能放；原版斧打生物消耗 2 点耐久 |
| 右键方块 | 不做任何事（`useOn` 返回 PASS） | 不能去皮、刮铜锈、去蜡 |
| 重量 | 2.3 kg | `item_mass/core_v1.json`，估计值 |
| 网格背包 | 1×3 | `item_size/core_v1.json`，和撬棍一样 |
| 挥砍体力 | 10 | `stamina/stamina_v1.json` 的 `melee_items`（撬棍 8）；砍树仍用 `costs.chop` |
| 名字 | Felling Axe / 伐木斧 | `lang/en_us.json`、`zh_cn.json` |

没有加进 `#minecraft:axes`：AFL 不改原版标签，近战标签直接写了这把斧。

## 4. 大小和持握（AFL 骨骼）

道具、两个动作都由 `tools/author-felling-axe-actions.mjs` 写出（`--check` 查是否过期，`--report` 用 AFL Rig 插件里和游戏同一套的姿势求解器打印检查数字）。

- **道具** `player_props/felling_axe.json`：
  - 比例 **0.75**（第一版 0.508）。0.508 是真实的 32 英寸斧：在方块人手里只有 13 个模型像素，斧头 1.8 px，比 4 px 的手还小，所以看着很小。现在 25.5 px 的柄 = 1.2 格，斧子长度是玩家身高的六成多，斧头 2.7 px，和手差不多大，和原版工具在手里的观感接近。
  - 握点（离柄尾的距离，烘焙后 px）：`grip_end` 2.8（左手，紧挨柄尾鼓起的地方），`grip` 8.3（右手往下滑到左手旁边，劈下去时），`grip_high` 13.1（右手在柄上部，持握和举起时）。手有 4 px 高，等于 5.3 px 的柄，两只手正好并排。另有 `end`、`top`、`eye`、`edge`、`poll`。生成脚本的 `points` 和它保持一致。
- **持握** `player_actions/item/felling_axe.json`：撬棍的静止姿势，左手留在第一版的位置（腹部左侧），柄斜向右前上方，右手在柄上部、胸口右侧，斧头在右肩前上方。斧子变大以后右手和斧头都离得更远，左右手都还够得着（离握点 0.00 / 0.03 px）。
- 第一人称、第三人称都用骨骼（`first_person: body`）。左撇子按道具的 z 对称镜像。

## 5. 挥斧和砍树

### 5.1 动作 `tool/felling_axe_chop`

一斧 1.0 秒，从持握开始、回到持握结束，换动作时不跳。手臂由 IK 抓在道具的握点上，身体用片段 `tool.felling_axe_chop`（`tools/author-player-actions.mjs`，遮罩 `upper`，优先级 60）。

| 时间 | 斧子 | 身体 |
|---|---|---|
| 0 | 持握 | 不动 |
| 0–0.2 | 往右边甩出去（先把斧头移到头的外侧，不擦过头） | 开始往右转 |
| 0.2–0.4 | 举到右肩上方：双手在脸的右侧，斧头朝后上方 | 胸口右转 32°、后仰 6° |
| 0.4–0.55 | 从右上斜着劈到左下，**从静止加速，砍进去时最快**（关键帧 `ease: in`）；右手滑到左手旁边 | 转到左边 12°、前压 14° |
| 0.55 | **砍进树里**（服务端在这一刻结算） | |
| 0.55–0.6 | 斧头吃进木头，再往里一点就停 | 前压 15° |
| 0.6–0.75 | 拔出来，往回一点 | 起身 |
| 0.75–1.0 | 回到持握，右手最后 0.15 秒滑回柄上部 | 回正 |

- 劈下去那一段的转轴是举起和砍中两条柄线的公垂线，所以刃口一直顺着挥的方向走。
- 砍中时斧头在身前约 1 格、离脚 0.65 格高；平视时在画面下方外面，低头看树根（35°）时在画面中间偏下。
- 为了这个动作，道具关键帧加了 `ease`（`smooth` 默认 / `in` / `out`，`skeleton/action/ActionPose.keyEase`，插件预览同步；见 `docs/dev/player_actions_v1_plan.md`）。
- **镜头**（`tree/FellingSwingClient.cameraShake`，接在镜头导演的晃动层）：自己第一人称挥斧时，举起时视角抬 1°，劈下去时往下带 1.8°，砍中时一下 3 tick 的震动（和撬棍砸击同一条曲线），斧子回来时视角也回来。

### 5.2 什么时候播放

`client/skeleton/SkeletonActions` 主手是伐木斧时按顺序选：

1. **砍树的一斧**（`tree/FellingSwingClient` 的时钟）：自己的在客户端发出这一斧时当场开始，别的玩家的在服务端通知到达时开始。
2. **近战挥砍**：原版的攻击挥手刚开始时，播放同一个动作，快 2.2 倍（0.45 秒，砍中在第 0.25 秒）。伤害还是按原版在点击那一刻算，动作只是表现。砍完一斧 0.3 秒内不算近战（原先按住砍树时原版一直在挥手；2026-10-20 起砍树不再有原版挥手，见 5.3，这条留着防万一）。
3. 其余时间是持握。

### 5.3 砍树的节奏（`tree/FellingRules`、`FellingClient`、`FellingServer`）

- 对着树干底部左键挥一斧，按住不放就上一斧挥完接着挥下一斧。一斧 20 tick（`CHOP_TICKS`），第 11 tick 砍进去（`IMPACT_TICKS`）。之前是按住每 10 tick 砍一刀，没有挥斧的过程。
- 客户端发出时（`TreeNetwork.Chop`）服务端先查一遍（够得着、主手是斧头、是站着的树、同一名玩家同时只能有一斧、离上一斧开始至少 18 tick），然后告诉附近的玩家（`SWING` 消息，协议 4 → 5），11 tick 后落下时整套再查一遍才算一刀（账本两刀至少隔 16 tick）。落下时人下线了或主手已经不是斧头，这一斧落空。
- 服务端不再调原版的挥手广播。
- 原版挖掘完全不插手（2026-10-20，用户："删掉原版的，不然有点出戏"）：拿斧头对着能砍的树干按下或按住攻击键时，`FellingClient.attackKey` 在 Forge 的 `InputEvent.InteractionKeyMappingTriggered` 里把这一下攻击拿走（取消，不挥手），在那里开始挥斧。原版的挖掘就不会开始：没有每 4 tick 一次的挖掘敲击声（这个声音在原版代码里比 Forge 的"按住挖掘"事件先播，拦那个事件拦不住），没有方块碎屑粒子，也没有原版挥手。生存、创造一样。没拿斧头时照旧走原版挖掘（挖不动）并提示"需要斧头"。
- 每刀的功、耐力（`costs.chop`）没改，所以连续砍的速度减半，砍倒一棵树用的时间大约翻倍，每秒耗的耐力减半。这是所有斧头共用的规则，不只是伐木斧；动画只有伐木斧有，其他斧头还是原版挥手。

### 5.4 砍口在玩家砍的那一面

- 每一斧落下时重新判（`FellingRules.hitSide`）：从玩家眼睛沿视线的水平方向，先碰到切口处树干圆周的那个点就是砍到的地方，取 8 个方向里最近的一个；看偏了，取圆周上离视线最近的点；正好看着树心往下，取朝玩家的一面。
- 树干中心用树形在切口高度的真实轴线（`FellingServer.trunkCentre`，跟着树的朝向转），声音和木屑也在那里。之前用的是格子中心，而且只在第一刀定一次方向。
- 换个方向砍，砍口转过去，已经砍下的进度（阶段）不变；倒树方向的规则没改。

- 静止时照旧由区块画（`WoodGunRackChunking` 的录制认 `entityCutoutNoCull`）。
