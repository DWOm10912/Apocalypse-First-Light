# 幸存者开局模板池：架构决定

状态：**架构决定（用户 2026-10-14，同日补充模板类型），未实现。** 本轮只记录决定：模板系统、模板内容和开局演出都没有做，当前 V0 的继任流程（`survivor_death_succession_v0.md`）保持不变。记录位置：Worktree `AFL-survivor-v0`（分支 `feature/survivor-v0`，未合并）。

## 1. 决定

- 首次创建角色和死亡后的随机继任，共用同一套「幸存者开局模板池」，不分别开发两套开局系统。
- 共用的是同一套框架：幸存者背景、人物身份、初始物资、过场演出。还有出生安全检查。
- 结构生成方式可以不同（补充决定）：首次开局可以生成专属结构，死亡继任只用世界里实际存在的地点（第 2 节）。最初一版决定写的是“共用结构选址”，以本条为准。
- 首次开局：玩家可以选择州、背景模板，或者随机。
- 死亡继任：系统只从当前世界条件下合法、并且允许继任的模板里随机抽取。人物姓名、外貌和具体出生位置另外随机确定，不跟模板走。
- 继任池只有独立行动的普通幸存者。幸存者营地居民、聚落 NPC、商人和重要剧情人物全部排除，玩家不能接管。
- 继任时由服务器确定并保存人物身份、皮肤、模板和出生位置。客户端按模板播放实时演出；跳过演出不能重新抽取。
- 目标是几十套模板，每套有背景、初始场景、随机出生位置、基础物资和实时过场。首版先沿用 V0 的继任流程，模板和演出以后逐步增加。

## 2. 模板类型与继任禁令

| 类型 | 用途 | 进入继任池 | 条件 |
|---|---|---|---|
| 专属结构型 | 首次开局，可以生成专属住宅或基地 | 默认不进入 | 只在合适的地形上生成 |
| 既有建筑型 | 在世界里现有的建筑中随机继任 | 可以 | 接手时检查建筑仍然存在、出生位置安全；不重建被玩家拆掉的建筑 |
| 开放环境型 | **死亡继任的主要来源**：公路、荒野、城市街道、山区等 | 可以 | 必须依赖世界里实际存在的合法环境 |

死亡继任**绝对不能**：

- 强制重新生成初始小屋；
- 修复玩家拆毁的建筑；
- 覆盖玩家建造的基地；
- 重置已经搜刮过的物资；
- 在错误的地形上生成专属结构；
- 重复生成可以无限获取的高价值物资。

最后一条意味着：继任时发的初始物资不能被“反复死亡刷物资”利用。前任的东西都留在遗体上（V0 第 8 节），所以每位继任者的物资都会在世界里累积。

选中的候选地点不再合法时，先换候选地点，再换其他合法模板。

**首发回退**：首发继续用 V0 现有的安全野外出生（`wilderness_ring`，再不行就用原版出生点兜底，V0 第 5 节）作为回退。不为了做完整模板池而阻塞死亡系统的验收。V0 的继任只传送玩家、不放置也不改动任何方块，已经满足上面的禁令。

## 3. 多人与困难模式

- 普通模式：单人和多人用同一套随机继任，不开发团队传承，不设全员阵亡判定，也不需要队友接应。
  - 任何玩家死亡后，原角色永久死亡，该玩家独立随机接管另一名幸存者。其他玩家的生死和在线状态都不影响继任。
  - 全部在线玩家同时死亡，世界也不结束，各自照常继任。设定：联邦境内还有很多幸存者，大多单独行动。
- 困难模式：暂时沿用现有的个人永久死亡（V0 第 10 节），不加团灭逻辑。

## 4. 模板字段

用户定义每个模板统一包含下表的字段。“负责”按第 6 节的分工；没有明确归属的写“未分配”，在统一契约时再定。

| 字段 | 说明 | 负责 | V0 现状 |
|---|---|---|---|
| 模板 ID | 稳定，存档按它引用模板 | C、D 共同（契约） | 没有 |
| 模板类型 | 专属结构型 / 既有建筑型 / 开放环境型（第 2 节） | C、D 共同（契约） | 没有；V0 只相当于一个“开放环境型（荒野）” |
| 允许的州与自然环境 | 州用联邦分支的稳定 ID `s1`..`s6`（`FederalStateId.key()`）；自然环境的写法待定 | C | 没有；V0 不认识州 |
| 出生位置与结构条件 | 需要什么结构、什么地形；既有建筑型还要能判断建筑仍然存在 | C | 只有野外环 `wilderness_ring` 和出生安全检查（V0 第 5 节） |
| 角色背景 | | D | `SurvivorRecord.Background` 预留，为空 |
| 初始物资 | 继任时不能是可以反复刷的高价值物资（第 2 节） | 未分配 | 继任者空手开始（V0 第 8 节） |
| 可选职业与身体特质 | | 未分配 | `Profession` / `Traits` / `Body` 预留，为空；职业、特质、身体系统都还没有 |
| 开局演出 ID | 客户端按它播放实时演出 | D | 没有；V0 只显示标题“姓名”和副标题“第 n 位幸存者” |
| 适用的世界时间阶段 | “阶段”怎么划分待定 | 未分配 | 没有 |
| 是否允许进入随机继任池 | 专属结构型默认不允许；不允许的模板只能在首次开局时选 | C、D 共同 | 没有 |

不在模板里、每位幸存者单独随机的：

- 姓名、性别、外貌：D。V0 已有固定名册 `SurvivorRoster`：60 人，每人一个全名和一套只画基础服装的皮肤，先抽性别，同一世界里一个人只出场一次。
- 具体出生位置：在模板条件里选点，C。V0 是 `SurvivorSpawns`。

首位幸存者的身份仍按 V0 第 13 节：账号名或自定义昵称，账号皮肤。模板池只决定首位幸存者的背景、位置、物资和演出。

## 5. 目标流程

首次开局：

1. 玩家选州、背景模板，或者随机。在哪个界面选还没定。
2. 按州、环境和时间阶段过滤出合法模板，选址（C）。专属结构型在这时生成结构。做出生安全检查（共用）。
3. 建立首位幸存者记录（V0 第 13 节），发初始物资，播放开局演出。

死亡继任：

1. 死亡瞬间：
   - 过滤出合法并且允许继任的模板，随机抽一个；
   - 随机姓名和外貌，规划出生点；
   - 和 V0 一样立刻写盘，记录里多存模板 ID。
2. 重生接手：
   - 精确落地，做出生安全检查；既有建筑型还要确认建筑仍然存在；
   - 不合法就换候选地点，再换其他合法模板，最后用野外回退（第 2 节）；
   - 发初始物资；
   - 客户端按模板播放演出。跳过不改变任何已决定的内容。

V0 已经在死亡瞬间决定并保存继任者的姓名、外貌和出生规划点（V0 第 5 节），所以“跳过动画不能重抽”对这几项已经成立。以后只需把模板 ID 也放进同一次决定。

V0 接手时也已经是“规划点不行就试后面的候选，最多 8 次落地检查，最后兜底”（V0 第 5 节）。“换候选、再换模板”可以接在这个循环上。

## 7. 契约待定项

实现前由 C、D 一起定下面这些：

1. **模板的载体**：数据包 JSON 还是代码注册；一个模板一个文件，还是 C、D 各写一部分再合并。
2. **模板 ID 的格式**，以及删掉某个模板后，旧存档里引用它的记录怎么处理。
3. **州和自然环境条件的写法**：
   - 州用 `s1`..`s6`；
   - 环境用生物群系标签，还是联邦模板的地貌主题。
4. **选址接口**：
   - 输入是模板、世界和随机种子，输出是出生规划点；
   - 死亡时规划不能加载或生成区块（V0 第 5 节），带结构条件的模板也要满足这一点。
5. **既有建筑的判定**：
   - 怎么确认建筑“仍然存在”（结构记录加接手时的方块检查？）；
   - 怎么识别被玩家拆毁的建筑和玩家建造的基地，让继任避开。
6. **世界时间阶段**的定义。
7. **初始物资、职业和特质**归谁负责；继任物资的价值上限怎么定，才不能反复刷。
8. **首次开局在哪个界面选**：创建世界界面，还是第一次进入世界时。
9. **没有合法模板时怎么办**：首发已经定为 V0 的野外回退（第 2 节），契约只需确认这条退路的接口。

D 侧初步意见：

- 记录里只存模板 ID 字符串。读档时遇到不认识的模板 ID 不报错：已接手的人照常玩，等待接手的人退回 V0 的野外环继任，跳过演出。
- 姓名和外貌继续由 D 随机，不进模板文件。

## 8. 现有 V0 代码里的接入点

| 接入点 | 位置 | 以后的用途 |
|---|---|---|
| 预留字段 `OriginState` / `Background` / `Profession` / `Traits` / `Body` | `SurvivorRecord` | 存模板给出的背景、职业、特质；模板 ID 要新增字段 |
| 出生点提供器 | `SurvivorSpawnProvider`、`SurvivorSpawns.register` | 按模板选址的提供器插在 `wilderness_ring` 前面；`wilderness_ring` 留作首发回退 |
| 接手时的落地重试 | `SurvivorSpawns`（最多 8 次落地检查，最后兜底） | 接上“换候选、再换模板” |
| 姓名、外貌 | `SurvivorRoster`（名册） | 不变，和模板分开选 |
| 死亡瞬间决定并写盘 | `SurvivorRecord` 的 `PENDING` 状态 | 加上模板 ID，保证跳过演出不重抽 |
| 接手时的标题 | 继任接手（`PlayerRespawnEvent`） | 换成或接上模板的开局演出 |
