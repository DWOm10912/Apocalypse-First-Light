# 幸存者死亡与随机继任 V0

状态：**开发中（独立 Worktree `feature/survivor-v0`，未合并 Main）**。只做过一次离线编译检查，见文末“验证”；没有实机测试，下面写的是代码行为，不是实机结论。

首次公开测试的 P0：玩家扮演的是“一个幸存者”，不是不死的账号。幸存者死亡是永久的；普通模式由随机继任者接手同一世界，困难模式整局结束。

代码：`src/main/java/com/antaurora/apofirstlight/survivor/`。

## 1. 范围

本轮包含：模式数据、幸存者身份与生命记录、死亡接入、状态重置、持久尸体与搜刮、随机继任、困难模式终止、AFL 死亡结算界面。

本轮不包含：Mesh 人物、骨骼、IK、布娃娃、腐烂、死亡镜头、过场、剧情模式、技能系统、职业/特质/身体系统、出身州与背景的实际内容。

## 2. 模式

`SurvivorMode`：`UNSET` / `NORMAL` / `HARD`，存在世界的幸存者数据里，与原版难度和原版极限标志分开。一旦确定就锁定，游戏内没有任何途径改回。

| 情况 | 模式 |
|---|---|
| 原版极限（hardcore）世界 | 固定 HARD，不询问 |
| 专用服务器新世界 | 读 SERVER 配置 `apocalypse_firstlight-survivor.toml` 的 `dedicatedServerMode`（默认 NORMAL），只读一次 |
| 本系统出现前就存在的世界（没有 fresh 标记） | 开服时直接定为 NORMAL |
| 单人新世界 | 保持 UNSET，等房主首次进入时选择 |
| 选择前就有玩家死亡 | 锁定为 NORMAL，日志警告 |

“新世界”由 `LevelEvent.CreateSpawnPosition` 判定（只在创建世界时触发；Terrain V2 会取消这个事件，所以监听时 `receiveCanceled = true`），写入 `freshWorld`。

| 模式 | 死亡后 |
|---|---|
| NORMAL | 该幸存者永久死亡；世界继续；死亡瞬间决定一位随机继任者，重生即由继任者接手 |
| HARD | 该幸存者永久死亡；该玩家这一局结束；不再生成继任者，不能重生；世界保留作纪念存档，不删除任何东西 |

没有剧情模式。

## 3. 数据结构

世界数据 `SurvivorWorldData`（`SavedData`，跟随主世界保存为 `<世界>/data/apocalypse_firstlight_survivors.dat`）：

- `Mode`：模式；`Fresh`：新世界标记。
- `Lineages`：每个账号 UUID 一条“传承”（`SurvivorLineage`）：账号名、状态、全部生命记录（旧→新）、最后一位死者的床位置。
- 传承状态：`ACTIVE`（当前幸存者存活）、`AWAITING_SUCCESSOR`（NORMAL：已死亡，继任者已决定，等待重生）、`ENDED`（HARD：结束）。

生命记录 `SurvivorRecord`：

| 字段 | 含义 |
|---|---|
| `Id` | 幸存者唯一 ID |
| `First` / `Last` | 姓名 |
| `Life` | 职业生涯序号：该玩家在本世界的第 n 位幸存者，从 1 开始 |
| `Roll` | 生成该幸存者的随机种子（审计用） |
| `State` | `PENDING`（已决定未接手）/ `ALIVE` / `DEAD` |
| `StartGame` / `StartDay` | 开始的世界游戏刻 / 世界日时间 |
| `DeathGame` / `DeathDay` | 死亡的世界游戏刻 / 世界日时间 |
| 存活天数 | `(DeathDay - StartDay) / 24000`，不小于 0（按世界日时间计，睡觉跳过的夜晚也算） |
| `Cause` / `CauseId` | 死亡消息（Component JSON，受害者名字换成幸存者姓名）/ 伤害类型 msgId |
| `DeathDim` / `DeathPos` | 最终死亡维度与方块位置 |
| `Corpse` | 尸体 ID |
| `PlanX` / `PlanZ` | 继任者出生规划点（死亡时决定，不加载区块） |
| `SpawnDim` / `SpawnPos` / `SpawnSource` | 实际出生点与来源（提供者 ID、`fallback` 或 `initial`） |
| `OriginState` / `Background` / `Profession` / `Traits` / `Body` | 预留字段，V0 一律为空，没有任何系统读取 |

玩家自身持久数据根下写入 `apocalypse_firstlight:survivor_id`（该玩家存档属于哪位幸存者），用于识别崩溃后过期的玩家存档。

## 4. 死亡流程（服务器权威）

只有生存/冒险模式的玩家受幸存者规则约束；创造/旁观模式死亡保持原版。

1. `LivingDeathEvent`（最低优先级；被其他模组取消的死亡不处理）：
   - 当前记录必须是 `ALIVE`，否则什么都不做——记录状态本身就是防重复结算的账本，同一幸存者第二次死亡事件不会再结算。
   - 写入死亡时间、死因、位置；记住床位置后清除玩家的重生点（重生不会回到旧床，新身体也不会继承它）。
   - NORMAL：传承进入 `AWAITING_SUCCESSOR`；HARD：传承进入 `ENDED`。
   - 建立尸体记录（第 6 节），尸体实体立刻出现。
2. `LivingDropsEvent`（最低优先级，被取消的也处理）：原版掉落和 Curios 加入的掉落全部收进尸体，世界里不生成掉落物；身上剩下的（keepInventory、Curios 保留规则、装饰栏）也一并收走（第 8 节）。
3. `PlayerEvent.Clone`（最低优先级，在 Curios 复制栏位之后）：兜底检查新身体，任何被其它逻辑带过来的物品移进同一具尸体并记日志。
4. 本服务器刻结束时：先立刻写入幸存者数据文件，再保存所有玩家存档（`PlayerList.saveAll()`）。
5. 登录核对：玩家存档里的幸存者 ID 在世界数据中已是 `DEAD`、而存档里的玩家却活着，说明服务器在两次写入之间停止，玩家存档早于死亡。此时清掉存档里的过期物品（它们已在尸体里），把玩家恢复为死亡状态，照常进入死亡界面与继任流程，不会复制物品。反过来（玩家存档已写、幸存者数据未写）只会丢失这次死亡的尸体，不会复制。

首位幸存者：玩家第一次进入世界时随机生成（只有姓名），记录开始时间，来源 `initial`。V0 不提供姓名选择。

## 5. 随机继任（NORMAL）

**死亡瞬间决定，立即持久化。** 死亡记录写入的同一刻生成继任者（`PENDING`）并决定出生规划点，随幸存者数据一起写盘；重登、重启都读回同一个人，不会重抽。

- 姓名：`SurvivorNames`，60 个名 × 60 个姓（北美常见、混合族裔，对应哥伦比亚联邦的人口），连续两位不会同名同姓。种子 = 世界种子 × 账号 UUID × 生涯序号，确定性。
- 玩家不能选择姓名、职业、州、地点或能力。V0 **只随机姓名和出生点**；职业、特质、身体、出身州、背景只是预留字段，没有实现对应系统，随机姓名不等于职业 / 能力系统。
- 出身州与背景以后只在建立世界时选择；州尚未完成，代码里不写任何州或建筑的名字。

出生点（`SurvivorSpawns`，总在主世界）：

1. 死亡时规划（不加载、不生成区块）：出生点提供器（`SurvivorSpawnProvider`）依次给候选列，粗筛条件：
   - 世界边界内且离边界 ≥ 32 格；
   - 离死亡点 ≥ 192 格，离旧床 ≥ 128 格；
   - 自然辐射区不是重度沉降或极端；
   - 有 Terrain V2 规划时：干地（水类 0）、离岸 ≥ 24 格、坡度 ≤ 0.25；
   - 生物群系（噪声采样）不是海洋、深海、河流、沙滩。
   第一个通过的列存为规划点。
2. 接手时（重生）精确落地：加载 / 生成该列区块，取最高的非树叶实心方块：不是液体、树叶、原木、AFL 树、火、营火、岩浆块、仙人掌、细雪、甜浆果丛；站立空间无碰撞，身体周围 0.5 格内无液体。规划点不行就继续后面的候选，最多 8 次落地检查。
3. 兜底：全部失败时留在原版重生放置的位置（世界出生点附近），来源记为 `fallback`，记日志。兜底不检查离死亡点的距离。

V0 唯一的提供器 `wilderness_ring`：世界出生点周围 `successorRingMin`–`successorRingMax`（默认 256–1024 格，SERVER 配置）的环内按面积均匀随机。以后州、城镇、POI 的提供器用 `SurvivorSpawns.register` 插在它前面，无结果时返回 null。

接手（`PlayerRespawnEvent`，最高优先级，末地通关返回除外）：

- 传送到出生点，朝向随机；继任者变为 `ALIVE`，记录开始时间、实际出生点与来源；传承回到 `ACTIVE`；玩家存档盖上新幸存者 ID；没有重生点。
- 屏幕标题显示新姓名，副标题“第 n 位幸存者”。
- 本刻结束时写幸存者数据和玩家存档。
- 特殊情况：创造 / 旁观模式死亡后的重生仍是同一位幸存者；服务器在写入死亡记录前停止导致“数据里没有这次死亡”的重生，补记为死亡（死因不明、没有尸体，物品丢失而不是复制），再按模式继任或结束。

## 6. 尸体

记录（`SurvivorCorpseRecord`，存在世界幸存者数据 `Corpses` 里）才是真相：ID、所属账号、幸存者 ID、姓名、生涯序号、维度、位置、朝向、死亡时间、物品、搜索状态。实体（`SurvivorCorpse`，注册 ID `apocalypse_firstlight:survivor_corpse`）只是世界里的躯体和点击目标：

- `noSave` + `noSummon`：不随区块保存，不能召唤；`/kill` 或区块卸载移除实体也不影响记录。
- 服务器每 20 tick 检查一遍尸体记录：所在区块的实体已加载、却找不到同 UUID 的实体，就放回一个。实体 UUID 就是尸体 ID，世界自己的 UUID 检查拒绝第二份。
- 每 tick 什么都不做：无物理、无重力、不着火、不能受伤、不能推动、可以穿过；可以被点击（准星选中），会挡住子弹（无伤害）。
- 位置：死亡时站在地上就用原位置（含 Terrain Smooth 的斜坡）；空中、水中等向下落到第一个有碰撞的表面；虚空死亡放到该列顶部；卡在方块里就留在原处。
- 外观（占位）：原版玩家模型绑定姿态，仰面躺下，沿死亡朝向，以尸体位置为中心，整体压暗。皮肤：主人在玩家列表里时用其皮肤，否则用其 UUID 对应的默认皮肤。没有腐烂、骨架或布娃娃。
- 名字：`<姓名> 的遗体`（实体 `getName`；没有单独的 Jade 提供器，Jade 是否显示这个名字未实机确认）。准星提示（`client/WorldInteractionHint`）：未搜完“搜索”，搜完“查看”。

搜刮：接入渐进容器搜索（实体宿主，见 `progressive_container_search_v1.md`）。

- 物品按顺序挤在最前面的格子里，网格取能装下的最小 9×1..6（目前最多 36+4+1+Curios 3 格+装饰 3 格 = 47 堆，小于 54）。超过 54 堆（以后其它模组加很多 Curios 栏位）时多出的放在尸体旁的地上，不销毁，记日志。
- 所有格子一开始隐藏，每格 16 tick（约 0.8 秒，±15%），搜完后以后打开就是普通箱子界面。尸体 V0 不发出搜索噪声，用通用翻找声。
- 多人同时搜：共用一个容器对象和一个搜索进度，与箱子相同；最后一个人离开就暂停。
- 服务器判定：记录存在、同一维度、8 格内、玩家活着；点击由服务器验证，客户端不能改物品。
- 物品取走即时标记数据脏，随自动存档和死亡刷新写盘；拿取与存档之间的崩溃窗口与原版箱子相同。

尸体永久保留（V0 不清理空尸体），每次死亡一具。

## 7. 状态重置

死亡即换人。继任者是新的身体，不继承：

| 系统 | 死亡后 | 代码 |
|---|---|---|
| 累计辐射剂量 | **清零（本轮改动）** | `radiation/RadiationExposureEvents.copyOnClone` |
| 残留污染 | 清零（原有） | 同上 |
| 口渴 / 体温 / 体力 | 重置（原有） | `PlayerThirst` / `PlayerTemperature` / `PlayerStamina` 的 Clone 处理 |
| 饥饿 / 生命 | 原版新玩家默认值 | 原版 `restoreFrom` |
| 耳鸣 | 清除（原有） | `GunshotExposureTracker.onRespawn`、客户端 `ExplosionTinnitusClientState` |
| 经验 | AFL 原本就不给经验（`VanillaProgressionEvents`） | — |
| 技能成长 / 伤病 / 疲劳 | 当前不存在这些系统 | — |

辐射设计文档 `docs/项目内容/01 - 设计/辐射/辐射系统.md` 的保存规则表与“死亡不能清除累计剂量”已同步改为死亡清零。

## 8. Curios、keepInventory 与末影箱

规则（生存 / 冒险模式死亡）：幸存者身上的一切都留在尸体上，继任者空手开始。

| 来源 | 处理 |
|---|---|
| 原版物品栏 36 格、盔甲、副手 | 原版掉落时从掉落列表收走；keepInventory 开启时原版不掉，由本系统直接从物品栏收走 |
| Curios 栏位与装饰栏 | Curios 自己以最高优先级把要掉的加进同一掉落列表，本系统以最低优先级一起收走；Curios 的 `keepCurios` / ALWAYS_KEEP 留在栏位里的也收走 |
| 诅咒消失 | 与原版一致：直接消失，不进尸体 |
| 其它模组取消掉落事件 | 本系统仍会收到（`receiveCanceled`）并收走物品 |
| 漏网（例如灵魂绑定类效果把物品复制到新身体） | Clone 兜底检查，移进同一具尸体 |
| 末影箱 | **不处理**：末影箱内容属于账号，继任者打开末影箱仍能拿到。这是已知漏洞，待决定（禁用末影箱配方 / 死亡时清空 / 视为账号仓库） |

`keepInventory` 因此对生存 / 冒险死亡**不再保留物品**。这条规则写在模式选择界面上，开局前就告诉玩家。创造 / 旁观模式死亡不受影响。

## 9. 命令

只读审计，权限 2：`/afl survivor`、`/afl survivor player <玩家>`、`/afl survivor list`、`/afl survivor corpses`（每具尸体的位置、物品堆数、搜索状态）。没有任何命令能改模式、重抽继任者或复活。

## 10. 困难模式

- 死亡：传承进入 `ENDED`，不生成继任者；尸体照常留下，其他玩家（多人）可以搜。
- 服务器拒绝该玩家的重生请求（`mixin/SurvivorRespawnGateMixin`，注入在原版 `handleClientCommand` 切到服务器线程之后；末地通关返回不受影响）。客户端无论发多少次都不会复活。
- 其它途径强制重生（其它模组、命令）时，接手逻辑发现传承已结束，立刻把新身体恢复为死亡状态。
- 原版极限世界：本系统先拦截重生，原版“重生成旁观者”不会发生。
- 世界不删除、不锁定文件，作为纪念存档保留；重新进入时直接回到死亡结算界面（第 11 节），只能结束旅程。
- 多人：每个账号各自一条传承；一个玩家结束不影响其他玩家。

## 11. 死亡结算界面与模式选择（客户端）

客户端只显示服务器发来的内容，不做任何判定（`survivor/SurvivorPackets`，`client/survivor/`）。网络协议版本 `AflNetwork.PROTOCOL` 39 → **40**（新增 3 个包）。

| 包 | 方向 | 内容 |
|---|---|---|
| `Summary` | 服务器 → 客户端 | 姓名、生涯序号、存活天数、死因、维度、坐标、是否整局结束（HARD） |
| `ModePrompt` | 服务器 → 客户端 | 打开 / 关闭模式选择 |
| `ModeChoice` | 客户端 → 服务器 | 房主的选择；服务器检查：模式仍是 UNSET、不是专用服务器、发送者是单人世界的房主 |

死亡结算 `AflDeathScreen`（替换原版死亡界面）：

- 发送时机：死亡事件里（早于原版的死亡包）、死亡状态下登录、重生被拒或被撤回时。
- 内容：姓名（放大）、“第 n 位幸存者 · 存活 x 天”（不足一天 / 1 天 / n 天）、死因、地点（维度 + 坐标）、结束语。
- NORMAL：“开始另一段人生”（就是原版重生请求，服务器把身体交给已决定的继任者）和“返回标题画面”。
- HARD：只有“结束旅程”（断开并回到标题画面）。界面不能用 Esc 关；原版死亡界面每次想出现都被换成 AFL 界面；重新进入世界仍回到这个界面。任何菜单都不能复活，服务器本身就拒绝。
- 按钮出现 1 秒后才能点（同原版，防止战斗中的点击误触），界面 12 tick 渐入。
- 样式：现代浮层样式（暗色半透明面板、暖色细线、强调色只用于结束语），见 `docs/ui/afl_overlay_ui_style_v1.md` 10.5。

模式选择 `AflSurvivorModeScreen`（单人新世界，房主第一次进入时）：

- 两个选项：普通（“死亡不可逆，由另一位幸存者继续。”）/ 困难（“死亡不可逆，旅程就此结束。”）。
- 提前说明物品规则：“死亡后随身物品全部留在遗体上，保留物品栏规则不保留任何物品。”；“选定后不可更改。”
- 选中后点“开始”，服务器锁定并立即写盘，再回包关闭界面；回包前按钮显示“正在开始…”且不可再点。
- 界面暂停单人游戏、不能 Esc 关；在地形加载界面之后、没有别的界面时才打开。

已知限制：

- 开启原版 `doImmediateRespawn` 时，原版客户端收到死亡包立即请求重生，NORMAL 的死亡结算不会出现（继任者的标题照常显示）；HARD 的重生被服务器拒绝，结算界面照常出现。
- 死亡时聊天栏里的原版死亡消息仍用账号名；结算界面和记录里用幸存者姓名。
- 继任者仍用该账号的皮肤（V0 没有身体 / 外观系统）。

## 12. 已知问题与待决定

- 末影箱：继任者能拿到前任末影箱里的东西（第 8 节）。
- 首位幸存者的姓名不能选，与继任者同样随机。
- 旧世界（本系统之前就存在）开服直接定为 NORMAL，不询问。
