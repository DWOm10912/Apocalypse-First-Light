# 幸存者死亡与随机继任 V0

状态：**开发中（独立 Worktree `feature/survivor-v0`，未合并 Main）**。在本 Worktree 的开发客户端做过实机测试，范围见文末“验证”；没写进“验证”的部分只是代码行为，不是实机结论。

首次公开测试的 P0：玩家扮演的是“一个幸存者”，不是不死的账号。幸存者死亡是永久的；普通模式由随机继任者接手同一世界，困难模式整局结束。

代码：`src/main/java/com/antaurora/apofirstlight/survivor/`。

## 1. 范围

本轮包含：
- 模式数据，以及创建世界界面上的模式选择。
- 固定原版难度（第 2 节）。
- 幸存者身份与生命记录。
- 死亡接入、状态重置。
- 持久尸体与搜刮。
- 随机继任、困难模式终止。
- AFL 死亡结算界面。
- 幸存者外貌：运行时切换。继任者来自固定名册：60 个人，每人一个全名和一套皮肤，只画基础服装，女性用 Slim、男性用 Classic；性别随机，同一世界里一个人只出场一次。另有聊天、Tab 与头顶名牌的幸存者姓名，以及首位幸存者自定义昵称（第 13 节）。

本轮不包含：Mesh 人物、骨骼、IK、布娃娃、腐烂、死亡镜头、过场、剧情模式、技能系统、职业/特质/身体系统、出身州与背景的实际内容、模块化装备（外套、背心、帽子等，以后做，不画进皮肤）、创建世界界面的现代化 UI。

## 2. 模式

`SurvivorMode`：`UNSET` / `NORMAL` / `HARD`，存在世界的幸存者数据里，与原版难度和原版极限标志分开。一旦确定就锁定，游戏内没有任何途径改回。

| 情况 | 模式 |
|---|---|
| 原版极限（hardcore）世界 | 固定 HARD，不询问 |
| 专用服务器新世界 | 读 SERVER 配置 `apocalypse_firstlight-survivor.toml` 的 `dedicatedServerMode`（默认 NORMAL），只读一次 |
| 本系统出现前就存在的世界（没有 fresh 标记） | 开服时直接定为 NORMAL |
| 单人新世界 | 在原版“创建新的世界”界面上选择（见下），创建世界时写入 |
| 单人新世界，但创建时没有拿到选择（例如别的模组替换了创建世界界面） | 保持 UNSET，等房主首次进入时在游戏内选择（`AflSurvivorModeScreen`，第 11 节） |
| 选择前就有玩家死亡 | 锁定为 NORMAL，日志警告 |

“新世界”由 `LevelEvent.CreateSpawnPosition` 判定（只在创建世界时触发；Terrain V2 会取消这个事件，所以监听时 `receiveCanceled = true`），写入 `freshWorld`。

创建世界界面（`client/survivor/SurvivorCreateWorldClient`，原版风格按钮，现代化 UI 以后统一做）：

- “游戏”页原来的“难度”按钮隐藏，原位置换成“幸存者模式：普通 / 困难”按钮，大小相同，只在“游戏”页显示。
- 按钮的悬停提示写明这个模式的死亡规则、物品规则（“死亡后随身物品全部留在遗体上……”）和“选定后不可更改。”
- 选了原版“极限”游戏模式时，按钮固定为“困难”并变灰，提示加一行“极限模式固定为困难。”
- 点“创建新的世界”后，选择在 `CreateSpawnPosition` 里写进新世界的幸存者数据（`Survivors.applyCreateScreenChoice`），只用一次；回到世界列表或标题画面时丢弃未用的选择。专用服务器不读它。
- 找不到原版难度按钮时（界面被别的模组改过）什么都不加，退回游戏内选择。

原版难度：固定为“普通”并锁定（`survivor/AflDifficulty`，`mixin/AflDifficultyLockMixin`）。

- 普通、困难（以及以后的剧情模式）只在“死亡意味着什么”上不同，游戏数值完全一样。没有和平难度，不能靠切和平删除敌对生物。
- 服务器启动时把世界难度设为普通并锁定，所有维度的刷怪开关随之更新，写进 `level.dat`。旧世界用这个版本打开一次就会被永久锁定。
- 原版改难度或解锁的入口都在 `MinecraftServer.setDifficulty` / `setDifficultyLocked` 被拦下，结果仍是普通、锁定。这些入口包括：
  - `/difficulty`；
  - 单人房主在“选项”里的难度按钮和锁定按钮；
  - 专用服务器 `server.properties` 的 `difficulty`；
  - 原版极限模式强制的“困难”。
- `/difficulty <难度>`（含 `/execute … run difficulty …`）直接拒绝，提示“AFL 的难度固定为普通，不能更改。”；不带参数的 `/difficulty` 照常显示当前难度。
- 客户端“选项”里的难度按钮因为已锁定而变灰，锁图标显示已锁定。

| 模式 | 死亡后 |
|---|---|
| NORMAL | 该幸存者永久死亡；世界继续；死亡瞬间决定一位随机继任者，重生即由继任者接手 |
| HARD | 该幸存者永久死亡；该玩家这一局结束；不再生成继任者，不能重生；世界保留作纪念存档，不删除任何东西 |

没有剧情模式。

多人（用户正式决定 2026-10-14）：普通模式单人和多人用同一套随机继任，每个玩家走自己的传承（第 3 节 `Lineages`）。不开发团队传承，不设全员阵亡判定，也不需要队友接应。

- 任何玩家死亡后，原角色永久死亡，该玩家独立随机接管另一名幸存者。其他玩家的生死和在线状态都不影响继任。
- 全部在线玩家同时死亡，世界也不结束，各自照常继任。设定：联邦境内还有很多幸存者，大多单独行动。
- 出生点和单人一样随机（第 5 节），不安排在队友附近。
- HARD：暂时沿用个人永久死亡，死亡的玩家这一局结束，其他玩家继续（第 10 节）。不加团灭逻辑。
- 继任池只有独立行动的普通幸存者；营地居民、聚落 NPC、商人、重要剧情人物全部排除。V0 还没有这些人物。
- 计划（未做）：首次开局和死亡继任共用「幸存者开局模板池」的框架（背景、身份、初始物资、过场演出），结构生成方式可以不同。模板分专属结构型、既有建筑型、开放环境型；死亡继任主要用开放环境型，绝不重建初始小屋、修复被拆的建筑、覆盖玩家基地或重置已搜刮的物资。见 `survivor_start_template_pool.md`。首版沿用本文的继任流程。

## 3. 数据结构

世界数据 `SurvivorWorldData`（`SavedData`，跟随主世界保存为 `<世界>/data/apocalypse_firstlight_survivors.dat`）：

- `Mode`：模式；`Fresh`：新世界标记。
- `Lineages`：每个账号 UUID 一条“传承”（`SurvivorLineage`）：账号名、状态、全部生命记录（旧→新）、最后一位死者的床位置。
- 传承状态：`ACTIVE`（当前幸存者存活）、`AWAITING_SUCCESSOR`（NORMAL：已死亡，继任者已决定，等待重生）、`ENDED`（HARD：结束）。

生命记录 `SurvivorRecord`：

| 字段 | 含义 |
|---|---|
| `Id` | 幸存者唯一 ID |
| `First` / `Last` | 姓名（首位幸存者：`First` 是账号名或自定义昵称，`Last` 为空） |
| `Named` | 姓名是否已定。只有首位幸存者生成时为 false，等房主在姓名界面确认（第 13 节）；旧记录没有这个字段时视为已定 |
| `Skin` / `Arms` | 外貌：皮肤 ID（`account` = 账号皮肤）与手臂类型（`account` / `classic` / `slim`），生成时确定，不再改变（第 13 节） |
| `Sex` | 继任者的性别（`FEMALE` / `MALE`），生成时先抽，决定从名册的哪一半里选人（第 13 节）。首位幸存者和性别抽签出现前的旧记录没有这个字段 |
| `Life` | 职业生涯序号：该玩家在本世界的第 n 位幸存者，从 1 开始 |
| `Roll` | 生成该幸存者的随机种子（审计用） |
| `State` | `PENDING`（已决定未接手）/ `ALIVE` / `DEAD` |
| `StartGame` / `StartDay` | 开始的世界游戏刻 / 世界日时间 |
| `DeathGame` / `DeathDay` | 死亡的世界游戏刻 / 世界日时间 |
| 存活天数 | `(DeathDay - StartDay) / 24000`，不小于 0（按世界日时间计，睡觉跳过的夜晚也算） |
| `Cause` / `CauseId` | 死亡消息（Component JSON，受害者名字换成幸存者姓名）/ 伤害类型 msgId |
| `DeathDim` / `DeathPos` | 最终死亡维度与方块位置 |
| `Corpse` | 尸体 ID |
| `PlanX` / `PlanZ` | 继任者出生规划点（死亡时决定，不加载区块） |
| `SpawnDim` / `SpawnPos` / `SpawnSource` | 实际出生点与来源（提供者 ID、`fallback` 或 `initial`） |
| `OriginState` / `Background` / `Profession` / `Traits` / `Body` | 预留字段，V0 一律为空，没有任何系统读取 |

玩家自身持久数据根下写入 `apocalypse_firstlight:survivor_id`（该玩家存档属于哪位幸存者），用于识别崩溃后过期的玩家存档。

## 4. 死亡流程（服务器权威）

只有生存/冒险模式的玩家受幸存者规则约束；创造/旁观模式死亡保持原版。

1. `LivingDeathEvent`（最低优先级；被其他模组取消的死亡不处理）：
   - 当前记录必须是 `ALIVE`，否则什么都不做——记录状态本身就是防重复结算的账本，同一幸存者第二次死亡事件不会再结算。
   - 写入死亡时间、死因、位置；记住床位置后清除玩家的重生点（重生不会回到旧床，新身体也不会继承它）。
   - NORMAL：传承进入 `AWAITING_SUCCESSOR`；HARD：传承进入 `ENDED`。
   - 建立尸体记录（第 6 节），尸体实体立刻出现。
2. `LivingDropsEvent`（最低优先级，被取消的也处理）：原版掉落和 Curios 加入的掉落全部收进尸体，世界里不生成掉落物；身上剩下的（keepInventory、Curios 保留规则、装饰栏）也一并收走（第 8 节）。
3. `PlayerEvent.Clone`（最低优先级，在 Curios 复制栏位之后）：兜底检查新身体，任何被其它逻辑带过来的物品移进同一具尸体并记日志。
4. 本服务器刻结束时：先立刻写入幸存者数据文件，再保存所有玩家存档（`PlayerList.saveAll()`）。
5. 登录核对：玩家存档里的幸存者 ID 在世界数据中已是 `DEAD`、而存档里的玩家却活着，说明服务器在两次写入之间停止，玩家存档早于死亡。此时清掉存档里的过期物品（它们已在尸体里），把玩家恢复为死亡状态，照常进入死亡界面与继任流程，不会复制物品。反过来（玩家存档已写、幸存者数据未写）只会丢失这次死亡的尸体，不会复制。

首位幸存者：玩家第一次进入世界时生成，先以账号名记录，外貌是账号皮肤（第 13 节），记录开始时间，来源 `initial`。随后弹出一次姓名界面，玩家确认账号名或输入自定义昵称（第 13 节）；没确认就死亡时，姓名定为账号名，界面关闭。

## 5. 随机继任（NORMAL）

**死亡瞬间决定，立即持久化。** 死亡记录写入的同一刻生成继任者（`PENDING`）并决定出生规划点，随幸存者数据一起写盘；重登、重启都读回同一个人，不会重抽。

- 性别：先抽，男女各半，与账号无关（第 13 节）。
- 姓名和外貌：一起从固定名册 `SurvivorRoster` 里选一个人（第 13 节）。名册 60 人，女 30、男 30，每人一个全名和一套皮肤，名字和长相对得上（北美常见、混合族裔，对应哥伦比亚联邦的人口）。
  - 同一世界里一个人只出场一次，所有玩家的所有生涯一起算：两个玩家不会遇到同一个人，也不会撞见还在走动的人的遗体。
  - 60 人都出场过之后，离开最久的那位（死亡时间最早）重新出场，日志里有一条警告。
  - 现任幸存者的名字和名册里的人重名时（首位幸存者的昵称可以是任何名字），跳过这个人。
  - 种子 = 世界种子 × 账号 UUID × 生涯序号，确定性；选中的人随记录写盘（姓名、皮肤 ID、手臂类型）。
  - 以前的随机名字池（女名、男名、中性名、姓）已经删除。
- 玩家不能选择姓名、性别、外貌、职业、州、地点或能力。V0 **只随机性别、姓名、外貌和出生点**；职业、特质、身体、出身州、背景只是预留字段，没有实现对应系统，随机姓名不等于职业 / 能力系统。
- 出身州与背景以后由开局模板池决定（`survivor_start_template_pool.md`，未实现）：首次开局可以选州、背景模板或随机，继任时从合法并允许继任的模板里随机抽。州尚未完成，代码里不写任何州或建筑的名字。

出生点（`SurvivorSpawns`，总在主世界）：

1. 死亡时规划（不加载、不生成区块）：出生点提供器（`SurvivorSpawnProvider`）依次给候选列，粗筛条件：
   - 世界边界内且离边界 ≥ 32 格；
   - 离死亡点 ≥ 192 格，离旧床 ≥ 128 格；
   - 自然辐射区不是重度沉降或极端；
   - 有 Terrain V2 规划时：干地（水类 0）、离岸 ≥ 24 格、坡度 ≤ 0.25。规划取这个世界生成器绑定的那一份（`RandomStateSeedAccess.apocalypse$terrainPlanSurface()`），不按种子查：同一个种子的 r1 世界和联邦世界规划不同（2026-10-14 同步 Main 时改的，以前按种子查，联邦世界会读到 r1 的规划；联邦世界里的继任出生还没有实机测过）；
   - 生物群系（噪声采样）不是海洋、深海、河流、沙滩。
   第一个通过的列存为规划点。
2. 接手时（重生）精确落地：加载 / 生成该列区块，取最高的非树叶实心方块：不是液体、树叶、原木、AFL 树、火、营火、岩浆块、仙人掌、细雪、甜浆果丛；站立空间无碰撞，身体周围 0.5 格内无液体。规划点不行就继续后面的候选，最多 8 次落地检查。
3. 兜底：全部失败时留在原版重生放置的位置（世界出生点附近），来源记为 `fallback`，记日志。兜底不检查离死亡点的距离。

V0 唯一的提供器 `wilderness_ring`：世界出生点周围 `successorRingMin`–`successorRingMax`（默认 256–1024 格，SERVER 配置）的环内按面积均匀随机。以后州、城镇、POI 的提供器用 `SurvivorSpawns.register` 插在它前面，无结果时返回 null。

`wilderness_ring` 加原版出生点兜底就是首发的继任回退（用户决定 2026-10-14）：完整模板池没做完也不阻塞死亡系统验收（`survivor_start_template_pool.md` 第 2 节）。继任只传送玩家，不放置、不改动任何方块。

接手（`PlayerRespawnEvent`，最高优先级，末地通关返回除外）：

- 传送到出生点，朝向随机；继任者变为 `ALIVE`，记录开始时间、实际出生点与来源；传承回到 `ACTIVE`；玩家存档盖上新幸存者 ID；没有重生点。
- 屏幕标题只显示新姓名，副标题留空。原来的副标题“第 n 位幸存者”已去掉：用户 2026-10-14 觉得刻意。生涯序号只留在记录、命令和日志里。
- 本刻结束时写幸存者数据和玩家存档。
- 特殊情况：创造 / 旁观模式死亡后的重生仍是同一位幸存者；服务器在写入死亡记录前停止导致“数据里没有这次死亡”的重生，补记为死亡（死因不明、没有尸体，物品丢失而不是复制），再按模式继任或结束。

## 6. 尸体

记录（`SurvivorCorpseRecord`，存在世界幸存者数据 `Corpses` 里）才是真相：ID、所属账号、幸存者 ID、姓名、生涯序号、外貌（`Skin` / `Arms`）、维度、位置、朝向、死亡时间、物品、搜索状态，以及布娃娃停下来的姿势（`PoseV` = 1 和 `Pose`：11 个刚体 × 7 个浮点数，布娃娃 V1 起，见 `docs/dev/ragdoll_v1_plan.md` 第 3 节）；还在半空时区块就卸载了的尸体带 `Unsettled` 标记，下次实体放回时先落到下面的地面上。实体（`SurvivorCorpse`，注册 ID `apocalypse_firstlight:survivor_corpse`）只是世界里的躯体和点击目标：

- `noSave` + `noSummon`：不随区块保存，不能召唤；`/kill` 或区块卸载移除实体也不影响记录。
- 服务器每 20 tick 检查一遍尸体记录：所在区块的实体已加载、却找不到同 UUID 的实体，就放回一个。实体 UUID 就是尸体 ID，世界自己的 UUID 检查拒绝第二份。
- 布娃娃 V1（2026-10-16 写好，未实机确认）：
  - 死亡时，能倒下的尸体从死者站的位置开始，由服务端按布娃娃模拟倒下。
  - 停下以后，把落点和姿势写进记录，实体也移到落点。
  - 以下情况不倒，直接用下面的旧位置规则：虚空、骑乘、水中或岩浆中、卡在方块里、全服已有 8 具尸体正在倒。
- 停下以后每 tick 什么都不做：无物理、无重力、不着火、不能受伤、不能推动、可以穿过；可以被点击（准星选中），会挡住子弹（无伤害）。
- 位置（不倒的尸体）：死亡时站在地上就用原位置（含 Terrain Smooth 的斜坡）；空中等情况向下落到第一个有碰撞的表面；虚空死亡放到该列顶部；卡在方块里就留在原处。
- 外观（占位）：原版玩家模型绑定姿态，仰面躺下，沿死亡朝向，以尸体位置为中心，整体压暗。这是没有布娃娃姿势的尸体；有姿势的按姿势画，倒下过程也画出来（`docs/dev/ragdoll_v1_plan.md` 第 4 节）。皮肤与手臂类型：死者生前的外貌，建尸体时从死者记录复制，与主人后来换成谁无关（第 13 节）；首位幸存者的遗体显示主人的账号皮肤（主人不在玩家列表里时用其 UUID 对应的原版默认皮肤）。没有腐烂和骨骼遗骸。
- 名字：`<姓名> 的遗体`（实体 `getName`；没有单独的 Jade 提供器，Jade 是否显示这个名字未实机确认）。准星提示（`client/WorldInteractionHint`）：未搜完“搜索”，搜完“查看”。

搜刮：接入渐进容器搜索（实体宿主，见 `progressive_container_search_v1.md`）。

- 物品按顺序挤在最前面的格子里，网格取能装下的最小 9×1..6（目前最多 36+4+1+Curios 3 格+装饰 3 格 = 47 堆，小于 54；网格背包 V0 分支加了胸挂栏和 4 个口袋：36+4+1+4+4+4 = 53 堆，仍小于 54）。超过 54 堆（以后其它模组加很多 Curios 栏位）时多出的放在尸体旁的地上，不销毁，记日志。
- 所有格子一开始隐藏，每格 16 tick（约 0.8 秒，±15%），搜完后以后打开就是普通箱子界面。尸体 V0 不发出搜索噪声，用通用翻找声。
- 多人同时搜：共用一个容器对象和一个搜索进度，与箱子相同；最后一个人离开就暂停。
- 服务器判定：记录存在、同一维度、8 格内、玩家活着；点击由服务器验证，客户端不能改物品。
- 物品取走即时标记数据脏，随自动存档和死亡刷新写盘；拿取与存档之间的崩溃窗口与原版箱子相同。

尸体永久保留（V0 不清理空尸体），每次死亡一具。

## 7. 状态重置

死亡即换人。继任者是新的身体，不继承：

| 系统 | 死亡后 | 代码 |
|---|---|---|
| 累计辐射剂量 | **清零（本轮改动）** | `radiation/RadiationExposureEvents.copyOnClone` |
| 残留污染 | 清零（原有） | 同上 |
| 口渴 / 体温 / 体力 | 重置（原有） | `PlayerThirst` / `PlayerTemperature` / `PlayerStamina` 的 Clone 处理 |
| 饥饿 / 生命 | 原版新玩家默认值 | 原版 `restoreFrom` |
| 耳鸣 | 清除（原有） | `GunshotExposureTracker.onRespawn`、客户端 `ExplosionTinnitusClientState` |
| 经验 | AFL 原本就不给经验（`VanillaProgressionEvents`） | — |
| 技能成长 / 伤病 / 疲劳 | 当前不存在这些系统 | — |

辐射设计文档 `docs/项目内容/01 - 设计/辐射/辐射系统.md` 的保存规则表与“死亡不能清除累计剂量”已同步改为死亡清零。

## 8. Curios、keepInventory 与末影箱

规则（生存 / 冒险模式死亡）：幸存者身上的一切都留在尸体上，继任者空手开始。

| 来源 | 处理 |
|---|---|
| 原版物品栏 36 格、盔甲、副手 | 原版掉落时从掉落列表收走；keepInventory 开启时原版不掉，由本系统直接从物品栏收走 |
| 口袋（网格背包 V0 分支，2026-10-14） | `SurvivorCorpses` 在收原版物品和 Curios 时一起把口袋清空收进尸体（掉落、Clone 兜底、过期存档三处）；胸挂和背包里的东西在它们自己的 NBT 里，跟着胸挂 / 背包进尸体。非幸存者死亡（创造等）且没有 keepInventory 时，口袋随原版物品一起掉在地上（`Inventory.dropAll` 末尾） |
| Curios 栏位与装饰栏 | Curios 自己以最高优先级把要掉的加进同一掉落列表，本系统以最低优先级一起收走；Curios 的 `keepCurios` / ALWAYS_KEEP 留在栏位里的也收走 |
| 诅咒消失 | 与原版一致：直接消失，不进尸体 |
| 其它模组取消掉落事件 | 本系统仍会收到（`receiveCanceled`）并收走物品 |
| 漏网（例如灵魂绑定类效果把物品复制到新身体） | Clone 兜底检查，移进同一具尸体 |
| 末影箱 | **不处理**（用户决定 2026-10-14）：末影箱按原计划删除配方，幸存者系统不为它做任何处理。配方删除不在本任务内，目前仍是原版配方，删除之前继任者打开末影箱仍能拿到前任放进去的东西 |

`keepInventory` 因此对生存 / 冒险死亡**不再保留物品**。这条规则写在创建世界界面“幸存者模式”按钮的悬停提示里（游戏内的模式选择界面也写着），单人新世界开局前就告诉玩家（专用服务器、旧世界看不到，见第 12 节）。创造 / 旁观模式死亡不受影响。

## 9. 命令

只读审计，权限 2：`/afl survivor`、`/afl survivor player <玩家>`、`/afl survivor list`、`/afl survivor corpses`（正在倒下的尸体数 `falling=`、布娃娃服务端耗时 `ragdoll_ms_per_tick`；每具尸体的位置、姿势 `pose=ragdoll|lying`、物品堆数、搜索状态）。测试用（布娃娃 V1）：`/afl survivor ragdoll [hit|shot|blast|drop|collapse|clear]` 在面前放一具不属于任何传承的替身尸体并让它倒下，`clear` 全部删掉（`docs/dev/ragdoll_v1_plan.md` 第 3 节第 8 条）。传承列表每一位显示 `look=<皮肤>/<手臂>`，有性别的继任者再加 `sex=female|male`；接手日志行末尾也带性别（首位和旧记录是 `null`）。替身命令只加删替身尸体；没有任何命令能改模式、重抽继任者或复活。

## 10. 困难模式

- 死亡：传承进入 `ENDED`，不生成继任者；尸体照常留下，其他玩家（多人）可以搜。
- 服务器拒绝该玩家的重生请求（`mixin/SurvivorRespawnGateMixin`，注入在原版 `handleClientCommand` 切到服务器线程之后；末地通关返回不受影响）。客户端无论发多少次都不会复活。
- 其它途径强制重生（其它模组、命令）时，接手逻辑发现传承已结束，立刻把新身体恢复为死亡状态。
- 原版极限世界：本系统先拦截重生，原版“重生成旁观者”不会发生。
- 世界不删除、不锁定文件，作为纪念存档保留；重新进入时直接回到死亡结算界面（第 11 节），只能结束旅程。
- 多人：每个账号各自一条传承；一个玩家结束不影响其他玩家，没有团灭判定（第 2 节“多人”）。

## 11. 死亡结算界面与模式选择（客户端）

客户端只显示服务器发来的内容，不做任何判定（`survivor/SurvivorPackets`，`client/survivor/`）。网络协议版本 `AflNetwork.PROTOCOL` 39 → 40（阶段 D，新增前 3 个包）→ 41（外貌原型，新增 `Appearance`）→ 42（身份：`Appearance` 换成 `Identity`，新增 `NamePrompt`、`NameChoice`）→ **43**（2026-10-14 同步最新 Main：Main 那边暗线第 5 阶段也把 39 升到了 40，两边包集合不同，合并后的版本和两边都不能互连，所以取 43）。之后的版本号随 master 走；布娃娃 V1 R-B 新增 `CorpsePose`，D 分支先从 50 升到 51；master 的 T15 车灯也用了 51，所以 D 分支改为 **52**（2026-10-16，合并时以 52 为准）。

| 包 | 方向 | 内容 |
|---|---|---|
| `Summary` | 服务器 → 客户端 | 姓名、生涯序号、存活天数、死因、维度、坐标、是否整局结束（HARD） |
| `ModePrompt` | 服务器 → 客户端 | 打开 / 关闭模式选择 |
| `ModeChoice` | 客户端 → 服务器 | 房主的选择；服务器检查：模式仍是 UNSET、不是专用服务器、发送者是单人世界的房主 |
| `Identity` | 服务器 → 客户端 | 某个账号 UUID 当前幸存者的姓名、皮肤 ID 与手臂类型（第 13 节） |
| `NamePrompt` | 服务器 → 客户端 | 打开 / 关闭首位幸存者的姓名界面，或拒绝原因（`invalid` / `taken`） |
| `NameChoice` | 客户端 → 服务器 | 首位幸存者选的姓名；服务器重新检查字符、长度和重名 |
| `CorpsePose` | 服务器 → 跟踪该尸体的客户端 | 布娃娃 V1：倒下时每 tick 一次刚体位置和朝向；停下时再发一次（`last`），带落点；空姿势表示仰面躺平 |

死亡结算 `AflDeathScreen`（替换原版死亡界面）：

- 发送时机：死亡事件里（早于原版的死亡包）、死亡状态下登录、重生被拒或被撤回时。
- 布娃娃 V1：第一人称死亡、自己的尸体会倒下时，先由死亡镜头跟着尸体的头倒下，身体停下 1 秒后（从死亡起最多 6 秒）才出这个界面（`client/survivor/DeathCamera`，`docs/dev/ragdoll_v1_plan.md` 第 4 节）。第三人称和旁观时照旧立刻出现。
- 内容：姓名（放大）、存活天数（“存活不足一天” / “存活 1 天” / “存活 n 天”，2026-10-14 起不显示“第 n 位幸存者”；`Summary` 包仍带生涯序号，界面不用）、死因、地点（维度 + 坐标）、结束语。
- NORMAL：“开始另一段人生”（就是原版重生请求，服务器把身体交给已决定的继任者）和“返回标题画面”。
- HARD：只有“结束旅程”（断开并回到标题画面）。界面不能用 Esc 关；原版死亡界面每次想出现都被换成 AFL 界面；重新进入世界仍回到这个界面。任何菜单都不能复活，服务器本身就拒绝。
- 按钮出现 1 秒后才能点（同原版，防止战斗中的点击误触），界面 12 tick 渐入。
- 样式：现代浮层样式（暗色半透明面板、暖色细线、强调色只用于结束语），见 `docs/ui/afl_overlay_ui_style_v1.md` 10.5。

模式选择 `AflSurvivorModeScreen`：现在只是后备。正常情况下模式在创建世界界面上选（第 2 节）；只有创建时没拿到选择的单人新世界，才在房主第一次进入时弹出：

- 两个选项：普通（“死亡不可逆，由另一位幸存者继续。”）/ 困难（“死亡不可逆，旅程就此结束。”）。
- 提前说明物品规则：“死亡后随身物品全部留在遗体上，保留物品栏规则不保留任何物品。”；“选定后不可更改。”
- 选中后点“开始”，服务器锁定并立即写盘，再回包关闭界面；回包前按钮显示“正在开始…”且不可再点。
- 界面暂停单人游戏、不能 Esc 关；在地形加载界面之后、没有别的界面时才打开。

已知限制：

- 开启原版 `doImmediateRespawn` 时，原版客户端收到死亡包立即请求重生，NORMAL 的死亡结算不会出现（继任者的标题照常显示）；HARD 的重生被服务器拒绝，结算界面照常出现。

## 12. 已知问题与待决定

- 末影箱：不处理，配方按原计划删除（不在本任务内）；删除前继任者仍能拿到前任放进末影箱的东西（第 8 节）。
- 名册 60 人，同一世界用完后才有人重新出场；外套、背心、帽子等留给以后的模块化装备（第 13 节）。姓名和外貌不跟开局模板走，继任时单独随机（`survivor_start_template_pool.md`）。
- Tab 列表：设了显示名后，原版不再给名字套队伍颜色和前缀；排序仍按账号名。
- 离开消息用的是当前记录的姓名：死后还没接手就退出时，显示的是死者的名字（例如“Maria Ramirez left the game”）。
- 创建世界界面的模式按钮靠找到原版的难度按钮来放置；界面被其他模组改掉时不加按钮，退回游戏内选择。原版“极限”的提示文字仍写着“最高难度”。
- 昵称字符集按 Unicode 字母、数字判断，不含组合附加符号。
- 用这个版本打开旧世界（包括用和平难度建的世界）后，难度会被永久锁成普通，开始刷敌对生物。
- 旧世界（本系统之前就存在）开服直接定为 NORMAL，不询问。
- 兜底出生点不检查离死亡点的距离（第 5 节）。
- 兜底就落在世界出生点附近（死亡时已清掉床重生点）。溪谷老宅的世界级开关打开后，世界出生点设在老宅前廊（Main 的 M4），这时很少见的兜底会把继任者放在老宅门口，违反“老宅不进继任池”（`survivor_start_template_pool.md` 第 6 节）。**老宅开关在普通世界正式打开之前由 D 修**：兜底改到离世界出生点足够远的野外。M4 在独立测试世界里做不受影响。
- 尸体会挡住子弹（可被准星选中的实体）；Jade 是否显示尸体名字未确认。
- 尸体永久保留，没有清理，也没有腐烂。
- 物品规则的提前告知在创建世界界面模式按钮的悬停提示里（后备的模式选择界面也写着）：专用服务器和旧世界的玩家开局前看不到这条规则。
- 开放局域网的单人世界里，房主还没选模式就死亡时，模式被锁定为 NORMAL，但客户端的模式选择没有被关掉：重生后它会再出现一次，点任何一项都只是关闭（服务器拒绝修改）。

- 客户端 `NameFormat`（HIGH，只在客户端世界里）：用 `Identity` 包里的姓名，画头顶名牌。
- 换人、确认姓名时调用 `refreshDisplayName()` 和 `refreshTabListName()`，并广播 `Identity`。
- 优先级取 HIGH：AFL 先换成幸存者姓名，昵称、前缀类模组之后还能叠加。
- 不受影响：
  - 命令参数（`/tp`、`/msg` 等）仍用账号名；
  - Tab 排序按账号名；
  - 原版显示名悬停仍显示账号名，点击建议 `/tell <账号名>`；
  - 聊天签名不含显示名。

首位幸存者姓名（`client/survivor/AflSurvivorNameScreen`）：

- 首位幸存者生成时 `Named` = false，房主进入后弹出一次姓名界面（在模式界面之后、没有别的界面时）。
- 输入框预填账号名；“使用账号名”或输入昵称后“确定”（回车也可）。确定后不可更改。
- 昵称规则（`SurvivorNames.nickname`）：
  - 去掉首尾空格，多个空格合并为一个；
  - 最多 20 个字符，至少一个字母；
  - 只能用字母、数字、空格和 - ' . _（字母包括中文等各种文字）。

- 不能 Esc 关；单人游戏暂停。
- 还没确认就死亡：姓名定为账号名，界面关闭。
