# 幸存者背景与加点 V1：设计

状态：**设计（2026-10-15），未实现。** 这份文档定内容和数据契约，代码、界面、数据都还没有。实现由谁做等契约定了再分（用户 2026-10-15）。

和现有文档的关系：

- 接在 [幸存者开局模板池](survivor_start_template_pool.md) 上：首次开局和死亡继任共用一个池（用户 2026-10-14 的架构决定），这里不另起一套开局系统。池里的**人物背景**和**开局场景**是两种分开的数据，可以自由组合（用户 2026-10-15 补充，第 1 节）。
- 继任、身份、名册、遗体按 [幸存者死亡与继任 V0](survivor_death_succession_v0.md)，不变。
- 能力只改现有系统的数值：[体力 V1](stamina_system_v1.md)、[负重 V1](weight_system_v1.md)、[温度 V1](temperature_system_v1.md)、[容器逐格搜索](progressive_container_search_v1.md)、[便携柴油发电机](../machines/portable_diesel_generator_v1.md) 的拉绳 QTE、[第一人称武器晃动](../native_guns/first_person_weapon_sway_v1.md)。

## 1. 用户 2026-10-15 定的四点

| 问题 | 决定 |
|---|---|
| 加点自由度 | **背景打底 + 少量自由点**。首位幸存者在背景之外再分 4 点，可以拿负面特质换点；继任者不选，按同样的点数随机分 |
| 技能会不会涨 | **会，慢慢涨**。做什么练什么，涨得慢、有上限；人死了，继任者从自己的背景重新开始 |
| 在哪里选 | **第一次进入世界时**，每个玩家各选各的（多人也能用） |
| 谁做 | 先写这份设计文档，作为 C、D 的数据契约；实现以后再分 |

同日补充（用户 2026-10-15）：

- **背景和出生不绑死**。背景要是强制决定出生地点，四个人就会分散到不同位置，和规划中的联机大厅冲突。所以模板池在数据上分三样：
  - **人物背景**：身份、职业、技能、身体、特质；
  - **开局场景**：出生结构、州、位置、初始物资、演出；
  - **模板组合**：单人可以把某个背景和某个场景关联起来（推荐搭配）；多人由房主统一决定场景，每个玩家只选自己的背景。
  两者不是不可拆分的绑定；开局系统不用重做。
- **点数相同不等于能力相同**。继任者随机分同样的点数预算，但不同技能组合的实际价值不一样，要后期平衡。
- **电工、木工、急救**现在没有完整玩法没关系，但没有可靠经验来源之前不加它们的升级逻辑。

## 2. 原则

- 普通人，不是超人。满级大约是"干这行很多年的熟练工"，每一级的差距控制在 10–20%。
- 技能只改**快慢、耗体力、成功率**，不锁动作。没学过的人也能接线、修枪、拉发电机，只是更慢、更容易失败。
- 有 QTE 的物理动作（锁视角 + 时机条 + 按键，[QTE 约定](../machines/portable_diesel_generator_v1.md)"拉绳"）：技能决定绿区宽度。
- 动作动画的长度不改（换弹、装附件都跟着动画和声音走，`MaintenanceAttachmentOperation.DURATION_TICKS` 51 tick 对着 2.48 秒的声音）。V1 不按技能缩短动画。
- 只做现有系统能体现出来的效果。医疗、车辆、木匠台这些系统还没有，对应技能只有背景和加点给的起始等级，不涨经验；效果和升级等系统做出来、有可靠经验来源时再接（第 4 节标"以后"）。
- 继任不能刷点数：每个继任者的总点数预算和首位一样。这只保证预算相同，不保证实际能力相同：不同技能组合在游戏里的价值差别要后期平衡（第 11 节）。

## 3. 身体

两项，1–5，默认 3。

| 项 | 1 | 2 | 3 | 4 | 5 | 改什么 |
|---|---|---|---|---|---|---|
| 力量 | 24 kg | 27 kg | 30 kg | 33 kg | 36 kg | 舒适负重（`comfort_capacity_kg` 30） |
| | ×1.2 | ×1.1 | ×1 | ×0.9 | ×0.8 | 近战、撬棍、劈柴、拉绳的体力消耗（`melee`、`melee_items`、`chop`、`recoil_pull`） |
| 耐力 | 85 | 92 | 100 | 108 | 115 | 体力上限（`max` 100） |
| | ×0.85 | ×0.92 | ×1 | ×1.08 | ×1.15 | 体力恢复（`regen` 15） |

- 负重的分档（`weight` 里的 `load_ratio`）按新的舒适负重算，档位比例不变。
- 身体不随使用涨（V1）。以后要的话按"长期负重行走慢慢涨力量"另议。

## 4. 技能

六项，0–5。背景给起始等级，开局时单项最高 3（自由点也不能超过 3），之后靠使用涨到 5。

| 技能 | 现在能接上的效果 | 以后 |
|---|---|---|
| 枪械 | 第一人称武器晃动幅度 ×1.25（0 级）… ×0.75（5 级）；体力低时的额外晃动（`fatigue.sway_extra` 1.5）同比缩小 | 卡壳排除、维护台的检查 / 判断 |
| 机械 | 柴油发电机拉绳 QTE 的绿区：0 级 14%，每级 +2.4%，5 级 26%（现在 18% ≈ 1.7 级） | 车辆、发电机故障、修机器 |
| 电工 | 暂无可接（接线 V1 没有耗时和失败） | 接线、配电盘的耗时和失误 QTE |
| 木工 | 暂无可接 | 木匠台：做家具的耗时、木料损耗（[木材体系计划](../dev/wood_system_plan_v1.md)） |
| 急救 | 暂无可接 | 医疗系统 |
| 野外 | 劈柴的体力消耗 ×1.2（0 级）… ×0.8（5 级）；生火（柴炉点火）以后加失败率时接 | 打猎、追踪、野外取水 |

**涨经验**（第 1 节"慢慢涨"）：

- 只有有可靠经验来源的技能才涨：**枪械**（开枪命中、拆装附件）、**机械**（拉绳每一下）、**野外**（劈柴）。具体每个动作加多少在实现时列表。
- **电工、木工、急救**：V1 没有升级逻辑，也不记经验（用户 2026-10-15）。它们只有背景和加点给的起始等级，等接线耗时 / 木匠台 / 医疗做出来、有了可靠的经验来源再加。
- 升级要的经验逐级翻倍（1 → 2 要 1 份，2 → 3 要 2 份，…，4 → 5 要 8 份）。从开局的 3 级练到 5 级，大约要游戏里认真干这一行几周（实际数值实现时按测试定）。
- 只有成功、有意义的动作才算：空拉、对着空气开枪、反复拆装同一个附件这类刷法有冷却或收益递减。
- 经验跟着这个人走：死了就没了，继任者从自己的背景重新开始。遗体不带走技能。

## 5. 特质

正面特质花点，负面特质给点；负面最多 2 个（最多换 2 点）。V1 只做现有系统能体现出来的：

| 特质 | 点数 | 效果 |
|---|---:|---|
| 耐寒 | −1 | 冷的阈值低 1 °C（`comfort_low` 14 → 13，`cold_start` 跟着挪） |
| 怕冷 | +1 | 冷的阈值高 1 °C |
| 耐热 | −1 | 热的阈值高 1 °C |
| 怕热 | +1 | 热的阈值低 1 °C |
| 大块头 | −1 | 力量 +1（可以超过 5，最高 6 = 39 kg），走路、跑步耗体力 ×1.1 |
| 手脚麻利 | −1 | 容器逐格搜索每格 40 tick → 32 tick（±15% 不变） |
| 手笨 | +1 | 所有 QTE 的绿区 ×0.8 |
| 耳背 | +1 | 枪声耳鸣更轻、更短；听不清：远处的声音小一些（[耳罩](../equipment/simple_hearing_protection_v1.md)那套音量处理） |
| 烟瘾、失眠、夜盲…… | | 以后有需求、睡眠、视觉系统再做 |

点数一栏："−1"是花 1 点，"+1"是给 1 点。互斥的不能同时选（耐寒 / 怕冷，耐热 / 怕热，手脚麻利 / 手笨）。

## 6. 点数

- 每个背景给：身体（力量、耐力，可以 ±1 偏离默认 3）、技能起始等级（合计 4 级，例如 2 + 2 或 3 + 1）、0–1 个背景特质（不算点）。
- 首位幸存者另有 **4 个自由点**：1 点 = 身体 +1 或技能 +1（上限见第 3、4 节）；也可以把背景给的身体降 1 换 1 点（最低 1）。
- 负面特质最多 2 个，各给 1 点；正面特质各花 1 点。
- 继任者：随机抽一个允许继任的背景，再把 4 个自由点随机分掉；不随机抽负面特质（V1）。点数预算和首位一样，实际强弱不保证相同（第 2 节）。出生场景另外随机抽（第 7 节），不跟背景走。
- 选完确认后不能改，也不能重选（和继任"跳过演出不能重抽"一个道理）。

## 7. 首批背景、开局场景和组合

背景和场景分开定义，再用组合把它们推荐地搭在一起（第 1 节补充）。

**人物背景**（只管人，不管出生）：

| 背景 | 身体 | 技能（合计 4） | 背景特质 | 进继任池 |
|---|---|---|---|---|
| 林区住户 | 力量 3、耐力 3 | 野外 2、木工 2 | 耐寒 | 进 |
| 卡车司机 | 力量 3、耐力 4 | 机械 3、野外 1 | — | 进 |
| 便利店店员 | 力量 2、耐力 3 | 急救 1、电工 1、机械 1、枪械 1 | 手脚麻利 | 进 |

第二批背景：电工（电工 3、机械 1）、汽修工（机械 3、电工 1）、退伍军人（枪械 3、急救 1，耳背）、猎人（枪械 2、野外 2）、护士（急救 3、野外 1）。都是联邦本地的普通人，说明一两句，不写长故事；名字、外貌照旧从名册随机（模板池第 4 节）。首位幸存者照旧用账号名或自定义昵称、账号皮肤。

**开局场景**（只管出生，归 C 和 Main，模板池第 2 节的三种类型）：

| 场景 | 模板类型 | 进继任池 | 现状 |
|---|---|---|---|
| 溪谷老宅 | 专属结构型（前廊） | 不进 | Main 已有前廊出生 |
| 公路路肩 | 开放环境型 | 进 | C3.4 路边锚点的一种（C 2026-10-15 答复，下面）；之前用 V0 的 `wilderness_ring` |
| 加油站 / 便利店 | 既有建筑型 | 进 | 规划上有（C 的沿路地块 + Main 的结构放置）且结构记录里没标损坏（下面）；之前用 `wilderness_ring` |
| 野外 | 开放环境型 | 进 | V0 的 `wilderness_ring`，现在就能用 |

C 对两个场景的答复（2026-10-15）：

- **公路路肩**：用纯规划查询就够了。建成路网在第一个区块生成之前就绑定好了（`RoadNetworkRuntime`）；路面高度、断面、桥涵、禁止超车区都是 `RoadDesign` / `RoadWorks` 里的纯函数，区块也按同一套函数施工。所以不加载区块就能给出准确的出生点和高度。
  - C 把它做成 C3.4 路边锚点的一种：只出在州道（R2）外侧路肩上，不出在州际路面和硬禁区里；
  - 避开桥、涵洞、超高弯道、禁止超车区（视线差的地方）、截断端头和交叉口附近；
  - 多人：同一侧路肩上每隔约 3 m 一个点，一次给 N 个，都在路肩上，不进车道；
  - 没有路的世界（关了 terrain_works、整段没建）返回 null，退回 `wilderness_ring`；
  - C3.4 排在 C3.3a C–E 组和 C3.3b–d 之后。到那时 C 先把锚点和地块的接口草案发给 Main。
- **加油站 / 便利店**分两层：
  - 规划上有没有：C 只给沿路地块（带出入口的那块地），建筑放没放、放的是什么由 Main 的结构放置决定。两边都是确定的纯函数，就能不加载区块判断"这里规划了一座加油站"。这类地块在路口和互通旁边，要等 C3.3b（路口）和 C3.4（锚点、地块）；
  - 实际上还在不在（被玩家拆了、炸了，多人继任时常见）：只看规划判断不了。由 Main 的结构放置登记"已放置 / 已损坏"，或者出生前读一次已加载的区块；
  - V1 的判断：规划上有，且结构记录里没标损坏。没有地块之前退回 `wilderness_ring`。

**模板组合**（推荐搭配，不是限制）：

| 组合 | 背景 + 场景 |
|---|---|
| 老宅的主人 | 林区住户 + 溪谷老宅 |
| 抛锚的卡车 | 卡车司机 + 公路路肩 |
| 夜班 | 便利店店员 + 加油站 / 便利店 |

- 单人：选一个组合，或者分别选背景和场景（任意搭配），或者随机。
- 多人：房主统一决定场景（所有人一起出生，接联机大厅）；每个玩家只选自己的背景和加点。
- 继任：背景和场景各自随机抽（都要"进继任池"），互不影响。专属结构型场景永远不进继任池。

## 8. 选择界面（第一次进入世界）

- 什么时候出现：首位幸存者第一次登录、身份建好以后（V0 `Survivors.ensureSurvivor` 之后）。继任者不出现这个界面。
- 等待时是一个**新的"选择中"状态**（D 审阅 2026-10-15：V0 没有现成的。V0 的等待接手是死亡画面；V0 的首位幸存者一登录就是 ALIVE，人在原版出生点，起名时也能动）。
  - 由服务器强制：不能动、不受伤、别人看不见，感染者找目标时跳过他。
  - 这个状态存进记录（第 9 节 `Setup`）。选到一半退出，再登录时仍然冻结，重新弹界面。
- 顺序：模式选择（房主，V0 已有）→ 这三步。V0 的起名界面（`SurvivorIdentity`：账号名或自定义昵称）并进第 3 步"确认"，不再单独弹一次，免得连续四个界面。
- 一个现代面板（和生存 HUD 同一套风格，不做 RPG 或像素风），三步：
  1. **开局**：单人先选组合，或者"自定义"后分别选场景和背景；多人场景已由房主定，这一步只选背景。左边列表（名字 + 一行说明），右边详情（背景：起始身体、技能、特质；场景：出生地、初始物资）。顶上一个"随机"。
  2. **加点**：身体两项、技能六项，每项一行，加减按钮，显示剩余点数；特质一栏可以勾，互斥的灰掉。
  3. **确认**：汇总一屏，加上名字（账号名或自定义昵称），"开始"。
- 文字短：按钮一个词，说明一两句；数值写成"负重 33 kg""绿区 22%"这样的读数，细节放到维基。
- 服务器校验点数和上限，确认后写盘。以下都放在确认这一刻做，不在登录时做：
  - 写 `startGameTime` / `startDayTime`（V0 现在在 `ensureSurvivor` 里写）。选择界面花的时间不算"活了几天"；
  - 首位幸存者先在原版出生点等，确认后才按场景传送；
  - 发初始物资，播演出（演出以后做）。
- 多人场景由房主在哪里定（建世界界面，还是联机大厅）：跟着联机大厅的设计定，这里只要求"世界有一个统一场景"这个设置。
- 已有存档：判断"V0 旧记录"要看显式的 `Setup` 键，不能看"背景是空的"，因为新建的首位幸存者在选完之前背景也是空的（D 审阅）。
  - V1 新建的首位幸存者写 `Setup = "choosing"`，确认后写 `"done"`。
  - 没有 `Setup` 键的 ALIVE 记录才是 V0 旧存档：记成"普通人"（身体 3 / 3、技能全 0、无特质、无背景），写 `"done"`，不弹界面。
  - 旧存档里已经掷好、还在 PENDING 的继任者也没有背景和点数：在接手（`takeOver`）时按它的 `rollSeed` 补抽背景、场景和点数，不当普通人。

人物页：E 界面（D 的网格背包）里加一页"人物"：背景、身体、技能等级和经验条、特质。只看，不能改。网格背包界面现在没有分页，要先加一个页签栏。这是 D 的代码，实现时由 D 做。

## 9. 数据契约（给 C、D）

记录在 `SurvivorRecord`（V0 已预留 `OriginState` / `Background` / `Profession` / `Traits` / `Body`）：

| 字段 | 内容 |
|---|---|
| `Setup` | 新增：字符串 `"choosing"` / `"done"`。没有这个键的 ALIVE 记录 = V0 旧存档（第 8 节） |
| `Scene` | 新增：选的开局场景 ID，字符串 `afl:<name>`（C 侧意见）。不认识的 ID 退回 `wilderness_ring` |
| `SpawnSource` | V0 已有，保留：实际是怎么出生的。比如场景找不到地方，就退回 `wilderness_ring` 或 `fallback`。`Scene` 是选了什么，`SpawnSource` 是实际结果 |
| `OriginState` | V0 预留：记实际出生的州，由 C 填 |
| `Background` | 人物背景 ID，同样是 `afl:<name>`；和 `Scene` 分开存，互不依赖。**只用来显示**，不认识的 ID 显示成"未知"，不影响能力 |
| `Body` | V0 预留的是 `@Nullable String`（NBT 字符串 `"Body"`），V0 从来没写过。V1 改成复合标签 `Body: {Strength: int, Endurance: int}`。V0 读字符串时会检查 TAG_STRING，碰到复合标签只返回 null，不会出错 |
| `Skills` | 新增：按技能 ID 存成键值，不按顺序：`Skills: {"afl:firearms": {Lv: int, Xp: int}, ...}`。`Xp` 是当前等级内的进度。读取时把等级夹到 0–5。以后加技能不会错位 |
| `Traits` | V0 已有的字符串列表；ID 用 `afl:<name>` |
| `Profession` | V1 不用（背景已经包含职业） |

**存的是最终值**，不是"背景 + 加点"（D 审阅）：`Body`、`Skills`、`Traits` 都存确认后的结果。各系统只读这些值，不从背景定义重算。这样以后改了背景数据（或数据包），活着的人能力不会跟着变。

**继任者**：在 `Survivors.roll()` 里用 `rollSeed`（`SurvivorNames.stream`）抽背景、场景和 4 个自由点，结果可以复现。场景要在 `SurvivorSpawns.plan()` 之前抽好，plan 按场景选出生方式。

背景的字段（模板池第 4 节"角色背景""可选职业与身体特质"两行，由这份文档填上）：起始身体、起始技能、背景特质、能不能进继任池。场景的字段留在模板池第 4 节（州、环境、出生条件、初始物资、演出、能不能进继任池）。组合只是（背景 ID，场景 ID，显示名），不进存档。

世界设置：多人统一场景（场景 ID，或"每人自选"）。和 V0 的起始模式放在一起、用同一套来源：
- 存进 `SurvivorWorldData`，挨着 `mode`；
- 专用服务器从 `SurvivorConfig` 读（和 `resolveStartMode` 一样）；
- 单人在建世界界面选（和 `applyCreateScreenChoice` 一样）。

同步：
- 本人的身体、技能、特质发给自己的客户端（人物页、晃动、QTE 绿区要用）；别人只看得到名字（V0 不变）。
- 登录、接手、确认时，发整份数据。
- 经验变化很频繁：只在升级时发，或者节流发，不要每加一次经验就发一个包。
- 新包要升协议号。master 现在是 46（1eed4ac7），谁后合并谁升下一个号，合并时和 C 对一下。

效果的接法：各系统读一个统一的查询（"这个玩家的某项能力 / 特质"），不在各系统里各自读记录。查不到（创造模式、旁观、记录没建好、选择中）按"普通人"。晃动、QTE 绿区在客户端算，所以这个查询要有一份客户端镜像，默认值同样是普通人。

## 11. 待定

- 每个动作加多少经验、升一级大约要多久：实现时测了再定。
- 继任者要不要随机带负面特质（V1 不带）。
- 力量要不要影响近战伤害（V1 不影响，只影响体力消耗）。
- 技能组合的平衡：同样的点数，加在枪械上和加在电工上实际价值差很多（电工现在几乎没用）。V1 先接受，系统多起来以后调背景和每级效果。
- 联机大厅怎么定场景、玩家在大厅里怎么选背景：等大厅的设计。
- 初始物资每个背景给什么、价值上限（模板池第 7 节第 7 项）。
