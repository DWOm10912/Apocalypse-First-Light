# 世界时间 V1：B 负责部分的时间单位（2026-10-24）

C 的世界时间 V1（C 工作区 `docs/gameplay/world_time_v1_design.md` 第 6–8 节）把一天改成现实 60 分钟：
- `dayTime` 每 3 tick 走 1 个单位，一天仍是 24,000 单位，游戏 1 小时 = 3,000 tick = 150 s；
- `gameTime`、实体 tick、物理不变慢；
- 天长是服务器配置 `world_time.day_minutes`，默认 60。

C 问了 B 负责的几处时间单位。这里是 B 的决定。

**这一轮不改代码**：用户这一轮不许改 B 的生存、水体、天气倍率、植物参数。下面只定单位和接口，按 C 的 `AflTime` 接口名写；具体数值放在 T4，由用户定。

## 1. 原则

用户的分法：
- 动作之内的事用模拟时间（tick，DT = 0.05 s）；
- 按"天""小时"说的事用世界时间；
- 口渴、饥饿由 B 定。

B 的补充：
- 物理过程本身的速度（水流、热传导、草被踩倒后回弹）用模拟时间；
- 生理和环境"每天多少、每小时多少"的量用游戏小时。

## 2. 水体

| 项 | 单位 | 做法 |
|---|---|---|
| 降雨 mm/h | **游戏小时**（和天气预报的 HOUR 一致） | 每 tick 的水量改成 `AflTime.perTick(mm_h × 1000 mL)`。60 分钟一天时是 1/3 mL/tick，零头进现有的 `rainCarry`。现在的 `LiquidUnits.ML_PER_TICK_PER_MM_H = 1.0` 默认游戏 1 小时 = 1,000 tick，T1 合并后要换掉，否则每场雨的总量是 3 倍 |
| 积水、蒸发、入渗、天然水体水位变化 | 游戏小时 | 同一个换算（第 3 包） |
| 流动、扩散、盆地找平 | 模拟时间 | 不变，DT = 0.05 s |
| 账本 | 不受影响 | 整毫升加存档里的零头，换天长只改每 tick 的换算 |

- **卸载后补算（同意，第 3 包做）**：区块重新加载时，按卸载期间 `dayTime` 走过的世界时间（含睡觉跳过），把这块地的降雨、蒸发、入渗对天气模型积分，一次记进账本，按汇水区落到盆地里。不按 tick 数，不跑物理。没有第 3 包的汇水和入渗之前不做（第 2 包的测试雨是开发命令）。
- **睡觉跳过**：只改世界时间，不快进模拟（用户定的）。跳过的几小时按上一条只结算账本，第 3 包做。
- **原版睡醒清雨**：对 AflWeather 没有影响。原版自己的全局天气一直关着（`ServerLevelWeatherMixin`），各地天气是 `RegionalWeather` 按 `dayTime` 算出来的，睡觉推进 `dayTime`，天气跟着走到醒来的时刻。T1 合并后在游戏里看一次。

## 3. 生存和天气

| 项 | 现在 | 决定 |
|---|---|---|
| 伤口和骨折的"几天"（`WoundConfig.dayTicks = 24000`） | 现实 tick，60 分钟一天时 3 天的骨折一个游戏天就好 | **世界时间**：`dayTicks` 改成 `AflTime.ticksPerDay()` |
| 睡觉愈合（`PlayerHealth.sleepFinished`） | 把跳过的 `dayTime` 单位当 tick 喂给 `Fractures.step`，回血按 skipped / 1200 | **按跳过的游戏小时算**：`Fractures.step(player, AflTime.gameHoursToTicks(skipped / 1000.0), true)`，和醒着熬过同样的游戏小时相当（加上原来的"睡着"加成），回血同样换算。以后订阅 `AflTimeJumpEvent`（只认 `SLEEP`），不再自己算差值 |
| 口渴（`PlayerThirst basePerHour / 72000`） | 现实小时 | **游戏小时**：人一天要喝 2–3 L，是"每天"的量，三天不喝水是三个游戏天 |
| 饥饿 | 同上 | **游戏小时** |
| 体温变化速度 | 每 tick 的热交换 | 模拟时间不变；昼夜气温曲线读 `dayTime`，会自动变慢 |
| 雷击（`AflWeather` perMinute / 1200） | 现实分钟 | **模拟时间不变**：一场雷暴打雷的频率是眼睛看到的物理量。雷暴在现实里持续得更久，一场的雷击总数会是 3 倍，嫌多在 T4 调 |
| 草被踩倒、车压倒后回弹（`MeshPlantBlock` TROD / WHEEL / RISE_TICKS） | tick | **模拟时间不变**：是物理回弹，不是"按天"的生长 |
| 雨区漂移、锋面推进 | 按 `dayTime` 算 | 单位不变，但现实里看起来会慢 3 倍（风是 m/s，雨区按游戏时间漂）。要不要让雨区按模拟时间漂，放进 T4 让用户看 |

## 4. 合并顺序

- T1 合并进 master 之后，B 按第 2、3 节改代码。
- 要先等用户放开这一轮"不改 B 的生存、水体、天气、植物参数"的限制。
- 改完要重跑 `liquidCheck`：降雨场景按新换算算总量。

## 5. 实施：生存部分（2026-10-25）

用户原话："先做世界时间 B 单位：伤口、骨折、睡觉愈合、口渴、饥饿改成按游戏时间算"。C 的 T1 / T2 已经随 e611dc09 进了 master，B 在新分支 `B-Workbench` 上改。

| 项 | 改法 | 60 分钟一天时的结果 |
|---|---|---|
| 伤口、骨折、雷击伤的"天" | `WoundConfig.dayTicks` 默认改成 0，表示世界的一天；新方法 `dayTicks()` 返回 `AflTime.ticksPerDay()`，填正数仍可覆盖（测试用）；`wounds_v1.json` 的 `day_ticks` 改成 0；`Fractures`、`Wounds`、`LightningInjury`、`ClientLightningInjury` 都改读 `dayTicks()` | 一天 72 000 tick（以前 24 000）：3 天的腿骨折要现实 3 小时，和 wiki 写的"游戏日"一致 |
| 睡觉愈合 | `PlayerHealth.sleepFinished` 把跳过的世界时间单位换成同样游戏小时的现实 tick（`AflTime.gameHoursToTicks(skipped / 1000)`），骨折按它愈合（加原来的睡眠加成），回血也按它算 | 睡过半天（12 000 单位）= 36 000 tick 的愈合；回血有 `sleep_max` 30 的上限，实际不变 |
| 口渴基础消耗 | `base_per_hour`（每现实小时 100）改成 `base_per_game_hour`，默认 100 / 72 ≈ 1.3889，`PlayerThirst` 用 `AflTime.perTick` 换算 | 站着不动还是 3 个游戏日喝空（设计稿原意），现实里是 3 小时（以前 1 小时） |
| 口渴出力消耗、肠胃感染的时长 | 不变（模拟时间：按耐力花费、按秒） | 一个游戏日里出力占的比例变成以前的 3 倍 |
| 饥饿 | 原来只来自动作（走、跑、跳、挖、打、寒冷、生病，原版 exhaustion），没有按时间的基础消耗；用户定加上，见第 6 节 | 站着不动 3 个游戏日饿空 |

- 已经在身上的伤口和骨折存的是剩余 tick，按旧的一天算的不会重算。
- 第 2 节（降雨按游戏小时换算）还没做：`LiquidUnits.ML_PER_TICK_PER_MM_H` 还是按 1 000 tick 一小时，每场雨的总量是设计的 3 倍。水这条线暂停中，等用户恢复时一起改，并重跑 `liquidCheck`。
- 编译通过；没有覆盖这几处的离线检查或 GameTest，没进游戏。

## 6. 基础饥饿（2026-10-25）

用户原话："加按游戏小时的基础饥饿，站着不动 3 个游戏日饿空，和口渴一样"。

- **数值：** `health_v1.json` 新段 `hunger.base_per_game_hour` = 20 / 72 ≈ 0.2778 点饥饿值每游戏小时（`HealthConfig.Hunger`），满格 20 点 3 个游戏日扣完，和口渴一样；一天 60 分钟时是现实 3 小时。
- **怎么扣：** `PlayerHealth` 每秒的生命值结算里调 `causeFoodExhaustion`，按 1 点饥饿值 = 4 exhaustion 换算（`AflTime.perTick`）。走原版的路，所以先扣饱和度、再扣饥饿值；幸存者属性 `hunger_rate` 照样乘上去；动作、寒冷、生病的消耗叠加在上面。
- **饱和度：** 刚吃饱时饱和度要先扣完，所以吃饱后实际能撑得比 3 天久一些（最多多 20 点饱和度，再约 3 个游戏日）。
- **不扣的情况：** 和平难度、创造、旁观、死亡时不扣。睡觉跳过的时间不补扣（用户定的：睡觉只改世界时间，口渴也一样）。
- **后果：** 新世界里现在还拿不到吃的（原版食物已退役，AFL 食物没做），几个游戏日后饥饿值会掉到 7 以下，不能自然恢复生命值、耐力恢复变慢；饿死伤害在 `damage.never_below_one` 里，不会饿死。
- 编译通过，没进游戏。


## 7. 游戏内怎么测（2026-10-26）

- **先把一天调短：** 把存档里 `serverconfig/apocalypse_firstlight-time.toml` 的 `day_minutes` 改成 10，保存后马上生效，不用重进。测完改回 60。
  - `/afl time` 应该显示一天 10 分钟，游戏 1 小时 25 s。
  - 能调短是因为这几项都按游戏时间算：天越短，掉得越快。这本身就是在验证"按游戏时间"。
- **生存模式、非和平难度。** 创造、旁观、和平难度都不扣饥饿和口渴。

| 项 | 做法 | 10 分钟一天时应该看到 |
|---|---|---|
| 口渴 | `/aflthirst set 100`，站着别动，隔一段时间输 `/aflthirst` | 每 25 s 少约 1.4；10 分钟（一个游戏日）少约 33。疾跑、挖东西会额外多扣 |
| 饥饿 | 新角色站着别动一个游戏日 | 先扣完饱和度（出生时 5），再掉饥饿值：一天约少 1.7 点（不到一个鸡腿）。之后每天约 6.7 点（3 个多鸡腿） |
| 骨折 | `/afl health fracture left_leg` 再 `/afl health fracture left_leg splint`，用 `/afl health` 看进度 | 上了夹板的腿每个游戏日进度 +0.2（5 天好），10 分钟 +0.2；`/afl health advance 1` 也是 +0.2 |
| 伤口 | `/afl health scratch`，用 `/afl health` 看 | 按"天"的检查和愈合跟着变快（1–1.5 个游戏日，10–15 分钟） |
| 睡觉愈合 | 骨折上夹板后 `/afl time set 21:00`，有床就睡到天亮 | 醒来骨折进度跳一截：跳过的小时数 / 24 / 5 × 1.5（睡着加成），睡 9 小时约 +0.11。口渴、饥饿不补扣 |

改回 60 分钟后，同样的量都慢 6 倍（口渴每现实小时约 33）。
