# 世界时间 V1：B 负责部分的时间单位（2026-10-24）

C 的世界时间 V1（C 工作区 `docs/gameplay/world_time_v1_design.md` 第 6–8 节）把一天改成现实 60 分钟：
- `dayTime` 每 3 tick 走 1 个单位，一天仍是 24,000 单位，游戏 1 小时 = 3,000 tick = 150 s；
- `gameTime`、实体 tick、物理不变慢；
- 天长是服务器配置 `world_time.day_minutes`，默认 60。

C 问了 B 负责的几处时间单位。这里是 B 的决定。

**这一轮不改代码**：用户这一轮不许改 B 的生存、水体、天气倍率、植物参数。下面只定单位和接口，按 C 的 `AflTime` 接口名写；具体数值放在 T4，由用户定。

## 1. 原则

用户的分法：
- 动作之内的事用模拟时间（tick，DT = 0.05 s）；
- 按"天""小时"说的事用世界时间；
- 口渴、饥饿由 B 定。

B 的补充：
- 物理过程本身的速度（水流、热传导、草被踩倒后回弹）用模拟时间；
- 生理和环境"每天多少、每小时多少"的量用游戏小时。

## 2. 水体

| 项 | 单位 | 做法 |
|---|---|---|
| 降雨 mm/h | **游戏小时**（和天气预报的 HOUR 一致） | 每 tick 的水量改成 `AflTime.perTick(mm_h × 1000 mL)`。60 分钟一天时是 1/3 mL/tick，零头进现有的 `rainCarry`。现在的 `LiquidUnits.ML_PER_TICK_PER_MM_H = 1.0` 默认游戏 1 小时 = 1,000 tick，T1 合并后要换掉，否则每场雨的总量是 3 倍 |
| 积水、蒸发、入渗、天然水体水位变化 | 游戏小时 | 同一个换算（第 3 包） |
| 流动、扩散、盆地找平 | 模拟时间 | 不变，DT = 0.05 s |
| 账本 | 不受影响 | 整毫升加存档里的零头，换天长只改每 tick 的换算 |

- **卸载后补算（同意，第 3 包做）**：区块重新加载时，按卸载期间 `dayTime` 走过的世界时间（含睡觉跳过），把这块地的降雨、蒸发、入渗对天气模型积分，一次记进账本，按汇水区落到盆地里。不按 tick 数，不跑物理。没有第 3 包的汇水和入渗之前不做（第 2 包的测试雨是开发命令）。
- **睡觉跳过**：只改世界时间，不快进模拟（用户定的）。跳过的几小时按上一条只结算账本，第 3 包做。
- **原版睡醒清雨**：对 AflWeather 没有影响。原版自己的全局天气一直关着（`ServerLevelWeatherMixin`），各地天气是 `RegionalWeather` 按 `dayTime` 算出来的，睡觉推进 `dayTime`，天气跟着走到醒来的时刻。T1 合并后在游戏里看一次。

## 3. 生存和天气

| 项 | 现在 | 决定 |
|---|---|---|
| 伤口和骨折的"几天"（`WoundConfig.dayTicks = 24000`） | 现实 tick，60 分钟一天时 3 天的骨折一个游戏天就好 | **世界时间**：`dayTicks` 改成 `AflTime.ticksPerDay()` |
| 睡觉愈合（`PlayerHealth.sleepFinished`） | 把跳过的 `dayTime` 单位当 tick 喂给 `Fractures.step`，回血按 skipped / 1200 | **按跳过的游戏小时算**：`Fractures.step(player, AflTime.gameHoursToTicks(skipped / 1000.0), true)`，和醒着熬过同样的游戏小时相当（加上原来的"睡着"加成），回血同样换算。以后订阅 `AflTimeJumpEvent`（只认 `SLEEP`），不再自己算差值 |
| 口渴（`PlayerThirst basePerHour / 72000`） | 现实小时 | **游戏小时**：人一天要喝 2–3 L，是"每天"的量，三天不喝水是三个游戏天 |
| 饥饿 | 同上 | **游戏小时** |
| 体温变化速度 | 每 tick 的热交换 | 模拟时间不变；昼夜气温曲线读 `dayTime`，会自动变慢 |
| 雷击（`AflWeather` perMinute / 1200） | 现实分钟 | **模拟时间不变**：一场雷暴打雷的频率是眼睛看到的物理量。雷暴在现实里持续得更久，一场的雷击总数会是 3 倍，嫌多在 T4 调 |
| 草被踩倒、车压倒后回弹（`MeshPlantBlock` TROD / WHEEL / RISE_TICKS） | tick | **模拟时间不变**：是物理回弹，不是"按天"的生长 |
| 雨区漂移、锋面推进 | 按 `dayTime` 算 | 单位不变，但现实里看起来会慢 3 倍（风是 m/s，雨区按游戏时间漂）。要不要让雨区按模拟时间漂，放进 T4 让用户看 |

## 4. 合并顺序

- T1 合并进 master 之后，B 按第 2、3 节改代码。
- 要先等用户放开这一轮"不改 B 的生存、水体、天气、植物参数"的限制。
- 改完要重跑 `liquidCheck`：降雨场景按新换算算总量。
