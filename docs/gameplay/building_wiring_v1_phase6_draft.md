## 0. 要解决的事

1. **导出的房子没有线**。暗线存在区块里，不在方块里。AFL 的导出（`/afl_author export`，`authoring/BuildingAuthoringService`）只抄方块和方块实体，所以老宅导出成模板放到别处，灯、开关、配电箱都在，墙里一根线也没有，接上发电机也不亮。
2. **M4 要靠模板放老宅**。新世界开局（森林开局计划包 P3）要把老宅当模板放下去，所以这一步是开局的前提。
3. **现在还没有正式放建筑模板的地方**。A1 是用开发桥一块块搭的，老地堡的放置已经退役，只有 GameTest 在放模板。所以这一阶段顺便做一个开发用的放模板指令，M4 的正式放置用同一个函数。

## 1. 你会看到什么

平时玩没有任何变化，只有两处：
1. **导出时**：聊天栏多一行，比如"暗线 147 个节点 · 配电箱 1 个 · 没打包 0 个"。
2. **放下模板以后**：配电箱放好后的第一个 tick 就把线写回墙里。
   - 拿扳手看，线和原来一模一样，房子转了方向的话线也跟着转；
   - 接上发电机就亮，开关照样管它的组；
   - 有的区块还没加载、线没写全时，配电箱的 Jade 多一行"线路待展开"，写全后消失。

## 2. 导出：把线打包进配电箱

- 在 `/afl_author validate` 和 `export` 抄方块的同一步做：
  - 对地块里每个配电箱（商业配电盘、住宅配电箱），沿线做广度优先搜索：和求解一样走连线和斜连线，只走地块里面的格子；
  - 搜到的节点打包进这个配电箱在模板里的方块实体数据 `PackedWiring`（相对配电箱的坐标 + 节点值）；
  - 再记下配电箱当时的朝向 `PackedFacing`。
- 进线（第 5 路）也一样：进线盒、电表箱靠进线连到配电箱，所以进线跟着配电箱走。
- 指向地块外的连线位和线头去掉，因为模板外面没有东西接。
- 连不到任何配电箱的节点不打包，报告里写数量和前几个坐标。两个配电箱连在一起（互连）时，节点只打包一次，报告写"互连"。
- 只改模板的副本，世界里的配电箱不变（和现在的导出状态 `ExportState` 一样）。
- 配电箱的模式、总闸、分路、灯光组开关照原样进模板：导出时总闸合着，放下来也合着。电量照旧清零。
- 导出本来就不许有物品（枪架上的枪、柴炉里的柴、柜子里的东西都会让导出失败），地块里也不许有人和实体。所以导出的就是"没有物资"的老宅。

## 3. 放置：转方向和镜像

- **AFL 的放法**：`worldgen/structure/AflBlockEntityProcessor` 现在给插头、进线盒的相对坐标转方向，这次再加上 `PackedWiring`：
  - 坐标跟着转；
  - 连线、线头、线头分组、斜连线的水平方向跟着转和镜像，上下不变；回路号和组号不变；
  - `PackedFacing` 改成转后的朝向。
- **不经过 AFL 处理器的放法**（原版 `/place template`，以后别的工具）：配电箱自己的方块状态会转，`PackedFacing` 不会。展开时两者不一样，就按两个朝向之间的旋转把线转过来。
- **镜像这样补不回来**：镜像一下和转 180° 看朝向是一样的。所以不经过处理器的镜像放置不支持，线会接到错的位置。报告和文档里写明。

## 4. 展开：放下以后写回墙里

- 配电箱的服务端 tick 里，`PackedWiring` 还有东西，就把能写的写进区块，写一个删一个：
  - 格子所在的区块没加载：留着，以后每 20 tick 再试；
  - 格子已经不能铺线（放的地方这一格变成了空气、玻璃……）：丢掉，记一条日志；
  - 那一格已经有同一路的线：合并在一起（`WiringNode#merge`）。
- 列表随配电箱存档：写到一半存档、退出、重进，会接着写。写完，`PackedWiring` 和 `PackedFacing` 都删掉。
- 这两项不发给客户端：配电箱同步给客户端的数据里去掉它们。设计第 9 节说的"配电箱单独写同步内容"不做全套，只去掉这两项。
- 写进去算布线改动：配电箱重新求解，灯、插座、开关按线接上，扳手的透视也马上看得到。
- 放的地方原来就有暗线的（比如在老宅原地再放一次）：原来的线不删，能铺线的格子里和新线合在一起。

## 5. 怎么测：开发指令

`/afl dev template`，和 `/afl dev wiring` 一样只在开发环境、2 级权限：

| 指令 | 作用 |
|---|---|
| `place <模板> <pos> [旋转] [镜像]` | 按 AFL 的正式放法放（带处理器）。`<模板>` 是 `afl_authoring_exports/` 里导出的文件名，或者资源里的 ID |
| `place_raw <模板> <pos> [旋转] [镜像]` | 不带 AFL 处理器放，模拟原版 `/place template`（原版指令读不到导出目录里的文件） |
| `info <pos>` | 读一个配电箱：还有几个节点没展开、`PackedFacing` |

- M4 正式放老宅（P3）用 `place` 同一个函数。
- 模板是整块盖下去的（地块里的空气也算），所以要放在空地上。

## 6. 验收

**GameTest**（`WiringGameTests` 加一项 `template`）：
- 测试场里搭一栋小房子：配电箱、进线盒、两路线、一盏灯、一个开关、一个插座，一段线走屋顶斜坡。用真正的导出流程（`BuildingAuthoringService.capture`）抄成模板。
- 放 8 次：4 个旋转 × 不镜像 / 镜像（镜像加旋转就覆盖了所有 8 种摆法），每次都放在 x、z 都跨区块边界的位置，配电箱和设备分在不同区块。每次查：
  - 每个节点的位置、连线、线头、分组、斜连线都对；
  - 求解结果和原房子一样；
  - 灯亮、插座有电、开关管着它的组。
- 不经过处理器放 4 个旋转：靠 `PackedFacing` 转回来，结果一样。
- 写到一半存档、读回：没写的还在列表里；写完列表就没了。
- 打包报告：地块外的线、连不到配电箱的线都列出来。
- "区块没加载就留着以后写"：GameTest 里做不出真正没加载的区块，用测试钩子模拟。
- 再跑一次 `GasStation01GameTests`：A1 的配电盘是 `LEGACY_AREA`，没有暗线，打包以后应该什么都不变。

**你实机**（用「house test」里的真老宅）：
1. 你进游戏，输 `/afl_author resume forest_home_b_m1 -785 83 -144 37 26 13 3`。先把枪架上的枪、柴炉里的柴、柜子里的东西拿走，人站到地块外面。
2. 我用开发桥的 `authoring_validate` 先读一遍打包报告，不写文件，对一下是不是第 4 阶段的 147 个节点加你第 5 阶段改过的线。
3. 你输 `/afl_author export`，得到 `run/afl_authoring_exports/forest_home_b_m1.nbt`。
4. 在空地上 `/afl dev template place forest_home_b_m1 …`，转一个方向、跨区块边界放。接发电机、开灯、扳开关，拿扳手看线。
5. 再用 `place_raw` 放一个转了方向的。

## 7. 不在第 6 阶段

- **WorldEdit 复制粘贴**（开发桥的 `we_copy` / `we_paste`，或者 `//copy`、`//paste`）：线在区块里，WorldEdit 抄不到。这一轮不做：复制过去的房子要用扳手重接，或者导出成模板再放。
- 不经过处理器的镜像放置（第 3 节）。
- 老宅的正式模板 `forest_home_b`（森林开局计划 T2）、新世界放置（P3）：都在 M4。
- 把模板放进资源 `data/apocalypse_firstlight/structures/`：M4 做 T2 时再放。
- 插头、进线盒电缆这些别的方块实体，不经过处理器时相对坐标不会转。这是现有的问题，和暗线无关，这一轮不修，只写进报告。

## 8. 要你定的（2026-10-14 都按推荐）

1. **用「house test」里的真老宅验收**：你自己 resume 和 export（开发桥没有导出操作），导出前拿走屋里的东西。ID 用 `forest_home_b_m1`，只做测试，不进资源。

## 9. 实现时和草案不同的地方（2026-10-14）

- **Jade 不靠同步**：配电箱的 Jade 本来就向服务端要数据（`IServerDataProvider`），所以「线路待展开」直接读服务端剩几个节点，更新包里不用另加计数。更新包只去掉 `PackedWiring`、`PackedFacing` 两项。
- **展开不管模式**：`LEGACY_AREA` 的配电箱带着打包的线也照样写回墙里（只是它不按暗线供电）。
- **打包从安装格出发**：配电箱的安装格不在地块里（配电箱贴着地块边）时，这个配电箱不打包。
- **丢掉的格子**：邻格指向它的连线也去掉（已经写进去的和还留着没写的都去），不留断头。
- **导出前还没写完的配电箱**：它身上剩下的 `PackedWiring` 不带进新导出，新导出只按世界里的线重新打包。
- **报告文字**：`暗线 N 个节点 · 配电箱 N 个 · 没打包 N 个`，后面按情况跟"（前 5 个格子）""互连 N 路""出界剪掉 N 处""有一路超过 4096 个节点，没打包全"。接在 `VALIDATED` / `EXPORTED` 那一行后面（那一行其余是英文）。
- **放模板**：`/afl dev template place` 先加载模板盖到的区块，放方块时不发邻格更新（标志位 2，和原版 `/place template` 一样）。`<模板>` 不写命名空间时先找导出，写了只找资源。
- **逐条查过的放置路径**（设计第 10 节要求）：
  - 带处理器：`worldgen/structure/AflTemplatePlacer`（`/afl dev template place`，以后 M4 P3 也用它）、`GasStation01GameTests`；
  - 不带处理器：原版 `/place template`、结构方块（读不到导出目录，要先把模板放进资源或 `generated`）、`place_raw`：靠朝向差转回来，镜像不行；
  - WorldEdit（开发桥 `we_copy` / `we_paste`、`reference_paste`、`//copy` / `//paste`）：只抄方块和方块实体，世界里配电箱写完以后身上没有 `PackedWiring`，所以不带线；
  - AFL 现在没有别的建筑放置（城市生成器、拼图结构都还没有）。
- **GameTest 里的"区块没加载"**：没用测试钩子，直接把两个节点的偏移指到 4,000 格外真的没加载的区块。
