## 2. 生存与健康 V2 总体架构

### 2.1 一个身体，几层数据

```
          事件（伤害、环境、进食、喝水、治疗）
                       │
        ┌──────────────┼───────────────────────────┐
        ▼              ▼                           ▼
   伤势 Injury     病症 Condition            生理量 Vitals
 （部位、类型、     （肠胃感染、辐射病、        （生命、血量、呼吸储备、
   严重度、处理）     伤口感染…，有阶段）          能量、水分、核心体温…）
        └──────────────┼───────────────────────────┘
                       ▼
            症状 Symptom（强度 0–1，有来源）
                       ▼
       功能通道 Channel（移动、双手、瞄准、平衡、视觉、
       听觉、意识、呼吸、耐力、恢复）
                       ▼
     属性修饰 + 动作限制 + 屏幕 / 声音效果 + 徽章 / 健康页
```

- **伤势**是身体某个部位的具体损伤；**病症**是全身性的病程（有阶段、会好或会恶化）；**生理量**是持续数值。三者都不直接改属性或画效果，只**产生症状**。
- **症状**是唯一和玩法、画面打交道的一层。新病症只要声明"哪个阶段给哪些症状、多强"，不用重新开发视觉效果和属性修改（用户第六节要求）。
- **生命值**是生理量之一，代表总体状况；伤势和病症通过"压低恢复上限"和"持续消耗"影响它（第 3 节）。

### 2.2 服务端状态：`BodyState`

- 挂在 `LivingEntity` 的 Capability 上（不只玩家），这样以后 AFL 自己的感染者、NPC、动物可以用同一套部位和伤势（`afl_fauna_plan_v0.md` 的方向）。玩家先用；非玩家实体默认不创建，按实体类型开关。
- 字段（V1 用到的先做，V2/V3 的先留位）：

```
BodyState {
  version
  vitals { blood_ml, breath, hypoxia, energy, hydration(=现在的口渴值), ... }   // 核心体温、耐力仍归原系统，只读
  injuries: [Injury]         // V2
  conditions: [Condition]    // V1（迁移现有两个 MobEffect）
  symptoms: {id -> 强度, 来源}  // 每秒重算，不存档
  hp_cap                     // 恢复上限（第 3.2 节），每秒重算，不存档
}
```

- 存档：玩家 persistentData 新键 `afl_body`（和现有 `afl_thirst` 等同级，死亡时删除）；非玩家实体存进实体 NBT。
- 每秒一次结算（和体温、口渴同频，按实体 id 错开），事件驱动的变化（受伤、治疗）立即结算。

### 2.3 现有系统的去重原则

同一个状态只能在一个地方计算一次：

- 现在体温、口渴、辐射病、肠胃感染、耐力各自直接改属性、各自阻断回血、各自扣血。V2 改成：它们**只报告自己的量或阶段**，由症状层统一换算成后果。
- 例：现在"不回血"由 `FoodDataThirstMixin` 同时问口渴和体温；V2 由恢复区间（第 3.3 节）统一判断，Mixin 只问一个地方。
- 例：辐射病现在自己加移速修饰、自己给反胃；V2 辐射病阶段只给"虚弱""恶心"症状，移速和反胃由症状层统一施加，和肠胃感染的恶心取同一个通道，不会叠出两份反胃。

### 2.4 数据驱动

和现有体温、口渴、成长一样走 JSON + `/reload`：

- `D/body/injuries/*.json`：伤势类型（V2）。
- `D/body/conditions/*.json`：病症和阶段。
- `D/body/symptoms/*.json`：症状 → 功能通道曲线 + 客户端效果。
- `D/body/damage_rules/*.json`：伤害类型 → 生命损失 + 伤势生成规则。
- `D/body/treatments/*.json`：医疗物品 → 对哪些伤势 / 病症起什么作用（V2）。
- `D/body/body_v1.json`：全局数值（恢复区间、生命上限规则、呼吸、能量、水分）。

## 3. 100 HP 与伤害平衡原则

### 3.1 生命值的含义

- 基础最大生命 100（改玩家 `generic.max_health` 基础值）。**所有人都是 100**，不随身体等级或成长增加（避免成长膨胀，见第 8 节）。
- 生命 = 总体生理储备。0 = 死亡（或进入"心跳骤停"状态，第 7.6 节）。
- 生命本身不说明哪里受伤；行动能力由伤势和症状决定。所以同样剩 50 HP：
  - 甲：大腿枪伤已止血、骨折已固定 → 能走但跛、不能疾跑，生命能慢慢回；
  - 乙：全身擦伤、轻度脱水 → 行动基本正常，喝水休息就回；
  - 丙：腹部伤还在渗血 → 看着行动正常，但生命在持续往下走，必须处理。

### 3.2 恢复上限（`hp_cap`）

严重伤病不能只靠吃饱自动痊愈，做法是**压低生命的恢复上限**，而不是持续扣血：

- `hp_cap = 100 − Σ(每个伤势 / 病症的上限压制)`，最低 10。
- 生命可以自然恢复，但**只能恢复到 `hp_cap`**；伤势处理好、病症好转后上限回升，生命才能继续回。
- 例（平衡参数）：未固定的骨折 −15，已固定 −5；感染中的伤口 −10，扩散成全身感染 −30；失血 II 级 −15、III 级 −35、IV 级 −60；辐射病 III 期 −20、IV 期 −40；饥饿衰竭每天 −10（累积）。
- 生命高于新上限时**不会立刻掉下来**，而是按 1 HP/s 降到上限，避免"处理伤口前 100，摔一下突然只剩 40"的跳变感（真正的即时伤害另算，见 3.4）。

### 3.3 健康恢复区间

不要求食物、水分、体温全满。只要同时满足下面几条，就处在"恢复区间"，生命按速度回升到 `hp_cap`：

| 条件 | 阈值（平衡参数） |
|---|---|
| 水分 | ≥ 30 |
| 能量储备 | ≥ 20（第 5 节） |
| 核心体温 | 35.5–38.5 °C |
| 没有正在出血的伤口 | 已止血或已包扎的不算 |
| 没有"阻止恢复"的病症阶段 | 例如肠胃感染发作期、辐射病 III 期以上、全身感染 |

恢复速度（平衡参数）：

- 清醒活动中 1.5 HP/分钟（从 50 回到 100 约 33 分钟，约 1.7 个游戏日）。
- 休息（坐、躺、在车里不开车）4 HP/分钟。
- 睡觉跳夜：按跳过的时长一次性结算（休息速度），但同样受 `hp_cap` 限制。
- 吃饱喝足（能量 ≥70 且水分 ≥70）再 ×1.25；`natural_regen` 属性乘在最后。
- 处在恢复区间外：不回血，但也不因此扣血（扣血只来自出血、极端状态和即时伤害）。

### 3.4 伤害换算：不是全部乘 5

- **即时伤害**仍走原版 `hurt` 流程。换算放在 `LivingDamageEvent`（护甲、附魔减免**之后**）：原版护甲的减免和伤害大小有关（`CombatRules.getDamageAfterAbsorb`：伤害越大，护甲越不顶用）。先按原版尺度算完护甲再换算，现有护甲手感不变；直接把伤害 ×5 再进护甲，会让护甲突然变弱。
- 每种伤害类型由 `damage_rules` 定义：生命损失 = 原版尺度伤害 × 换算系数（多数 4–6，因类型而异），外加伤势生成（V2）。没有规则的类型（其他模组、原版生物）按默认 ×5 处理，保证不崩。
- **示例目标**（平衡参数，V1 只有生命部分，V2 加伤势）：

| 事件 | V2 目标 | 说明 |
|---|---|---|
| 感染者抓一下 | 6–10 HP，可能擦伤 / 割伤（手臂、躯干） | 现在原版僵尸普通难度 3 点 ≈ 15%，改后 ~8% |
| 感染者咬 | 12–18 HP + 咬伤（高感染风险） | 咬和抓的区分要等 AFL 自己的感染者（动物计划） |
| 摔落 4–6 m | 5–15 HP，脚 / 小腿扭伤概率 | 原版 3 格以下不伤保留 |
| 摔落 6–10 m | 15–40 HP，骨折概率 | |
| 摔落 10–15 m | 40–80 HP，骨折很可能，头部外伤概率 | |
| 9 mm 命中躯干（PvP / 以后 NPC） | 25–35 HP + 枪伤（出血） | 头部按致命设计 |
| 步枪命中躯干 | 50–70 HP + 枪伤（大出血、骨折概率） | |
| 被大树压中 | 现有公式 × 4，加骨折 / 头部外伤 | 上限 40 → 160，等于大树能压死人 |
| 站在火里 | 每秒 2–3 HP + 烧伤累积 | |
| 爆炸 | 按距离：生命 + 多处割伤 + 脑震荡 + 耳鸣 | |

- 原版的回复类效果（再生、瞬间治疗、金苹果、吸收）按同一系数 ×5 换算，保持相对强度；以后可单独调低（AFL 不应有"喝药瞬间回满"）。

### 3.5 持续伤害

V2 里持续掉血**只**来自：正在出血、严重缺氧、心跳骤停、极端体温（C3/H3 之后）、辐射病 IV 期、严重脱水 / 饥饿的最后阶段。其余伤病都通过 `hp_cap`、症状和行动限制表现。

### 3.6 现有扣血的换算（V1）

| 现有 | V1 改成 |
|---|---|
| 脱水 =0 每 10 s 扣 1 | 病症"严重脱水"：`hp_cap` 每游戏小时 −10，到底后再持续扣（第 5.4 节） |
| 失温 / 中暑每 15 s 扣 1 | 保留为持续伤害，按 ×5 换算成每 15 s 5 HP（约 5 分钟从满到 0，和现在相同），同时给症状 |
| 辐射病 IV 期每 5 s 扣 1 | 每 5 s 5 HP 保持相对强度；加 `hp_cap` −40 |
| 闪电 1000 | 改成伤情驱动（第 7.6 节） |

## 4. 氧气与呼吸

### 4.1 三个量要分开

医学上"想呼吸的冲动"主要由二氧化碳驱动，和血氧不是一回事：先过度换气的人冲动来得晚，血氧却可能先降到昏迷（浅水晕厥，CDC MMWR 2015）。所以不把一个氧气百分比当血氧：

| 量 | 含义 | 范围 |
|---|---|---|
| 呼吸储备 `breath` | 这口气还能撑多久（游戏量，不是血氧） | 0–1 |
| 呼吸急迫 `urge` | 憋得难受的程度（驱动画面和声音） | 0–1 |
| 缺氧 `hypoxia` | 身体真正缺氧的程度（驱动症状和危险） | 0–1，存在 `vitals` |

陆地正常呼吸时三者都不需要管理：`breath` 自动满、`urge` 为 0、`hypoxia` 自然消退。

### 4.2 耗氧

- 容量（平衡参数）：普通人（体能 3）静止憋气约 45 s（Tipton 团队给出的空气中最大憋气 45–60 s；研究强调个体差异极大，这个数字不是安全阈值）。
- 体能等级 1–10：容量 ×0.8 … ×1.35；以后的"肺活量"特质和潜水装备乘在这里；原版"水下呼吸"附魔、潮涌核心、水肺效果当作装备处理。
- 耗氧倍率（平衡参数；"运动缩短多少"没有找到可靠定量，是设计假设）：

| 活动 | 倍率 | 普通人约多久 |
|---|---|---|
| 静止 / 漂浮 / 慢慢下沉 | 1.0 | 45 s |
| 正常游泳 | 1.6 | 28 s |
| 疾游（冲刺游泳） | 2.5 | 18 s |
| 水下挖掘、战斗、搬重物 | 2.2 | 20 s |
| 负重超标 | 再 ×(1 + 0.3 × 超标程度) | |
| 体温 C2 以下 | 再 ×1.2 | |

- `urge` 随 `1 − breath` 上升，过 0.6 开始画面收窄、心跳声，过 0.9 时每秒有概率**不由自主地吸一口**（平衡参数 25%/s）：在水里就吸进水，`breath` 立刻归 0 并记一次"呛水"。

### 4.3 冷水休克

研究：低于约 15 °C 的水里，突然入水会引发喘气反射和过度换气，60–90 s 达到峰值后减弱；5 °C 水中平均憋气只剩约 9.5 s（National Center for Cold Water Safety；Barwood 等 2018）。

- 入水时水温 <15 °C（用体温系统的水温），给 60–90 s 的"冷水休克"：容量 ×0.35、`urge` 上升 ×2。
- 耐寒成长等级减轻它（反复冷水浸泡确实会减弱反应）；皮下脂肪挡不住，所以"大块头"不减。
- 这是**唯一会让玩家意外溺水的情况**，入水前的体温徽章和水面寒气要给足提示。

### 4.4 缺氧分期

`breath` 到 0 后 `hypoxia` 开始上升（平衡参数：约 20 s 从 0 到 1）。

| 阶段 | hypoxia | 表现 |
|---|---|---|
| 呼吸急迫 | 0（breath 低） | 画面收窄、心跳声、气泡声；行动正常 |
| H1 缺氧 | 0–0.3 | 视野边缘发灰，游泳速度 ×0.85 |
| H2 动作障碍 | 0.3–0.6 | 不能疾游，手上动作（挖、交互）失败率升高，游泳 ×0.6，画面去色 |
| H3 意识障碍 | 0.6–0.85 | 操作漂移、视线模糊、随时会黑过去 |
| H4 失去意识 | ≥0.85 | 玩家失去控制，人随浮力漂浮或下沉；**生命每秒 −4**，约 25 s 后死亡 |

- 回到空气中：`breath` 几秒回满；`hypoxia` 约 20–40 s 消退，期间大口喘气、耐力恢复减半。
- 到过 H3 的，留下"缺氧后"病症（头痛、乏力，约 1 个游戏小时）。呛过水的留"呛水"（咳嗽，V3 有小概率发展成肺炎）。
- 失去意识的人如果被拉出水面（以后多人 / NPC 施救），`hypoxia` 开始消退；单人时漂到水面也算。

### 4.5 以后扩展：呼吸介质和装备

为浓烟、一氧化碳、密闭空间预留接口（V3）：

```
interface BreathingMedium { // 按头部位置查询
  double oxygen();     // 可用氧，空气 1.0，水 0
  double smoke();      // 刺激、视线
  double carbonMonoxide(); // 进入"碳氧血红蛋白"病症，按小时级半衰期消退（McMaster：室内空气 4–6 小时）
}
interface BreathingGear { BreathingMedium filter(BreathingMedium in); double capacityBonus(); }
```

- 缺氧环境（OSHA：氧浓度 ≤19.5%）、烟雾、CO 都走同一套 `hypoxia` 和症状，不另做一套"空气血条"。
- 发电机和皮卡文档里"不模拟 CO"的决定保持不变，直到用户另行决定。

### 4.6 和原版的关系

- 用 Mixin 接管玩家的 `LivingEntity#baseTick` 里的 air 逻辑（`decreaseAirSupply` / `increaseAirSupply` / 溺水伤害），原版 `airSupply` 字段只作为显示代理（= `breath` × 最大值），HUD 和其他模组读到的值仍然合理。
- 非玩家实体保持原版。

## 5. 食物、水分与长期营养

### 5.1 现在的问题

原版饥饿条：疾跑、跳跃、干活几分钟就掉一格，饱食 ≤6 不能疾跑、耐力恢复减半，饿到 0 开始扣血。玩家被迫每隔几分钟吃东西——这正是用户不想要的。口渴 V1 的速度（满到空约 3 个游戏日）已经比较合理，主要问题在饥饿。

### 5.2 四个量

| 量 | 含义 | 平时感受 |
|---|---|---|
| 胃（饱腹，短期） | 刚吃了多少；沿用原版 `foodLevel` 0–20，兼容所有原版和以后的食物 | "有点饿了"只是提示，**没有惩罚** |
| 能量储备（长期） | 新增 0–100；约等于几天的热量储备 | 满储备普通活动约 3 个游戏日才见底 |
| 水分 | 沿用现在的口渴值 0–100 | 和现在一样 |
| 营养质量（V2） | 最近几天吃得杂不杂 | 只影响伤口愈合和抗病，±10–15% |

- 吃东西先进胃（原版 `nutrition`），然后按消化速度把"胃里的量 + 原版饱和度"转成能量储备（平衡参数：每点营养 / 饱和度 ≈ 1.2 能量）。胃大约半个游戏日排空。
- 能量消耗 = 基础（满到空约 3 个游戏日）+ 花掉的耐力（和口渴同一个接口）+ 寒冷寒颤额外消耗。这样**一个游戏日吃 1–2 顿**就够了（现实 10–20 分钟一顿），短时间不吃没有后果。
- 原版饥饿的消耗度（`causeFoodExhaustion`）、饱食 ≤6 的耐力减半和不能疾跑、原版饿死扣血**全部停用**，由能量储备替代。`hunger_rate` 属性改成乘能量消耗。

### 5.3 能量储备的分档（平衡参数）

研究：糖原 2–3 天耗尽，之后靠脂肪和蛋白；正常体重的人只喝水可存活约 2 个月（Swiss Med Wkly 2012）；短时空腹主要影响长时间耐力运动（Aird 2018）。游戏里压缩：

| 能量 | 状态 | 后果 |
|---|---|---|
| ≥30 | 正常 | 无 |
| 15–30 | 体力不济 | 耐力上限 −15%，耐力恢复 ×0.85 |
| 5–15 | 虚弱 | 耐力上限 −30%，伤口愈合 ×0.5，**不在恢复区间**（第 3.3 节阈值是 20） |
| 0–5 | 饥饿衰竭 | `hp_cap` 每游戏日 −10（累积），疾跑时可能眼前一黑（短暂黑屏 + 摔倒） |

- 从 0 能量到饿死约 10 个游戏日（现实约 3 小时），给足处理时间；吃回去后 `hp_cap` 的压制按每游戏日 +20 恢复（再喂养不做惩罚，V3 才考虑）。

### 5.4 水分的分档（重定口渴 V1 的后果）

研究：运动中体重丢失 >2% 成绩下降（ACSM 2007），轻度 ≤5–6%、中度 7–10%、重度 >10% 危及生命（各来源切点不一）。

| 水分 | 状态 | 后果（平衡参数） |
|---|---|---|
| ≥30 | 正常 | 无 |
| 15–30 | 口渴 | 耐力恢复 ×0.85（现在是 ×0.75） |
| 5–15 | 脱水 | 头痛、头晕症状；不在恢复区间 |
| 0–5 | 严重脱水 | 意识混乱症状；`hp_cap` 每游戏小时 −10 |
| 0 | 虚脱 | `hp_cap` 降到底后每分钟 −5 HP（约 20 分钟死亡，现在是 200 s） |

- 消耗速度不变（基础 + 出力 + 热 + 肠胃感染 + `thirst_rate`）；热环境的倍率保留。
- 煮沸 / 纯净 / 生水、肠胃感染的规则不变，只迁移成病症（第 7.2 节）。

### 5.5 和现有食物、烹饪、疾病的兼容

- 原版食物全部能吃，按原版 `nutrition` / `saturation` 进胃和能量；不需要先做 AFL 食物。
- 口渴表里带水分的原版食物（西瓜、炖菜等）保留。
- V2 加"食物中毒"：生肉、腐肉、变质食物有概率（和生水同一套病症框架）；烹饪（原版熟食、箱式炉）消除风险。
- 腐坏、保质期、冰箱：不在本设计范围（`食物.md` 的设想保留，以后单独做），但能量和胃的接口能直接接上。
- 营养质量（V2，可选）：食物按 4 类（主食、肉蛋、蔬果、油脂）计入最近 3 个游戏日的"吃得杂不杂"，只影响伤口愈合速度和抗病，**不做维生素和缺乏病**。

## 6. 身体部位、伤势与症状数据结构

### 6.1 部位

和玩家骨骼（16 骨骼，`player_skeleton_v1`）对齐，合并成 11 个部位：

| 部位 | 对应骨骼 | 主要影响 |
|---|---|---|
| 头 HEAD | head | 意识、视觉、平衡、听力 |
| 胸 TORSO | chest | 呼吸、耐力、出血危险 |
| 腹 ABDOMEN | pelvis | 内出血危险、恶心、弯腰动作 |
| 左 / 右臂 ARM | upper + lower arm | 瞄准稳定、换弹、近战、搬运 |
| 左 / 右手 HAND | hand | 精细动作（换弹、包扎、搜索、QTE） |
| 左 / 右腿 LEG | upper + lower leg | 移动速度、跛行、跳跃、疾跑 |
| 左 / 右脚 FOOT | foot | 跛行、跳跃、潜行噪音 |

命中部位：

- 子弹：用命中点对玩家骨骼姿势求最近的骨骼（骨骼已有每帧姿势；服务端用简化胶囊）。
- 近战：按攻击者高度和朝向加权随机（感染者偏手臂、躯干、头）。
- 摔落：脚 → 腿 → 腹 / 头（高度越高越往上）。
- 火、爆炸、雷击：按暴露面分配到多个部位。

### 6.2 伤势记录

```
Injury {
  type        // 伤势类型 id（D/body/injuries/*.json）
  part        // 部位
  severity    // 0–1
  bleed       // 当前出血速度（由类型 + 严重度 + 处理状态算）
  dirt        // 污染 0–1（伤口进了泥、异物）
  infection   // 感染 0–1
  treatment   // 处理状态：压迫 / 包扎(质量, 脏了没) / 清洗 / 消毒 / 夹板 / 止血带(时间) / 烧伤敷料 / 缝合
  healing     // 愈合进度 0–1
  age         // 游戏 tick
}
```

伤势类型 JSON 声明：创建时的生命损失、出血曲线、疼痛、对部位功能的影响、感染风险、是否会恶化、需要什么处理、愈合时间。新伤势只写 JSON。

### 6.3 伤势表

时间尺度：**伤势按"现实一周 ≈ 一个游戏日"压缩**（游戏日 20 分钟）。研究给出的愈合时间（伤口增生期 2–4 周、骨折 4–10 周、扭伤 2–12 周）按此换算后落在 1–10 个游戏日，既有分量又不至于拖死节奏。各类天数都是平衡参数；擦伤 / 割伤 / 刺伤各自的天数没找到可靠来源。

| 伤势 | 来源 | 部位 | 症状 | 影响行动 | 会恶化吗 | 处理 | 恢复（游戏日） |
|---|---|---|---|---|---|---|---|
| 擦伤 | 摔、擦撞、感染者抓 | 手、臂、腿、头 | 轻痛，短时少量渗血 | 几乎没有 | 脏了会感染 | 可不处理；清洗包扎降感染 | 1–2 |
| 割伤 | 玻璃、刀、感染者抓、爆炸破片 | 任意 | 痛、出血（随严重度） | 手 / 臂：换弹、搜索变慢 | 不包扎持续出血；感染 | 压迫 → 包扎；深的要缝（V3） | 2–5 |
| 刺伤 | 钉子、木刺、刺物 | 脚、手为主 | 痛、少量出血 | 脚：跛行 | **感染风险高** | 清洗消毒、包扎 | 2–4 |
| 咬伤 | 感染者、动物 | 臂、手、腿、颈 | 痛、出血 | 同割伤 | 感染风险很高 | 清洗消毒、包扎（感染者是否传播感染另定） | 3–6 |
| 枪伤 | 子弹 | 任意 | 剧痛、大量出血 | 按部位严重受限 | 不止血会致命；感染；可能骨折 | 压迫 / 止血带（四肢）→ 包扎 → 取弹（V3） | 5–10 |
| 爆炸伤 | 爆炸 | 多处 | 多处割伤 + 烧伤 + 脑震荡 + 鼓膜 | 综合 | 同各伤 | 逐个处理 | 视组成 |
| 出血（不是单独伤势） | 上面各伤的 `bleed` 汇总 | 全身 | 失血分级症状（6.5） | 见 6.5 | 是 | 止血 | 血量按每游戏日约 15% 恢复（需水分、能量在恢复区间） |
| 烧伤（一 / 二 / 三度） | 火、岩浆、热炉面、电击、燃料火 | 暴露部位 | 痛；二度起水疱 | 手：精细动作变慢；面积大时全身虚弱 | 感染（二度起）；面积大时脱水加快 | 冷却（离开热源后用水）→ 烧伤敷料；三度需要 V3 | 一度 0.5–1；浅二度 1–3；深二度 3–8；三度不自愈，只能处理到稳定（留疤：小幅永久功能影响，可选） |
| 电击伤 | 电线（以后）、雷击 | 入口 / 出口 + 沿途 | 局部烧伤、肌肉痛、心律问题 | 肌肉无力 | 心脏急症（小概率） | 烧伤处理、休息 | 1–3 |
| 扭伤 | 摔 4–6 m、疾跑落地、崴脚 | 脚踝、手腕 | 痛、肿 | 脚：跛行、不能疾跑；手腕：换弹慢 | 带伤负重会加重 | 休息、包扎（加压）、夹板可选 | I 度 1；II 度 2–3；III 度 4–6 |
| 骨折 | 摔 6 m 以上、重物压、枪伤 | 四肢、肋骨 | 剧痛、该部位几乎不能用 | 腿：不能疾跑跳跃，移动 ×0.5；臂：不能双手持枪、不能攀爬 | 不固定时疼痛不减、愈合 ×0.3、`hp_cap` −15 | 夹板固定（V2）；正骨 / 手术不做 | 5–10（胫骨最长） |
| 头部外伤 / 脑震荡 | 摔、重击、爆炸、树压 | 头 | 头晕、头痛、视物模糊、平衡差、恶心、对光声敏感 | 瞄准晃动、偶尔踉跄 | 再次撞头会加重；危险征象（反复呕吐、越来越重）→ 颅内出血（罕见，需要 V3 医疗） | 休息、少剧烈活动 | 1–3 |
| 听力损伤 | 枪声、爆炸、雷击 | 耳 | 耳鸣（现有）、听不清 | 世界声音变小、方向感差 | 反复暴露累积 | 耳罩预防；短时损伤自己好 | 暂时性：几十分钟到一个游戏日；永久性：只做小幅、可选（见 7.5） |
| 伤口感染 | 脏伤口、刺伤、咬伤、未处理 | 伤口所在 | 红肿热痛加重 → 发烧 | 局部更痛；全身感染时虚弱、发烧 | 局部 → 全身（败血症） | 清洗消毒；抗生素（V2 基础） | 处理后 1–3 |
| 疼痛（症状） | 上面各伤 | — | 痛 | 瞄准晃动、动作变慢、睡不好 | 随伤势 | 止痛药只压症状，不治伤 | 随伤势 |

"伤势不全部表现为持续扣血"：上表中只有未止血的出血会直接持续消耗生命；其余都通过行动限制、`hp_cap` 和症状表现。

### 6.4 功能通道

症状不直接改属性，而是改下面这些通道（每个 0–1，1 = 正常），再由一个地方统一写成属性修饰和动作限制：

| 通道 | 作用到 |
|---|---|
| move | 移动速度、能否疾跑、跳跃高度、跛行动画 |
| hand_l / hand_r | 换弹、搜索、交互、QTE 的时间和失败率 |
| aim | 武器晃动、后坐力回复（乘在成长的每级系数上） |
| balance | 偶尔踉跄、攀爬失败、摔落伤害 |
| vision | 模糊、去色、视野收窄 |
| hearing | 世界声音音量（复用 `hearing` / 耳罩那条路径） |
| consciousness | 操作漂移、黑屏、失去意识 |
| breath | 耗氧、耐力恢复 |
| stamina | 耐力上限、消耗、恢复 |
| recovery | 生命恢复速度、伤口愈合速度 |

### 6.5 失血分级

血量用毫升记（成人约 5000 mL），分级按 ATLS（教学用分级，实际伤员常不符合，所以只当游戏分档）：

| 失血 | 症状 | 后果（平衡参数） |
|---|---|---|
| <15% | 无 | 无 |
| 15–30% | 心慌、口渴 | 耐力上限 −10%，`hp_cap` −15 |
| 30–40% | 头晕、视野发灰、意识混乱 | 不能疾跑，`hp_cap` −35，偶尔踉跄 |
| >40% | 意识模糊 | 随时昏倒；`hp_cap` −60；继续出血会致命 |

### 6.6 症状系统

症状定义（`D/body/symptoms/*.json`）：

```json
{
  "id": "dizziness",
  "channels": { "balance": [[0, 1], [1, 0.6]], "aim": [[0, 1], [1, 0.8]] },
  "client": { "sway": 0.6, "blur": 0.3, "stumble_chance_per_min": [[0.5, 0], [1, 2]] },
  "badge": { "icon": "dizzy", "show_from": 0.2 },
  "hint": { "from": 0.5, "key": "...", "cooldown_s": 120 }
}
```

- 来源（伤势、病症、生理量）各自报告"症状 id + 强度 + 来源"；同一症状多个来源按"最强一个 + 0.5 × 其余"合成（和体温热源同一规则），夹到 1。
- 客户端效果复用现有实现：寒颤镜头、热浪扭曲、霜花、辐射静电、耳鸣贴图和声音、HUD 脉冲；新加的只有模糊、去色、视野收窄、踉跄几种通用效果。
- 首批症状：疼痛、出血（看得见）、头晕、视物模糊、视野收窄、恶心、虚弱、乏力、呼吸急迫、寒颤（现有）、热衰竭（现有热阶段）、发烧、意识混乱、耳鸣（现有）、听力下降、跛行、手臂受限、失去意识。
- 每个症状**必须有来源**，来源消失症状就消失；不允许"挂着就永远不走"的症状。

## 7. 疾病与医疗恢复

### 7.1 概念分开

- **病症**（全身病程）：肠胃感染、辐射病、伤口感染（全身）、食物中毒、缺氧后、呛水、严重脱水、饥饿衰竭；以后：肺炎、感冒、一氧化碳中毒。
- **伤势**：部位上的损伤（第 6 节）。
- **症状**：病症和伤势表现出来的东西。

例：肠胃感染（病症）→ 腹痛、恶心、脱水加快（症状）；头部外伤（伤势）→ 头晕、视物模糊、平衡差（症状）。

### 7.2 病症定义

```json
{
  "id": "gastroenteritis",
  "stages": [
    { "id": "onset", "duration_s": [60, 120], "symptoms": { "nausea": 0.3 } },
    { "id": "acute", "duration_s": [180, 300], "symptoms": { "nausea": 0.6, "abdominal_pain": 0.5 },
      "effects": { "thirst_rate": 2.0, "energy_rate": 1.3 }, "blocks_recovery": true, "episodes": { "every_s": [60, 90] } },
    { "id": "recovering", "duration_s": [120, 240], "symptoms": { "weakness": 0.3 } }
  ],
  "treatments": { "oral_rehydration": { "stage_speed": 1.5 }, "antidiarrheal": { "symptom_scale": 0.5 } },
  "on_end": "none"
}
```

- 每个病症都有**出路**：要么到时间自己好，要么处理后好；会恶化的必须有能看见的征兆和可用的处理。
- 不做"不可逆、无法处理"的长期负面状态。允许的永久后果只有小幅、可选的（例如三度烧伤的疤痕、少量永久听力下降），由用户决定要不要。

### 7.3 迁移现有病症

| 现有 | V2 |
|---|---|
| `gastroenteritis` MobEffect | 病症，阶段同上；口渴 ×2、发作时口渴 −8 / 饱食 −2 保留；加"口服补液"处理（盐 + 糖 + 净水，或以后的电解质饮料） |
| `radiation_sickness` MobEffect | 病症，阶段按剂量（2/5/10/20 RU）保留；移速、治疗倍率、反胃改由症状层给；V3 加降剂量的药物（`辐射系统.md` §20） |
| 体温 C1–C3 / H1–H3 | 不存成病症（由核心体温直接推出），阶段后果改成症状；名字改成"冷 / 很冷 / 失温"等，避免和医学分级混淆 |
| 口渴阶段 | 同上，由水分直接推出 |
| `gasoline_soaked` / `diesel_soaked` | 保持 MobEffect（是环境状态，不是病），不迁移 |

### 7.4 医疗：处理框架

研究里的急救优先级（TCCC 的 MARCH：先大出血，再气道、呼吸、循环、头部和低体温；民用 ABC + 压迫止血）给出了处理顺序。游戏版：

| 处理 | 物品（V2） | 作用 | 时间（平衡参数） |
|---|---|---|---|
| 压迫止血 | 空手 / 布 | 按住期间出血 −70% | 按住，松手失效 |
| 包扎 | 布条（拆衣物、床单）/ 无菌绷带 | 止住轻中度出血；重度 −80%；绷带会被血浸透、会脏，脏了提高感染 | 4–6 s |
| 止血带 | 止血带 / 简易（布 + 木棍） | 四肢大出血立即止住；该肢体不能用；绑太久（平衡参数：1 个游戏日）有肢体损伤风险 | 5 s |
| 清洗 | 净水 | 降低污染 | 3 s |
| 消毒 | 酒精、碘伏 | 降低感染风险，治初期局部感染 | 3 s，痛 |
| 夹板 | 夹板 / 简易（木棍 + 布） | 骨折：疼痛下降、愈合正常速度、`hp_cap` 压制变小 | 8 s |
| 烧伤处理 | 冷水冲（离热源后）、烧伤敷料 | 降痛、降感染 | 冷却 5–10 s，敷料 5 s |
| 止痛药 | 对乙酰氨基酚 / 布洛芬 | 只降疼痛症状，有持续时间和每日上限 | 吃下 |
| 抗生素 | 抗生素（一个疗程多次服用） | 治伤口感染和全身感染 | V2 简化为数次服用 |
| 休息、营养 | 床、坐、吃喝 | 进入恢复区间（第 3.3 节） | — |
| 口服补液 | 盐 + 糖 + 净水 | 加快脱水和肠胃感染恢复 | 喝下 |

- **急救包是装着上面东西的容器**，不是一键回满。
- 轻伤：一次包扎就够，不包也能慢慢好；不打断节奏。
- 重伤：止血 → 包扎 → 固定 → 回去休息，要几步但每步都直观。
- 操作入口：人物页加"身体"页签（身体示意图 + 伤势列表），点伤势列出背包里能用的处理；也可以拿着医疗物品对自己按右键，自动选最需要的伤势。处理有时长（以后接骨骼动画），疾跑、游泳时不能处理。
- 多人：给别人处理（V3）。
- 处理效果可以接以后的"急救"成长项（V3 可选）。

### 7.5 听力

- 现有短时耳鸣保留（`GunshotExposureTracker`、爆炸耳鸣）。
- V2：单次大于阈值的暴露留"暂时听力下降"（研究：暂时性阈移通常 16–48 小时消失 → 游戏里几十分钟到一个游戏日）。
- 永久听力损失：研究确认枪声单次就可能造成永久损伤、毛细胞不能再生，但没有可靠的剂量阈值。建议**只做极小幅、可选**（例如反复不戴耳罩打大口径枪，世界音量永久 −5%，最多 −15%），由用户决定；默认关。

### 7.6 雷击：从 1000 点改成伤情

研究（Cooper & Holle 2010，作者自述数据不精确）：地电流 50–55%、侧闪 30–35%、上行流光 10–15%、直接雷击 3–5%、接触 3–5%，另有冲击波钝伤；最常见死因是当场心跳呼吸骤停；Merck 给出的死亡率约 10%（各来源不一）；常见后果有羽毛状浅表灼伤（Lichtenberg 纹，不是真烧伤）、鼓膜穿孔、短暂下肢瘫痪（keraunoparalysis，通常数小时内缓解）、意识障碍、长期神经症状。**下表的概率都是游戏平衡参数，不是医学统计。**

判定（每道闪电，对附近每个活物）：

| 类别 | 判定（平衡参数） |
|---|---|
| 直接雷击 | 被雷击中的目标本身（原版 AABB 内、离落点水平 ≤1 格的最高者） |
| 侧闪 | 离被击中的物体（树、杆、另一个人）0.5–2 格 |
| 地电流 | 离落点 2–8 格，站在地上；地面湿或站在水里范围 ×1.5；在有顶的建筑里没有 |
| 接触电压 | 碰着被击中的金属（铁栅栏、铁轨、以后的电线）——V2 以后有金属导体时再做 |
| 附近落雷 | 30 格内：闪光、雷声（现有），15 格内耳鸣、受惊 |

后果：

| 类别 | 心跳骤停 | 生命 | 其他 |
|---|---|---|---|
| 直接雷击 | 75% | 存活者 −50~70 | 多处浅表烧伤 + 1–2 处二度烧伤；腿部短暂瘫痪 60%（1–3 游戏小时）；失去意识 30–90 s；耳鸣 + 鼓膜破裂（听力下降）；衣服着火（现有 8 s） |
| 侧闪 | 15% | −25~45 | 浅表烧伤；短暂瘫痪 40%；失去意识 30%；耳鸣 |
| 地电流 | 2% | −5~25（随距离） | 腿部肌肉痉挛 → 摔倒（可能二次外伤）；腿痛；短暂瘫痪 15%（几分钟） |
| 附近落雷 | 0 | 0 | 耳鸣、闪光眩目 |

- **心跳骤停**：立刻失去意识，30 s 内没有心肺复苏就死亡。V1/V2 单人没有施救手段，所以直接雷击对单人仍然极其危险（约 3/4 死亡）；V3 多人加心肺复苏 / AED 后可救。这样"直接雷击极其危险、但不是每次必死"，被侧闪或地电流击中的大多能活下来。
- **车辆保护**：研究确认硬顶全封闭金属车身能保护乘员（电流走外壳，不是轮胎绝缘），敞篷、软顶、摩托车不安全，车内不要碰金属部件。
  - 每种载具在定义里给 `lightning_shield`（0–1）；T15 驾驶室座位在**门全关**时为 1（乘员只有耳鸣和闪光，车本身可能电子故障，V2 再做），开着门 0.5（按侧闪处理的概率减半），车斗座位 0。
  - 以后的敞篷、玻璃钢车身为 0。
- 实现位置：`LightningStrikes` 保留"每道闪电对每个实体只处理一次"，把 `hurt(1000)` 换成按类别生成伤势和病症。

## 8. 与人物特质、成长系统的兼容

### 8.1 原则

- 最大生命**所有人都是 100**，任何等级、成长都不加生命上限（现在只有 ±2 的特质，改掉）。
- 个体差异放在"抵抗和恢复"上，幅度控制在 ±10–25%；成长项不碰生命。
- 现在的膨胀在耐力（续航 ×2–2.9）和负重（×1.6），不是生命；本设计不改它们，但把能量消耗和耐力消耗挂钩后，高续航的人会多吃一点，抵消一部分。

### 8.2 新属性（V1 起按需加）

| 属性 | 默认 | 作用 |
|---|---|---|
| `breath_capacity` | 1 | 呼吸容量 |
| `bleed_rate` | 1 | 出血速度 |
| `wound_healing` | 1 | 伤口、骨折愈合速度 |
| `infection_resist` | 1 | 伤口感染、生病几率（乘在概率上，<1 更不容易） |
| `pain_tolerance` | 1 | 疼痛症状强度 |
| `injury_severity` | 1 | 新伤的严重度 |

已有的 `natural_regen`、`raw_water_sickness`、`radiation_sensitivity`、`body_temp_rate`、`fall_damage` 保留并接入新系统。

### 8.3 特质调整建议（需要用户确认；用户也在重新设计特质）

| 特质 | 现在 | 建议 |
|---|---|---|
| 体质好 | 生命 +2、回血 ×1.2 | 去掉生命 +2；回血 ×1.2、`infection_resist` ×0.85 |
| 体弱 | 生命 −2、耐力恢复 ×0.9 | 去掉生命 −2；`injury_severity` ×1.1、`infection_resist` ×1.2、耐力恢复 ×0.9 |
| 落地稳 | 摔伤 ×0.8 | 摔落的生命损失 ×0.8、扭伤 / 骨折概率 ×0.7（更能感觉到） |
| 铁胃 / 肠胃弱 | 生水生病 | 同时作用于以后的食物中毒 |
| 烟瘾 | 耐力上限 −10 | 加 `breath_capacity` ×0.85 |
| 运动员 | 耐力 | 加 `breath_capacity` ×1.1 |
| 可新增（供用户参考） | — | 不怕见血（处理伤口更快）、凝血差（`bleed_rate` ×1.3）、恢复快（`wound_healing` ×1.2）、怕疼 / 能忍疼（`pain_tolerance`） |

### 8.4 身体和成长

- 体能：加 `breath_capacity` 曲线（1 级 ×0.8 … 10 级 ×1.35）；体能经验来源加"憋气游泳"。
- 力量：可选小幅降低摔落和挤压伤的严重度（`injury_severity` 最多 ×0.9），不加生命。
- 耐寒成长：同时减轻冷水休克。
- 以后的"急救"成长项（V3，可选）：处理速度、包扎质量。

## 9. 现有系统迁移和存档兼容

### 9.1 逐个系统

| 系统 | 保留 | 调整 | 迁移 / 停用 |
|---|---|---|---|
| 生命 | 原版生命字段、原版同步 | 最大 100；恢复改成恢复区间 + `hp_cap` | 原版饱食回血停用（`FoodDataSurvivorStatsMixin`、`FoodDataThirstMixin` 改为接新规则） |
| 伤害 | 原版 `hurt` 流程、护甲、伤害类型标签 | `LivingDamageEvent` 里按 `damage_rules` 换算 | 闪电 1000、脱水 / 失温 / 辐射扣血按第 3.6 节换算 |
| 饥饿 | 原版 `foodLevel` 当"胃" | 新增能量储备 | 原版消耗度、饱食 ≤6 惩罚、饿死停用；`hunger_rate` 改乘能量消耗 |
| 口渴 | 数值、存档键、包、饮水全部保留 | 后果分档按第 5.4 节 | 直接扣血 → 病症 |
| 耐力 | 全部保留 | 新增"上限修正"入口给能量、失血、骨折用 | 饥饿 / 口渴 / 体温的恢复倍率改由症状层给（避免重复） |
| 体温 | 全部保留 | 阶段后果改成症状 | 直接加的移速修饰、扣血交给症状层和第 3.6 节 |
| 辐射 | 剂量、Capability、盖革全部保留 | 辐射病 → 病症 | MobEffect 停用（读档时转换） |
| 肠胃感染 | 感染规则保留 | → 病症，加处理 | MobEffect 停用（读档时转换剩余时间） |
| 耳鸣 | 全部保留 | 加暂时听力下降 | — |
| HUD | 生存模块布局保留 | 生命弧改连续弧（100 HP 不再按 2 HP 一格，30 格上限去掉）；徽章接症状；人物页加"身体"页签 | 生命数字显示 `当前 / hp_cap`（上限被压低时用另一种颜色标出被压掉的部分） |
| 遗体、死亡 | 全部保留 | 死因写入伤势摘要（"失血""失温"等） | — |
| 幸存者属性 | 全部保留 | 加第 8.2 节的新属性 | 体质好 / 体弱的 `max_health` 修饰改掉 |

### 9.2 存档

- 新键 `afl_body`（带版本号）。旧存档没有这个键 → 按健康状态创建。
- 生命：第一次以新版本登录时，最大生命从 20 变 100，当前生命按比例换算（`× 5`），并夹到新上限。`SurvivorModifiers` 每次登录都会按名字前缀重建修饰，所以去掉体质好 / 体弱的生命修饰不会留下残余。
- MobEffect：读档时把剩余的 `gastroenteritis` / `radiation_sickness` 转成病症再移除。
- 口渴、耐力、体温的存档键不变。
- 死亡时 `afl_body` 和其他生存键一起删除（现有规则）。
- 协议号加 1（新的身体状态包）。

### 9.3 网络同步

- 本人：完整身体状态（伤势列表、病症、症状强度、`hp_cap`、血量、呼吸、能量），变化时发，最长 2 s 必发一次。
- 其他玩家：只发看得见的东西（跛行、捂伤口、流血粒子、失去意识姿势），给骨骼动作用。
- 服务器权威；客户端只画。

### 9.4 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 原版和其他模组的伤害都在 20 HP 尺度 | 改成 100 HP 后不换算会变得极难死 | 默认 ×5 兜底 + 已知类型逐个写规则 |
| 护甲公式依赖伤害大小 | 先乘再算护甲会让护甲变弱 | 在护甲之后（`LivingDamageEvent`）换算 |
| 原版回复效果（再生、瞬间治疗、金苹果、吸收、不死图腾） | 不换算会显得很弱 | 同系数换算；以后再按 AFL 口味调 |
| 原版生物（感染者现在就是原版僵尸） | 伤害、伤势生成要单写 | 感染者近战单写规则；AFL 感染者重做时（动物计划）一起定 |
| 多个系统都在改同一属性 | 重复计算 | 第 2.3 节：只由症状层写 |
| 现有 GameTest（幸存者属性、口渴、体温） | 断言会失败 | 实施时同步改 |
| 闪电已实机 PASS | 行为大改 | 分开做，单独给用户看 |
| HUD 是 GPU 着色器（最多 48 条 band） | 生命弧改连续弧 | 正好减少 band 数 |
| 多人 / NPC | 以后要共用 | `BodyState` 从一开始挂在 `LivingEntity` 上 |
