# Pavement Markings V1：停车场地面标线

状态（2026-10-08）：**已做进游戏，用户 PASS**。方案图用户同意（轮椅标志 1 格就行）。A1 停车场的标线 2026-10-08 写进开发存档（294 格，读回一致），用户看过后手动改了一部分线，PASS。

用户第一次实机（同日，截图）提了三点，第二版都改了：
1. **"为啥这个线是黄色的"**：交叉斜线默认是黄色，物品图标却是白的。现在不带颜色的物品都是白色，创造栏里白、黄、蓝各放一个，图标和名字跟颜色走。
2. **"这些小型的模型你没有用 mesh 吗，锯齿感有点重"**：第一版的斜线、箭头、轮椅标志是从贴图里按透明度抠出来的，45° 和弧形的边每 4 mm 一个台阶，近看是锯齿。现在这些图形是多边形 mesh（`forge:obj`），边由几何决定。直线（格边线、格中线、宽条）和像素对齐，本来就没有台阶。
3. **"两种斜线的对角不是一样的"**：不是有意的。第一版线宽只加在对角线的一侧，两个方向不对称；单块时角上还多出一个小三角（相邻格的线经过这个角的部分）。用户又指出"左上角的斜线不是还有一点残留吗"。现在线居中压在对角线上，角上的小三角只在旁边真有斜线接着时才画（见下面"斜线的角"）。

## 为什么做

- A1 下一步是停车场。用户问现有的标线够不够用。
- 现有的三种是高速那一轮做的：`edge_lane_white` / `edge_lane_yellow`（格边线）、`white_lane_divider`（格中线，可画虚线）。
  - 它们是放在地面上面那一格的薄片（`RoadMarkingBlock`），线宽 12.5 cm，相邻自动接转角和拐弯，1 格高差有过渡件。
  - 原来贴图 16 × 16，没有 PBR。
- 停车场能用它们画直的车位线和车道边线。缺的是：
  - 无障碍车位（蓝线、斜线通道、轮椅标志）；
  - 箭头、人行横道、停止线；
  - 黄色禁停斜线；
  - 地面文字、路缘漆（等路缘）。
- 这些都是通用资产，以后别的停车场、城市道路、高速都能用。

| `pavement_arrow` | 地面箭头 / Pavement Arrow | `PavementArrowBlock` | `facing`、`kind`（straight / left / right）、`part` 0..5 | 直行 1 × 3 格（2.8 m），part 0 箭头 … 2 箭尾；转弯 2 × 3 格，part = 行 × 2 + 列（左转的画法，右转是它的镜像）；part 4（箭尾旁边那格）没有漆，不放方块 |

物品：
- `edge_lane_blue`、`pavement_accessible_symbol` 是普通方块物品。
- `pavement_hatch`、`pavement_crosshatch`、`pavement_bar` 的物品（`PavementPaintBlockItem`）带颜色：颜色写在原版的 `BlockStateTag` 里，放下时原版会套用；不带标签是白色。创造栏每种列白、黄、蓝三个，图标按颜色着色，名字后面带颜色（"地面交叉斜线（黄）"）。中键选取拿到同色的物品。
- 箭头方块没有自己的物品；`pavement_arrow_straight` / `_left` / `_right`（直行箭头 / 左转箭头 / 右转箭头，`PavementArrowItem`）一次放下整个箭头。点的那一格（或点的地面上面那一格）是箭尾，箭头指向玩家看的方向；每一格都要空着、下面有完整顶面，否则放不下。中键选取拿到对应的箭头物品。

规则：
- **`facing`**：放置时取玩家看的方向。箭头指过去；轮椅标志对着这个方向的人是正的；宽条横在这个方向上（停止线：站在车道里朝前放；人行横道：站在横道上朝过街方向放）。
- **改色**：拿白、黄、蓝染料右键斜线、交叉斜线、宽条，换颜色（生存模式消耗 1 个染料），准星提示"涂色"。颜色是方块着色（`client/PavementMarkingClient`），贴图本身是白漆。
- **放置**：下面要有完整顶面，下面的方块没了漆也没了。没有碰撞，很薄的选择框（0.25 px）。
- **拆**：拆箭头任何一格，整个箭头一起没。
- **结构旋转 / 镜像**：`facing` 跟着转；镜像时左转、右转互换。

挖掘审计（AGENTS）：和现有道路标线一样，漆面不是可回收的材料。
- 硬度 0.1，一下就碎；不需要工具，不加挖掘标签和等级。
- 没有掉落表，拆了什么都不掉。
- 活塞推会碎。
- 重量 `item_mass` 0.05 kg（估计，和现有标线相同），只在物品栏里有意义。

## 斜线的角

- 斜线从格子一角画到对角，线有宽度，所以经过别的格角时，有一个小三角落在这一格里（相邻格的线经过这个角）。
- 拼成一片时，这些小三角把线在格角处接上；没有它们，每个格角的线会收成一个点（像领结）。单块时它们看着像残留。
- 所以四个角各有一个状态（`ne` / `sw` / `nw` / `se`，模型坐标：按朝北画，随 `facing` 转）。只有旁边同种方块把线接过来时才画：
  - `ne`：模型北边或东边的邻居；`sw`：南边或西边（主对角线）；
  - `nw`：北边或西边；`se`：南边或东边（交叉斜线的另一条，只有交叉斜线有）。
  - 单向斜线的邻居还要斜向相同（`facing` 同轴）才算接得上。
- 放下时、邻居变化时（`updateShape`）重算。方块状态里多了四个布尔值，渲染是 multipart：主线一直画，四个角按状态加。

## 贴图和模型

生成器：`tools/build-pavement-markings-v1.mjs`（不带参数写资源，`--check` 校验）。
- **规格**：每格 240 texel，和 [地面材料](ground_materials_v1.md) 同一档。
- **颜色**：白 [236,235,230]、黄 [228,180,60]、蓝 [46,98,172]。斜线、交叉斜线、宽条用白漆贴图加着色：黄 0xF6C343、蓝 0x326ABF（方块按 `color`，物品按 `BlockStateTag`，`client/PavementMarkingClient`）。
- **mesh（第二版）**：
  - 斜线、交叉斜线、宽条、箭头、轮椅标志都是 `forge:obj` 模型（`models/block/marking/*.obj`），离地 0.1 px，轮椅图形的白色在蓝底上面 0.12 px。
  - 生成器把图形写成多边形（斜线是沿对角线的长条，箭头是轮廓，轮椅是圆、粗线段、圆弧带），拆三角形（耳切法），再按格子裁开，每格一个 OBJ。
  - UV 等于格内位置，贴的是线用的漆面贴图（`edge_lane_white` / `edge_lane_blue`），着色件在 MTL 里写 `forge_TintIndex 0`。
  - 只有朝上的面，平面光照（`ambientocclusion: false`），`solid` 层。
  - 拆三角形时，落在耳朵边上的顶点也算挡住；第一次没算，直行箭头底边上的共线点被拆出一个跑出轮廓的三角形，按格子画回来检查时发现并改了。
- **漆面**：
  - 完整的新漆，只有很淡的大块色调变化（±1.2%）。
  - 漆厚 0.8 mm，边上的法线有一点斜面。
  - LabPBR：光滑度 105、F0 14、孔隙度 12。
- **磨损**：第一版做过磨损（漆磨掉露出沥青的斑点）。用户问"这些坑是啥"，要第一版先做完整的，等以后做全世界通用的磨损 / 破坏系统再说，所以去掉了。生成器 `paint()` 留着 `worn` 选项，默认关。
- **渲染**：三种旧线、蓝线和台阶过渡件在 `AflBlockRenderTypes` 里从 `cutout` 改成了 `cutoutMipped`（240 的漆面不带 mipmap 远处会闪）。mesh 拼块是 `solid`。
- **现有标线升级**：
  - `edge_lane_white` / `edge_lane_yellow` / `white_lane_divider` 的贴图换成 240 的漆面（满格都是漆，模型取哪一块都一样）。
  - 它们的模型、边界转角、台阶过渡件和 `highway_ribbon_*` 父模型的 UV 由生成器改成按几何实际尺寸。原来是随手取的贴图小块，换成 240 贴图会把漆面纹理拉长。
  - 这些是高速那一轮的文件，所以高速上的标线也一起变了。
- **蓝色边线**：复制白色边线的方块状态和 5 个模型，只换贴图。
- **物品图标**：同样的多边形画成一格的图（`textures/item/pavement_*.png`），箭头整个缩进一格，斜线只画主线。
- **文件位置**：漆面贴图在 `textures/block/`（`edge_lane_*`、`white_lane_divider`）；mesh 在 `models/block/marking/`。第一版抠图用的 `textures/block/marking/` 已删除。
