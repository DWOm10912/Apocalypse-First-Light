# AFL Equipment Meshes V1（装备网格）

> 2026-10-10：AFL 的 Mesh 加载与渲染已迁移到独立库 Vextris，`AflMeshLoader` / `AflMeshCache` / `AflMeshRenderer` / `AflHybridMeshRendering` / `AflMeshModel` / `AflMeshPart` 已删除；本文中的这些类名是当时的历史名称，对应关系见 [Vextris 迁移 V1](../dev/vextris_migration_v1.md)。

状态：**已实现（2026-10-03），生成脚本 `--check` 通过，编译通过，没有实机验证**。2026-10-14 加了撬棍、网格背包的五件装备和隔音耳罩（见下文“2026-10-14 新增”），同样没有实机验证。2026-10-15 加了盖革计数器 V2（见文末“2026-10-15 新增”），没有实机验证。

装备类物品（随身带的、戴在身上的）用和 Material Meshes（`material_meshes_v1.md`）同一套 bake：
- 物品栏里是一张由网格按图标视角渲染出来的平面图（2026-10-21 起是带贴图的 64×64 渲染图，以前是 16×16 像素图标，见 [material_meshes_v1.md](material_meshes_v1.md)「物品栏图标」）；
- 手持、掉落、展示框，以及戴在身上（各自的 Curios 渲染器）时，显示 AFL 网格；
- 每件一张 256 的 LabPBR 贴图集（Base Color / `_s` / `_n`），一个骨骼。

用户的决定（2026-10-03）：装备的网格由 Claude 制作，要做 PBR；做一个装备专用的网格生成脚本，以后的装备（背包、生存监测仪等）都往里加。

## 生成脚本

`tools/build-equipment-meshes-v1.mjs`

```text
node tools/build-equipment-meshes-v1.mjs [id ...]               写出源文件、贴图集、geo、AFL 网格、图标、物品模型
node tools/build-equipment-meshes-v1.mjs [id ...] --check       检查所有输出是否最新
node tools/build-equipment-meshes-v1.mjs [id ...] --preview DIR 只把输出写到 DIR，用来离线看
```

- `ITEMS` 里每件装备一个函数，返回 `{PARTS, MATS, icon, anchor?, worn?, hud?, atlas?, meshOnly?}`，交给 `build-material-meshes-v1.mjs` 的 `bake()`。加新装备就是加一项。
- 输出位置和材料网格相同：`src/main/blockbench/<id>.bbmodel`（可编辑源）、`geo/<id>.geo.json`、`meshes/<id>.aflmesh.json`、`models/item/<id>.json`（`forge:separate_transforms`）、`textures/item/<id>.png`（图标）、`textures/item/<id>_mesh{,_s,_n}.png`（也复制到 `src/main/blockbench/textures/`）。
- 打印的统计里有 `verticalOffset`（填到 `AflStaticMeshItemClient` 的 `bind`）；戴在身上的装备还有 `wornAnchor`，即身体锚点（比如手臂轴线）在烘焙后网格里的位置（单位：像素），填到对应的 Curios 渲染器里。
- 尺寸按图标大小建模（单位：像素），和材料网格一样。

## `bake()` 新增的能力（`build-material-meshes-v1.mjs`）

这些都是可选项，不用时输出和以前逐字节相同（材料网格、电池的 `--check` 都通过）。
- **玻璃**：材质写 `alpha`（0–255），它的 UV 岛在 Base Color 里就用这个透明度；全部由这种材质组成的部件进入网格的半透明层（`render_layer: translucent`，游戏里由 `AflHybridMeshRendering` 画）。玻璃按 AFL 规则：F0 10、光滑度 235，透明度至少 26（光影的 alpha 测试），一般用 70–110 才能在 Sundial 下看得见。
- **图标 `xray`**：列出的材质（玻璃）只在后面没有别的部件时才画，所以图标里能看到玻璃里面的东西。
- **`display`**：按场合覆盖物品的显示变换（细长的工具按原版手持物品的方式拿）。没写 `display` 的物品，第三人称的平移按网格算，让离手最近的一点落在扳手的握点上（2026-10-21，见文末「第三轮」）。
- **图标 `seamless`**：列出的部件周围不画深色接缝（1 像素的指针会留下一个深色十字）。
- **图标 `depthSeam`**（2026-10-13，给绝缘铜线的线卷加的）：同一个部件前后两段相差超过这个深度时也画接缝，见 [Material Meshes V1](material_meshes_v1.md)「物品栏图标」。
- **`atlas`**（2026-10-14）：贴图集边长，默认 256；背包、胸挂这类大件用 512，保持贴图密度。
- **`meshOnly`**（2026-10-14）：不写物品模型和图标，只要网格（没有物品、只由代码画的东西，比如斜挎在身上的枪背带）。
- **`texelsPerPx`**（2026-10-22）：UV 展开的起始贴图密度，默认 40（不写时输出不变）。很薄、面积小的物品（书）图集只用到一小块时调高，让贴图填满图集。
- **图标 `hide`**（2026-10-14）：列出的部件不画进图标，图标的取景也不算它们。穿戴装备绕身体的带子（肩带、腰带、腿带）离开身体会变成悬空的圈，图标里只画装备本体。

## 物品

### 体温计 `clinical_thermometer`

- 一根 8 棱的玻璃管（直径约 1.3 像素，长 12.35 像素），里面有白色搪瓷衬条和红色液柱；一端是装满红色液体的感温泡，另一端玻璃收圆。沿 X 轴放，感温泡在 -X。
- 材质：玻璃（alpha 110）；红色液体 `[168,52,44]`，介电质；白色搪瓷 `[206,203,194]`。
- 图标：视角 `[30, 45, 0]`，感温泡在左下，红色液柱透过玻璃看得到。
- 手持显示：`verticalOffset` 0.46189。拿在手上的变换不用材料网格的“拿方块”尺寸规则，而是照原版木棍、剑（handheld）的变换，Z 轴多转 -135°：原版手持图标的杆从左下指向右上，这个网格沿 X 轴、感温泡在 -X，这样转完是捏着玻璃尾端、感温泡朝外（第三人称 `[0, -90, -80]`，平移 `[0, 4, 0.5]`，缩放 0.85；第一人称 `[0, -90, -110]`，平移 `[1.13, 3.2, 1.13]`，缩放 0.68）。

## 2026-10-14 新增：撬棍、网格背包装备、隔音耳罩

用户 2026-10-14 看了 E 界面后的要求：撬棍先用网格重做，再从网格出一张剪影；新加的装备不能只有 2D 图标，要有网格模型；胸挂、背包、枪背带、手枪枪套要实时画在玩家身上；别忘了 PBR。同一轮又加了一句：隔音耳罩也顺便网格化。

### 生成脚本新增的部分（`tools/build-equipment-meshes-v1.mjs`）

- 工具函数：`loft`（截面环连成管，开口端补盖）、`hexSection`（六角钢截面）、`strap`（扁带：沿一串点放矩形截面，带子宽度贴着身体，厚度朝外）。
- **身体壳**：带子都贴在一个“圆角盒子”上：内盒加半径，正好包住身体部件和皮肤外层，转角是圆的，带子翻过肩膀、腰侧时不会切进身体。`TORSO`（躯干）、`LEG`（腿）；`onShell`、`shellArc`（在一个平面里绕壳一圈）、`shellLine`（沿折线压到壳上）。
- 几条带子的离壳高度各不相同（胸挂腰带 0.11、胸挂肩带 0.13、背包肩带 0.12、登山包腰带 0.2、胸带 0.42、身上的枪背带 0.4），同时穿戴时不会有两条带子落在同一个面上。
- **穿戴坐标**（`worn: true`）：装备按它所在身体部件的坐标建模，烘焙后统计里多一个 `origin`（烘焙平移），渲染器先平移 `-origin / 16` 再画，就回到建模时的位置：
  - 躯干：原点在身体的轴点（脖子，躯干顶面中心），+X 是玩家的左边，+Y 向上（躯干 y -12..0），+Z 向前（躯干 z -2..2）。Java 里是 `body.translateAndRotate` 再 `scale(1, -1, -1)`。
  - 右腿：原点在髋关节，+X 朝外（玩家右边），+Y 向上（腿 y -12..0），+Z 向后。Java 里是 `rightLeg.translateAndRotate` 再绕 Z 转 180°。
  - 头：原点在头的轴点（脖子），+X 玩家左边，+Y 向上（头 y 0..8），+Z 向前；和躯干一样转。
- **HUD 剪影**（`hud`）：从网格正交投影画一张武器列表用的侧视剪影，写到 `textures/gui/melee/<id>_hud.png`。配色照枪的 `textures/gui/gun/*_hud.png`：平涂灰色、左上方来光，外轮廓一圈稍暗，2 倍超采样抗锯齿。`hud: {screen, toward, scale, aspect}`：网格坐标到屏幕的映射、朝向观察者的方向、每个网格像素画多少屏幕像素；`aspect` 可选，图片宽高比的上限，细长的武器上下补透明行，武器列表（按行高画）里就不会比手枪剪影长。

### 撬棍 `crowbar`（替换 V1 方块模型）

- 锻造六角钢撬棍，对边 0.87 像素，全长 27.6 像素。下端向 +X 弯 22° 成扁铲口；上端是鹅颈弯（半径 1.75 像素、弯 185°），末端是分叉的起钉爪，V 形开口往尖端变宽。
- 材质：杆身红色粉末涂层 `[150,38,32]`（光滑度 128，F0 22）；铲口最后 1.25 像素和鹅颈后半段到起钉爪是裸锻钢 `[104,106,108]`（光滑度 96，F0 230）。真实撬棍出厂涂漆，两个工作端磨亮。
- 建模坐标就是 V1 方块模型的坐标（杆在 x = 0，沿 +Y，爪弯向 -X），所以第一人称的绑定不变（见 [Crowbar First-Person V1](../crowbar_first_person_smash_v1.md)）。
- 588 个三角面，256 贴图集，贴图密度 9.5 texel/像素。烘焙平移 `origin` = `[1.456, 5.0271, 0]`。
- 物品：`verticalOffset` = (-0.8 - 5.0271) / 16 = -0.36419375，杆的高度和 V1 一样；水平方向比 V1 偏了约 0.46 像素（V1 的杆在物品坐标 x = 9，网格的居中方式到不了），我接受了这点偏差。手持、掉落、展示框沿用 V1 的显示变换；物品栏是网格画的 2D 图标（视角 `[0, 0, -45]`）。
- HUD 剪影：`textures/gui/melee/crowbar_hud.png`，1107 × 207，每个网格像素画 40 像素，爪在左、向上弯。
- **挂起来**（2026-10-21，编译通过，未实机）：`WorkbenchRenderer.crowbar`，真实大小（缩放 0.508，全长 86 cm）。按全钢算，网格体积 20.36 立方像素，约 5.1 kg，重心在网格 `(-0.359, 10.434)`。鹅颈钩内径 7.9 cm，钩不住一对钉，只挂一根。
  - 木质工具架：挂在 -x 那根钉上自由下垂，转 -8°，重心正在钩心下面，往下垂 84 cm。
  - 工作台：桌面离钉子只有 72 cm，所以挂在 +x 那根钉上，铲口拄在桌面上斜靠，转 -37.75°。
  - 每种挂法存一个网格点（烘焙后的像素）：这个点落在槽位中间、钉子中心的高度。工具架是 `(1.1419, 26.4254)`，工作台是 `(-1.8002, 25.3175)`。
