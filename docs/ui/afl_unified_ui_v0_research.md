# AFL 统一界面与网格背包：塔科夫调研和方案草案

状态：**调研和草案（2026-10-14），没有实现。** 现有界面和背包规则都没有改。

后续（同一天）：用户把范围收窄到 HUD 层 + E 背包层的网格背包核心，背包格子随穿着动态显示，武器快捷栏定为 2 主 + 2 副 + 1 近战。这些决定和第一轮概念图见 [afl_inventory_grid_v0_concept.md](afl_inventory_grid_v0_concept.md)；下面第 4 节里和它冲突的地方（快捷栏 9 格全部当快速使用栏、先出四张界面概念图）以那份文件为准。

## 1. 用户的目标（2026-10-14）

- 统一界面：生存模式物品栏、创造模式物品栏、新建世界、主界面、加载界面，用同一套 AFL 样式。
- 背包像塔科夫：物品按重量、大小占不同的格子数。
- 模块化装备：头盔、内衬、外套、防弹插板、手套、手表等。
- 用户让我先查塔科夫的界面是什么样。

## 2. 塔科夫的界面（调研结果）

来源：Steam 商店页截图（Battlestate Games，app 3932890）、官方 wiki（escapefromtarkov.fandom.com）的容器、胸挂和护甲页面。

### 2.1 角色 / 装备界面（Gear）

- 左栏：装备栏位，每个是带标题的方框，里面画物品图标：
  - 耳机、头部、面罩；
  - 臂章、防弹衣、眼镜；
  - 狗牌；
  - 武器：背带上的主武器、手枪套、背上的第二把主武器、刀鞘。
- 中间：人物剪影，跟着装备变化。
- 下方：一行数值（负重、生命、水分、能量）。
- 右栏：
  - 胸挂：它自己的格子布局；
  - 口袋：4 个 1×1；
  - 背包：它自己的格子布局；
  - 特殊栏位。
- 再往右：仓库，一整块网格。左边一列图标按类别筛选，上面有搜索和整理按钮。
- 屏幕底部：快速使用栏（数字键 4–0）。最底一行是全局导航：角色、商人、跳蚤市场、改枪、手册、消息。

### 2.2 网格规则

- 每件物品占一个矩形，例如 1×1、2×1、5×2。很多物品可以旋转 90° 塞进空位。
- **容器套容器**：一个物品在外面占的格子少，里面开一块更大的网格。
  - 例：保温袋外面 3×3，里面 8×8；文件包外面 2 格，里面 4×4。
  - 有的容器只能放某几类东西（医疗箱只放药品，弹药箱只放弹药）。
- **胸挂、背包的内部不是一整块**，而是几块独立的小格：
  - 例：一件胸挂里面是 4 个竖着的 1×2 弹匣袋，加上下面 3 个大小不一的口袋，共 20 格；
  - 所以一个 2×2 的东西放不进两个相邻的 1×2 袋里。
- 物品图标上有短名、数量、耐久；未检视的物品显示问号。

### 2.3 护甲是模块化的（0.14 改版以后）

- 防弹衣、带甲胸挂主要是**载具**：提供插板槽（前、后，有的还有侧面），自带一部分软甲区域。
- 插板决定硬甲等级。软甲最高 3 级，插板最高 6 级，所以主要防护来自插板。
- 带甲胸挂占胸挂栏，同时挡住防弹衣栏（不能同时穿）。
- 头盔可以加部件：护颊、护目镜、头顶附加板，以及夜视仪支架。部件各自覆盖头顶、后脑、耳朵、眼睛、下颌这些区域。
- 头盔会挡住别的栏位：有的头盔戴上就不能再戴耳机、眼镜或面罩。

### 2.4 衣服和装备是分开的

- 塔科夫的上衣、裤子是纯外观（在商人那里换），不在装备栏里，不影响数值。
- AFL 不一样：用户要外套、内衬这些参与保暖，所以 AFL 的衣服要进装备栏（第 3 节）。

### 2.5 其它界面

- 主界面：深色背景，人物站在中间，几个大号文字按钮；底部一行全局导航。
- 加载：1.0 版的进入战局加载有进度条，显示当前阶段、预计时间和已等待时间。
- 商人 / 换装界面：顶部一排商人头像，中间是穿着当前衣服的人物，两侧是上身、下身的衣服列表，每行标着“可用 / 已装备 / 不可用”。
- 整体风格：深灰到黑的底色，细边框的方框，标题小字大写，强调色很少（黄、绿、红）。

## 4. 方案草案（待用户决定）

### 4.1 背包怎么接到 Minecraft 上

Minecraft 的背包是 36 个“格子 + 一叠物品”。网格背包要处理的地方很多：拾取、所有容器界面、Shift 点击、漏斗、死亡、创造模式、其它模组。草案：

- **原版 36 格只留快捷栏 9 格**，当作快速使用栏。生存模式现在本来就是这样。
- **网格存在装备里**：口袋固定在玩家身上；胸挂、背包各自带内部网格，随物品存档，掉落、放进尸体时东西还在里面。
- **物品尺寸用数据文件**（像 `item_mass` 一样），按真实大小定。没写的物品默认 1×1；可以旋转。
- **堆叠**：保留 Minecraft 的堆叠，一叠占一个物品的格子；大件的堆叠上限另外审。
- **拾取**：地上的东西先进快捷栏，再按口袋、胸挂、背包的顺序找第一个放得下的位置；放不下就留在地上。
- **容器**：
  - 尸体和 AFL 的搜刮容器改成网格；
  - 原版箱子、机器、其它模组的容器保留格子，只换样式。从这些容器拿东西进网格时，照样按尺寸放。

### 4.2 装备栏位（初稿）

| 部位 | 栏位 | 说明 |
|---|---|---|
| 头 | 头盔 / 帽子 | 头盔可加部件：护目镜、夜视支架、附加板；有的头盔挡住耳部或面部栏 |
| 面 | 面罩 / 口罩，眼镜 | 防毒面具以后和辐射、烟雾挂钩 |
| 耳 | 耳罩 / 耳机 | 已有（耳部栏） |
| 身体 | 内衬 | 贴身保暖层，例如保暖内衣、抓绒 |
| 身体 | 外套 | 夹克、大衣，管保暖和防风雨，可以带几个口袋格 |
| 身体 | 防弹衣（插板载具） | 前、后、侧插板槽；插板单独是物品，有等级和耐久 |
| 身体 | 胸挂 | 内部是几块独立小格；带甲胸挂同时占防弹衣栏 |
| 背 | 背包 | 已有（背部栏）；内部网格 |
| 手 | 手套 | 保暖，以后影响操作 |
| 手腕 | 手表 / 腕式仪器 | 已有（手腕栏，腕式温度计） |

“内衬”这里理解成贴身穿的衣服层；如果用户指的是头盔或防弹衣的内衬，就改成头盔部件或载具里的软甲层。

### 4.3 统一界面的范围

| 界面 | 现在 | 方向 |
|---|---|---|
| 生存模式物品栏 | 原版，加 3 个 Curios 格 | 换成塔科夫式装备界面：左边装备栏位，中间人物（Slim / Classic 都对），右边胸挂、口袋、背包的网格；底部是快速使用栏和负重、体温等数值 |
| 创造模式物品栏 | 原版标签页（10 页） | **不改**（用户，2026-10-14：正常游玩开不了创造，只在录视频时用） |
| 新建世界 | 原版，加了模式按钮 | AFL 样式的单页：世界名、模式（普通 / 困难）、种子、世界类型 |
| 主界面 | 原版 | AFL 标志，深色背景，以后可以换成动态场景（例如老宅）；按钮少而大 |
| 加载界面 | 原版 | 进度条加阶段文字（生成地形、准备出生点……）。Forge 在游戏窗口出来之前的那个早期加载窗口几乎改不了，只统一游戏里能接管的部分 |

### 4.4 推荐顺序

1. **概念图一轮**：装备界面、主界面、加载、新建世界，各出一张 PNG，用户一次定风格。
2. **网格背包核心**：尺寸数据、快速使用栏、口袋、胸挂、背包、拾取、尸体，单人和多人同步。这是风险最大的一块，先做。
3. **装备栏位和第一批装备**：头盔、内衬、外套、插板载具和插板、手套；每件都有网格、穿在身上的样子、保暖和负重数据。
4. **其余界面换样式**：主界面、新建世界、加载、创造模式。

## 5. 要用户定的事

1. 原版箱子和其它模组的容器保留格子（只换样式），还是全部改成网格？草案：保留格子。
2. 物品要不要像塔科夫那样“检视”以后才知道是什么？草案：不做，AFL 已经有逐格搜刮。
3. 衣服进装备栏、参与保暖（和塔科夫相反）。草案：进。
4. 先做哪一步：草案是先出概念图，再做网格背包核心。
